## 1. The headline lesson is disposition, not detection

Most round-1 reviewer complaints were things our own pipeline had **already flagged** on the exact same lines. Reviewers independently confirmed the standards' judgment; the flagged code shipped anyway because enforced repairs broke matches and were retained per bank policy (`clean_lower_score` / `left_with_evidence`). A tier-1 finding a maintainer will reject must not ship merely because the clean form costs match %.

Batch 2+3 added the mirror lesson: our **self-flag comments are read and trusted**. Final tally across the series: **four True-family ratifications** ("True." on lbspdisplay 1313 and tyfigupon 1375; "True. Revert all of this garbage." on debug.h; "True, revert." on lbaudio 2571), **two "Not true — `lbl_804D38F4` is in `sdata` (mutable)" refutations**, **two function-symbol false positives** (§6#10), one usage-evidence refutation (grKongo, §4.5), and — a third disposition — **silent resolution**: ribbanya resolved at least a dozen self-flag threads himself with no reply (both [#2877](https://github.com/doldecomp/melee/pull/2877) round-0 style flags, both ftcpuattack flags, byte_base, grbigblue header-inline, the `__FILE__` thread on [#2852](https://github.com/doldecomp/melee/pull/2852)). Silent resolve = implicit acceptance; the flagged shape ships and stays. Threads whose flagged code has since been fixed should be resolved by us; still-relevant evidence threads stay open — but see §9.2.g: a shipped self-flag without recorded measurements becomes reviewer homework, and session-era evidence rots (three proven instances, §10.3).

## 2. Cross-module policy (the isolation rule is inverted)

ribbanya, [#2877](https://github.com/doldecomp/melee/pull/2877) cycle: *"It's okay to modify any file as long as the primary motivation is to match something in the target TU and doesn't break anything"* — explicitly including cross-module signature/type tweaks (*"It's very rare that changing `s32` to `int` affects codegen, are you sure you can't modify the signature to `int`?"*). He identified our slice-manifest gating as the **root cause** of the banned shapes (shadowed declarations, `#ifdef __MWERKS__` signature blocks, local re-prototypes, extern overlays): the hacks existed only to avoid touching out-of-manifest files.

Operational gates (proven on the `Ground_801C57F0(int)` / `Ground_801C1DD4` fix):
- (a) primary motivation = a match in the slice's own TU;
- (b) **zero codegen movement in the touched foreign TU** (whole-unit objdiff; `s32`↔`int` and an ignored parameter are byte-neutral);
- (c) upstream CI parity;
- (d) when two open PRs ship the same foreign file, byte-identical mirror hunks (debug.h, ground.c/h precedents) or zero textual overlap — verify with `git merge-tree` in both orders.

Where even the cross-module route measurably breaks matches, **evidence replies are accepted**: the u8-prototype case (int signature de-matches the callee 100→90.29 plus nine 100% callers) was documented with numbers, the penalty taken, no pushback.

## 3. Matching tactics: the current line (narrows the original 100% ruling)

Round 2 of the test bed established *"tactic + measured 100% = keep."* Batch 2 **narrowed it**: the score is not the line — **whether the shape lies about data ownership is.**

**Dead even at true 100% (class-wide, Ford-confirmed):** base+literal-offset reads into pooled strings/data, overlay typedefs cast over merged data regions, promoted pool strings, extern references to pool slots (another TU's or one's own). ribbanya on lbaudio_ax: *"Revert and fix the data section instead."* All five lb instances reverted to master's exact forms at sanctioned costs up to −20pt (100→79.6 on `lbAudioAx_80027AB0`), data sections held at 100% throughout via anchors. "Fix the data section" means config **only when the section isn't already named/anchored** — in lbaudio_ax's case no config change was needed.

**Alive at 100% (ownership-truthful shapes):**
- `sdata2_order`/`order_data` **anchors: try to REMOVE first, bless with `@todo` second.** The original ruling ([#2851](https://github.com/doldecomp/melee/pull/2851) mnitemsw): *"it's better to embed the literals in the function bodies, and if it can be done while maintaining the `.sdata2` section match, this function should be removed"* — removal at zero cost is the preferred outcome (achieved there: literals at natural first-use, .sdata2 byte-identical). Where the anchor is load-bearing it's blessed: *"this `sdata2_order` function is fine because it's easy to address later and maintains data ordering… Just mark it with a todo comment."* Accepted wording: `/// @todo .sdata2 order hack` (todo section names are reviewed for accuracy — *"This is `.data` not `.sdata2`"*). Second explicit ratification [#2895](https://github.com/doldecomp/melee/pull/2895): *"It's fine. Should be considered a controlled/acceptable hack."* Ratified as a lint-rule change on [#2880](https://github.com/doldecomp/melee/pull/2880): *"The rule should be changed to allow these ordering functions as long as they have a todo comment"* — amend `literals_and_data_ownership`'s anchor detection to pass anchors that carry the todo.
- `PAD_STACK` (*"Stack padding is fine"*), fake consume-functions with `@todo`, comma-assign literal forms (`x *= scale = 1.0f;`), dead-string emission idioms.
- A tactic at true 100% whose clean form measurably regresses may stay **when the reviewer's instruction allows** (`@todo` route) — but expect data-ownership tactics to be ordered out regardless.

**Scoped cast exception + the hybrid recovery ([#2877](https://github.com/doldecomp/melee/pull/2877) round 4):** *"Reintroduce casting where it facilitates a 100%"* — casts are re-sanctioned narrowly at sites where they buy a TRUE exact match; typed/M2C_FIELD forms everywhere else. And when a typed parameter costs score, measure the hybrids before conceding: on the gmtoulib draw family, BOTH `cast + correct arg type` and `M2C_FIELD + correct arg type` fully recovered the typed-arg losses — the re-materialized field address was the load-bearing part, not the `void*` parameter. Pooling arcana for the record: a same-TU duplicate literal can only emit as a distinct object via extern-decl + const def AFTER its user — `(void)` anchors pool-merge (object never emits) and def-before-use emits but MWCC folds the use's relocation back to the pool slot (verify at the reloc level, not just bytes). **Final ruling on this saga** ([#2877](https://github.com/doldecomp/melee/pull/2877), 20 seconds before merge, unanswered): *"That means a split is missing. Address in next pass."* — when no natural spelling emits a distinct object, the diagnosis is a missing split (gm_804DAC88 needs its own `.sdata2` slot; §10.2 follow-up). The emission trick is interim-only.

**Small conventions collected across rounds:** `_noinline` suffix for codegen-shaping local wrappers (*"Rename to `HSD_RandF_noinline`"*); data constants carry address comments with address names (*`/* 3B7FD4 */ const grKg_SplineChoiceList grKg_803B7FD4`*); canonical math headers are ordered even at cost on sub-100 functions (*"Use `math_ppc` version"* — −0.9 on a 92.5 function, accepted); register-allocation-only diffs are reported as **"regswap"**, not instruction dumps (§9.2.c).

**Canonical forms are subject to the same measurement ([#2880](https://github.com/doldecomp/melee/pull/2880) round 3):** even blessed canonical macros get measured before adoption — `GET_JOBJ(arg0)` is a cast-only token change yet it flipped MWCC's register allocation on grPura_80212CD4 (100→98.79), and jobj.h's `HSD_JObjGetChild` inline adds a null-check retail lacks (−0.5). Both of ribbanya's explicit suggestions were declined with numbers (offering to take them anyway if preferred) without pushback; a third (`GET_JOBJ(*gobjp)`) was accepted after fixing its typo. Suggestion blocks are asks, not commands — verify they compile and measure before committing.

**Round-4/5 extensions of the typed doctrine ([#2880](https://github.com/doldecomp/melee/pull/2880)):** real **bitfields** are the typed form for flag/lane bytes (*"These are accessing bitfields on `bp`"*) — model them as actual C bitfields (`u8 state : 6;`), replacing both manual shift-mask reads and `asm` blocks; measure the ladder (all-typed / M2C_FIELD / open-coded / hybrid) and present the numbers — but know that the maintainer may order the WORST-scoring rung anyway: *"Yes, use the proper bitfields"* shipped 94.15 over the 96.36 hybrid and below the 95.46 pre-PR baseline. The synthesis of the whole series: **data-shape follows type truth even at score cost when directed; control-flow shape follows score** (*"If it improves the match it's fine"* — grfourside ABS expansion; *"100% is preferred."* — grpura). The typed form then becomes the base for future match-hunting: *"Let's just keep the bitfield accesses for now and try to find a better match that way."* **Retyping can RECOVER score**: `x8_blocks` as `grGreens_BlockVars (*)[6]` (pointer-to-2D-array) collapsed all casts AND improved the worst function +3.76; the `gv.homerun` union move gained +0.46. When a cast keeps showing up, the type definition is wrong — *"Just modify the original type"* — and gr/types.h-style owning-header edits are the vector (foreign-TU zero-movement proof via tree-wide strict compare). `HSD_ASSERTREPORT` joins the accepted assert-family forms (byte-identical where OSReport+assert pairs occur).

**Typed access beats raw, even vs master ([#2878](https://github.com/doldecomp/melee/pull/2878) round 3):** where master itself uses raw pointer math (`*(int*)(base + off)`), the preferred form is clean field access on the REAL datatype — *"Use `M2C_FIELD` instead of direct pointer manipulation. Preferably modify the datatype for clean field access"* — with `M2C_FIELD` as the fallback where a true typed shape can't match. Improvements over master's shapes are welcome when they match: the lbaudio_ax typed round recovered most of the class-sweep's sanctioned losses legitimately (unit .text 97.53→99.40, e.g. 79.6→99.2 on `lbAudioAx_80027AB0`) with zero data-section movement and no M2C_FIELD needed anywhere. The distinction that decides §3: a type that describes the REAL object layout = good, regardless of master; an overlay typedef faking a merged region = banned, regardless of score.

## 4. Literals, data ownership, and splits

1. **Literals are always TU-owned — no exception** (ribbanya, [#2850](https://github.com/doldecomp/melee/pull/2850)): *"A literal being used out of place suggests a problem with `splits.txt`, not with the source of the unit."* Repair vector is config metadata, never pool-slot naming or referencing another TU's data symbol.
2. **Orphaned literals → expand the TU's split** ([#2877](https://github.com/doldecomp/melee/pull/2877), two comments: *"the split needs to expand its `sdata2` section to encompass it"*). Proven byte-conserving mechanics: extend the section range to absorb the auto-split unit carrying the literal; define the object in-TU (`const f32 gm_804DAC88 = 1.0F;`) — **after its only user** when def-before-use would pool-merge it with an earlier identical literal; keep master's address-name. Extern-into-auto-unit is exactly what he rejected.
3. **`extern`-of-own-TU-data is a defect class** (three sightings): grvenom's externs suppressed `.rodata`/`.sbss` emission entirely (objdiff pairs nothing; verify gates read a missing section measure as 0/broken); tydisplay's externs link-resolved onto the anonymous initializer templates of its own functions (fixed as named in-TU `static const` tables at zero cost); gmtou's cross-TU float externs exposed a genuine `.sdata2` boundary misplacement between gmtou_0/gmtou_1 (boundary-move follow-up offered upstream). Rule of thumb: an extern for data at an address inside or adjacent to the TU's own ranges = splits/definition bug, never a shape to keep.
4. **Ownership evidence and structure patterns** (accumulated): (a) **DOL usage suffices as data-ownership evidence** — *"Its only usage in the dol is by `grKongo_801D651C`, what more evidence is needed?"* (the `literals_and_data_ownership` evidence bar was over-strict); (b) spurious named pool symbols can be fixed by marking the slots **anonymous locals in symbols.txt** with literals inline — no splits change ([#2850](https://github.com/doldecomp/melee/pull/2850) [`8add446b3c`](https://github.com/doldecomp/melee/commit/8add446b3c)); (c) **nested unions inside a `gv` member are a smell** (*"Why are they two different union members? This is not typical for HAL. Is there a split missing?"*) — distinct Ground-gobj subtypes get their own top-level `gv` union members (`homerun`/`homerun2`, per the venom/venom2, zebes/zebes2 precedent).
5. **Mixed-use fields become f32/s32 unions, not casts** ([#2880](https://github.com/doldecomp/melee/pull/2880): *"Change the type of the members to `s32` instead of casting pointers"*): fields used only as ints are retyped `s32` outright (14 casts dropped from grvenom); fields used as floats elsewhere (e.g. serving as a Vec3 base) get union views with `_int` members for the integer stores — following the codebase's existing xDC precedent. Fix the real type in its owning header (cross-module per §2), never cast at use sites.
6. **Data-order preservation without variables**: embed literals as `(void)` statements at natural first use, or order anchors per §3 — not named-anchor arrays, not `sdata2_order`-free reorderings that break pools.

## 5. Names, declarations, strings, pragmas

### 5.1 Renames stay out of matching PRs
ribbanya ([#2877](https://github.com/doldecomp/melee/pull/2877)/#2880): *"Please keep renames out of these matching PRs and submit separate naming PRs if you wish. Renaming local variables is fine, but anything that hits the public API needs to be justified and documented in the corresponding `.dox` file of that TU, and if the names originate from an LLM, the specific model needs to be cited. The exception is for renaming literals in `symbols.txt`, in which case they must be named by _value_ and not _meaning_"* — `gm_1601_f32_1_0` / `gmRegClear_str_GmRegClr` fine, `gm_DefaultGameSpeed` not. Value-basis confirmed in code too — full quote carries a second criterion: *"These renames are fine. **They're shared by multiple TUs** and the names are based on value, which is clearly demonstrated by the data (`0xFFFFFFFF` and `0x000000FF`)."* Converse exception ([#2893](https://github.com/doldecomp/melee/pull/2893), §9.2.f): an apparent meaning-rename may be a pre-existing **human name that simply wasn't in symbols.txt** (unsplit symbol) — *"The symbol was already named that by humans"* — check headers/source for prior art before flagging. Size/scope/`@`-string-split symbols.txt lines are not renames. (~30 meaning-names from batch 2 are queued for a future naming PR with model citation.)

### 5.2 Declaration hygiene: no shadowing of any kind
The largest single comment cluster (8 of [#2877](https://github.com/doldecomp/melee/pull/2877)'s 12 round-1 comments):
- *"Fix the type declaration or suffer the match penalty; do not shadow existing symbols."* / *"rework the original signature to match at the call site, or make a note of the necessary signature change in a `@todo` comment, but don't shadow signatures."* WIP stripped-signature variants go in **`#if 0` + todo, not `#ifdef __MWERKS__`**.
- *"Function declarations must appear either in the containing unit's header file, or at the top of a C file as a `static` declaration."* Mid-file externs move to the top.
- *"All of this preprocessor declaration black magic must go. Just declare the symbols normally"* — macro-generated declarations, header re-`#define`s of function names, `__FILE__` redefinitions. (On [#2877](https://github.com/doldecomp/melee/pull/2877) all removals were byte-identical once the real declarations were fixed in their owning headers per §2.)
- *"Don't create type aliases like this. The necessity of the cast suggests that the declared type is wrong or needs to be merged with another type."*
- **Earliest evidence (07-01, [#2781](https://github.com/doldecomp/melee/pull/2781))**: the shadowing ban predates the series — ribbanya wished for "a better solution" to an in-function redeclaration (the accepted "fix" used the exact `#ifdef MWERKS_GEKKO` dual-signature shape he banned on [#2877](https://github.com/doldecomp/melee/pull/2877) a fortnight later), and r-burns stated the principle cleanly: *"we should drop these local overrides of function declarations if they're only improving fuzzy percentage… the final full match will be with a declaration that is visible globally and works for every caller."* ribbanya ultimately resolved it himself in [#2846](https://github.com/doldecomp/melee/pull/2846) by matching the function. ([#2781](https://github.com/doldecomp/melee/pull/2781) is also the fifth maintainer-pushes-code instance: 6 commits, self-approved-merge.)
- **Anatomy of the duplicated-header-decls failure** ([#2850](https://github.com/doldecomp/melee/pull/2850)): a dropped owning-header `#include` + pasted decl block, with **hallucinated address comments** on the pasted decls (*"The address comments here appear to be hallucinated"*). Maintainer-recommended tooling: *"Tell the model it can use `tools/scaffold.py` to generate the declaration placements and then fill in the templates with the actual function declarations."*

### 5.3 String literals: the decision tree
ribbanya ([#2877](https://github.com/doldecomp/melee/pull/2877)): *"If a string occurs in a function, it is a literal. If it's referenced in a data structure, it can usually also be a literal, and only if it can't should it be declared as its own variable."*
1. In-function string → inline literal, always.
2. Data-structure-referenced string → literal in the initializer where the match allows.
3. Own variable only where measured impossible — then value-named per §5.1.
4. Assert/panic idiom rules (refined across all three cycles):
   - The invented `HSD_ASSERTMSGFILE`/`HSD_ASSERTREPORTFILE` macro family is dead: *"True. Revert all of this garbage."*
   - **Where master already has an HSD_ASSERT-family body, keep it verbatim** — converting to raw `__assert(struct.filename, …)` is an idiom downgrade even when it preserves bytes (*"None of these assertion regressions are allowed"*, grhomerun round 3, reverting our own earlier grkongo-precedent conversion). The `__assert(struct.filename, …)` form is only for sites master itself writes that way.
   - **An assert retail doesn't have gets deleted, not idiom-ized** (grbigblue: removing `HSD_ASSERT(979, jobj)` is what completed the 100% — retail's function has no assert call; ribbanya accepted the evidence).
   - Pooled case (lbaudio_ax): plain `HSD_ASSERT`/`HSD_ASSERTMSG` + a master-style `order_data` anchor pre-emitting `__FILE__` and the messages in retail pool order (MWCC pooling reuses them; zero config).
   - **`__FILE__` caveat** (grgreens): when retail's asserts reference a TU-named file-string array (`grGr_803E7728`), canonical `__FILE__` pools a *second* copy of the filename and costs exact matches (four 100s → 99.9, .data 100 → 99.23). The compliant form was still ordered — cost documented in-thread; the only exact forms are banned shapes (`#undef __FILE__` redefines).
5. **Strictness ruling ([#2877](https://github.com/doldecomp/melee/pull/2877) round 3):** *"The linting should be _extremely_ strict about regressing string literals. Using the literals is preferable to a better match"* — the only exception is when the data section would unmatch. String-literal restoration outranks .text score; sweep any tactic that traded a literal away for match % and take the cost.
6. `__FILE__` is byte-safe under MWCC `-cwd source` (proven in three TUs). Un-aggregating string blobs: restore inline literals + per-string `data:string` symbols (particle.c precedent); unreproducible pool-base offsets documented with immediate-operand evidence.

### 5.4 Pragmas and diagnostics
Allowed pragma uses require `#pragma push`/`#pragma pop` form — manual off/on restores are a violation. Clang/clangd-only diagnostics are suppressed in `compile_flags.txt`, never source pragmas.

## 7. Review-process facts worth encoding

1. **Evidence replies are the accepted format** for irreducible cases: "tried your suggestion, here are the exact numbers, took the least-bad form."
2. **Reviewer questions are measurement requests** (*"Do these changes affect codegen...?"*) — build both forms, answer with numbers, keep or revert accordingly. Style-only churn without codegen justification does not belong in matching PRs.
3. **Self-flag comments vs reviewer asks**: reviewers treat pipeline findings as context (and sometimes ratify them into asks); only external-reviewer comments demand action by default. **Reviewer-supplied artifacts are a third input category**: sadkellz handed over a working decomp.me scratch (adopted → 100% on [#2849](https://github.com/doldecomp/melee/pull/2849)) and maintains a parallel camera branch; jurrejelle supplied the exact comma-assign shape. Adopting reviewer code is the accepted move — and check for parallel-branch collisions on cm/camera work.
3b. **Comment format ruling** ([#2851](https://github.com/doldecomp/melee/pull/2851), generator-encoded): AI-generated prose in `>` block quotes; unordered lists, never `|` separators. **Outside-diff findings post as PR issue comments** (the debug.h macro flag traveled that way on [#2852](https://github.com/doldecomp/melee/pull/2852) when the file left the slice). Un-replied asks draw "@fjooord" nudges within hours — lint-rule requests want explicit confirmation replies. Meta-precedent: ribbanya asked whether reviews reach the model directly ([#2877](https://github.com/doldecomp/melee/pull/2877) issue [5010952336](https://github.com/doldecomp/melee/pull/2877#issuecomment-5010952336)); Ford described the harness and invited direct pings.
4. **Bot-report "before" column is the master baseline** — regressions vs the session are systematically understated; always measure against both master and the session pre-state. **Origin of data-value diffing**: the report originally compared reloc names only — r-burns spotted his data matches being silently reverted on [#2782](https://github.com/doldecomp/melee/pull/2782) (07-01, the series' first external damage warning), proposed value-diffing, and shipped it upstream next day ([#2785](https://github.com/doldecomp/melee/pull/2785) [`ac66f466e0`](https://github.com/doldecomp/melee/commit/ac66f466e0)); that CI change is why data reverts are visible at all.
5. **PR hygiene and review dynamics**: no markdown file lists in the OP (*"we have the GitHub UI for that"*); maintainers merge master into PR branches mid-review (ribbanya did on all four batch-1 branches, lb, gr) and **occasionally push code** (his own suggestion applied himself in [`f42a65e49d`](https://github.com/doldecomp/melee/commit/f42a65e49d) on gr — which left a duplicate `placeholder.h` include in master; and see §9.2.h) — always re-fetch and read branch history before pushing. **Approval is volatile and fast**: [#2849](https://github.com/doldecomp/melee/pull/2849) went APPROVED → CHANGES_REQUESTED 35 seconds later → re-approved; all of batch 1 merged in a 40-minute window. **Pushing after approval auto-dismisses it** (repo setting; the [#2893](https://github.com/doldecomp/melee/pull/2893) forward-edge merge cost a 9-hour re-review) — land evaporation merges BEFORE approval. **Reviews race pushes**: a "True, revert." landed on code fixed 20 minutes earlier — reply with the fix commit id rather than re-fixing. Merge does not discharge parked items (*"Good enough, can revisit the rest later"*).
6. **Verification gates**: zero-epsilon regression checks must cover every measure at total/unit/section/function level **including section existence** (a missing section measure = 0/broken — grvenom); repair validation needs the whole-unit fuzzy gate (the `!== 100` filter shipped −28.5pt damage); `needs_rework`/`blocked` repair residue can ship in sweep commits — diff every file against the pre-repair state regardless of queue status.
7. **Config metadata must be sliced with the code**: symbols.txt/splits.txt hunks whose addresses fall in a slice's units ship in the same PR (same commit as their paired lines); orphaned config collapses data pairing PR-wide.
8. **Evidence lives in PR threads, never in source comments.** ribbanya, [#2880](https://github.com/doldecomp/melee/pull/2880) round 3: *"Keep the 'Objdiff' comments to yourself, please"* (plus "Remove yap comment" / "Remove unnecessary comment" ×several). Workers had been leaving measurement commentary ("Objdiff checkpoint: this pad preserves the exact frame") in the code; sweep all tooling narration before push. The class extends past Objdiff narration: stray function-name comments (`/// grVenom_802056B0`), status/percentage notes, and load-bearing-offsets commentary all got deleted (several via empty suggestion blocks, one flagged just "???"). The only sanctioned in-source annotations: `@todo` markers (order hacks, fake functions, WIP notes) and genuine semantic documentation.
