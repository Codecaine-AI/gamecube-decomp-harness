# Yoshi initialization and presentation infrastructure

## Registration and resources
`ftyoshi.c` defines Yoshi's character-specific motion table, material-animation helpers, lifecycle hooks, article registration, and asset-name tables. The header declares the callable interface and three exported data objects. The motion table contains the commented state range 341–368: five guard entries, ten neutral-special entries, eight side-special entries, two up-special entries, and three down-special entries. Every record uses `ftCamera_UpdateCameraBox`; neutral, up, and down special entries have NULL IASA slots. Callback names and flag names are not reliable ground/air classifiers: the side-special records contain inconsistent `Air` names and explicit naming TODOs. Numeric registrations are preserved rather than normalized. [Table](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftYoshi/ftyoshi.c#L27-L338)

The source also defines a zero `Vec3`, six costume filename/joint/material-animation triples, four demo-motion names, the main and animation archive filenames, and a six-element costume-list declaration. These declarations do not establish compiled section extents or literal-pool placement. [Resources](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftYoshi/ftyoshi.c#L529-L566)

## Material-animation pipeline
`ftYs_Init_8012B6E8` traverses a descriptor's signed count and byte DObj indices, obtains each material AObj, and sets its rate to zero. It writes the animation end frame to external attribute `xC` whenever `xC == 0`; otherwise it asserts on unequal end frames. This is a value-based sentinel, not a first-entry flag: an end frame of zero can be replaced by a later nonzero end frame without triggering the mismatch assertion. The descriptor is not null-guarded. A null DObj produces a null MObj that is subsequently dereferenced, so this is not a safe skip path. [Setup](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftYoshi/ftyoshi.c#L347-L385)

`ftYs_Init_8012B804` does guard a null outer descriptor. Otherwise, it requests the supplied frame and immediately evaluates each selected MObj. A null DObj is passed onward as a null MObj, not skipped locally. `ftYs_Init_8012B8A4` computes `dat_attrs->xC * (1 - shield_health / starting_shield_health)` and applies it to descriptor groups 0 and 1. There is no local clamp or zero-denominator guard. `ftYs_Init_8012B918` applies frame zero to both groups. Source proves the health-dependent frame mapping, but not the exact colors contained in material assets. [Application and callers](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftYoshi/ftyoshi.c#L387-L437)

Canonical guard code independently confirms the update call in GuardOn's final else branch, after the effect and animation-completion branches. GuardHold setup uses the exported zero vector for both hurtbox endpoints, with a selected bone, mid height, grabbability, and unit scale. The side-special model sequencer calls the frame-zero reset only for an in-bounds table entry equal to 1, before its mode/flag updates. ## Loading and cross-file lifetimes
OnLoad explicitly asserts only the primary descriptor, zeroes external `xC`, initializes both descriptor groups, then uses `PUSH_ATTRS` to copy the resulting attributes into backup storage and bind `dat_attrs` to it. It registers article definitions 0/1/2 as EggThrow/Star/EggLay and sets `x2226_b1`. Registration stores article pointers; it does not spawn live items. `LoadSpecialAttrs` instead copies external attributes into the existing active attribute storage. [OnLoad](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftYoshi/ftyoshi.c#L447-L476) · [Macros](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/inlines.h#L21-L35)

`ftYs_Init_8012BA8C` calls egg cleanup before tongue cleanup. Cross-file creation and launch identify persistent `u.ys.x2238` as a held EggThrow reference. Damage/secondary-death callbacks are installed while that reference exists; launch clears the reference and callbacks. Interruption cleanup destroys the egg only when the reference is nonnull and `mv.ys.specials.x0 == 0`, but always clears the reference and both callbacks. Tongue cleanup is conditional on `target_item_gobj`; its destruction-mode flag is true only for the four explicitly tested SpecialN states. It then clears `x1A64` and the target reference. Consequently, reference reset must not be equated with unconditional item destruction. OnDeath requests part-0 selection 0 and clears `x2238`; it does not itself call article destruction. The attribute getter returns active `x120` unchanged, without establishing its gameplay meaning. ## Event adapters and naming review
Pickup/drop forward their boolean and fixed options 1,1; visibility hooks forward selector 1. Shared visibility handlers exclude heavy items. Knockback hooks perform shared animation processing, then apply selection 3 on entry or 2 on exit to parts 3 and 4 at frame zero. They do not calculate knockback magnitude or directly change motion state.
