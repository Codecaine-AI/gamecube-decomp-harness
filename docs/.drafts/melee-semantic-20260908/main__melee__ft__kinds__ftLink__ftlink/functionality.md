## Link initialization and lifecycle integration

The owned source defines Link's motion dispatch table, archive/demo/costume identifiers, attribute initialization, article bookkeeping, item-event adapters, knockback-event adapters, and a passive-shield response callback. The header declares the public functions and data. Canonical and rendered views were read completely; rendered names were treated as hypotheses, not independent evidence.

### Dispatch and resources

The table contains 21 records, commented as states 341–361: forward-smash follow-up, two appeal placeholders with all callback slots NULL, six neutral-special phases, six side-special variants, grounded/aerial up and down specials, and AirCatch/AirCatchHit. NULL IASA slots and differing ground/air flags are preserved rather than normalized. These descriptors route work to other translation units; they do not implement those moves locally. Resource declarations include five costume triples, four demo labels, archive names, and a five-element zero-initialized costume list. Source declarations and address comments do not prove compiled .data/.sdata2 membership or layout. ### Attribute and resource initialization

OnLoad derives attackairlw_hit_anim_frame_end using fighter-data entry 72 before PUSH_ATTRS copies the external Link-layout attributes into fighter-owned backup storage and installs that storage as dat_attrs. It then processes item entries 0–4 with attributes x48, x2C, xBC, xC and x10, respectively, and supplies entry 6 to the fighter-part attachment helper. Entry 5 is not processed here. OnLoadForCLink accepts Fighter*, not HSD_GObj*, and only performs the shared copy/install operation. Young Link's caller supplies its own external attributes and separately adds wall-jump and milk-resource setup. LoadSpecialAttrs recopies external attributes into active storage before multiplying specialhi_pos_y_offset by vertical scale when scale.y != 1.0; repeated calls therefore do not simply compound the previous scaled value. ### Article lifetimes and cleanup

BoomerangExists is strictly a non-NULL test of the tracked pointer; it does not validate object liveness. OnDeath queues selection 0 for model groups 0, 1 and 2, clears boomerang usage and tracked references, and zeros xC, x14 and x18, including the duplicate xC assignment. This reset is not itself article destruction.

ftLk_800EAF38 delegates to null-guarded boomerang removal. Side-special creation installs it in death3_cb, so the rendered OnDeath2 hypothesis remains unresolved. ftLk_800EAF58 unconditionally dispatches, in order, boomerang removal, ftCo_800D94D8, arrow cleanup, bow cleanup, and ftCl_Init_80149268. Neutral-special setup independently installs this aggregate callback in take_dmg_cb and death2_cb, supporting OnDamage as a tentative descriptive name. Boomerang, arrow and bow teardown are individually pointer-guarded; their ownership must not be generalized to all already-released projectiles. The CLink hook visibly delegates to checkFighter2244; its rendered milk-removal name is not proof of deeper behavior. ### Item and knockback events

Extended pickup/drop queue selection 1/0 for model slot 1 only when itIsHeavy returns exactly 1, and for slot 2 unconditionally, before forwarding to the ordinary callback. The setter records pending selections and a dirty flag; it does not immediately select a named sword/shield mesh. Ordinary callbacks forward the object and boolean unchanged with two fixed true options. Shared pickup excludes heavy items, maps hold kinds 1–4 to presentation values 1,0,2,3, and conditionally issues its visibility update. Shared drop always resets its presentation selection to -1 and conditionally issues invisibility. Visible/invisible callbacks exclude heavy items. Knockback entry/exit are unconditional adapters; their shared implementations call ftAnim_800704F0 for indices 1 and 0 with values 3.0/0.0, not local knockback magnitude calculations. ### Passive shield

ftLk_800EB334 is independently registered with Link's ShieldDesc when pending model selection 2 equals 0. It computes a guard response from x19A4 and external attribute xD8, multiplies by common x294, preserves the result when specialn_facing_dir < 0 and negates it otherwise, replaces gr_vel, and requests SFX 160106 with arguments 127 and 64. There is no local acceptance guard, timer, motion transition, or velocity clamp. Backward recoil describes the ordinary parameter domain; positivity of the formula for arbitrary attribute values is not established. OnPassiveShieldHit remains a descriptive hypothesis rather than a recovered original symbol.
