## Functionality and semantic review

This unit contains five callback families—BackDisappear, Wait1_1, Grab, Fail and Cancel—and their associated entry/event helpers. The header declares all 25 externally visible functions. Canonical and rendered views were read completely; rendering reported no parse errors.

### Disappearance is distinct from grab acquisition
BackDisappear invokes the stored `mv.mh.unk0.x4` continuation when animation frames are exhausted, delegates physics to animation-translation velocity, and has an empty collision callback. Its continuation is installed by the entry routine in `ftmasterhandbackcrush1.c`. Canonical action selection uses that entry for BackPunch/BackCrush, whereas Throw/Slam grab selections enter Wait1_1 directly. File adjacency therefore does not establish BackDisappear as the opening Squeeze phase. See [continuation installation](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftMasterHand/ftmasterhandbackcrush1.c#L12-L18) and [separate selections](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftMasterHand/ftmasterhandwait10.c#L319-L343).

### Timed approach and grab
Wait1_1 entry preserves the current animation frame, applies `x110_pos.y` as playback rate and initializes countdown `x8` from `x110_pos.x`. Its animation callback decrements the countdown and enters Grab exactly when the result equals zero. A separate animation-completion test then runs, even after that transition; it can restart Wait1_1 from frame zero. There is no `else` or early return between these checks.

Approach physics obtains a reference position, adds `x108/x10C`, forces destination Z to zero and computes a three-dimensional displacement length. Below the strict `x2C` threshold, remaining displacement XY becomes velocity directly. Otherwise the normalized displacement is multiplied by `length * x28`. Only XY self velocity is assigned; Z still contributes to the length calculation. The inline square-root approximation performs three reciprocal-square-root refinements for positive input and returns nonpositive input unchanged. See [approach implementation](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftMasterHand/ftmasterhandbackdisappear.c#L43-L145).

Grab entry selects Grab, initializes animation, registers the grab event and victim-side callback with constant 128, and clears `x20`. The successful-grab event stops XYZ velocity, sets `x20`, clears the grab-enable bit and enters Squeezing0. Independently, Grab animation exhaustion stops velocity and enters Squeezing1. Thus animation exhaustion alone does not prove acquisition. Downstream Squeezing completion checks `x20 == 1`, entering active Squeeze or Fail. See [registration](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftcommon.c#L895-L904), [Squeezing entries](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftMasterHand/ftmasterhandwait11.c#L9-L29), and [success/failure decision](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftMasterHand/ftmasterhandsqueezing.c#L20-L31).

### Recovery and cross-object lifetime
Fail and Cancel initialize a recovery destination from `x30_pos2` XY with zero Z. Their physics first applies animation translation, then replaces XY velocity through the shared destination helper. That helper writes zero to `x18` inside the arrival threshold, otherwise the measured distance; these parameters describe a threshold and proportional velocity scale, not acceleration. Fail collision is empty. Cancel collision clears all self velocity when `x18 == 0`.

Victim-side mash expiry first enters CaptureWaitMasterHand on the victim, then enters Cancel on the linked Master Hand. Cancel initializes `x24` from `x120`, arms `cmd_vars[0]` and stops velocity. Its animation callback predecrements the timer; when nonpositive and armed, it invokes the victim helper, clears `x20` and consumes the latch. The helper restores visibility, reverses facing and enters CaptureCut—not CaptureWaitMasterHand. Animation exhaustion independently invokes waiting recovery, so the code does not guarantee that delayed release precedes exit for every possible timer/animation configuration. The victim pointer is used without a local null guard. See [escape caller](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftMasterHand/ftmasterhandcapturemasterhand.c#L36-L44), [earlier CaptureWait entry](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftMasterHand/ftmasterhandcapturedamagemasterhand.c#L18-L27), and [delayed CaptureCut](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftMasterHand/ftmasterhandthrownmasterhand.c#L13-L19).
