## PERF sampling and event history

This file implements frame-history performance sampling using processor counters, GX metrics, memory-request registers, draw-sync tokens, and an OS periodic alarm. Initialization allocates frame, sample, and event storage through caller callbacks, initializes drawing through `__PERFDrawInit`, and installs the PERF draw-sync callback. Event names are stored as pointers, not copied; the deallocator is saved but never invoked in this file. Allocation constants are source expressions, not verified compiled structure sizes. [Evidence](code://c302741689bd67c361cd7faadb221df3193992c3/extern/dolphin/src/dolphin/perf/perf.c#L210-L259)

Memory snapshots combine pairs of 16-bit register reads and collect XF/raster metrics. Draw-sync processing forwards non-PERF, generation-mismatched, or inactive-frame tokens to `DSCB`. Accepted tokens delimit GP samples, using the token's low byte as a sample index and a four-bit frame generation. An end token with no active GP token rotates the automatic sample; an end-token index mismatch closes the currently tracked sample instead. Assertions preserve assumptions about mutually exclusive GP and automatic sampling. [Evidence](code://c302741689bd67c361cd7faadb221df3193992c3/extern/dolphin/src/dolphin/perf/perf.c#L66-L208)

Frame start resets counters and begins an automatic sample. Frame end closes automatic sampling, restores `DSCB`, records totals, advances the frame ring, clears event-open indices, and advances the generation modulo 16. It does not cancel the periodic alarm or explicitly wait for queued GX work. CPU events record counters directly; GP events emit draw-sync tokens; combined events do both through switch fallthrough. Duplicate starts, unmatched ends, and unknown start types have explicit diagnostic paths. The sample allocator saturates at the final slot rather than reporting exhaustion. [Evidence](code://c302741689bd67c361cd7faadb221df3193992c3/extern/dolphin/src/dolphin/perf/perf.c#L261-L401)

Automatic samples use id `0xFF`. A timer tick during an active GP interval copies that sample into another slot, closes the copy with id `0xFF`, refreshes the original's starting metrics, and marks the original interrupted. Generation mismatch instead rotates automatic sampling; missing automatic state without an active GP token reports an error. Starting periodic sampling schedules an alarm. Stopping it records only the automatic sample's end timestamp and memory/GX metrics before canceling the alarm: unlike `PERFEndAutoSample`, it neither updates ending instruction/cache counters nor clears `CurrAutoSample`. [Evidence](code://c302741689bd67c361cd7faadb221df3193992c3/extern/dolphin/src/dolphin/perf/perf.c#L403-L501)
