## Stage setup and callback structure

The TU defines six joint records, eleven component callback records, the Great Bay stage descriptor, stage-attribute declarations and shared retained attribute storage. Initialization loads the attributes, changes two stage flags and sets up objects in order 0, 3, 4, 2, 1, 9, 10 before its final boundary-related helper calls. The stage-local setup helper binds rendering, installs optional callbacks, invokes initialization synchronously and registers a process at priority 5 for object 10 or 4 otherwise. Missing objects are reported and returned as null. The Moon initializer additionally creates objects 5–8 through this helper and retains their results.

Several hooks are empty or return false. The local setup helper does not consume the callback table's Boolean second slot, so names implying process gating or per-frame invocation remain unverified. Background and foreground-water initializers request animation and looping and write numeric processing flags. Their source labels do not establish a larger visual narrative.

## Turtle-labeled component

Initialization applies configured scale and translation, retains a sampled joint Y, seeds state 0 and a randomized timer, and clears its retained effect pointer. The update follows numeric states 0→1→3→2→0 using timer and animation-predicate guards. State 0 tests a negative timer before transitioning; state 3 decrements a saved timer and tests its old value. The controller changes hierarchy visibility, requests effects at specific timer values, retains and conditionally releases an effect pointer, changes transforms and invokes map-joint helpers.

On transition to state 2 it selects a weighted configuration and clears the item-attempt completion bit. Configuration 2 asserts both during configuration setup and during subsequent orientation dispatch. The common tail updates joint-derived collision vertices and attempts an item only while state 2 has an unset completion bit. Ordinary execution reaches the end of this void function; it is not non-returning. Sink/emergence animation identity, rideability and exact collision activation semantics remain deferred.

## Item-backed component

A reported Y below -50 triggers replacement, resets fields and returns early. ## Selection, geometry and effect helpers

Configuration selection samples four weights, mapping indices 2, 1, 0, 3 to results 1, 2, 0, 3. It retries matches with the current result, eventually falls back to zero, and has an assertion for an unmatched selection.

The item-attempt helper obtains a position through joint 2, forces Z to zero and returns false for a missing joint or a position at/below the bottom boundary offset. Otherwise it can finish without creating an item: probability rejection, exactly zero total weight or no selected entry return true. Negative totals are not rejected by the zero test. On selection it copies the template, assigns kind and both positions, invokes the creator and ignores its result. A true result is completion, not proof of successful spawning. Airborne and item-filter semantics remain deferred.

The collision-vertex helper processes seven entries from an eight-row table. The lifecycle query returns true only for Great Bay with a nonnull map object 1, nonnull payload and nonzero xC4. This is not independently an availability or fighter-boundary test.

The registered crossing handler retrieves two vectors, requires another predicate to be false and tests strict downward crossing of Y = -5. It clamps the local current Y, scales an external scalar by one tenth, requests a generator and a numeric stage event, then always returns false. The generator helper multiplies all three scale axes if creation succeeds. Water/splash identity and external accessor, camera, sound and resource meanings remain deferred.
