## Boundaries, ownership and callback lifetime
The timer guard is after decrement and mash, not before. At that source comparison, either signed zero, negative finite values and negative infinity release; positive finite values and positive infinity continue. An unordered NaN comparison is false and continues. These statements concern the resulting value: earlier arithmetic can itself generate or propagate exceptional values. There is no local clamp, finite check or null check. Attribute accessors provide no positivity/finiteness guarantee, so arbitrary inputs do not guarantee termination. Facing reversal is arithmetic negation, not normalization to +/-1. Active processing requires a valid Fighter object and capture relationship; the empty callbacks themselves never dereference their parameters.

No owned function locally allocates or frees objects or retains a stack pointer. This is not a transitive no-allocation/no-deallocation guarantee for the motion engine: for example, Fighter_ChangeMotionState can remove an existing accessory object when preservation is not requested. The installed accessory callback is an ordinary function pointer, not a closure. ftCo_800DB464 calculates cur_pos from XRotN plus scaled offsets and forces z=0. The dispatcher invokes accessory1_cb only when x221F_b3 is clear and the x2219_b5 early-return path is not taken, then copies cur_pos to the root joint. Motion transition clears accessory1_cb, explaining installation after transition and removal by a later CaptureCut transition; other state owners may also overwrite it.
