## Fox/Falco fighter-side Blaster

This unit implements the shared grounded and aerial neutral-special Start/Loop/End callback families, held-gun bookkeeping, laser-emission orchestration, and Blaster presentation during throws. The header declares the public callbacks and two position-output helpers. Both owned files were read completely in canonical and rendered form; rendered substitutions were treated as hypotheses rather than proof.

### Entry and firing cycles

Ground and aerial entry select their respective startup motions, clear all four command variables and the repeat latch, then construct the held gun using the fighter position, facing, right-thumb bone and configured item kind. Ground entry additionally zeros ground velocity and all self-velocity components; aerial entry does not. Successful construction stores the gun, passes scale 0.85 and installs damage/death cleanup callbacks. Failure reports a caution and asserts, with caller-supplied assertion lines 305 and 333. [Source](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftFox/ftfoxspecialn.c#L237-L309)

Startup updates the gun and consumes command 3 only when it equals 1 and a gun exists. Animation exhaustion enters the first firing loop independently of repeat input, preserving model/graphics and installing the shot accessory callback. Loop animation completion either repeats and clears the latch or enters End and sets command 1 to 1. Repetition installs OnChangeAction with SkipAttackCount; that callback refreshes attack-instance and tracking context through two ordered common calls. Pending command 2 is consumed independently after loop-transition processing. [State logic](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftFox/ftfoxspecialn.c#L311-L510)

Start/Loop IASA callbacks share a helper that sets the repeat latch when command 0 is nonzero and input.pressed_buttons contains B. The helper does not clear the latch or change motion. Held-versus-edge semantics are not inferred without inspecting the input producer. Both End IASA callbacks are no-ops, which establishes only the absence of callback-local interruption logic. Shot creation consumes nonzero command 2 before issuing one prepare/fire sequence. Two right-thumb-relative points use a common local Y offset and distinct local Z offsets. Neutral-special firing flattens the muzzle position to Z=0 and uses the configured angle for facing==1, otherwise pi minus that angle. The laser constructor receives configured velocity and item kind; the held gun is notified and Fox/Falco sounds are selected using facing-dependent table indices. No projectile-construction success guarantee is inferred. ### Ending, collision and cross-file lifetime

End processing forwards command 1 to the gun, calls the pickup helper when command 1 equals 2, and consumes command 3==2 only with a gun present. On animation exhaustion, the fighter reference and both cleanup callbacks are cleared. Ground End then calls ft_8008A2BC; aerial End selects ordinary Fall for zero landing-lag attribute or forwards nonzero lag into ftCo_80096900. These reference clears are not direct item destruction. [End processing](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftFox/ftfoxspecialn.c#L415-L450) [Aerial recovery](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftFox/ftfoxspecialn.c#L515-L528)

The item independently consumes the action classifier and null-slot predicate to decide teardown. Its reciprocal cleanup invokes fighter ClearBlaster only under owner equality, then clears item ownership and effects; destruction is a separate operation. CheckBlasterAction returns the fighter flag for nine recognized motions and true for other motions or NULL GObj. Its item consumer interprets true as not-needed, not permission to retain the weapon. GetBlasterAction separately guards NULL Fighter and defaults to 9, using symbolic enum-base subtraction for recognized motions. Exact numeric expansions remain unverified. Ground physics delegates to friction and ground movement; aerial physics delegates to fast-fall/gravity processing. Aerial collision synchronizes positions and, on qualifying contact not suppressed by ft_80081A00, selects recovery using a vertical-velocity threshold. Ground collision delegates to ft_80083F88, whose canonical guard enters Fall when the query equals GA_Ground. That surprising polarity is preserved rather than rewritten as an intuitive loss-of-support condition. ### Throws and exceptional branches

Throw processing is gated to Fox/Falco. Animation exhaustion clears fighter bookkeeping immediately. Command 1==1 attempts construction only when the gun is absent and returns even if construction fails; unlike special entry, it does not assert. Throw scale includes fighter and common model scaling. With an existing gun, commands 3==1 and 3==2 are consumed, and the throw-fire event computes atan2 from the two hand points, not an opponent position. ThrowB/Hi/Lw use a distinct constructor; a default-action constructor branch remains. Up/down and back throws use different sound selection, with back-throw facing indexing reversed relative to neutral-special firing. Command 1==2 clears bookkeeping and plays a closing sound only when a gun is present; command 1==0 clears bookkeeping and calls the pickup helper.
