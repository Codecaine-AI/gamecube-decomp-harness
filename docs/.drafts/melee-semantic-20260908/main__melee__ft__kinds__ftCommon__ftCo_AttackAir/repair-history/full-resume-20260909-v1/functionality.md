# Common aerial attacks

The public input checker and source-local checkItemThrowInput accept newly pressed A or a new C-stick axis threshold crossing. For a neutral/forward selection and category-3 held item they call ftCo_800CDDA0; otherwise they call decideFighter. Both return true after dispatch. The item dispatcher recognizes Ray Gun, Fire Flower and Super Scope and has a default no-op branch, so true is accepted dispatch rather than proof of a motion change. The local helper has no writable KB identity but is fully reviewed here.

## Stick selection and entry

Despite the canonical FromCStick names, selection uses current C-stick only when an axis crossed from below its absolute threshold in the previous sample to at-or-above it now. Otherwise the main stick is used. Both angle helpers use atan2f(y, ABS(x)). Neutral requires both axis magnitudes strictly below thresholds. Above the positive angle boundary gives up aerial; below its negative gives down aerial; boundary equality falls through to facing-relative horizontal selection, with zero product selecting forward.

Link and Young Link use their family wrapper, which adds down-air hit/animation callbacks after common entry. Game & Watch chooses dedicated neutral/back/up entries and common forward/down entries. Other fighters use the common selector wrapper. EnterFromMsid does not validate its supplied ID: it clears allow_interrupt, cmd_vars[0] and throw_flags, changes motion at frame zero and rate one with KeepFastFall, then invokes animation/action updates. KeepFastFall prevents the motion-change helper from clearing existing fast fall.

## Lifecycle and input arbitration

The common table installs shared Anim, Phys and Coll callbacks for motion IDs 65 through 69, with a directional IASA callback for each. Anim consumes and clears throw bit 3 before reversing facing; a sustained uncleared request is not required. It enters Fall on exhausted frames. Collision and IASA exits remain independent of animation completion.

All five IASA bodies expand the same macro. If allow_interrupt is true, the order is held-item throw, immediate item pickup, tether air catch, local new-aerial/item-use check, delayed pickup timer, then aerial jump. First true returns. The first throw helper's second argument has bool* type: the source false is a NULL optional output pointer, not an interrupt policy. Immediate pickup performs item acquisition, and the delayed helper writes x209C; neither should be described as invariably entering another motion. The delayed helper's reachability after the earlier A-consuming check is not established from this bounded review. The chain has no direct air-dodge candidate.

Phys checks fast fall, applies fast fall or gravity/terminal velocity, then delegates drift. Coll passes LandingAir_EnterWithLag to the shared collision routine. The landing callback uses dedicated landing lag only when cmd_vars[0] is enabled and the current motion is a recognized common aerial. Otherwise it uses basic landing. For recognized states, x67F below the common timing threshold enables lag division/truncation with zero rounded to one. No fixed numerical L-cancel timing or per-fighter script frame is asserted.
