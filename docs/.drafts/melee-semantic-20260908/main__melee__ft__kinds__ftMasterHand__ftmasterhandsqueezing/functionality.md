This unit defines six `void(HSD_GObj*)` routines: Squeezing animation, IASA, physics and collision callbacks, a Throw entry routine, and the Throw animation callback. Full owned-file and baseline coverage is inherited from the research handoff; the lead independently checked proposed-fact citations and contradiction evidence in canonical source. ### Squeezing
Animation completion tests `mv.mh.unk0.x20 == 1` exactly. That value calls `ftMh_MS_378_80154A78`, whose implementation enters Squeeze. Every other value calls `ftMh_MS_374_801546D8`, which enters Fail—not BackDisappear. While frames remain, neither transition occurs. [Callback](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftMasterHand/ftmasterhandsqueezing.c#L20-L31), [Squeeze destination](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftMasterHand/ftmasterhandsqueeze.c#L18-L32), [Fail destination](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftMasterHand/ftmasterhandbackdisappear.c#L171-L180).

IASA checks player slot type zero and calls `ftBossLib_8015BD20`, whose body simply returns. Its rendered CrazyHand-specific name establishes no additional behavior. [IASA](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftMasterHand/ftmasterhandsqueezing.c#L33-L39), [hook](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftbosslib.c#L31-L34).

Physics calls `ft_80085134`, then passes destination `xC`, output `x18`, threshold attribute `x2C`, and scale attribute `x28` to `ftBossLib_8015BE40`. The helper computes three-dimensional distance. Strictly below threshold it writes zero to the output while retaining raw displacement; otherwise it writes distance and scales normalized displacement by distance times scale. Only x/y self-velocity are written. Zero `x18` therefore does not itself mean zero velocity. Squeezing collision is empty, unlike Squeeze collision, which stops velocity when `x18 == 0`. [Owned callbacks](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftMasterHand/ftmasterhandsqueezing.c#L41-L51), [helper](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftbosslib.c#L52-L80), [Squeeze collision](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftMasterHand/ftmasterhandsqueeze.c#L70-L79).

### Throw entry and release lifetime
`ftMh_MS_376_80154E78` enters the explicitly named `ftMh_MS_Throw`, calls `ftAnim_8006EBA4`, and clears command slot zero. This independently supports the speculative name `ftMh_Throw_Enter`. Squeeze animation selects this entry at animation exhaustion when `u.mh.x2250 == ftMh_MS_Throw`. [Entry](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftMasterHand/ftmasterhandsqueezing.c#L53-L59), [caller](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftMasterHand/ftmasterhandsqueeze.c#L43-L50).

Throw animation consumes any nonzero command slot zero before release processing. Its first handoff calls `ftMh_CaptureWaitMasterHand_80155D6C` on the stored victim. That helper dereferences both its argument and the reciprocal `victim_gobj`, copies facing, enters `ftCo_MS_ThrownMasterHand`, restores visibility, and installs `ftCo_800DE508` as an accessory callback. Its second parameter is unused. The caller's later null check is consequently not a safe entry-null guard. After the handoff, the caller rechecks its victim pointer; if present, it calls `ftCommon_8007E2F4`, calls `ftCo_800DE2A8`, negates the victim's `dmg.facing_dir_1`, and calls `ftCo_800DE7C0`, in that order. It then clears `x20` outside that null guard. Command consumption prevents repetition without rearming, not all future externally armed events. [Throw callback](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftMasterHand/ftmasterhandsqueezing.c#L61-L82), [handoff](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftMasterHand/ftmasterhandthrownmasterhand.c#L29-L42).

Animation exhaustion is checked independently, including on an update that consumes a release event. It calls `ftMh_MS_389_80151018`; the embedded number does not prove destination motion-state ID 389. The helper clears `x20`, constructs a return position from `x30_pos2`, assigns `Wait2_1` to the stored selector, and then tests for `Wait2_0`, consequently calling the Wait1_2 entry helper. It stores the return destination and deferred callback. Waiting collision processing stops velocity and invokes a non-null callback when the distance output is zero. This is a return-positioning lifecycle rather than an immediately completed idle transition. [Return setup](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftMasterHand/ftmasterhandwait12.c#L115-L138), [entry](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftMasterHand/ftmasterhandwait12.c#L19-L32), [collision](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftMasterHand/ftmasterhandwait12.c#L104-L113).
