## MetroTRK file support

`support.c` implements debugger-mediated file reads/writes and synchronous ACK exchange. Existing function names fit their canonical behavior; both rendered files match canonical names with no substitutions or parse errors. `support.h` declares these functions and open/close/position support interfaces, but does not establish implementations for the latter.

`TRKSuppAccessFile` rejects null data or zero requested count, constructs requests in chunks of at most 0x800 bytes, and serializes command, 32-bit handle, 16-bit length, and write payload. Reply mode requests a minimum five-byte ACK with retry argument 3; polling timeout is disabled specifically for reads of handle zero. It parses I/O status and returned length after the two ACK bytes. Read payload-length inconsistencies replace the reported length with buffer length minus five and change zero status to numeric 1. Oversized read replies are not copied. Any returned-length mismatch stops the transfer; a shorter read need not synthesize an error. One-way mode sends without reading or copying a response.

The returned count is accumulated bookkeeping, not an unconditional completed-transfer guarantee: the current length is added even after buffer/message errors, and oversized replies may contribute bytes that were never copied. Reply buffers returned by `TRKRequestSend` are released here; outgoing buffers are released after each iteration. The source also calls release on failure paths, including a reply identifier of -1; allocator/release behavior is not established by this unit alone.

`TRKRequestSend` initializes the output identifier to -1 and uses an attempt counter initialized from unsigned `p2 + 1`, assigned to an int. For ordinary configured counts this permits one initial send plus retries. With timeout enabled, unsuccessful packet polls increment a counter toward 79,999,980; this is not a wall-clock timeout and processing intervening commands is not itself bounded. Commands below ACK are handed to `TRKProcessInput`, after which this helper forgets their identifiers. Reply candidates must meet minimum length and carry ACK/no-error bytes. Rejected candidates are released; accepted replies remain allocated for the caller, positioned after their two header bytes. Malformed replies with no read error may retry, but send/read errors stop the outer loop. Every terminal no-buffer state becomes `kWaitACKError`, masking the earlier error.

The target-support caller obtains arguments from saved target registers, invokes file support, translates local failures when the I/O status is still successful, flushes read memory, and advances the saved PC. No compiled layout or section conclusions are drawn.
