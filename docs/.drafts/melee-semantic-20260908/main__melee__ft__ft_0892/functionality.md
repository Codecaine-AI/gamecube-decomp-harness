## Functionality
This unit defines twelve core-fighter combat-bookkeeping and query routines. `ft_800892D4` clears current attack metadata, parallel received-hit metadata, initialized context fields and occurrence identifiers during fighter reset/death cleanup. `ft_80089460` rebuilds the current context from integer-truncated damage and six independent fighter conditions without replacing its occurrence identifier.

`ft_800895E0` accepts packed MotionState flags. It allocates an occurrence identifier when the incoming category is zero or differs from the previous category, before applying the Luigi 0x71→0x240063 and qualifying held-item 0x62→0x44003D substitutions. It then commits the packed word and refreshes the context. The shared `ft_80089768` resets a larger record prefix despite its Vec2 pointer declaration; it does not clear the separately maintained occurrence identifier. Item code copies these contexts through fighter/item ownership chains or selects a neutral baseline. `ft_80089824` preserves classification, refreshes context, allocates an occurrence and calls statistics processing with previous classification zero; downstream counting still has its own guards.

Five small accessors expose borrowed fighter-owned metadata/context pointers or the stored received-hit occurrence value. Their consumers update attack/hit statistics, item provenance, death snapshots, guarded KO history and recovery bonuses. Pointer results remain aliases, not independent snapshots. The statistics occurrence sequence must not be conflated with the separately maintained stale-move identity.

`ft_800898C0` combines current categories 113, 114 and 99 with a historical special-AppealS query and feeds guarded bonus decision 0x8B. Ordinary current-category checks and the special historical query have different lifetimes. `ft_80089914` implements a character-sensitive numeric range predicate: outside the AttackS3Hi–AttackS4LwS bounds it rejects; Fox/Falco additionally reject three consecutive values beginning at AttackS3LwS, and Mewtwo rejects AttackS3S. Its damage-processing caller supplies a packed classification byte, so the apparent motion-ID domain is not established.
