# Sheik Transform semantic review

## Ownership and state flow
This unit owns both Sheik's outgoing Transform startup and her destination-side finishing phase after Zelda transforms into Sheik. These are opposite directions of the bidirectional move, not consecutive phases on the same outgoing Sheik object.

Grounded and aerial startup enter states `0x169` and `0x16B` at frame zero. Both reset `cmd_vars[0]`, divide inherited horizontal and ground velocity by attribute `x60`, divide vertical velocity by `x64`, process the TopN position through the positional helper, and schedule `fn_80114034`. Division establishes scaling; attenuation depends on attribute values not established here. See [startup](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftSeak/ftseakspeciallw.c#L54-L104).

When either startup animation has no frames remaining, its animation callback installs `fn_8011412C`; it does not immediately perform the transformation. That accessory callback clears its slot and calls `ftCommon_8007EFC8` with Zelda's finish initializer. Common transformation logic obtains a separate destination fighter object, transfers position, velocity, situation and other state, performs conditional status/item handling, and invokes the continuation on `dst_gobj`. See [scheduling](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftSeak/ftseakspeciallw.c#L47-L52), [animation guards](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftSeak/ftseakspeciallw.c#L106-L123), and [cross-object handoff](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftcommon.c#L1240-L1369).

Conversely, Zelda supplies `ftSk_SpecialLw_80114758` as her continuation. This initializer selects grounded Sheik finish state `0x16A` or aerial finish state `0x16C`, begins at attribute `x70`, and schedules `fn_801140B0`. Six existing game mappings incorrectly associate these destination-side functions with transformation into Zelda; the saved proposals correct that direction. See [Zelda caller](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftZelda/ftzeldaspeciallw.c#L58-L69) and [Sheik finish entry](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftSeak/ftseakspeciallw.c#L239-L256).

## Effects and callback lifetime
`fn_80114034` conditionally spawns effect `0x4FC` on `FtPart_R2ndNb`; `fn_801140B0` conditionally spawns `0x4FD` on HipN. Both test `x2219_b0`, set it after spawning, and unconditionally install effect-hitlag callbacks and clear `accessory4_cb`. Thus an already-set latch skips spawning but does not skip callback setup or retirement. Surface transitions reinstall the appropriate callback without themselves proving that a new effect will spawn. The owned file does not establish the latch's complete reset/destruction lifetime. See [effect callbacks](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftSeak/ftseakspeciallw.c#L25-L45).

## Physics, collision and exits
All four IASA bodies are empty. Both grounded physics callbacks delegate to `ft_80084F3C`, whose common implementation applies ground friction, scales it above maximum walking speed, and applies ground movement. Both aerial callbacks pass `x68` and `x6C` to `ftCommon_Fall`, then call `ftCommon_8007CEF4`. The Fall helper directly establishes gravity and terminal-speed parameter roles. See [ground physics helper](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_084E.c#L42-L53) and [falling helper](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftcommon.c#L462-L468).

Collision transfers preserve the current animation frame through common inline helpers. Startup transfers select `0x169`/`0x16B`; finish transfers select `0x16A`/`0x16C`. The exact mask is `ftCommon_GroundAirColl_MF | Ft_MF_KeepGfx | Ft_MF_KeepColAnimHitStatus | Ft_MF_SkipHit`. No stronger claim that every collision or hit-state field is preserved is made. See [mask](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftSeak/ftseakspeciallw.c#L21-L23) and [frame-preserving helpers](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/inlines.h#L71-L89).

The literal collision guards remain important: grounded callbacks dispatch when `ft_80082708(...) == GA_Ground`; aerial callbacks dispatch when `ft_80081D0C(...) != GA_Ground`. These returned enum values must not be treated as the fighter's current situation. Both helpers update collision/fighter positions before returning, including when the caller does not dispatch a transition. One saved correction removes the baseline's incorrect no-mutation claim. See [ground query](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_081B.c#L392-L404) and [aerial query](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_081B.c#L105-L123).

Finish animation exhaustion calls `ft_8008A2BC` on the ground or `ftCo_Fall_Enter` in the air. Wait and Fall are normal outcomes, not unconditional guarantees: the common routines contain Hand-specific routes and other exceptional-state guards. Fall normally preserves fast-fall, clamps air drift and initializes fall bookkeeping. See [finish animation callbacks](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftSeak/ftseakspeciallw.c#L175-L187), [neutral dispatcher](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_08A1.c#L53-L109), and [Fall entry](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_Fall.c#L31-L71).
