# Sheik Transform: independently verified TU review

## Scope and integration
This unit implements Sheik's grounded and aerial Transform startup, a deferred outbound handoff to Zelda, and the destination-side Sheik finishing states used when Zelda transforms into Sheik. SpecialLw2 is not a second outbound Sheik-to-Zelda transformation. The active motion table installs the four Anim/IASA/Phys/Coll suites and gives each FtMoveId_SpecialLw: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftSeak/ftseak.c#L239-L282. Zelda supplies ftSk_SpecialLw_80114758 to common transformation logic: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftZelda/ftzeldaspeciallw.c#L61-L69. These consumers, rather than numeric state names alone, establish the move and phase mapping.

The header declares 23 external void(Fighter_GObj*) routines. Three accessory callbacks and ftSk_unk_inline are static in the C file. The header repeats address comment 11444C for ftSk_SpecialLw_80114758; neither that comment nor a symbol suffix proves a compiled address. See code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftSeak/ftseakspeciallw.h#L1-L30.

Canonical fn_80114034, fn_801140B0, fn_8011412C and the address-suffixed transition helpers remain the source identities. Rendered CreateStartGFX, CreateFinishGFX, TransformToMainCharacter, GroundToAir, AirToGround and SpecialLw2_Enter names are useful descriptive hypotheses, not recovered original symbols. External rendered names such as lbDynamics_CreatePointWindEffect cannot establish their own meaning. The renderings preserve source control flow and contain no parse errors.

## Startup
ftSk_SpecialLw_Enter and ftSk_SpecialAirLw_Enter select 0x169 and 0x16B respectively, passing flags 0, animation-start argument 0, speed 1, blend argument 0 and NULL alternate animation object. They call ftAnim_8006EBA4, obtain Fighter and ftSeakAttributes, clear cmd_vars[0], divide self_vel.x and gr_vel by x60 and self_vel.y by x64, obtain the TopN position, process it through ftSk_unk_inline, and install fn_80114034. See code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftSeak/ftseakspeciallw.c#L54-L104.

These unchecked divisions are scaling, not guaranteed attenuation. Divisors below one can amplify, negative divisors can reverse, and zero or nonfinite inputs have no local handling. No runtime attribute values or finite-positive invariant were supplied. State entry precedes the divisions, so the values divided are those present after the common entry and animation calls, not necessarily untouched pre-entry velocity.

ftSk_unk_inline passes the position, 120, 0.4F, 0.003F and M_PI/3 to lb_800119DC. That callee copies the Vec3 into a local descriptor and passes it onward to lb_800100B0; this proves descriptor setup, not the rendered point-wind interpretation or a gameplay hitbox. See code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/lb/lb_00F9.c#L1065-L1080. The TU stores no pointer to its stack Vec3. Downstream descriptor allocation, retention and failure semantics remain unresolved. With NULL position input, lb_8000B1CC reads matrix translation for a parented joint and joint translation for a root; a NULL joint instead dereferences the NULL position input. Thus a valid TopN joint is a precondition: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/lb/lb_00B0.c#L105-L140.

## Effects and callback lifetime
fn_80114034 conditionally spawns 0x4FC on parts[FtPart_R2ndNb].joint. fn_801140B0 conditionally spawns 0x4FD on parts[FtPart_HipN].joint. Each tests x2219_b0, spawns and sets the latch only when clear, then unconditionally installs effect-hitlag callbacks and clears accessory4_cb. Neither checks spawn success. One-shot describes retirement per callback installation and suppression while the latch remains set, not the visual asset's duration. The anatomical expansion 'right second-nearest bone' is unsupported. See code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftSeak/ftseakspeciallw.c#L25-L45.

Fighter_SetEffectHitlagCallbacks assigns efLib_PauseAll and efLib_ResumeAll: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/inlines.h#L43-L47. Installation does not guarantee immediate execution; state changes or other assignments can replace the slot. This TU does not explicitly destroy effects or reset their latch.

## Animation and bidirectional handoff
The two startup Anim callbacks assign fn_8011412C when ftAnim_IsFramesRemaining returns zero and otherwise make no local write. They do not invoke the callback directly. fn_8011412C clears accessory4_cb before calling ftCommon_8007EFC8(gobj, ftZd_SpecialLw_8013B4D8). See code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftSeak/ftseakspeciallw.c#L47-L52 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftSeak/ftseakspeciallw.c#L106-L123.

The common routine obtains a destination entity, swaps transformed bookkeeping, initializes the destination, copies position, velocity, ground/air, damage and input state, and conditionally transfers statuses and items. It finally invokes the continuation with dst_gobj, not the source object. Its optional branches include metal, status flags and nullable item references; notably line 1324 assigns src->x198C = 2 rather than comparing it. No claim that the handoff is a pure copy is warranted. See code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftcommon.c#L1240-L1370. Zelda's continuation selects 356 or 358 and installs its finish callback: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftZelda/ftzeldaspeciallw.c#L303-L321.

Reciprocally, ftSk_SpecialLw_80114758 selects 0x16A only when ground_or_air equals GA_Ground; every other value selects 0x16C. It passes unchecked x70 as the animation-start argument with flags 0, speed 1, blend argument 0 and NULL alternate object, then installs fn_801140B0. See code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftSeak/ftseakspeciallw.c#L239-L256. A start argument is not necessarily the immediately stored frame: common entry initially stores anim_start minus speed. Also blend argument zero can select an asset-provided blend value; it does not prove disabled blending. See code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/fighter.c#L1220-L1295.

ftSk_SpecialLw2_Anim delegates to ft_8008A2BC on animation exhaustion; the ordinary Sheik path reaches ft_8008A348, normally Wait, with earlier x2224_b2 and ftCo_800C5240 branches. ftSk_SpecialAirLw2_Anim delegates to ftCo_Fall_Enter; its normal branch enters Fall with KeepFastFall, clamps drift and initializes bookkeeping, but common exceptional branches can redirect. Neither wrapper guarantees an unconditional Wait/Fall destination. See code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftSeak/ftseakspeciallw.c#L175-L187, code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_08A1.c#L53-L108 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_Fall.c#L31-L71.

The animation query scans eligible parts and chooses joint versus x4_jobj2 according to whether blend frames equal zero. No eligible active animation also returns false; this is not a numeric remaining-frame comparison. NaN blend frames select the nonzero branch. Exact asset duration is unknown. See code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftanim.c#L515-L538.

## IASA and physics
All four IASA bodies are empty. They provide no local input-driven transitions; that does not establish global uninterruptibility or that the dispatcher requires non-NULL callbacks. Both grounded Phys callbacks delegate unconditionally to ft_80084F3C. It selects ground friction, scales it only when ABS(gr_vel) > walk_max_vel, then applies friction and ground movement. Equality and unordered comparisons do not take the scaling branch. See code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftSeak/ftseakspeciallw.c#L125-L143, code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftSeak/ftseakspeciallw.c#L189-L207 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_084E.c#L42-L53.

Both aerial Phys callbacks call ftCommon_Fall(fp,x68,x6C), then ftCommon_8007CEF4(fp). Fall subtracts gravity and clamps only below -terminal_vel; equality is unchanged and unordered comparisons do not clamp. The active SOLUTION==0 friction branch writes x74_anim_vel.x: use -self_vel.x when absolute friction is at least absolute velocity; otherwise negate friction for positive velocity and retain it on the other branch. No local input or fast-fall branch exists. Negative, infinite and NaN parameters are not sanitized. See code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftcommon.c#L263-L281 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftcommon.c#L462-L468.
