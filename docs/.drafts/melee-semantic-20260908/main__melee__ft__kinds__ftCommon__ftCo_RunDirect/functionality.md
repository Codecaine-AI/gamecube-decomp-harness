## RunDirect translation unit

The owned implementation consists of four externally visible `void(Fighter_GObj*)` callbacks, declared by the guarded header. It defines no local objects, allocation routines, entry routines or callback-registration operations. Source: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_RunDirect.h#L1-L11 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_RunDirect.c#L1-L57.

### Registration and shared behavior
The inherited table research establishes that these callbacks are installed together with the same `ftCo_SM_Run`, `ftCo_MF_Run`, move flags and camera callback as the adjacent Run record. This is evidence of a running variant, not a gameplay inference from a numeric state label. See code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftmotionstates.c#L365-L386. The inherited symbolic search found no RunDirect entry caller; numeric or indirect reachability and initialization remain unresolved.

Anim, Phys and Coll unconditionally forward the identical object pointer to the corresponding Run callbacks, without additional local state manipulation. See code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_RunDirect.c#L17-L20 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_RunDirect.c#L49-L57.

Run animation chooses cached `mv.co.run.x4` when the ground-friction multiplier is below 1, otherwise ground velocity. Nonpositive facing-relative velocity produces zero animation rate; otherwise the rate is absolute velocity divided by `run_animation_scaling`. Positive `mv.co.run.x0` is decremented by 1 without clamping. Physics obtains acceleration and target velocity, tapers acceleration only for nonzero target velocity and a ground/target ratio strictly between 0 and 1, caches target velocity times common-data `x440`, invokes the friction-aware velocity helper, and applies ground movement. Collision forwards to `ft_800844EC`; that helper's complete behavior remains outside the established scope. See code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_Run.c#L76-L99 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_Run.c#L130-L152.

### Interrupt dispatcher
IASA obtains a Fighter pointer once and checks, in order: `ftCo_SpecialS_CheckInput`, `ftCo_Attack100_CheckInput`, `ftCo_800D6824`, `ftCo_800D68C0`, `ftCo_800D8A38`, dash attack, guard, `ftCo_800DE9D8`, `fn_800CAF78`, guarded `fn_800CA698`, and finally `ft_8008A244`. A true predicate terminates the callback. `RETURN_IF` evaluates its condition once and returns on truth. See code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_RunDirect.c#L22-L47 and code://c302741689bd67c361cd7faadb221df3193992c3/src/Runtime/platform.h#L164-L169.

Dash success calls `ftCo_AttackDash_SetMv0` before returning. Guard success calls `ftCo_80091B90(gobj, p_ftCommonData->x410)` and then `ftCo_80091B9C(gobj)`. These setters write `mv.co.guard.x20` from the supplied integer and `mv.co.guard.x24` from common-data `x68`. The guard checker has a digital-trigger/timer branch followed by an alternate shield-health-dependent branch. These are source member accesses, not compiled offset or gameplay-meaning claims. See code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_Guard.c#L70-L128.

Despite its canonical name, `ftCo_Attack100_CheckInput` checks a non-null `ftData_SpecialHi[kind]`, requires `x686 == 0`, calls that handler synchronously, and returns true. The next two opaque checkers similarly dispatch `ftData_SpecialN`/`x689` and `ftData_SpecialLw`/`x687`. Absent handlers return false. Active table use contradicts the baseline rapid-jab interpretation. The true return does not independently verify that each character handler completed a motion-state transition. See code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_Attack100.c#L44-L101.

The inherited jump research identifies an optional branch in `fn_800CAF78` that directly returns `ftCo_800C5A50`, including when false. Otherwise it enters KneeBend for stick y at least the relaxed threshold with a timer strictly below the tap-jump window, or an X/Y press. See code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_Jump.c#L62-L84.

The late guard is exactly `fp->mv.ca.specials.grav <= 0.0F && fn_800CA698(gobj)`. It does not gate the final checker. Signed zeros and negative finite values pass; positive values fail. Under ordinary IEEE comparison semantics negative infinity passes, whereas positive infinity and NaN fail. Passing only permits the callee, which additionally requires facing-relative stick x at least common-data `x58_someLStickXThreshold`. Success enters Run preserving current animation frame and speed, initializes Run x0 to zero and Run x4 to ground velocity. A false comparison or false callee continues to the final checker, after which no local work remains. See code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_Run.c#L48-L74.

Ordinary Run shares the earlier checks but has a different tail: guarded `fn_800C9D40`, an early return on `!(mv.co.run.x0 <= 0.0F)`, then RunBrake. Unlike a strictly positive comparison, that early-return condition also accepts NaN under IEEE semantics. RunDirect instead uses its grav guard, Run entry and final generic checker. See code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_Run.c#L101-L128. A compiled-layout equivalence or timer alias between grav and Run x0 is not established.

### Ownership and uncertainty
All four arguments are borrowed object pointers forwarded without conversion or local retention beyond the invocation. This TU allocates/frees nothing, stores no argument and registers no delayed callback. IASA assumes valid Fighter and common-data pointers and retains its local Fighter pointer across unsuccessful checks. Successful dash and guard checks must leave the object valid for immediate setup. General lifetime and state-mutation guarantees inside downstream character handlers are not proved. The motion-state table stores function pointers, not per-invocation object ownership.

Rendered names are hypotheses: SpecialHi/N/Lw and guard setter interpretations have independent canonical support, but CatchDash, AppealS and Wait aliases remain unverified here. No character-specific gravity mechanic follows from the grav spelling. No source declaration establishes the .sdata2 target's payload, placement, size or padding; all four section claims remain deferred pending compiled evidence. The parameter #r3 identities likewise are not independently established as compiled ABI placements.

Floating-point code has no explicit sanitization: zero target velocity bypasses division, ratios equal to zero or one bypass tapering, NaN ratios fail the strict range tests, and animation scaling has no zero guard. Exceptional-value runtime reachability and compiled floating-point exception/optimization behavior remain unresolved.
