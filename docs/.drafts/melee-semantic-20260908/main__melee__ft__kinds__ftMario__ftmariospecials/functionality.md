# Mario SpecialS translation unit

## Scope and identity
The owned implementation and header define 18 exported fighter-side routines for Cape creation, cleanup, hitlag synchronization, entry, animation, IASA, physics, collision, and ground/air continuation. The header declares one `bool(HSD_GObj*)` predicate and 17 `void(HSD_GObj*)` routines; it contains no additional implementation. Canonical names are retained. The active Mario motion table connects both SpecialS variants to their corresponding callbacks and labels both with `FtMoveId_SpecialS`; the Cape constructor and tracked fields independently establish the article association. Identity is not inferred solely from numeric state names. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftMario/ftmariospecials.h#L1-L26; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftMario/ftmario.c#L65-L86.

## Entry and completion
`changeAction` calls `Fighter_ChangeMotionState(gobj, msid, 0, 0, 1, 0, NULL)`, then `ftAnim_8006EBA4`, clears command variables 2, 1, and 0, clears the move-local reflecting latch, and installs CreateCape in accessory4_cb. Ground entry first zeros self_vel.y. Air entry first divides self_vel.x by specials.vel_x_decay; it does not explicitly clear the persistent Cape-boost latch. Zero, negative, infinite, or NaN divisors are not rejected; speed reduction and finiteness are not guaranteed. Exact target exceptional floating-point behavior is not established by source alone. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftMario/ftmariospecials.c#L113-L146.

Both animation callbacks test `!ftAnim_IsFramesRemaining`. Ground calls ft_8008A2BC; air calls ftCo_Fall_Enter. The inherited common-source review establishes that the former is not an unconditional Wait transition: boss handling and neutral-path checks precede ordinary Wait setup. Both IASA bodies are empty, establishing no move-specific interrupt processing rather than global inability to interrupt. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftMario/ftmariospecials.c#L148-L164; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_08A1.c#L53-L98.

## Cape ownership and callback lifetime
CreateCape executes only when cmd_vars[2] is zero. It sets the latch before attempting creation, obtains right-thumb coordinates through lb_8000B1CC, and passes the fighter, facing direction, coordinates, bone index and specials.cape_kind to it_802B2560. The result is stored in both u.mr.x223C_capeGObj and x1984_heldItemSpec. The constructor can return NULL; otherwise it attaches the spawned item to the parent. Failed creation does not itself cause a retry: the latch remains set and accessory4_cb is cleared. A nonzero latch skips the entire body, including callback clearing. A zero latch does not guard against overwriting an already tracked article; lifecycle consistency is a caller invariant. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftMario/ftmariospecials.c#L25-L64; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/kinds/itmariocape.c#L17-L31.

setCallbacks installs death2_cb and take_dmg_cb only when a Cape pointer exists; otherwise it leaves their existing values alone. It always installs paired pre/post-hitlag callbacks. ftMr_Init_OnTakeDamage calls RemoveCape. EnterHitlag and ExitHitlag guard the tracked pointer and forward to it_802B26C0 and it_802B26E0. Their item wrappers call it_8026B724 and it_8026B73C. The inherited flag review establishes x3 setting on entry and conditional x5 setting plus x3 clearing on exit, but not the complete scheduler effects. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftMario/ftmariospecials.c#L25-L34; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftMario/ftmariospecials.c#L85-L99; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftMario/ftmario.c#L192-L195; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/kinds/itmariocape.c#L54-L62; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/it_26B1.c#L388-L406.

Reset invokes ExitHitlag before clearing the Cape pointer, death2_cb and take_dmg_cb. It does not clear heldItemSpec, hitlag/accessory callbacks, command variables or reflection flags. RemoveCape does nothing with a NULL tracked pointer; otherwise it calls it_802B2674 followed by Reset. The item helper itself resets a non-null owner before Item_8026A8EC. Under consistent ownership, the nested Reset performs guarded hitlag exit while the article is tracked; the outer Reset normally sees NULL. Item destruction and item-animation termination also reset the owner. Repeated Reset calls without intervening setup still clear callback fields but do not repeat the guarded article operation. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftMario/ftmariospecials.c#L66-L99; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/kinds/itmariocape.c#L33-L51; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/kinds/itmariocape.c#L97-L122.

CheckItemCapeRemove is read-only: it returns false within the inclusive SpecialS-to-SpecialAirS motion interval and true outside. The item animation consumer passes its owner, treats a missing owner as removal, and resets an existing owner when returning true. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftMario/ftmariospecials.c#L101-L111; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/kinds/itmariocape.c#L105-L122.

## Commands, reflection and movement
reflect creates a reflector with sa->cape_reflection and NULL callback only when command 1 equals exactly 1 and the local latch is false. Command 1 equal to zero with latch equal to true clears the local and fighter reflection flags. Other command values cause neither transition. ftColl_8007AEF8 runs regardless of reflector activity. Opponent reversal, collision response and script frame timing are not established here. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftMario/ftmariospecials.c#L166-L180.

Ground physics consumes command 0 only at exactly 1U, writing 2U before obtaining HipN coordinates, adding 3*facing_dir to x, and calling lb_800119DC with 120, 0.9, 0.02 and M_PI_3. ft_80084F3C and reflect always follow. Air physics samples command 0 into u32: zero selects ftCommon_FallBasic; all nonzero unsigned values select ftCommon_Fall using move gravity and terminal velocity. Exactly 1 also writes command 2, sets a previously clear persistent boost latch and assigns specials.vel.y, or assigns zero y when already latched. The configured value is not proved positive. Its HipN-relative lb_800119DC call uses 120, 3, 0.1 and M_PI_3. Move gravity follows the assignment in the same update; air friction using specials.vel.x and reflect run in every branch. The external effect call is established, but a visual-only classification and parameter meanings are not proved by its rendered alias. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftMario/ftmariospecials.c#L182-L247.

## Terrain continuation
Ground collision dispatches GroundToAir on ft_800827A0 == false; air collision dispatches AirToGround on ft_80081D0C != false. The inherited collision review records position synchronization and a non-obvious GroundOrAir boolean convention; rendered names must not replace these actual tests. Common terrain transitions change motion using the current animation frame, rate 1, blend 0 and supplied flags. GroundToAir then rewrites only a pending command 0 value of 1 to 2, preventing that pending event from entering aerial activation. AirToGround clears the persistent boost latch first. collUpdateVars restores fp->reflecting only when the local latch is set, installs callbacks and rearms CreateCape without resetting its creation latch. An already consumed creation callback can therefore remain installed without doing work. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftMario/ftmariospecials.c#L249-L302; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/inlines.h#L71-L89; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_081B.c#L105-L123; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_081B.c#L406-L423.

The explicit mask combines KeepColAnimHitStatus, SkipHit, SkipMatAnim, UpdateCmd, SkipColAnim, SkipItemVis, Unk19, SkipModelPartVis, SkipModelFlags and Unk27. Exhaustive preservation semantics require flag consumers. Death initialization also clears the boost latch and Cape pointer, so landing is not the only lifetime boundary and a global once-per-airtime invariant remains unproved. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftMario/ftmariospecials.c#L273-L302; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftMario/ftmario.c#L156-L166.

## Conventions and uncertainties
Nonempty routines require a valid fighter GObj/user_data; attribute and bone consumers additionally require initialized Mario-compatible attributes and joints. Nullable article pointers are checked, not arbitrary invalid pointers. Exported parameters are fighter objects; empty IASA bodies do not dereference them. ABI/register mappings, binary object layout, stack layout and compiled sizes were not verified. Padding and TODO comments are not compiled evidence. All four .sdata2 facts remain unresolved. Rendered substitutions are hypotheses, not independent proof, and no owned rename is proposed. Numeric attributes, exact activation timing, full item scheduler effects, heldItemSpec cleanup, flag consumers and complete boost-reset lifetimes remain follow-up questions.
