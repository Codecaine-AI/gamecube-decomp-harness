# Common fighter Entry translation unit

## Scope and canonical identity
The owned files are `src/melee/ft/ft_0C31.c` and its public header. The implementation supplies the Entry, EntryStart, and EntryEnd callback quartets, three state initializers, two shared collision-transition adapters, two accessory callbacks, and an out-of-line `HSD_JObjSetMtxDirty` wrapper. The header declares the public fighter routines with `void(Fighter_GObj*)` signatures; the two collision adapters have static forward declarations in the C file. The canonical identifiers remain authoritative. `ftCo_Entry.c`, `ftCo_Entry_Enter`, `ftCo_EntryStart_Enter`, `ftCo_EntryEnd_Enter`, the Ground/Air adapter names, and the Accessory1_Cb names are descriptive naming hypotheses, not recovered original symbols. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_0C31.h#L1-L24 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_0C31.c#L21-L73.

## Active consumers and startup
The actual motion-state table installs all twelve callbacks in the Entry, EntryStart, and EntryEnd records. EntryStart has `ftCo_SM_EntryStart`; Entry and EntryEnd have `ftCo_SM_None`. All three use `ftCo_MF_Rebirth` and the common camera-box callback. This is active table evidence, not gameplay inferred from numeric state names. Fighter startup selects `ftCo_800C61B0` when Player_GetFlagsBit3 is set, after Master Hand, Crazy Hand, and transformation branches and before ordinary startup. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftmotionstates.c#L3676-L3708 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/fighter.c#L898-L930.

## Initial Entry phase
`ftCo_800C61B0` obtains the Fighter and root JObj, initializes `entry.timer` through Player_GetUnk4C, saves the root scale in `entry.x8`, and constructs `entry.x14` with saved X/Z and common-data Y `x6C4`. It applies that scale, writes current Y through `mv.co.common.x4.x`, enters `ftCo_MS_Entry` with flags 0, frame 0, rate 1, and blend 0, then sets invisibility, x2219_b1, x221E_b1, x221E_b2, and x221F_b1 and calls ft_80084CB0 with `entry.x2C`. The player accessor returns a u8 promoted to int, so the initial delay source spans 0–255. The source-level correspondence between the common-union Y write and later entry.x4 reads is apparent, but compiled object-layout proof was not supplied. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_0C31.c#L24-L48 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/pl/player.c#L1686-L1702.

`ftCo_Entry_Anim` tests zero BEFORE decrementing. A zero input invokes `ftCo_800C6408`, which replaces the timer, and the original callback then decrements that replacement timer. A positive delay of one therefore becomes zero without transitioning until the following invocation. Entry_IASA, Entry_Phys, and Entry_Coll are entirely empty; this proves absence of work in those callback slots, not absence of every engine-wide update. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_0C31.c#L50-L73.

## EntryStart setup and interpolation
`ftCo_800C6408` writes common duration x6BC and enters EntryStart, then reasserts x2219_b1. If x221F_b4 is clear it creates an accessory from Fighter_804D6514. Its uniform scale is fighter x34_scale.y times co_attrs.trophy_scale, saved in entry.x24. Rotation has X/Z/W zero and Y equal to 1.5707963267948966 times facing_dir. The full displacement x20 and current displacement x28 are initialized to 1.497345 times accessory scale. Translation is `(-(facing_dir * ftCommon_800804EC(fp) - cur_pos.x), cur_pos.y, cur_pos.z)`. The rotation setter's exact Euler/quaternion interpretation and asset identity are not independently proved here. Unconditionally, including the x221F_b4 branch, it installs fn_800C69F4, queues effect 0x43E with argument class 3 and the address of saved scale entry.x8, plays audio 0x8B, and calls ftCo_800BFFD0 with 0x75 and 0. The final effect argument is saved SCALE storage, not a proved effect-position vector. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_0C31.c#L75-L135.

EntryStart_Anim decrements first and transitions through ftCo_800C6B6C only if the result equals zero. EntryStart_IASA is empty. EntryStart_Phys computes `p = (float)(x6BC - timer) / x6BC`, interpolates root Y scale as `p * (savedY - x6C4) + x6C4`, and applies entry.x14 for both entity branches. When x221F_b4 is clear it applies accessory scale `(x24, x24*p, x24)`, stores x28=x20*p, and sets Y=x4+x28. Otherwise it copies logical player entity 0's Y, with no null check. Mathematical endpoints require a nonzero duration and finite values; execution is not guaranteed to sample either endpoint. In particular the Entry-to-EntryStart callback already decrements the new timer, and EntryStart_Anim changes state at zero before a later physics dispatch can necessarily sample p=1. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_0C31.c#L137-L183.

## EntryEnd
`ftCo_800C6B6C` loads x6C0, restores the saved root scale, sets Y to x4+x20 or copies entity 0's Y, enters EntryEnd with flags 0x3000, and installs fn_800C6F34 after reasserting x2219_b1. EntryEnd_Anim decrements first; exact zero conditionally calls ftColl_8007B760 with x6C8 when Player_GetFlagsBit4 is true, then calls ftCommon_8007D92C. The latter selects ftCo_Fall_Enter for GA_Air and ft_8008A2BC otherwise. The optional collision helper's detailed intangibility semantics remain unverified in this review. EntryEnd_IASA is empty. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_0C31.c#L246-L279 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftcommon.c#L596-L604.

EntryEnd_Phys uses `q = (float)timer / (float)x6BC`, NOT x6C0, even though x6C0 initializes this phase. It applies `(x24,x24*q,x24)`, x28=x20*q, and Y=x4+x28, or follows entity 0's Y in the alternate branch. It neither restores root scale nor decrements the timer. Thus a normalized reverse of EntryStart requires additional duration/value assumptions; unequal x6BC and x6C0 can yield a discontinuous initial ratio. There is no local clamp or zero-denominator guard. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_0C31.c#L281-L304.

## Collision and associated entities
EntryStart_Coll and EntryEnd_Coll set entry.x2C.bottom to negative local x28, or negative entity 0's x28 when x221F_b4 is set. GA_Air selects ft_80083E64 with fn_800C63BC; every other ground_or_air value selects ft_800846B0 with fn_800C63E0. The air helper transforms the supplied box, updates collision position, and calls back only after successful collision and unless ft_80081A00 suppresses it. The grounded helper calls back when its collision test fails. Neither retains the event pointer in the inspected implementation. fn_800C63BC delegates to ftCommon_8007D7FC, which performs airborne bookkeeping and canonical grounding, resets jump/wall-jump use, unlocks the ECB, and asserts if supporting-floor validation fails. fn_800C63E0 delegates to ftCommon_8007D5D4, setting GA_Air, clearing ground velocity and selected Z/animation fields, setting jumpsUsed=1, and locking the ECB with timer 10. These helpers do not themselves change the Entry motion state. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_0C31.c#L63-L71, code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_0C31.c#L185-L201, code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_0C31.c#L306-L322, code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_081B.c#L995-L1025, code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_081B.c#L1156-L1179, and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftcommon.c#L509-L594.

fn_800C69F4 and fn_800C6F34 have equivalent positional logic. With x221F_b4 clear, each optionally obtains logical entity 1, requires it to exist and have x221F_b3 clear, and raises current Y only when that entity's Y is strictly greater. Equal values do not write Y; a NaN operand makes the comparison false under ordinary floating comparison semantics. Each then translates the accessory using the facing-adjusted X expression and current Y/Z. With x221F_b4 set it dereferences logical entity 0 without a null check and copies its Y, without updating a local accessory. Player_GetEntityAtIndex resolves indices through transformed[], so these are logical indices, not fixed physical object slots. The player's comment suggests Ice Climbers relevance but does not prove exclusive character mapping or every producer of x221F_b4. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_0C31.c#L203-L236, code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_0C31.c#L324-L354, and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/pl/player.c#L1047-L1078.

## Ownership, callback lifetime, and dependencies
The Fighter owns the accessory pointer operationally: ftCommon_SetAccessory asserts it was null and assigns HSD_JObjLoadJoint's result. Fighter_ChangeMotionState removes a non-null accessory unless Ft_MF_KeepAccessory is set, resets invisibility and presentation flags, and clears accessory1_cb when installing the state callback set. The EntryStart and EntryEnd initializers therefore install their accessory callbacks AFTER changing state. The accessory dispatcher skips x221F_b3 objects and routes x2219_b5 objects through accessory3 instead; otherwise it invokes accessory2 then accessory1 and updates root translation after each. Thus 'per-frame' means an eligible dispatcher invocation, not unconditional execution every frame. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftcommon.c#L977-L984, code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/fighter.c#L1038-L1118, code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/fighter.c#L1370-L1389, and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/fighter.c#L2526-L2550. The 0x3000 EntryEnd flags include the accessory-preservation bit defined as 1<<13 in code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/forward.h#L204-L204. Effect queuing uses Fighter-resident storage rather than a stack vector; exact async argument copying and retention remain unresolved. Motion changes flush x60C, and the later fighter process also flushes that queue: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/fighter.c#L947-L951 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/fighter.c#L2552-L2558.

The TU depends on common fighter state, player timing/entity access, collision-box helpers, JObj transforms, accessory loading, async effects, audio, and color animation. Stateful routines assume valid Fighter_GObj/Fighter/root objects and valid common data. The alternate entity-0 paths assume that entity exists; only entity 1 is optional. No allocation-failure recovery is present locally.

## Matrix wrapper and data sections
The parenthesized HSD_JObjSetMtxDirty definition returns for null or already-dirty input and otherwise calls HSD_JObjSetMtxDirtySub. The subroutine marks the object dirty and recursively visits clean parent-dependent children, stopping below instance objects and skipping parent-independent children. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_0C31.c#L238-L244 and code://c302741689bd67c361cd7faadb221df3193992c3/src/sysdolphin/baselib/jobj.c#L1445-L1459. ## Boundaries and uncertainties
The countdown member is canonically declared `bool timer`; its underlying project typedef/compiled representation was not established, so signed-width/overflow claims are not proved. Source arithmetic decrements without saturation and tests equality, not <=0. Initial zero enters EntryStart immediately; Start/End zero before decrement does not take their zero-result branch under integer countdown semantics. x6BC=1 on the normal Entry handoff leaves a new timer of zero before EntryStart_Anim next decrements it, an important boundary requiring runtime/configuration verification. Both interpolation paths divide by x6BC without validation; negative/out-of-range progress, zero denominators, NaN, infinity, and overflow are not repaired locally. Finite endpoint algebra is not a guarantee of exact floating endpoint values or actual sampled frames. Debug fighter mapping contains NaN-position assertions but is not a local numerical recovery mechanism. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/types.h#L360-L369 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/fighter.c#L2501-L2514. Exact asset/effect/audio/color identities, original names, compiled union layout, duration constraints, and character-exclusive mappings remain explicitly unresolved.
