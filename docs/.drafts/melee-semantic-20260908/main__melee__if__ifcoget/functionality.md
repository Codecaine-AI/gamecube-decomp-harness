## Coin Get numeric presentation

This unit owns a shared numeric count-up display, not coin spawning or collection logic. `un_802FF1B4` sets the first status bit, disables presentation, loads `IfCoGet.dat` and resolves `ScInfCgt_scene_data`, then calls `un_802FEFAC`. The constructor creates camera, light and UI GObjs, registers `fn_802FED14` at process priority 17, initializes the JObj hierarchy hidden at animation frame zero, and retains its owning UI GObj. The first status bit is written but never read in this unit; interpreting it as a lifecycle marker is an inference. [Source](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/if/ifcoget.c#L77-L135)

`un_802FF128` enables presentation, resets the current count, configures a target and cadence, stores X directly and negates Y. Bounds apply before narrowing: the interval is raised to one if necessary and then stored in two unsigned 3-bit fields; the target is capped only above 100 and then stored as an unsigned byte. Consequently an interval of eight becomes zero, and a negative target can become a byte value above 100. Negating the most-negative signed integer has no defined portable C result. [Declarations](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/if/ifcoget.c#L18-L30), [configuration](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/if/ifcoget.c#L105-L120)

The process hides the hierarchy and returns when disabled. When enabled and current is at most target, it reveals the hierarchy, advances by one when the countdown reaches zero, plays sound 0xB4 at nonzero multiples of ten or 0xB3 otherwise, applies X = stored_X / 10.9589 - 29.2 and Y = 24 + stored_Y / 10, and evaluates the animation at the current count. A stored cadence of zero or one increments every eligible process invocation. Equality continues position/animation updates without incrementing; enabled current greater than target performs none of those operations. [Process](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/if/ifcoget.c#L47-L75)

`un_802FF190` clears only two status bits. It neither destroys GObjs nor unloads the archive nor unschedules the process. The next process invocation hides the model. Common interface cleanup calls this reset, but final resource ownership and lifetime are not established here. Initialization has no local repeated-initialization guard or explicit load/allocation failure handling. [Reset and initialization](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/if/ifcoget.c#L122-L135), [common cleanup](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/if/ifall.c#L243-L271)

Canonical callers include regular-clear coin presentation and a results-player count presentation. These establish result-screen use, but do not independently establish the baseline's Coin Battle-specific association. That association remains unresolved rather than disproven.
