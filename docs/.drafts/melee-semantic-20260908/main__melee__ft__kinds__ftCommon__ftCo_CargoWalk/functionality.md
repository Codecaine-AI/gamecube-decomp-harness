# CargoWalk semantic synthesis

The complete owned implementation is `src/melee/ft/kinds/ftCommon/ftCo_CargoWalk.c` (60 lines), with its 13-line header. Both canonical and rendered views were independently read. The prior librarian's principal corrections are confirmed: source literals do not prove `.sdata2` layout; victim motion requests do not overwrite `victim_gobj`; initial input gating differs from tier reentry; and phase adjustment is quantized rather than exact synchronization. This synthesis additionally leaves baseline claims about exact on-back positioning unresolved rather than retaining them solely from the carrier table.

## Identity, interface and conventions
The header declares `bool ftCo_8009B67C(Fighter_GObj*)` and four void single-object callbacks, `ftCo_CargoWalk_Anim`, `_IASA`, `_Phys` and `_Coll`. `ftCo_8009B6C8(Fighter_GObj*, float)` has internal linkage through its preceding static declaration, despite the definition omitting `static`. `ftCo_CargoWalk_CheckInput` and `ftCo_CargoWalk_Enter` are descriptive inferred names, not canonical symbols. The rendered substitutions for foreign helpers likewise do not independently establish their semantics. The implementation depends on Runtime's `RETURN_IF`, shared walking, CargoWait, CargoJump, CargoThrow, the platform-pass adapter, Shouldered, Fighter types and Donkey attributes. The header uses the `GALE01_09B67C` include guard and fighter forward declarations. ## Initial entry and configuration
`ftCo_8009B67C` calls `ftWalkCommon_800DFC70`, enters through `ftCo_8009B6C8(gobj, 0)` and returns true on success, otherwise returns false without CargoWalk entry. CargoWait places this check last after its throw, jump, pass and turn checks. The shared walking predicate accepts `lstick.x * facing_dir >= walk_stick_threshold`, including equality. It does not validate fighter kind, ground state or victim ownership. [code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_CargoWalk.c#L16-L23; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_CargoWait.c#L52-L59; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftwalkcommon.c#L58-L69]

The internal entry reads `gobj->user_data` as Fighter and `fp->x2CC` as `ftDonkeyAttributes`. It passes base `x4_motion_state + 1`, `Ft_MF_None`, `anim_start`, fields x8/xC/x10 as slow/middle/fast frame parameters, fields x14/x18/x1C as animation-rate parameters and multiplier 1 to `ftWalkCommon_800DFCA4`. The shared initializer stores the multiplier before classifying speed, changes carrier motion to base plus walk type, initializes animation, and saves the walk configuration. Classification uses absolute actual ground speed, checks fast with >= first, then middle with >=, otherwise slow. Equality therefore selects the higher checked tier. The local zero-initialized 20-byte array has no subsequent source use and proves neither compiled stack layout nor a gameplay buffer. After carrier setup, entry recomputes walk type and passes `fp->victim_gobj` and `ftCo_MS_ShoulderedWait + walk_type` to `ftCo_8009C5A4`. This changes the referenced object's motion, not the pointer field. The consumer skips its body only if requested and current motion both equal ShoulderedWait; otherwise it changes motion at frame zero, optionally uses FreezeState when x2222_b6 is set, performs common setup and installs `ftCo_800DB464` as accessory1_cb. Correspondence here means a tier-derived motion request, not identical animation time or proved matching visual poses. ## Active consumers and callbacks
Donkey's active motion table assigns all four CargoWalk callbacks to ThrowFWalkSlow, ThrowFWalkMiddle and ThrowFWalkFast. Thus carrier three-tier cargo walking has active table evidence, not merely numeric enum-name inference. [code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftDonkey/ftdonkey.c#L151-L194]

`Anim` forwards the same object exactly once to `ftWalkCommon_800DFDDC`. Shared animation uses saved walk.x0 when the ground-friction multiplier is below 1, otherwise actual ground velocity. A nonpositive velocity-times-facing product sets animation rate zero. Otherwise the selected tier's rate parameter divides absolute velocity. The wrapper has no local timer or animation-end transition. [code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_CargoWalk.c#L37-L40; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftwalkcommon.c#L99-L128]

`IASA` evaluates `ftCo_8009BF3C`, `ftCo_8009BB1C`, `ftCo_8009C4F8`, then `ftCo_8009B4D0`, returning after the first true result. RETURN_IF evaluates its condition and returns from the void function when true. The first helper selects a directional cargo throw on newly pressed A/B: horizontal magnitude >= threshold has priority, with positive facing product selecting forward and the other branch backward; otherwise inclusive up/down thresholds select vertical throws. It reports success only for a different selected motion. Jump input first enters `ftCo_8009B9C8`, the cargo kneebend preparation path, not immediate airborne entry. The pass predicate requires downward stick <= its negative threshold, tilt timer strictly below its limit and a platform; its entry performs floor skipping and selects the cargo fall motion. The wait predicate accepts opposite-facing stick or absolute horizontal stick strictly below the walk threshold; equality does not trigger the magnitude-based stop branch. This dispatcher contains no ordinary attack or shield branch; a global prohibition is not established by that absence. If all four fail, IASA passes the internal entry function to `ftWalkCommon_800DFEC8`. That helper synchronously invokes it only when saved base plus newly selected tier differs from current motion. It stores no callback. For a change, it converts current frame / animation length to an s32 quotient, subtracts length times that quotient, scales the residual fraction by the destination frame parameter, converts to s32, then passes the result as float. This is integer-quantized phase adjustment, not exact continuous preservation or floor-modulo for negative frames. Initial input gating is not repeated. `Phys` forwards once to `ftWalkCommon_800E0060`. Shared physics combines stick-scaled acceleration with signed base acceleration, computes stick-selected target velocity using maximum walk velocity and saved multiplier, and applies a taper only for current/target ratios strictly between 0 and 1. It saves target times common x440 in walk.x0, calls `ftCommon_8007C98C` with acceleration, target and ground friction, then applies grounded movement. Zero stick takes the negative signed-base branch; zero target skips ratio division. Neither wrapper nor this common routine directly selects another motion state. ## Invariants and uncertainties
The code assumes valid carrier, user_data, compatible attributes and victim pointers, a coherent motion base and initialized walking configuration. It neither allocates objects nor establishes/releases grab ownership. The entry callback has static code lifetime and no stack capture; the shared tier helper does not retain it. Shouldered's installed accessory callback has a separate lifecycle not established here.

Under ordinary IEEE comparisons, NaN entry products fail >=; NaN ground speed falls through tier comparisons to slow. NaN thresholds can bypass individual tier checks, so a NaN fast threshold alone need not force slow if the middle comparison succeeds. Infinity, invalid attribute signs, zero denominators and nonfinite inputs are not sanitized. The animation routine can divide by zero and has no default assignment for an invalid motion offset; NaN facing products bypass its <= 0 freeze branch. Tier phase conversion has no zero-length, finite or representable-s32 guard. Physics skips division for zero target but not NaN target; tapering is conditional and is not guaranteed to reduce magnitude for arbitrary taper gain. Exact target-platform exceptional results remain unresolved, not asserted as normal gameplay. [code://c302741689bd67c3617faadb221df3193992c3/src/melee/ft/ftwalkcommon.c#L16-L214]

No compiled artifacts establish `.sdata2` extent, ordering, representation or relocation association. Float-position literals zero and one cannot prove an eight-byte literal pool. Parameter suffixes #r3/#r4 are baseline identities, not physical-register proof. Exact victim pose assets, global restrictions, callback destruction safety and compiled object layout remain unresolved.
