# Complete TU review

## Scope and naming
The owned files are `src/melee/ft/ftCo_800C7CA0.c` and its header. They implement the DownReflect wall-contact entry check, its parameterized initializer and four motion callbacks, plus two rendering-resource/configuration helpers. The header exports all eight routines and `HSD_MObj* ft_804D6580`; it contains no additional implementation. Canonical identifiers remain authoritative. `ftCo_DownReflect_Check`, `ftCo_DownReflect_Enter`, and `ftCo_DownReflect.c` are reasonable descriptive hypotheses, not recovered historical names. `ftCo_EnableCloakRender` is too narrow to treat as established: `ft_800C80A4` also has a caller in `ft_0C8C.c` unrelated to the immediately adjacent refraction initialization. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftCo_800C7CA0.h#L8-L18; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_0C8C.c#L136-L146.

## Wall-contact eligibility
`ftCo_800C7CA0(Fighter_GObj*)` reads horizontal knockback once and compares it with `p_ftCommonData->x1B0`. Its first branch requires `vel_x < -threshold`, `Collide_RightWallHug`, and `mv.co.downreflect.x4 != 1`; it uses the left ECB point and right-facing-wall normal, invokes the initializer with `ftCo_MS_DownReflect`, then stores marker 1 and returns true. Its second branch requires `vel_x > threshold`, `Collide_LeftWallHug`, and marker != 2; it uses the right ECB point and left-facing-wall normal, then stores 2 and returns true. Both offsets have z=0. Failure returns false without local writes. Equality does not satisfy the corresponding strict comparison. With a finite nonnegative threshold the directional descriptions hold; the routine does not validate that assumption. A negative threshold can make the ranges overlap, in which case the first successful branch wins. NaN velocity or threshold makes both ordered comparisons false; infinities follow the comparisons without sanitization. The marker suppresses the same recorded side, not all future bounces; this TU does not initialize or time-reset it. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftCo_800C7CA0.c#L22-L57.

Before each initializer call, `ftKb_SpecialN_800F1F1C` requests an additional effect only for Kirby, using effect 0x49E and part 0's joint. It is not an unconditional common impact-effect emitter and does not scale the offset. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftKirby/ftkirby.c#L4154-L4159.

## Entry and rebound construction
`fn_800C7DC4(HSD_GObj*, s32, Vec3*, Vec3*)` treats the object as a fighter and the vectors as borrowed inputs; it neither writes the vectors nor stores their addresses locally. It first calls `ftCommon_8007D5D4`, which sets GA_Air, clears ground velocity, shield-knockback z, position z and animation-velocity y, sets jumps-used to 1 and locks the ECB for 10. It then computes effect position from the now-current fighter position plus offset, and angle as `atan2f(-normal.x, normal.y)`. It requests effect 0x406 with spawn kind 5 and a small camera quake. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftCo_800C7CA0.c#L59-L75; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftcommon.c#L515-L525.

The outgoing knockback is not a mathematical reflection of the incoming vector: let m=`fp->xF0_ground_kb_vel` and k=`p_ftCommonData->x1BC`; it stores `(normal.x*m*k, normal.y*m*k, normal.z*m)`, preserving the source's multiply order. No absolute value, normal normalization, clamp, or finite-value check occurs. Thus a universal speed reduction or 20% reduction is not proved. It clears all self-velocity components and sets facing to -1 only if the resulting x is strictly negative; zero, negative zero and NaN take +1. It enters the caller-selected state with flags 0x18040, frame 0, speed 1, blend argument 0 and NULL. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftCo_800C7CA0.c#L76-L100.

After state change, the source tests `Collide_RightWallHug`: if set, it updates x using the explicit negated expression involving translation-node z, facing and offset.x; otherwise it updates y using translation-node y and offset.y. This is not a symmetric left/right x correction. The source explicitly has a branch-structure TODO; no compiled equivalence is claimed. It then calls `ftCo_80090574`, stores the saved m in `dmg.x18A8`, calls `ftCommon_8007EBAC(fp,7,0)` and `ftColl_8007B760(gobj,x1B8)`. Detailed meanings of the latter helper effects are not inferred from rendered aliases. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftCo_800C7CA0.c#L102-L121.

## Callback integration and exits
The active motion table binds the four DownReflect callbacks to WallDamage animation, with `Ft_MF_SkipMetalB` and the common camera callback. This is actual table evidence, not merely a numeric enum-name interpretation. The callbacks are static function addresses in the table, not temporary closures. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftmotionstates.c#L3819-L3829.

Anim calls `ftCo_80090780` only when `ftAnim_IsFramesRemaining` is false. The successor first makes a grounded fighter airborne if needed, then branches on parasol status != -1: the alternative calls `ftCo_800CF4DC`; otherwise it enters state 0x26, clamps air drift and calls `ftCommon_8007EBAC(fp,8,0)`. The active state-38 table entry uses DamageFall animation and callbacks, corroborating the ordinary DamageFall mapping. The detailed parasol successor implementation remains outside the proved behavior here. IASA is empty, including for a null argument; this proves no input-driven transition through this callback, not universal immunity to other state changes. Phys unconditionally calls `ft_80084DB0`, whose update checks fast fall, applies fast fall or normal fall with gravity and terminal velocity, then calls `ftCommon_8007D268`. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftCo_800C7CA0.c#L124-L136; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_DamageFall.c#L95-L109; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftmotionstates.c#L552-L562; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_081B.c#L1363-L1375.

The collision helper synchronizes positions, selects collision handling from SDI/ledge flags, conditionally adjusts JObj-source ledge-snap height, copies the resulting position back, and returns false if `ft_80081A00` handles the result. Therefore false means no additional transition by this wrapper, not necessarily that the fighter remains in DownReflect. ## Rendering helpers and resource flow
`ftCo_800C8064(void)` loads a joint from `Fighter_804D6504`, obtains its root DObj and caches that DObj's MObj in `ft_804D6580`, or NULL if the accessor returns NULL. `Fighter_LoadCommonData` obtains the descriptor from PlCo.dat table element 20; subsystem initialization calls this routine after loading common data. `ftMaterial_800BF2B8` uses the cache for `is_metal` under its material-selection guards, after an earlier refraction branch. The cache is not demonstrated to be a cloak material. The initializer performs no explicit retain, release or root-pointer preservation, and repeated-call ownership/teardown behavior remains unresolved. A NULL cache is not a demonstrated safe rendering fallback: the consumer subsequently dereferences its selected MObj. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftCo_800C7CA0.c#L145-L157; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/fighter.c#L140-L210; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftmaterial.c#L68-L89.

`ft_800C80A4(Fighter*)` iterates [0,parts_num) from the fighter-kind parts table. Only bones with flags_b1 participate. It sets JOBJ_LIGHTING, JOBJ_TEXGEN, JOBJ_SPECULAR and JOBJ_UNK_B18, clears JOBJ_UNK_B19 and JOBJ_UNK_B20, and walks each participating joint's DObj next-chain, replacing mask 0xE with value 2. A zero part count or empty DObj chain skips the relevant loop. The inner NULL alternative is redundant under the enclosing while condition. It does not replace materials, allocate models or initialize refraction itself. DObj replacement is explicitly `(old & ~mask) | (flags & mask)`. Selected-bit idempotence follows, but safety requires valid fighter/kind/table/parts and a finite acyclic DObj chain; no index or cycle validation is present. Shared model nodes can make effects observable through other aliases. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftCo_800C7CA0.c#L160-L185; code://c302741689bd67c361cd7faadb221df3193992c3/src/sysdolphin/baselib/dobj.c#L46-L53.

A refraction activation path calls this helper immediately before `lbRefract_80022BB8`; another caller sets x2227_b3 based on `Player_GetMoreFlagsBit0`. This supports shared special-render configuration, not cloak-exclusive naming. The item-specific Cloaking Device mapping is not established solely by these flags or rendered names. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_0C88.c#L31-L56; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_0C8C.c#L136-L146.

## Lifetimes, conventions and uncertainties
The entry helper requires a live fighter object, common data and valid normal/offset inputs; it has no failure/status path. Spawn kind 5 is EF_SPAWN_POS_OFFSET_PARAM. `efAsync_Spawn` copies both the vector and scalar into allocated queue storage before optionally linking the request or processing it, so this effect request does not retain addresses of the initializer's stack position/angle. Kirby's kind-2 request likewise copies its offset. Queue cleanup and the camera request's full lifetime contract are not proved here. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ef/types.h#L16-L29; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ef/efasync.c#L1405-L1464.

The source uses Fighter_GObj/HSD_GObj object wrappers, GET_FIGHTER, Vec3/f32 arithmetic and borrowed model pointers. PAD_STACK and TODO comments do not prove ABI or compiled layout. Source literals 0 and +/-1 are visible, but .sdata2 size, placement, padding and literal-pool loads are unresolved without compiled evidence. Likewise the declared MObj pointer is proved at source level, but its association with the baseline .sbss section is not independently compiled-proofed. Exceptional arithmetic is not sanitized; exact target atan2 exceptional behavior, asset values, normal invariants, side-marker reset ownership, and the positional TODO remain explicit uncertainties.
