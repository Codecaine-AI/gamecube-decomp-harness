## Blizzard article lifecycle

This unit implements the item-side lifecycle of the Ice Climbers' Blizzard attack. The fighter's SpecialLw accessory callback supplies a joint-derived emission position and facing direction. Emission is gated by an active flag and a zero counter; the counter is reloaded and decremented regardless of whether item construction succeeds. The public spawner's declared parent parameter is `Item_GObj*`, but the observed caller supplies a fighter object.

The spawn descriptor keeps two distinct positions: the supplied emission position becomes `prev_pos` with Z cleared, while `pos` is obtained through the originating fighter. Initial damage and velocity are zero, and both parent references receive the originating object. A null construction result bypasses all post-spawn initialization. Success snapshots the scale attribute, clears the Blizzard-local flag, runs initialization, and invokes debug/common setup helpers. See [construction](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/kinds/itclimbersblizzard.c#L34-L69) and [fighter caller](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftPopo/ftpopospeciallw.c#L175-L190).

## Initialization and numeric state

Initialization interpolates between article attributes `xC` and `x10` using one random sample. Exactly `facing_dir == 1.0f` preserves the angle; every other value negates it. After subtracting π/2, repeated additions/subtractions of τ normalize ordinary finite angles before speed attribute `x4` is converted into XY velocity; Z velocity is zero. These loops are not validation for nonfinite or extreme numeric inputs. Attribute `x0` initializes the life timer and a second timer scaled by a shared constant. The local flag becomes 1, then the fixed request selects state 0 with `ITEM_ANIM_UPDATE`. The source contains one state-table entry; this does not establish compiled section extent or a distinct animation identity. See [initializer and state entry](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/kinds/itclimbersblizzard.c#L72-L109) and [timer initialization](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/it_2725.c#L1413-L1421).

## Updates and interactions

The animation callback delegates to `Item_TickLifetime`. It tests the timer before decrementing: a nonpositive timer returns true unchanged; otherwise it subtracts 1 and returns false. Thus crossing zero is not reported until a subsequent invocation. Physics only adds attribute `x8` to vertical velocity, with no local clamp, position integration, or state transition; the attribute's sign is not established here.

Collision processing calls the shared collision routine, then executes both wall and ceiling queries and returns their bitwise OR. `bool` is an integer typedef, so there is no return-boundary normalization to 0/1. The wall helper returns 8 or 4, with the right-wall branch taking precedence if both masks are present; the ceiling helper returns 2. Both can update `xC30`, and a ceiling hit overwrites the earlier wall index. Floor contact is not included in this returned OR. See [callbacks](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/kinds/itclimbersblizzard.c#L111-L131), [lifetime boundary](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/inlines.h#L48-L55), [collision helpers](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/itmaplib.c#L323-L390), and [bool definition](code://c302741689bd67c361cd7faadb221df3193992c3/src/MSL/stdbool.h#L4-L14).

Damage-dealt, clank, shield-hit, absorption, and shield-bounce callbacks return true without local side effects. Reflection directly forwards to the shared helper and returns its result. Callback presence alone does not prove configured eligibility for each interaction, and a true return is not a survival guarantee.

Reference invalidation forwards both pointers to shared conditional cleanup, discarding its result. Matching owner, reflector, absorber, fighter/source, auxiliary-fighter, and toucher references are cleared; clearing the source reference resets its player field to numeric 6. The wrapper itself does not destroy the article, but its lifecycle caller caches the original owner and can destroy the item after cleanup when flag `x13` is set and that owner matches the supplied fighter. See [event callbacks](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/kinds/itclimbersblizzard.c#L133-L166) and [cross-file cleanup lifetime](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/it_26B1.c#L475-L525).
