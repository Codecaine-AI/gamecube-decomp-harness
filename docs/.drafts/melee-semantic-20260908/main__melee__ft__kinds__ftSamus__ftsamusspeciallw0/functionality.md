## Charge Shot cross-file interface
The trailing functions belong to held Charge Shot processing despite two SpecialLw-prefixed symbols. ftSs_SpecialLw_80129100 returns -1 without writing outputs for a null fighter object or absent x222C article reference; otherwise it writes x2230 and attribute x18 and returns zero. Output pointers are not checked. ftSs_SpecialLw_80129158 returns the x2071_b6 bit for states 0x157 through 0x15C and returns one otherwise, including null. ftSs_SpecialN_801291A8 returns zero for that set except 0x159, and one otherwise. The omitted state is the grounded cancel phase; the other states are startup, hold, ground fire, air startup, and air fire.

The held-item callback invokes these checks only when its retained fighter is non-null and equals its current owner, and only in the native Samus item-kind branch; Kirby has separate predicates. A nonzero predicate or failed charge query returns true immediately. Owner mismatch or a null retained reference skips those checks and still reaches scaling using existing item fields. Therefore the predicates' null behavior must not be mistaken for unconditional item-side null-owner destruction. The scale formula has no local zero-maximum guard.
