## Eligibility and boundaries
`ftCo_8009EDA4` obtains the Fighter and its collision data. It requires exactly `(facing_dir == -1 && env_flags & Collide_RightWallHug)` or `(facing_dir == +1 && env_flags & Collide_LeftWallHug)`, then `ABS(gr_vel) > co_attrs.walk_max_vel`. Success invokes the entry routine and returns true; failed guards return false without local state mutation or transition dispatch. Speed equality fails. Other facing values fail, including zero, infinities, and NaN under ordinary IEEE comparisons. The ABS macro is conditional negation, not a sanitizing library operation. NaN speed or threshold fails the strict comparison; infinite speed magnitude passes a finite threshold but not positive infinity; a negative threshold can admit zero speed. Neither controller input, signed travel direction, nor ground_or_air is checked locally. Thus movement 'into' the facing wall is not a proved signed-velocity invariant. ## Entry and ordered data flow
`ftCo_8009EE30` selects the left ECB endpoint whenever any RightWallMask bit is set; otherwise it selects the right endpoint. Both branches set z to zero. Right-mask selection wins if both sides are represented; this test is distinct from the predicate's narrower hug checks. It passes the stack Vec3 to `ftKb_SpecialN_800F1F1C`, requests `ftCo_MS_StopWall` with `Ft_MF_None, 0, 1, 0, NULL`, then assigns exactly `cur_pos.x = -(x68C_transNPos.z * -facing_dir - (cur_pos.x + vec.x))`. The saved ECB offset precedes the state change; position, facing, and translation reads in the assignment follow it. The expression is not replaced with an algebraically reassociated formula because rounding and exceptional floats need not be preserved. Position inputs are not sanitized. It finally calls `ft_800843FC`, then `ftCommon_8007E2FC`, without testing whether collision processing changed state.
