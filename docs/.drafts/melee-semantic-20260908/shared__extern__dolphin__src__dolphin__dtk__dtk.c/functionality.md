## DTK streaming playlist controller

This file maintains a global playlist, current track, playback/repeat state, cached stereo volume, and asynchronous DVD command blocks. Canonical and rendered source agree throughout the inherited completed review; the renderer reports no substitutions or parse errors. Existing descriptive source names fit the behavior and are retained. There are no owned baseline subjects, facts, or links to revise. The empty proposal is consistent with this assessment.

### Playback and notification
- AI startup applies cached volume, resets the sample count, schedules an interrupt trigger, and enables playback; stopping AI mutes both channels and disables playback. User notifications assert a non-null track and dispatch only the intersection of the requested event and the track's mask. Events used here are run `1`, stop `2`, pause `4`, queued `8`, ended `16`, and prepared-paused `32`. [Source](code://c302741689bd67c361cd7faadb221df3193992c3/extern/dolphin/src/dolphin/dtk/dtk.c#L31-L105)
- AI interrupts reschedule the trigger and request the stream play address. The address callback stores its result as position, then either requests stream status or processes a previously observed ended flag. Status with a zero low byte sets that flag and resets position. End processing advances or returns to the head for no-repeat/all-repeat, or prepares the same track for repeat-one; no-repeat stops at the tail. Callback results are not generally checked for failure. [Source](code://c302741689bd67c361cd7faadb221df3193992c3/extern/dolphin/src/dolphin/dtk/dtk.c#L73-L159)

### Playlist and lifetime
- Queueing opens the DVD file, stores the caller's track and filename pointers without allocating or copying them, and appends under interrupt exclusion. It returns `1` on open failure and `0` on success, emits event `8`, and starts preparation when adding the first track while logically running. Removal returns `2` for the current track; otherwise it closes the file and rewires links without freeing the track or validating membership. These retained objects must remain usable by subsequent callbacks and list operations. [Source](code://c302741689bd67c361cd7faadb221df3193992c3/extern/dolphin/src/dolphin/dtk/dtk.c#L237-L313)
- Flush ignores requests while BUSY. Otherwise it cancels asynchronously only when the previous state was RUN; other states execute cleanup immediately. Cleanup follows `next` pointers, closes files, clears playlist/current pointers, sets STOP, invokes the optional flush callback, then forces STOP again and clears the shutdown flag. Shutdown first forces STOP and disables AI, so its flush takes the immediate path rather than the RUN cancellation path. [Cleanup](code://c302741689bd67c361cd7faadb221df3193992c3/extern/dolphin/src/dolphin/dtk/dtk.c#L161-L181), [shutdown](code://c302741689bd67c361cd7faadb221df3193992c3/extern/dolphin/src/dolphin/dtk/dtk.c#L223-L235), [flush dispatch](code://c302741689bd67c361cd7faadb221df3193992c3/extern/dolphin/src/dolphin/dtk/dtk.c#L315-L329)

### State and controls
- State changes ignore identical requests and BUSY. RUN resumes AI from PAUSE, prepares an existing track otherwise, or records RUN with no track. STOP does nothing without a current track. PREPARE initiates preparation only from STOP with a current track, completing in PAUSE. A PAUSE request disables AI and emits event `4`, but changes the stored state only from RUN; a missing track reaches the notification assertion. [Source](code://c302741689bd67c361cd7faadb221df3193992c3/extern/dolphin/src/dolphin/dtk/dtk.c#L348-L395)
- Next/previous while running mute and cancel asynchronously, move the pointer, then restart through the saved state. Outside RUN they only move the pointer and restore state, including when paused; they do not prepare the newly selected track. Movement requires an actual neighboring link. [Movement](code://c302741689bd67c361cd7faadb221df3193992c3/extern/dolphin/src/dolphin/dtk/dtk.c#L55-L71), [completion callbacks](code://c302741689bd67c361cd7faadb221df3193992c3/extern/dolphin/src/dolphin/dtk/dtk.c#L189-L203), [navigation](code://c302741689bd67c361cd7faadb221df3193992c3/extern/dolphin/src/dolphin/dtk/dtk.c#L397-L427)
- Initialization selects STOP/no-repeat, frequency `48000`, and cached volumes `255`, while hardware volume/playback remain off. The sample-rate setter is obsolete and does nothing; its getter returns `1`. Repeat mode is assigned without validation. Volume updates hardware only in RUN, and its getter packs left in the high byte and right in the low byte. [Initialization](code://c302741689bd67c361cd7faadb221df3193992c3/extern/dolphin/src/dolphin/dtk/dtk.c#L205-L221), [setters](code://c302741689bd67c361cd7faadb221df3193992c3/extern/dolphin/src/dolphin/dtk/dtk.c#L331-L346), [getters and volume](code://c302741689bd67c361cd7faadb221df3193992c3/extern/dolphin/src/dolphin/dtk/dtk.c#L429-L472)

### Qualifications and independent reconciliation
The lead independently inspected canonical and rendered lines 161–400, confirming playlist ownership, cleanup ordering, shutdown dispatch, and exceptional state branches. ALLREPEAT endpoint removal explicitly makes `tail->next` point to the head, whereas queueing creates a null-terminated tail and flush walks until null. Thus the code does not support an unconditional claim that flush always terminates for every playlist topology. This qualification is retained, not treated as a contradiction of an existing fact. Numeric state-enum values, DVD result semantics, external callback guarantees, and compiled layout are not established by this file.
