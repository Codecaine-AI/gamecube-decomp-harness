## Yorster stage functionality

The unit registers `Gr_Kind_Yorster`, `/GrYt.dat`, two Ground-component callback rows, and stage lifecycle hooks. Yorster is Melee's Yoshi's Island, distinct from the returning OldYoshi/Super Happy Tree stage. Initialization caches the Yakumono parameter pointer, clears `stage_info.unk8C.b4`, sets `b5`, configures component IDs 0 then 1, and initializes camera and blast-zone ranges. Missing Ground objects produce diagnostics but do not stop this startup sequence. The component constructor independently guards optional callbacks and returns the acquired object, including NULL; it does not validate its callback-table index.

Component 0 requests animation configuration 0; its other registered callbacks are inert. Component 1 attaches collision joints, requests configuration 4 and additional animation calls for joints 23 and 26, queues deferred initialization, then sets `xC4=1`. The shared Ground queue retains the object/callback pair until after the stage start hook, invokes it once, and frees its queue node. Completion initializes nine element records, synchronizes collision, and clears the gate. The recurring process skips element updates while the gate is nonzero but still calls `lb_800115F4` and `Ground_801C2FE0`.

The nine records correspond to model joints 10–18 and retain JObj and material-object handles. Setup initializes their indices, state byte and two accumulators, registers material-hit and joint-collision callbacks, and configures animation and material handling. It does not initialize the timer fields. The hit callback conditionally assigns the fighter response value and independently adds the supplied hit value to the first matching material record's persistent `x04`. The collision callback accepts numeric environments 1, 2 and 3 only; environment 1 has an additional guard and substitutes the fighter's `pos_delta.y`. Thresholded fighter/item response calls are independent of the first-match joint lookup that accumulates `x08`. Neither callback directly changes the element state byte.

The updater handles states 0–4 for each record. States 0 and 1 prioritize the attack accumulator over vertical impact, disable material response, compute an animation offset and enter delayed state 2. State 2 removes collision and starts the selected animation only when its countdown is already nonpositive; otherwise it decrements the countdown. State 3 compares its timer with `0x143`, then either restores immediately or enters state 4 with an alternate animation when the spatial predicate is true. State 4 checks animation completion or timer `0x19`, resets the timer before its spatial test, and restores only when that test is false. A blocked retry remains in state 4. Restoration re-adds collision, reenables material handling, clears both accumulators and sets state 1. Every element update clears `x08`, including default-state handling; `x04` persists until consumed or restored. Numeric states, animation selectors and timer thresholds should not be conflated with visual disappearance or animation-frame counters.

The start hook invokes the shared generated-object manager with NULL and ignores its return; the manager schedules a persistent process and publishes its data, or frees that data on GObj creation failure. Other stage hooks are no-ops, constant false, NULL-descriptor or constant true endpoints.
