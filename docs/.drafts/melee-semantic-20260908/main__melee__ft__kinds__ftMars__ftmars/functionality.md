## Marth-family registration and support

`ftmars.c` defines 32 special-motion records, documented as states 341–372, covering grounded and aerial neutral, side, up and down specials. Each record supplies motion identifiers, flags, move-family bits and animation/IASA/physics/collision/camera callbacks. Callback sharing is significant: grounded SpecialS1 uses the SpecialAirS1 callbacks, and later side-special directional variants share stage callbacks. The unit also defines fighter and animation archive names, five costume descriptor sets, four demo-resource names and a five-element costume storage array. These are source-level declarations, not proof of compiled section boundaries. The header declares the public callbacks and resource objects. ## Lifecycle and attributes

Death schedules model groups 0 and 1 to selection zero and clears `u.ms.x222C`. The parts setter writes pending selections and marks them dirty; a separate routine applies them later. Pickup/drop forward the incoming boolean with fixed arguments 0 and 1. Visibility callbacks pass zero and the shared helpers exempt heavy items. Pickup additionally dispatches non-heavy hold kinds 1–4, with an optional presentation update; drop always resets the selection and conditionally hides presentation. Knockback adapters pass 1, with the shared helpers updating indices 1 and 0 using 3.0f on entry and 0.0f on exit. These adapters do not calculate launch physics. [Callbacks](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftMars/ftmars.c#L411-L485), [shared behavior](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/inlines.h#L142-L205), [pending selection protocol](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftparts.c#L555-L577)

OnLoad and OnLoadForRoy copy the current fighter's external MarsAttributes into `dat_attrs_backup` and install that buffer as `dat_attrs`. LoadSpecialAttrs copies external attributes into the already-active destination. Roy directly delegates both operations, sharing representation and implementation rather than necessarily sharing parameter values. ## Neutral-special callbacks and cross-file lifetime

`ftMs_SpecialN_801365A8` selects effects 1266/1297 for kinds 18/26; `ftMs_SpecialN_8013666C` selects 1267/1298. Both guard kind lookup and spawning with `!x2219_b0`, then set the latch even for an unmatched kind that spawns nothing. Every invocation installs effect pause/resume callbacks and clears `accessory4_cb`, including already-latched and unmatched-kind paths. Clearing the accessory slot is callback retirement, not effect destruction. [Effect bodies](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftMars/ftmars.c#L489-L533), [hitlag assignments](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/inlines.h#L43-L47)

The neighboring SpecialN implementation installs the first effect callback on grounded release and the second on aerial release; they are not established as sequential phases. Ground/air end-state transitions preserve the selected end variant and reinstall hitlag callbacks when the effect latch is true. Both startup entry routines install `ftMs_SpecialN_80136730` in `x21EC`. That helper unconditionally clears `cmd_vars[0]` and the integer `specialn.cur_frame`; it does not clear the effect latch. The charging loop increments this integer counter, sets command variable zero's slot true on automatic release, and clears it on button release.
