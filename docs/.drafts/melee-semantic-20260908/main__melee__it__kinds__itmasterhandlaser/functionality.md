## Shared Hand-boss laser article

The unit implements a fighter-joint-attached laser article with one registered item state, state 0. Its factory copies the supplied positions, kind and facing direction into a spawn descriptor, initializes zero velocity and damage, enters state 0, stores the selected fighter part and article root JObj, and attaches that root to the selected fighter joint. The allocation result is used without a null check. Although the factory parameter is spelled `Item_GObj*`, its body and fighter callers establish an effective fighter-owner domain.

State entry installs the accessory callback, clears `masterhandlaser.x0`, and loads the contact-effect counter `x8` from attribute `x4`. The nullable shutdown helper only sets `x0`; it does not synchronously destroy the article. Crucially, the animation callback first checks `it_80272C6C`: a zero result re-enters state 0 and clears any pending request before the subsequent flag test. Only an observed set flag causes removal of JObj-reference constraints and a true return. Physics is empty; collision always returns false. The unknown-event callback forwards both arguments unchanged to `it_8026B894`.

Accessory processing updates beam geometry, obtains the selected owner joint and dynamic bone 2 world positions, and supplies those endpoints to hitbox 0. The shared hitbox helpers only modify enabled capsules. Geometry starts from the attribute-defined full translation, queries the origin-to-endpoint XY segment, and adjusts bone 2 using the returned intersection and a mixed 3D/XY distance ratio. The caller does not establish intersection-selection order, and the XY denominator has no explicit zero guard. On contact updates only, the counter is decremented; a negative result emits effect `0x405` and reloads the counter. A no-contact update preserves full length and does not advance the counter.

Master Hand's FingerBeam sequence and Crazy Hand's corresponding code each create four instances and later signal and clear their stored handles. Crazy Hand's source uses numeric states `0x166`, `0x167`, and `0x168`; misleading callback labels are not sufficient to reinterpret those states. Another Crazy Hand action also signals retained resources during initialization. Fighter-side handle clearing is distinct from item-side deferred completion.

The five existing descriptive function names fit canonical behavior and are retained as hypotheses, not recovered original symbols. Both owned files were reviewed in canonical and rendered form. The header renderer leaves the factory declaration unsubstituted with `shadowed_binding`, despite substituting its definition in the C file. Source-level constants and table structure do not establish compiled section contents or layout.
