# Brinstar Depths / Kraid semantic review

## Registration and lifecycle
The unit registers `Gr_Kind_Kraid`, `/GrKr.dat`, five callback rows and six joint mappings. `grKraid_OnInit` caches the stage-provided yakumono parameter pointer, sets stage flags b4=false and b5=true, and sets up objects in order 0, 2, 3, 4, 1. Objects 4 and 1 initially have their JObj hierarchies hidden. The setup helper indexes the callback table without a bounds check, reports failed object retrieval and returns NULL; the initializer does not recover before using the returned objects for IDs 4 and 1. Demo initialization and loading are no-ops. Start invokes the shared generated-object manager with a NULL descriptor and ignores its result. The shared initializer schedules a manager and publishes persistent data on success; GObj creation failure reports, frees the newly allocated data and returns NULL. [Registration and setup](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gr/grkraid.c#L13-L108); [shared manager](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gr/grzakogenerator.c#L303-L329).

## Object roles
Object 0 selects animation 0. Object 1 receives uniform stage scale and numeric flag value 1, and its process contains a retained developer-facing animation audition control: second-controller A triggers advance a persistent selector through 0–6. There is no global debug-mode guard. Object 2 selects animation 0 and flag value 2. These flag values participate in the common renderer's camera-pass comparison; they should not be assigned invented gameplay-state names. Predicate callbacks return false and the remaining object-specific callback3 hooks are empty. The setup inline installs callback3, invokes on_init and schedules gobj_proc at priority 4, but does not install or invoke callback1. ## Cooperating rotation and Kraid controllers
Object 3 owns a two-state rotation controller. A nonzero activation/direction value starts a randomized hold interval and associated animation/sound. State 1 applies signed angular steps during that interval; the timer delays deceleration, not rotation. Afterwards it subtracts the signed decrement and stops only when the remaining speed magnitude is strictly less than the decrement magnitude. Applied steps are converted from degrees to radians before JObj Z rotation and a loop-quake request. Animation completion is handled independently, and common processing plus an empty terminal helper runs after the switch. The strike starter uses a float-zero reentry guard, derives speed from hand X, performs sequential clamps, applies the caller's sign and divides by `map_time_acl`. Its arithmetic includes division by `map_rot_spd_min`; no local zero-divisor validation exists. [Rotation controller and starter](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gr/grkraid.c#L187-L294).

Object 4 caches joints 31 and 47, builds an optional randomized wait and scans six candidate X coordinates with extrema initially anchored at zero. Its five numeric states implement waiting, entrance, an intermediate animation, a hand-dependent strike animation and departure. Appearance and strike gates use `(int) map->u.kraid.x4 == 0`, which is not equivalent to the starter's float-zero comparison for arbitrary values. Strike windows are 147–169 for animation 5 and 123–138 otherwise; the helper merely checks timer thresholds 158 or 130 and dispatches rumble. It performs no geometric contact test. A successful normal ±1 rotation start inhibits subsequent checks while the map remains active. State 2 increments its counter even after resetting it and transitioning to state 3. Departure hides both objects and rebuilds the randomized wait. [Initialization and cycle](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gr/grkraid.c#L296-L496); [impact predicate](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gr/grkraid.c#L546-L562).

Position selection either samples six indices while rejecting the previous index, or chooses between the initializer-produced extreme indices. It synchronizes object 4 and object 1 X translations and derives attack variant 0/1 from the coordinate's sign, randomizing at zero. Animation selection likewise updates both objects, narrowing the supplied index through signed-byte x1 and setting companion x0=1. That numeric write does not by itself establish a separately understood companion state machine. [Position and animation helpers](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gr/grkraid.c#L498-L544).

## Queries, names and evidence limits
The collision-line hook returns a null `DynamicsDesc*`; the shadow hook always returns true. The shadow caller supplies fighter position, -1 and the current stage joint and clears its exclusion flag on true. Existing rendered names generally fit canonical roles and are retained as hypotheses, not recovered-symbol proof. `CheckAttackImpact` denotes animation timing, not collision detection. The header renderer reports shadowed bindings for `grKraid_801FE0C4` and `grKraid_OnTouchLine`; the setup-helper name substitutes in C but not its header declaration. Header `bool` versus definition `int` for demo initialization, and Ground_GObj versus HSD_GObj spelling for position selection, are preserved without inventing ABI differences. No compiled artifact was supplied, so small-data placement, constant-pool composition and the claimed 32-byte `.sdata2` size remain unresolved.
