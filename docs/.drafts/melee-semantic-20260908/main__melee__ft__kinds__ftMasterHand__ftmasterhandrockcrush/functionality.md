## Scope and behavior
This unit defines twelve `void(HSD_GObj*)` routines: three motion-entry helpers, the RockCrushUp and RockCrushWait callback suites, and an empty Drill collision callback. The header declares all twelve; its `11 Punch` comment does not independently establish a player-facing move name. [Declarations](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftMasterHand/ftmasterhandrockcrush.h#L1-L22)

### State progression and timer lifetime
- `ftMh_MS_354_80152370` enters symbolic `ftMh_MS_RockCrushUp` with arguments `(0, 0, 1, 0, 0)` after the destination, then calls `ftAnim_8006EBA4`.
- Up animation completion calls `ftMh_MS_355_8015247C`, which enters symbolic RockCrushWait. Only after that helper returns does the caller copy special attribute `xA0` into `fp->mv.mh.unk0.x8`; the Wait entry helper itself does not initialize the countdown.
- Wait animation predecrements `x8` and invokes the Down entry helper exactly when the decremented result is zero. It then independently tests animation exhaustion. There is no return or `else`: if that subsequent query reports exhaustion, it re-enters RockCrushWait even after a Down entry call. The query therefore observes animation state after any preceding transition, not necessarily the original Wait animation.
- `ftMh_MS_356_801525E0` clears only `self_vel.x`, enters symbolic RockCrushDown, and calls the animation follow-up. Down's subsequent lifecycle is outside this unit.

The countdown is not tested with `<= 0`; an initially zero value does not trigger immediate expiry through this expression. No local validation of its initial range or attribute conversion is present. Numeric stems 354/355/356 are not used here as proof of numeric enum values. ### Physics and cross-file effects
Up physics delegates to `ft_80085134`, which writes horizontal velocity from translation-offset z times facing direction and vertical velocity from translation-offset y. Wait physics performs that same initialization, then calls `ftBossLib_8015C010(gobj, da->xA4)` to overwrite horizontal velocity with target-directed displacement capped by the supplied argument, then calls `ftBossLib_8015C190` to clamp current x position to floor 0 endpoints and clear horizontal velocity when outside them. Vertical velocity survives the latter two operations. The cap interpretation assumes a suitable nonnegative attribute; this caller does not validate it. [Caller order](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftMasterHand/ftmasterhandrockcrush.c#L71-L79), [translation velocity](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_084E.c#L120-L125), [steering and bounds](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftbosslib.c#L100-L156).

Target selection is nearest eligible fighter, not simply any nearest object: it applies same-player, status-bit and team exclusions and compares squared XY distances using a derived fighter position. The selected fighter's current position is subsequently copied for steering. Selection may return NULL, while the observed boss-helper chain forwards the result to a position accessor without a local null guard. No target pointer is retained by this unit. [Selection](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftlib.c#L113-L160), [position accessor](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftlib.c#L299-L303).

### IASA and collision
Both IASA callbacks dispatch `ftBossLib_8015BD20` only for player-slot type zero, canonically `Gm_PKind_Human`. That callee immediately returns, so the rendered `CrazyHand_IASA` hypothesis must not be interpreted as implemented input handling or an interrupt. Drill, Up and Wait collision callbacks are entirely empty.
