### Responsibilities and operation lifetime

This unit implements the two-channel Dolphin memory-card hardware layer, including EXI command transactions, asynchronous read/write/erase admission, status completion, timeout handling, removal notification, control-block reservation, initialization, capacity queries and synchronous waiting.

`__CARDStart` installs only non-null callback arguments, checks attachment, and either acquires/selects EXI or leaves a continuation waiting for availability. The launchers translate its BUSY result into READY to indicate accepted deferred work—not completed I/O. `__CARDUnlockedHandler` reports availability rather than granting ownership; `UnlockedCallback` must acquire EXI again. `Retry` executes saved command state for both deferred initial starts and status-error recovery. These paths are explicit in [startup and execution](code://c302741689bd67c361cd7faadb221df3193992c3/extern/dolphin/src/dolphin/card/CARDBios.c#L318-L462), while the [EXI queue](code://c302741689bd67c361cd7faadb221df3193992c3/extern/dolphin/src/dolphin/os/OSExi.c#L575-L632) retains availability callbacks and invokes them before restoring interrupts.

Reads use opcode 0x52, command latency bytes and a 512-byte receive DMA. Writes use opcode 0xF2 and a 128-byte transmit DMA. Erase-sector uses opcode 0xF1 without DMA; the whole-card erase helper uses 0xF4. Successful DMA launch retains selection and ownership until `__CARDTxHandler`; command-only paths release them after command transmission. DMA completion and final flash/status completion are separate stages. Write and erase callbacks occupy `exiCallback`, whereas read completion uses `txCallback`. See [launchers](code://c302741689bd67c361cd7faadb221df3193992c3/extern/dolphin/src/dolphin/card/CARDBios.c#L470-L618).

### Exceptional paths and numeric states

The EXI handler cancels the alarm before checking attachment. Lock failure reports FATAL_ERROR; status-read/clear failure takes the unlock-and-complete path. Status bits 0x18 select IOERROR. The handler pre-decrements `retry` before testing positivity, so an initial value of 3 allows at most two additional status-error reissues. Deferred initial execution does not consume that budget. [Status handler](code://c302741689bd67c361cd7faadb221df3193992c3/extern/dolphin/src/dolphin/card/CARDBios.c#L64-L114).

Timeout setup first cancels the previous alarm. It arms 100 ms for 0xF2 and two seconds multiplied by integer `sectorSize / 0x2000` for 0xF4 and 0xF1. The 0xF3 case does not arm an alarm; neither does the absent 0x52 case. Expiration disables EXI-event notification and consumes a pending EXI callback with IOERROR; this is not proof of hardware transfer abortion. The handler assumes its alarm belongs to one of the two control blocks rather than providing a general unmatched-alarm recovery path. [Timeout code](code://c302741689bd67c361cd7faadb221df3193992c3/extern/dolphin/src/dolphin/card/CARDBios.c#L274-L316).

Removal clears attachment, disables EXI notification, cancels the alarm and consumes eligible callbacks. Its result check occurs after the EXI callback returns; BUSY is preserved at that point. The external callback is consumed only at the mount-step threshold. DMA cleanup ignores the EXIUnlock return and probes only when a transfer callback exists and deselection succeeded. Unlock can itself dispatch another queued continuation before the handler subsequently reads its callback slot. [Handlers](code://c302741689bd67c361cd7faadb221df3193992c3/extern/dolphin/src/dolphin/card/CARDBios.c#L31-L147).

NOCARD in transaction helpers is an error classification, not conclusive proof of physical absence. Address and alignment constraints in low-level launchers are assertions, not recoverable validation branches. The header confirms READY=0, UNLOCKED=1, BUSY=-1, NOCARD=-3 and IOERROR=-5, and declares `mode` as unsigned, making the no-DMA -1 assignment correspond to 0xFFFFFFFF. [Definitions](code://c302741689bd67c361cd7faadb221df3193992c3/extern/dolphin/include/dolphin/card.h#L45-L84), [result constants](code://c302741689bd67c361cd7faadb221df3193992c3/extern/dolphin/include/dolphin/card.h#L149-L165).

### Shared state, identity and synchronous APIs

Acquisition reserves a configured, attached, nonbusy control block under interrupt exclusion. Release conditionally publishes the supplied nonbusy result, preserving an already-detached nonbusy state expected to be NOCARD; it does not wake waiters. `__CARDSyncCallback` ignores its result argument and wakes the queue. `__CARDSync` repeatedly reads the stored result and sleeps while it equals -1. Mount completion demonstrates publication before callback notification. [Reservation/publication](code://c302741689bd67c361cd7faadb221df3193992c3/extern/dolphin/src/dolphin/card/CARDBios.c#L649-L696), [waiter](code://c302741689bd67c361cd7faadb221df3193992c3/extern/dolphin/src/dolphin/card/CARDBios.c#L787-L800), [mount completion](code://c302741689bd67c361cd7faadb221df3193992c3/extern/dolphin/src/dolphin/card/CARDMount.c#L246-L250).

CARDInit uses both diskID fields as its initialization guard, constructs queues and alarms, sets initial NOCARD results, and registers the persistent ResetFunctionInfo descriptor. The disk-ID setter retains a shared non-owning pointer through sequential assignments; null selects `&__CARDDiskNone`. File access recognizes that sentinel by pointer identity and otherwise compares game/company identifiers. Empty entries still fail, and public fast-open is a separate access exception. Reset registration retains the descriptor in an intrusive priority queue. Preliminary OnReset calls short-circuit on channel-0 BUSY; the final phase performs no unmount work. [Initialization](code://c302741689bd67c361cd7faadb221df3193992c3/extern/dolphin/src/dolphin/card/CARDBios.c#L620-L647), [identity consumer](code://c302741689bd67c361cd7faadb221df3193992c3/extern/dolphin/src/dolphin/card/CARDOpen.c#L25-L103), [reset registry](code://c302741689bd67c361cd7faadb221df3193992c3/extern/dolphin/src/dolphin/os/OSReset.c#L37-L86).

The remaining helpers provide card identification, sleep/wakeup commands, result and geometry/encoding queries, and free-capacity reporting. CARDFreeBlocks multiplies FAT free blocks by sector size and independently counts directory entries whose first filename byte is 0xFF. Its two outputs are optional; missing FAT or directory metadata yields BROKEN after release. [Queries](code://c302741689bd67c361cd7faadb221df3193992c3/extern/dolphin/src/dolphin/card/CARDBios.c#L698-L785).
