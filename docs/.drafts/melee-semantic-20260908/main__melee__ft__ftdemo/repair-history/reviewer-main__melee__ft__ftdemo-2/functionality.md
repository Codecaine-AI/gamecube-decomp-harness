## Archive staging and dispatch
`ftDemo_SetArchiveData(int pairs_idx,HSD_Archive* archive,int arr_idx)` selects a shared per-kind entry and performs no lookup if its data pointer is already non-null. With a null pointer, selectors 0–3 obtain a name through the source's `char***` cast of `ftData_803C2468`; selectors 4–8 map to 9, 10, 11, 14, and 15 and call `ftDemo_GetMotionFileString`. Both branches store the result of `HSD_ArchiveGetPublicAddress` directly. A null result permits retry; a populated entry suppresses name generation even if the archive or selector changes. There is no byte copy, payload free, or storage of the archive object itself. This is staging rather than a permanently write-once cache: `ftData_80085B98` derives selected motion-entry addresses and clears the shared base. Later motion consumers copy and parse through derived addresses, so clearing the staging pointer does not establish that backing payload memory may immediately be reclaimed. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftdemo.c#L136-L150 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftdata.c#L1696-L1834.

There are no local index guards: negative direct selectors and extended selectors at least 9 lie outside represented domains. The pair index must remain valid even when a populated entry bypasses the name tables. Relevant tables are `FTKIND_MAX` sized. `Player_80036E20` forwards the same archive and selector for a primary mapping and optionally a secondary mapping. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftdata.h#L32-L55 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/pl/player.c#L2052-L2062.

`ftDemo_GetMotionFileString(int cb_idx,int cb_arg)` synchronously returns the selected callback result unchanged. It does not copy or free the string, validate its result, or directly assign persistent state. Callback effects and returned-string lifetime remain callback contracts. An absent callback reports `no demo vi anim! %d\n` and asserts. `MUST_MATCH` selects supplied diagnostic line 296; the other macro branch uses the current source line. ## Facing and exceptional values
`ftDemo_SetFacingDirection` first stores the input float in `Fighter.facing_dir`, then requests Y rotation `M_PI_2 * facing_dir` for part 0. There is no normalization, clamping, wrapping, or finite-value guard. Conventional ±1 inputs yield opposite quarter turns; zero yields zero and other finite inputs scale rather than collapse to a sign. NaN, infinity, signed zero, overflow, target rounding, and FP exceptions receive no special handling here; exact target outcomes remain unresolved. `ftPartSetRotY` uses the primary joint unless it uses quaternion rotation, in which case it uses `x4_jobj2`; it asserts if both use quaternion rotation. A failure occurs after the facing field write, without rollback. Part zero is established, but its exact skeletal-root identity is not. The player-facing setter invokes this helper for present transformed entity slots without checking demo slot type, so usage is not demo-exclusive.
