# pltrick semantic sweep

## Scope, naming, and dependencies
Independently reviewed all 439 implementation lines and all 23 header lines in canonical and rendered form, and enumerated all 39 owned subjects, 64 baseline facts, and 22 outgoing links. The librarian's principal corrections are supported: negative mask indices are not guarded, high-ID counting conflicts with the declared member bounds, event nullability is narrower than some baseline descriptions, the motion classifier receives a stored attack byte, and item-contact adapters pass ID-only integers. The librarian's unresolved 0x9B notification is now verified through its callee and the indexed increment primitive.

Canonical names remain authoritative. Rendered `ft_IsAttackS3OrS4` must not turn an attack-byte argument into a proven current-motion classification.

The TU collects combat telemetry into existing player and fighter storage. Dependencies include Player_GetActionStats, GET_FIGHTER, Struct2070, plAttackStats/plActionStats, fighter motion-data access, magnify state, shared bonus parameters, plbonuslib, and pl_040D notifications. It does not directly implement damage or knockback physics, allocate or free objects, retain input pointers, or register callbacks. Its event copies are by value. The header declares eight public functions; the static helper and forwarding inline remain implementation-local. The header's top-level volatile qualification on prev2070_int does not establish a different ABI. ## Consumers, invariants, and uncertainties
The bonus evaluator scans player slots 0..5 and kinds 1..16; each kind must have the selected victim bit or be unavailable to complete flag 0x11. Availability also exempts kinds in other variety scans. Flag 0x19 requires kind 2 available, nonzero equal attempts and filtered hits for kinds 1 and 2, and equal kind 3 counts only if kind 3 is available. These are verified numeric rules, not inferred move or bonus display names. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/pl/plbonus.c#L492-L531 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/pl/plbonus.c#L682-L697.

Magnify access returns a gated player edge value, which this TU reduces to nonzero. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_0892.c#L221-L224, code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/pl/plbonuslib.c#L133-L148, code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/pl/plbonuslib.c#L276-L313, and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/if/ifmagnify.c#L88-L100.

Statistics counters are declared u32 and are not saturated. Unsigned wrap and external resets preclude global monotonicity or a permanent filtered<=attempts invariant. A local aggregate guard is not proof of one uniquely credited hit per occurrence. Struct2070 integer reinterpretation, damage-descriptor writes, event overlays, and the Fighter first-member cast rely on target representation; no compiled object-layout claim is retained as proved. Source field-offset comments are not compiled evidence. Unknown x1A0/x1A4 categories, motion 0xFD, and numeric attack ranges remain unmapped beyond the active behavior above.

For finite representable percentages, conversion to int truncates toward zero. NaN, infinity, and out-of-range conversions have no established portable integer result, and no sanitization occurs. Under ordinary IEEE ordered comparison semantics, NaN makes rear and knockback comparisons false; equality is not rear but passes the >= knockback threshold. Infinity and signed zero have no special branches. Actual exceptional target conversion behavior remains unresolved.
