## ARQ semantic review
The unit implements asynchronous, priority-aware MRAM/ARAM DMA scheduling. ARQPostRequest initializes caller-owned descriptors, substitutes a non-null no-op callback when necessary, and appends requests under interrupt protection. Idle submission and DMA completion both prefer high-priority work. High-priority service launches a whole request; low-priority service launches one configured chunk and preserves the pending descriptor across intermediate completions. Callbacks run before their pending and callback slots are cleared. These behaviors support the existing function names and most baseline explanations (code://c302741689bd67c361cd7faadb221df3193992c3/extern/dolphin/src/dolphin/ar/arq.c#L19-L152).

### Corrections and exceptional behavior
- The low-priority quantum is configurable, not fixed at 0x1000. Initialization selects that default; ARQSetChunkSize rounds upward to a 32-byte boundary using unsigned arithmetic, without rejecting zero or guarding overflow. ARQGetChunkSize returns the current value (code://c302741689bd67c361cd7faadb221df3193992c3/extern/dolphin/src/dolphin/ar/arq.c#L222-L235).
- Every low-priority launch subtracts and advances by the full configured chunk size, including a shorter final DMA. Thus descriptor progress is not necessarily an exact completed-byte count (code://c302741689bd67c361cd7faadb221df3193992c3/extern/dolphin/src/dolphin/ar/arq.c#L32-L54).
- Removal by descriptor or owner rebuilds the queued lists and may clear a matching pending low request when no final callback is armed. Flush clears both queues and conditionally clears pending low state; none of these paths cancels pending high state or explicitly stops hardware DMA. The temporary append helper does not terminate the retained tail's next link, so removal must not be described as an unconditionally correct filtered-list reconstruction (code://c302741689bd67c361cd7faadb221df3193992c3/extern/dolphin/src/dolphin/ar/arq.c#L76-L89; code://c302741689bd67c361cd7faadb221df3193992c3/extern/dolphin/src/dolphin/ar/arq.c#L154-L219).
- ARQReset only clears the initialization flag; it does not itself drain queues or unregister the hardware callback. Reinitialization clears queue heads, pending slots and callbacks but does not explicitly reset queue tails (code://c302741689bd67c361cd7faadb221df3193992c3/extern/dolphin/src/dolphin/ar/arq.c#L91-L106).

### Cross-file lifetime
ARRegisterDMACallback stores the queue routine in the low-level AR callback slot; the hardware handler invokes that slot without arguments. ARInit also clears that slot, making initialization order relevant. DevCom submits persistent request descriptors and relay-buffer transfers, including a callback-less first leg followed by a completion-bearing second leg (code://c302741689bd67c361cd7faadb221df3193992c3/extern/dolphin/src/dolphin/ar/ar.c#L21-L31; code://c302741689bd67c361cd7faadb221df3193992c3/extern/dolphin/src/dolphin/ar/ar.c#L105-L126; code://c302741689bd67c361cd7faadb221df3193992c3/extern/dolphin/src/dolphin/ar/ar.c#L157-L172; code://c302741689bd67c361cd7faadb221df3193992c3/src/sysdolphin/baselib/devcom.c#L105-L199).
