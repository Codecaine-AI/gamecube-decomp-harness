Both branches reach the common helper calls, including argument `0x100`; next mode-state ID 0 is requested only when `gm_801721EC()` returns zero. There is no explicit WIN comparison. ## Movie End startup and frame control
Two static 26-entry tables provide movie filenames and integers initialized uniformly to 8. Adjacent entries share `MvEndZelda.mth`. Startup independently calls `gm_801BEFB0()` for each lookup; it does not cache the selector or locally bounds-check either index. It initializes a u32 progress value to 0 and a u8 delay to 30, constructs rendering objects, passes dimensions 640×480 and 448×336, and assigns offsets 96 and 72—the equal-margin centering relationship. Audio-mode calls bracket movie startup. Finally it assigns `fn_801AA0E8` to shared `gm_804D6724`; this TU shows no corresponding clear. Object creation and returned-object dereferences are unchecked locally. [Tables and startup](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gmmovieend.c#L66-L131)

Every frame first services MTHP and updates progress: nonzero `lbMthp_8001F604()` increments it, while zero replaces it with `lbMthp_8001F5C4()`. A nonzero delay is decremented and returns immediately, including the invocation that changes 1 to 0. Departure checks therefore first run on invocation 31 after initialization. After the guard, the special predicate is canonical `gmMainLib_8046B0F0.xC && lbMthp_8001F604() == 0`. Departure occurs on progress ≥420, newly triggered Start for the slot returned by `gm_801BF010()`, or that special predicate. Both audio calls precede transition. The special predicate selects `gm_801A4B74` even when another departure condition also holds; otherwise `gm_801A4B60` is called. Progress 420 is not independently established as 420 elapsed wall-clock frames. [Complete frame handler](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gmmovieend.c#L133-L164)

The registry has no Movie End exit callback. The outer runner calls `lbMthp_8001F800()` after scene processing, so teardown responsibilities extend beyond this TU. Neither the rendered `IsFinished` hypothesis nor baseline `resetting` spelling substitutes for proof of the literal status and `xC` semantics.
