## Mewtwo initialization and lifecycle integration

The unit defines twenty motion-state records, annotated as states 341–360, covering ten neutral-special phases, grounded/aerial side special, six up-special phases, and grounded/aerial down special. Each record supplies animation, IASA, physics, collision, and camera callbacks. All use `ftCamera_UpdateCameraBox`. The aerial up-special Lost record uses `ftMt_SM_SpecialHiLost`; the final up-special phases are canonically named `SpecialHi` and `SpecialAirHi`, not `End`. Resource declarations include fighter and animation archive names, four costume triples, demo strings, and a four-element costume-list declaration. These are source-level observations, not compiled-section layout claims. [Source](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftMewtwo/ftmewtwo.c#L21-L274)

`OnLoad` installs Mewtwo attributes, sets the TransN part flag and `x2221_b2`, and supplies item-resource slots 0 and 1 with the Disable and Shadow Ball kinds. The precise gameplay meanings of the two flags remain unspecified. Pickup, drop, invisible-item, and visible-item callbacks are no-ops. Knockback entry and exit forward the object and literal 2 to shared handlers; the literal is not assigned a stronger semantic meaning here. [Source](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftMewtwo/ftmewtwo.c#L287-L359)

`OnDeath` calls the parts helper and clears three retained object references, stored Shadow Ball charge, and the Confusion boost latch. It does not itself destroy those objects. `OnDeath2` removes Disable before invoking `ftMt_SpecialN_OnTakeDamage`, whose cleanup resets charge unconditionally for a valid object. Conversely, `OnTakeDamage` removes Disable before invoking `ftMt_SpecialN_OnDeath`, which preserves charge exactly equal to the floating-point configured maximum and resets other values. The counterintuitive callee names must not be exchanged. Object-presence guards do not make every cleanup effect conditional: the unconditional-charge path also clears visual state and effects after pointer cleanup. The wrappers require a valid fighter because Disable removal dereferences it without an object-null guard. [Wrappers](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftMewtwo/ftmewtwo.c#L276-L317) [Shadow Ball cleanup](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftMewtwo/ftmewtwospecialn.c#L145-L212) [Disable cleanup](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftMewtwo/ftmewtwospeciallw.c#L39-L46)

Confusion's boost is not once per life: aerial entry consumes the false latch, while its air-to-ground transition clears it again. Death is another reset boundary. [Entry](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftMewtwo/ftmewtwospecials.c#L102-L126) [Landing reset](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftMewtwo/ftmewtwospecials.c#L230-L243)

`UnkMotionStates4` requests color-animation entry 92 with argument 0 only when stored charge exactly equals the configured maximum. It is not a threshold or edge detector, has no else-side clearing, and ignores the helper's success result. Common color-animation refresh dispatches the fighter-kind callback after clearing a channel. This supports the proposed full-charge-colanim name, but does not prove that entry 92 specifically produces a constant left-hand glow. `LoadSpecialAttrs` copies attributes before multiplying both Disable offsets by vertical model scale when that scale differs from 1.0f. Disable creation later adds the facing-mirrored X offset and Y offset to a joint position, spawns the object, and installs death/damage callbacks only when the retained object is non-null. Those callbacks are also restored across ground/air transitions while the object exists.
