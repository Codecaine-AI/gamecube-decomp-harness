# Common Guard semantic review

The unit implements shield input, startup, held shielding, release, shield-hit reactions and timed reflection. A pure held-L/R query is distinct from the state-changing input gate. Fresh digital L/R presses within the analog timing window take priority over ordinary held shielding, whose health test is nonzero rather than positive. Dash seeds x20 only after successful entry; Run/RunDirect and late Dash apply movement-origin setup after shared initialization clears x20/x24.

Ordinary startup dispatches Yoshi to separate egg-shield code and adds model-group selection plus sound for Marth. Shared setup initializes counters, release latch, analog shield amount, player-colored effect and shield-joint transform. Analog normalization has a negative-input fallback but no upper clamp. Stick direction is smoothed across the shortest angular difference, and magnitude targets are capped at one. Presentation blends a directional or neutral pose; common scale depends on health and analog amount, while Yoshi uses fixed initial size and separate weakening presentation. Yoshi is excluded from common alpha updates.

Passive upkeep runs only with x221B_b0 set. It preserves the previous analog amount for a negative normalized input, drains shield health, and breaks only when the result is strictly below zero. Exact zero is not this break condition. A positive x10 timer counts down toward zero. GuardOn advances x0 before upkeep, then enters held Guard at x2E8 or supplies x0/x2E8 to presentation. Held Guard uses full presentation. Release detection monotonically latches xC; common arbitration requires xC with zero x10, or neither shield nor reflection enabled. Failed arbitration can still mutate counters. GuardOff has selective x1C-gated interrupts as well as animation completion, so it is not unconditionally locked until animation end. Completion uses a neutral dispatcher with boss and other exceptional paths, not unconditional Wait.

A shield hit enters common GuardSetOff or Yoshi's distinct damage path. Stored element 10 suppresses ordinary recoil assignment before a separate response is invoked. Common hit setup installs hitlag/post-hitlag callbacks, derives animation rate from hit response, conditionally creates an effect, caps signed ground pushback, and restores shield collision and scale. Hitlag SDI requires allow_sdi, grounding, magnitude and timing eligibility; post-hitlag displacement has grounding/magnitude gates but no local allow_sdi or timer check. Both move along the floor tangent. GuardSetOff has empty IASA, updates temporary windows, and chooses queued release or held shielding after animation completion. Yoshi's formula and animation handling must not be equated with common shieldstun.

Reflection has separate fresh-frame and frame-preserving conversion paths. Conversion preserves frame/graphics and disables ordinary shield flags; fresh common entry passes literal state 182, activates shield plus reflector and performs shared initialization. The source motion table associates 182 with GuardReflect, but no compiled identity/layout is inferred. Both initialize independent x14/x18 windows; expiry is strictly below zero. Primary expiry disables reflecting and reinstalls ordinary shield collision. The on-reflect callback supplies colored effect/sound; direct fighter-hit powershield bookkeeping is a separate collision branch that sets x1C and clears x10. Collision installers copy local descriptors into fighter-owned storage rather than retaining stack pointers.

Physics delegates grounded friction/movement and enables shield/reflector position updates as appropriate. Friction prepares acceleration and movement, with velocity integration later in fighter processing. Stage-collision wrappers delegate to ft_800845B4, except GuardSetOff selects an alternative when allow_sdi is set. A canonical cross-file inconsistency remains: ft_800845B4 tests !ft_80082708, but that producer returns GroundOrAir with GA_Ground=0. Conventional lost-ground prose is therefore not accepted as proven.

The shield geometry query writes a Vec3-compatible center and returns size before overall fighter model scale; Link-arrow consumers retain a fighter reference and impact angle and repeatedly recompute shield-boundary placement. Link-family passive shields also reuse the response scalar.
