# Adventure campaign data and result helpers

## Storage and lifetime
`gm_17E4.c` owns the mutable `lbl_80472C30` singleton and the 110-entry `lbl_803D7AC0` configuration table. The source asserts an `AdventureStageEntry` size of `0x1A`; this is a source-level assertion, not a compiled layout or section-placement finding. The configuration table has external linkage and static storage duration. Its initializers include `0xFF` first-byte values, including entries with other nonzero fields; these must not be treated as universal table terminators.

`gm_GetAdventureData` returns the singleton address without allocation, copying, validation or mutation. Adventure loading clears that same object in place, records the selected controller slot, and installs the accessor callbacks. Subsequent selection, encounter, route and completion callbacks mutate the shared object. Evidence: [declarations](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gm_17E4.c#L12-L159), [accessor](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gm_17E4.c#L161-L164), [load lifetime](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gmadventure.c#L1677-L1709).

## Controller and route lookups
`gm_8017E430` returns the stored player slot; visual code uses it to poll triggered Start input. `gm_8017E440` checks the stored slot and nametag with `gm_RumbleEnabledForPlayer`, returning four when disabled and the stored slot otherwise. The visual consumer suppresses dispatch for four. Neither accessor locally validates the slot range.

`gm_8017E48C` counts preceding `GS_VS` entries until the requested state ID is reached. Its byte result is an encounter ordinal, not the raw state ID. There is no missing-ID fallback. `gm_8017E4C4` instead performs a first-match descriptor search ending at key `0xFF`, returning `NULL` on failure. Consumers use descriptor fields, pointer-derived parallel-table indexes and the following entry; the result-classification function dereferences its lookup result without a null check. Evidence: [local helpers](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gm_17E4.c#L166-L206), [visual consumers](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/vi/vi.c#L27-L59), [descriptor consumers](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gmadventure.c#L1184-L1284).

## Configuration callback family
All table getters use the unchecked expression `second_argument + 5 * first_argument`. Canonical definitions call these arguments `difficulty` and `stage_slot`, but observed callers pass encounter ordinal first and campaign CPU level second. The source spelling and gameplay interpretation are therefore distinct evidence and must not be silently conflated.

- `gm_8017E500`, installed at `x48`, returns the first byte named `stage_kind`. Its consumer writes `rules.xB`, separately from `rules.stkind`; the name does not prove that this is a stage ID.
- `gm_8017E528`/`gm_8017E578`, installed at `x64`/`x68`, return `scale0_pct`/`scale1_pct` divided by `100.0F`. Canonical consumers assign these to attack/defense ratios.
- `gm_8017E5C8`/`gm_8017E5FC`/`gm_8017E630` read `pad_6[3*i + 0/1/2]`, installed at `x4C`/`x54`/`x50`. Consumers map these components to CPU level, color and CPU kind. Colors undergo further normalization/remapping; some enemy branches force index zero, and another branch overrides CPU kind.
- `gm_8017E664`/`gm_8017E6B4` return the same two percentage fields through `x6C`/`x70`, rather than different later percentage fields.
- `gm_8017E704`/`gm_8017E738`/`gm_8017E76C` read later tuple components at `pad_6[0x0E/0x0F/0x10 + 3*i]`, installed at `x58`/`x60`/`x5C`. Shared generation code routes this interface to member CPU level/color/type and attack/defense storage. Registration in Adventure is proven; execution of Classic's generation path by Adventure is not.

## Timeout and stage presentation
`gm_8017E7A0` does nothing for outcomes other than `OUTCOME_TIMEOUT`. On timeout it calls stock loss, HUD explosion initialization and HUD reactivation in that order, always for player zero. Stock loss is guarded by a positive count; explosion initialization does not restart an active explosion; existing status objects are checked before reactivation. Adventure's exit path subsequently increments the recorded stock count before common exit processing performs campaign timeout accounting. The local callback must not be described as an additional independent campaign debit.

`gm_8017E7E0` is exactly the read-only predicate `x7C == 0x14`, without an active-mode guard. Corneria uses it to choose random script IDs 4–7 versus 0–3 for the shared Star Fox sequence controller. Adventure writes `x7C` during opponent selection, so its lifetime extends across the selection and stage-consumer boundary. This is not a taunt-input detector. Evidence: [local functions](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gm_17E4.c#L266-L278), [timeout compensation](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gmadventure.c#L1428-L1468), [campaign accounting](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gm_17C0.c#L896-L917), [opponent selection](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gmadventure.c#L1554-L1583), [script selection](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gr/grcorneria.c#L463-L485), [sequence state](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gr/grcorneria.c#L1980-L2003).

## Optional finale routing
`gm_8017E7FC` ignores its match-result parameter. It selects the continuation flag only when the current mode is `GM_ADVENTURE`, `cpu_level >= 2`, and accumulated plus current frames are strictly below `0xFD20`. Success writes `x77 = 1`; failure writes `x77 = 0` and sets rules bit `x4_5`. Success does not clear that rules bit. Both paths schedule state `0x5A`. The state table identifies the Bowser trophy presentation followed by Giga transformation/battle/defeat states, and the trophy leave callback completes the run when `x77 == 0`. A victory test must not be invented from the inferred route name. Evidence: [decision](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gm_17E4.c#L280-L302), [state sequence](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gmadventure.c#L538-L597), [installation and consumer](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gmadventure.c#L1612-L1639).

## Completed-match accomplishment flags
`fn_8017E8A4` receives an integer-transported pointer, casts it to mutable `MatchEnd*`, and sets packed `_x448` fields without clearing the record. A positive pending-reward sum sets `flags[2].b3`. Under live rules gate `x4_5`, it sets `flags[0].b6`; CPU level four sets `flags[0].b3`; cumulative time below `0xC4E0` sets `flags[2].b6`, otherwise below `0x13560` sets `flags[2].b7`. Paired zero statistics set `flags[1].b1`. Stored `xE` and `xF` set `flags[2].b5` and `.b4`; stored `xD` sets `flags[1].b0`, otherwise retaining configured stocks sets `.b2`.

Independent route checks use descriptor keys: `3` and `0x53` search six slots for CPU Luigi and set `flags[1].b7` and `.b4`; `0x11` requires `unk_C >= 5` and sets `.b6`; `0x25` directly sets `.b5`; `0x5C` sets `.b3`. Successful checks for the first four cases return immediately. Numeric keys and incompletely understood stored statistics remain explicit. Evidence: [complete flag logic](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gm_17E4.c#L312-L400), [reward sum and commit](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gm_17C0.c#L1257-L1278).
