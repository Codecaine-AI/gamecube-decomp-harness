## Entry and terrain transitions
`fn_800D86E0` obtains `Fighter*` from `gobj->user_data`, passes `ftCo_MS_ItemScopeEnd` through `fn_800D769C`, changes motion with flags 0, frame 0, speed 1, blend argument 0, and NULL, then installs `fn_800D8378` in `take_dmg_cb`. `fn_800D874C` does the analogous AirEnd entry and clamps air drift after changing motion. Neither fresh-entry helper explicitly sets `ground_or_air`; their callers supply the appropriate situation. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_ItemScope.c#L9-L30.

The Rapid animation callers invoke these fresh entries only in the window `cur_anim_frame >= 0 && cur_anim_frame < frame_speed_mul`, after decrementing `mv.co.common.x0` to exactly zero. This is not a general `counter <= 0` test. A zero incoming counter decrements past zero rather than taking this exit; nonpositive speed makes the ordinary finite frame window empty, and NaN comparisons fail. The exit precedes the alternative item-present/empty query. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_ItemScopeRapid.c#L79-L138.

`fn_800D87C0` calls `ftCommon_8007D7FC`, selects End, and changes motion with `0x0C4C5080`, passing the existing `cur_anim_frame` and `frame_speed_mul`; it reinstalls the damage callback. `fn_800D8838` first calls `ftCommon_8007D5D4`, selects AirEnd, passes the same continuation arguments, clamps drift, and reinstalls the callback. No local validation normalizes negative, infinite, or NaN animation arguments. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_ItemScope.c#L32-L55.

The selector is a lower-bound test, not an ammunition query or a bounded family-membership test: `motion_id >= ftCo_MS_ItemScopeStartEmpty` returns the requested motion plus eight, otherwise it returns the request unchanged. Equality takes the offset branch, and unrelated higher motion IDs also satisfy it. The active table pairs End and EndEmpty with the same ground callbacks, and AirEnd and AirEndEmpty with the same air callbacks, but different submotions. This proves the normal/Empty callback pairing, not arbitrary visual details of exhausted ammunition. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_ItemScopeStart.c#L21-L27; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftmotionstates.c#L1905-L2047.

Ground initialization has conditional airborne bookkeeping, optional animation-derived horizontal velocity, jump/wall-jump resets, ECB unlock, and an assertion if the floor validity check fails. Air initialization sets GA_Air, clears ground velocity and selected z/y values, sets jumps used to one, and locks the ECB for ten. These effects come from canonical common-helper bodies, not their rendered aliases. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftcommon.c#L515-L594.

## Callback suite
Both `ftCo_ItemScopeEnd_Anim` and `ftCo_ItemScopeAirEnd_Anim` forward the same object to `ftCo_ItemScopeFire_Anim`. When `ftAnim_IsFramesRemaining` is false, that delegate calls `ftCommon_8007D92C` and then `ftCommon_8007E7E4(gobj, 1)`. The former chooses Fall for GA_Air and `ft_8008A2BC` otherwise. The latter calls `ftData_OnItemPickup[fp->kind]` only if non-NULL. Thus actual character-specific item handling is optional, and mode 1 alone does not prove a uniform visual result for every character. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_ItemScope.c#L57-L65; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_ItemScopeFire.c#L85-L91; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftcommon.c#L596-L604; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftcommon.c#L1023-L1029.

Animation completion is not a scalar `cur_anim_frame <= 0` test. `ftAnim_IsFramesRemaining` scans eligible parts and queries their joints. Exact zero blend frames selects primary joints; nonzero blend frames select secondary joints. With ordinary IEEE comparisons, NaN blend frames take the latter branch. No eligible remaining joint returns false. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftanim.c#L515-L538.

Both IASA bodies are empty: they do not read the argument or implement an input transition. This is a local no-op guarantee, not global immunity to damage or other engine transitions. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_ItemScope.c#L67-L69.

Ground Phys forwards through `ftCo_800CDE54` to `ft_80084F3C`. It selects `ground_friction`, multiplies it by `friction_when_above_walk_speed` only when `ABS(gr_vel) > walk_max_vel`, then calls ground friction and movement helpers. Equality does not scale. NaN in the comparison does not take the greater-than branch. The multiplier's name and multiplication do not establish that its runtime value exceeds one, so universally stronger braking is not proved. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_ItemScope.c#L71-L79; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_0CDD.c#L66-L74; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_084E.c#L42-L53.

Air Phys forwards through `ftCo_800CDE74` to the standard aerial path: check fast-fall activation, select fast-fall velocity if the resulting flag is set, otherwise subtract gravity and clamp below negative terminal velocity, then run `ftCommon_8007D268`. Fast-fall activation requires an unset flag, strictly negative vertical velocity, stick y at or below the negative threshold, and a tilt timer strictly below its limit. Zero vertical velocity and timer equality do not activate it. Horizontal control derives acceleration and target velocity from stick x and attributes; zero target delegates to air friction. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_081B.c#L1364-L1375; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftcommon.c#L342-L394; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftcommon.c#L462-L507.

The entry drift clamp compares `self_vel.x` first against `-air_drift_max`, then against `air_drift_max`. For a finite nonnegative limit it leaves exact endpoints unchanged and clamps infinities to the endpoints. NaN velocity or limit defeats the ordered comparisons; negative limits are not validated and do not represent a conventional symmetric interval. Gravity similarly has no NaN sanitization. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftcommon.c#L447-L478.

End Coll calls `ft_800841B8(gobj, fn_800D8838)`; its dispatcher invokes the callback synchronously when `ft_800827A0` is false. AirEnd Coll calls `ft_80082C74(gobj, fn_800D87C0)`; its dispatcher invokes synchronously on a truthy `ft_80081D0C` result. These callbacks are not stored by the dispatchers. The latter query updates collision positions, delegates to `mpColl_800471F8`, and has an `ft_80081A00` override. Its GroundOrAir return spelling must not be read as the fighter's resulting situation: the consumer treats it as a Boolean and the supplied callback explicitly grounds the fighter. Detailed geometry/override semantics remain outside the established local contract. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_ItemScope.c#L81-L89; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_081B.c#L1052-L1060; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_081B.c#L549-L556; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_081B.c#L105-L123.

## Ownership, lifetime, conventions, and uncertainties
All twelve functions have source signature `void (Fighter_GObj*)`; the twelve owned parameter subjects refer to that argument, although physical r3 placement is not independently established by compiled evidence. Nonempty paths require a valid object and associated Fighter and rely on engine-managed lifetime across calls. There is no ownership transfer or local object destruction. The IASA functions do not dereference even a null argument, but this does not make null a valid engine callback input generally.

The damage callback is stored on the Fighter after each motion change, unlike synchronous collision callbacks. Its body checks `item_gobj != NULL` before the optional kind-specific pickup dispatch with mode 1. The state-change implementation includes callback installation and clearing of `accessory4_cb` and `take_dmg_cb`; this explains reinstalling the damage callback and not installing a firing accessory callback here. Its exact persistence across all later engine paths is not guaranteed by this TU.
