## DVD filesystem semantic review

The unit implements the Dolphin file-oriented layer over the boot-provided FST. Its three-word entries encode a directory flag and string offset, plus either directory parent/subtree bounds or file disc position/length. `__DVDFSInit` refreshes the boot and FST pointers, deriving the entry count and trailing string table only when the FST pointer is non-null. `DVDInit` supplies the normal one-time initialization guard and initializes the shared thread queue.

Path lookup is case-insensitive, scans immediate children while skipping directory subtrees, and supports root, current-directory and parent-directory components. A slash encountered at the start of a traversal iteration resets to root; this also matters for repeated separators. The restricted-name checks are not a complete 8.3 validator: a dotless component longer than eight characters is not rejected for length. Lookup failure returns -1, whereas detected naming violations panic.

Opening copies FST position and length into caller-owned `DVDFileInfo`, clears its callback and sets `DVD_STATE_END`. Closing delegates to `DVDCancel` and returns TRUE without locally invalidating metadata; the absence of a local wait does not establish that cancellation is nonblocking. Directory-path reconstruction is bounded and NUL-terminates with FALSE on truncation. Directory iteration returns names pointing into the FST string table and skips descendants; directory close is a no-op success.

Read and seek wrappers translate file-relative offsets to absolute disc positions. Asynchronous reads assert alignment, enforce the two explicit range conditions, save the callback, submit an absolute read and return TRUE without forwarding the lower-level submission result. Completion recovers the containing file handle and conditionally invokes its current callback. The handle, embedded command block and callback association therefore must remain valid through completion. DevCom concretely uses this interface for direct and relay-buffered chunk reads.

Blocking read and seek wrappers handle submission failure, disable interrupts around their wait loops, inspect volatile command state and sleep on the shared queue. Preserve their literal mappings: state 0 yields transferred bytes for reads or zero for seeks, state -1 yields -1, and state 10 yields -6. Stream preparation instead uses symbolic terminal states/results and carries an explicit Revolution-SDK reconstruction caveat. It requires 32-KB-aligned absolute start and length, interprets zero length as the remaining file, and checks the requested range. Asynchronous stream preparation forwards the lower-level submission result, unlike asynchronous read and seek.

Transferred-size reporting returns accumulated bytes for the listed terminal/media states, zero while waiting, and accumulated plus current-transfer progress derived from `__DIRegs[6]` while busy. The default branch only asserts and does not assign `bytes`; it must not be described as a defined fallback result.

All canonical and rendered pages were reviewed. Rendered function names were unchanged, with zero substitutions and parse errors; existing function identities fit canonical behavior. Parameter and section names are outside the renderer's substitution coverage. Retained knowledge is recorded explicitly in checkpoints. One correction is proposed for restricted-name validation. Four section-specific facts remain unresolved because source literals and conflicting offset comments do not prove compiled placement or layout.
