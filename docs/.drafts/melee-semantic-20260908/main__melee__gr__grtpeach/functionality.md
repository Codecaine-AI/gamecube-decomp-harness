# Peach Target Test stage controller

## Registration and lifecycle
`grtpeach.c` defines `grTPe_StageData` for `Gr_Kind_TPeach`, resource `/GrTPe.dat`, and four `StageCallbacks` records: three populated rows followed by an all-zero row. The header exports only the stage descriptor. These declarations establish source-level configuration, not compiled section membership, extent, or layout. [Source](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gr/grtpeach.c#L39-L84) · [Header](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gr/grtpeach.h#L1-L9)

The initialization hook passes `grTPeach_80222958` to `Ground_InitTargetStage`. That inline clears `stage_info.unk8C.b4`, sets `b5`, requests objects 0, 1, and 2 in order, then invokes four common Ground helpers. It ignores object-creation results and does not traverse the fourth row as a sentinel. The local factory uses the supplied index for both callback-row selection and Ground-object creation, without a local bounds check. Successful creation triggers callback setup; failure emits an `OSReport` diagnostic and returns NULL. [Local setup](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gr/grtpeach.c#L88-L119) · [Common initialization](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gr/inlines.h#L51-L62)

Demo initialization and loading are empty. Starting calls `grZakoGenerator_801CAE04(NULL)` and discards its return. This creates a shared generated-item manager, not target objects directly. On successful GObj creation, the callee schedules its process and publishes the NULL descriptor and allocated data globally; on GObj failure it reports, frees the data, and returns NULL. The Peach wrapper supplies no retry or recovery, and its empty load/demo hooks do not establish manager teardown. ## Ground-object behavior
- **Object 0:** initializes archive-backed animation using its map ID and `false`, which the callee uses as animation-array index zero. Its process and callback3 bodies are empty.
- **Objects 1 and 2:** initialize through `Ground_JObjInline1`, which binds collision joints and initializes animation set zero. Both process callbacks invoke `Ground_801C2FE0`; object 2 first invokes `lb_800115F4`.
- **All three callback1 predicates:** return false without inspecting the object. They occupy table slots, but the actual `Ground_SetupStageCallbacks` inline neither installs nor invokes callback1. It assigns callback3, immediately calls on_init, and schedules gobj_proc at priority 4.
- **Flags:** only object 2 has callback-table bits 30 and 31 set. Their gameplay meaning is not inferred here.
