## Kinoko semantic review

The unit implements the established Super Mushroom world-item movement lifecycle and exposes an independent animation-resource accessor used by fighter size transformations. Existing rendered Ground, Fall, EnterSliding, GetTransformAnimJoint and ClearGObjReferences names fit canonical behavior; no naming writes are needed.

### Movement and state dispatch

`it_803F6110` contains two callback triplets. State index 0 is grounded sliding; state index 1 is falling. Both rows contain animation identifier 0, which must not be confused with the state index. Neither animation callback reads its argument or performs work; both return false. The table is a non-const C array, although these callbacks do not modify it. [Source](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/kinds/itkinoko.c#L11-L16)

Spawn chooses facing -1 for positive X and +1 otherwise, clears `xD5C` and cached speed `kinoko.x0`, initializes `kinoko.x4` to (0,1,0), and enters state 1 with `ITEM_ANIM_UPDATE`. Ground-loss entry selects the same state with `ITEM_UNK_0x1 | ITEM_HIT_PRESERVE`, without directly resetting velocity. The existing name `itKinoko_UnkMotion0_Air` describes its source-state transition role, not a destination of state 0. [Source](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/kinds/itkinoko.c#L24-L104)

Ground physics runs its assignments only when `ground_or_air != GA_Air`: cached speed becomes `KinokoAttrs.x0 * facing_dir`, and horizontal velocity becomes cached speed times the cached surface vector's Y component. Ground collision first performs shared support processing, then rechecks ground/air status. A floor refreshes the surface vector; absence of a floor clears only its X component. Either side-wall flag causes one reversal of facing and cached speed, followed by horizontal-velocity recomputation. The shared normal helper assigns the floor normal last, so floor contact wins over simultaneous wall or ceiling flags. [Callbacks](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/kinds/itkinoko.c#L60-L94) [Normal helper](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/itmaplib.c#L392-L406)

Fall physics invokes the shared gravity helper before horizontal drag. It snaps horizontal velocity to zero when its magnitude is strictly below `KinokoAttrs.x4`; otherwise it subtracts that value from positive velocity, then independently adds it if the resulting velocity is negative. For finite nonnegative drag, equality reaches zero through arithmetic and zero drag leaves velocity unchanged. No local validation establishes attribute positivity or finite values. The gravity helper tests speed before subtracting acceleration: its maximum-speed parameter gates another step rather than clamping the resulting velocity, so a step can overshoot the threshold. [Fall physics](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/kinds/itkinoko.c#L111-L135) [Gravity implementation](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/it_2725.c#L176-L204)

Fall collision supplies `it_802936E4` as a conditional landing callback. That callback restores cached horizontal speed, clears Y/Z velocity, performs shared setup, calls `Item_8026AE84` with 0x107/0x7F/0x40, and selects state 0 with preservation flags. Initial cached speed is zero until grounded physics refreshes it. Landing is not guaranteed for every floor contact: common gates can reject the transition, invoke destruction logic, or dispatch an entered-air callback instead. After shared collision processing, Kinoko caches a floor normal only if the item is non-airborne and has a floor flag; its collision callback returns false. ### Cross-file resources and references

`it_80293660` returns `KinokoAnim[idx + 2].joint` from the global Kinoko article's special attributes, without bounds or null checks. Fighter setup installs that resource on a lazily created `Fighter.x2184` helper joint. Subsequent fighter updates animate the joint and interpolate between stored scale endpoints using its X scale. This is separate from per-item movement fields; the accessor neither allocates an animation resource nor transfers ownership of an item instance.
