## Classic predicate and cross-file boss transition
`fn_8017EDDC` is a read-only boolean predicate: true requires `GM_CLASSIC`, `xD == 0`, `cpu_level >= 2`, and accumulated `x20 < 0x5208`; every other path returns false. Its relocated caller is present in `gm_17C0.c`: controller state 3 first handles slot-2 death, otherwise tests half-initial HP and this predicate before entering state 1 with substate zero. ## Match-end flags
`fn_8017EE40` receives an integer immediately cast to a mutable `MatchEnd*`. It sets, never clears, selected `_x448` bitfields. Independently of `rules->x4_5`, a positive pending reward sum sets byte 2 bit b3. Under that rule gate it sets byte 0 b7; CPU level 4 sets byte 0 b4. Combined accumulated and current frames below 0x3840 set byte 2 b6, otherwise values below 0x5460 set byte 2 b7. These branches are exclusive for this invocation, not a guarantee that previously set bits are cleared. Paired zero statistics set byte 1 b1. Nonzero xE/xF set byte 2 b5/b4. Nonzero xD sets byte 1 b0; only the else branch can set byte 1 b2 for stocks equal to configured stocks. Finally, independently of the rule gate, it scans slots 0–5 and sets byte 0 b0 on the first CPU Crazy Hand, then returns. Numeric fields are not relabeled as particular accomplishments without additional evidence. [Complete flag logic](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gm_17EB.c#L165-L226).

The external dispatcher selects this function for Classic when its own `unk_9` gate is nonzero. One observed finalization path populates flags before general result evaluation, skipping that evaluation for no-contest/retry outcomes. Pending reward data lives in another translation unit: its sum includes occupied entries, and a separate routine later applies them through `Toy_SetUnlockState`; this function does not consume or clear that queue.
