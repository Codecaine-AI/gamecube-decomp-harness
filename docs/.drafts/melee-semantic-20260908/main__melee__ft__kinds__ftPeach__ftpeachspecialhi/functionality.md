## Peach SpecialHi subsystem

The owned C file implements Peach's grounded and aerial up-special entry, startup and ending callbacks, plus generated-parasol ownership, cleanup, hitlag forwarding and activity predicates. The header declares the public callback surface. Canonical and rendered views were read completely; rendered substitutions were treated as naming hypotheses, not independent evidence.

### Entry and article ownership

Both entries select their startup motion, invoke animation initialization and reset command variables 0–2 and throw flags. Aerial entry additionally clears vertical self-velocity and multiplies horizontal velocity by Peach attribute x84. Shared initialization records either supported held-parasol kind and returns early; otherwise it schedules the accessory callback with It_Kind_Capsule serving as a pending-creation sentinel. These early returns do not themselves rebuild parasol ownership or install hitlag callbacks. [Source](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftPeach/ftpeachspecialhi.c#L145-L188)

The accessory callback consumes the sentinel, preserves any prior held item, creates a Peach Parasol at FtPart_109 and stores the result as both tracked parasol and current item. Death/damage callbacks are installed only for successful creation. Sentinel mismatch, an already tracked article and creation failure all still clear accessory4_cb and install the paired hitlag callbacks. Failed creation can therefore leave a saved previous item without an active generated parasol; the guarded removal helper does nothing when the active pointer is null. [Source](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftPeach/ftpeachspecialhi.c#L36-L113)

Cleanup unconditionally clears article tracking and death/damage callbacks, restores a saved item once, and returns whether restoration occurred. Without a saved item, this function does not explicitly clear item_gobj. Item destruction consumes the Boolean to decide whether to sever Item.owner; the outer fighter removal path can invoke cleanup again after item-side cleanup. Peach's death/damage wrapper and interruptible common landing also reach removal. ### Startup and continuation

The command-2 helper optionally clears its variable but always returns false, so animation exhaustion is the effective startup transition guard. The shared animation callback assigns FallSpecial as motion context and passes either common x59C or Peach x90 to ftCo_800CEFE0. Crucially, the current callee ignores that argument: it saves the incoming motion as prev_msid, enters the appropriate parasol-open motion and uses common x59C. Caller-side value selection must not be described as proven effective duration selection. [Caller](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftPeach/ftpeachspecialhi.c#L190-L220), [callee](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_ItemParasolOpen.c#L38-L85).

Startup steering is shared by grounded and aerial callbacks. While command 0 is zero, horizontal input above x7C produces an x80-scaled signed angle; only a strictly larger absolute angle replaces the stored angle. Turnaround is independently gated by ftCheckThrowB3 and x78. Startup physics either dispatches by current ground/air status or, for the aerial callback, selects gravity versus animation-derived velocity with xyz scaling by x8C according to command 0. [Source](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftPeach/ftpeachspecialhi.c#L222-L273).

### Ending, collision and lifetime

Ending animation completion requests common special fall with fixed arguments and x70/x74. Both ending IASA callbacks are empty. Ending physics preserves incoming vertical velocity across the animation-derived movement helper before applying common gravity; the aerial variant's intermediate y multiplication is overwritten, leaving x/z scaling. The common special-fall initializer has an x2224_b2 exceptional branch, so the request is not an unconditional guarantee of FallSpecial entry. [Ending callbacks](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftPeach/ftpeachspecialhi.c#L305-L352), [common exception](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_FallSpecial.c#L28-L59).

All four collision wrappers share a dispatcher. Non-airborne values use the grounded path. Airborne command-zero or nonnegative-y cases use ordinary airborne processing; only command-enabled, strictly descending cases use the callback-based landing path. Startup and ending landing callbacks ultimately request false/x74 special landing. The common landing initializer retains a hammer exception. The proposed CheckLanding names describe their callback role: the callbacks themselves do not test contact.
