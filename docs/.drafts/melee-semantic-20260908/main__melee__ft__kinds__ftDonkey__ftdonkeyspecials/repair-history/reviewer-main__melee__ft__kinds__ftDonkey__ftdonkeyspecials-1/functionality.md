# Donkey Kong SpecialS semantic review

## Scope and interface
The owned C file and header were independently read in full in canonical and rendered form. This review reconciles the librarian packet against the frozen baseline and pinned source, rather than treating the packet or rendered names as proof. The implementation defines ten public functions with signature `void(HSD_GObj* gobj)`, two internal transition helpers, and a static constant transition mask. The header declares the ten public functions and contains no data definitions. `doAirTransition` has internal linkage through its preceding static declaration; its definition's omitted `static` does not give it external linkage. `doGroundTransition` is explicitly static. The unused local `u8 _[8]` in grounded entry is source-visible, but proves no emitted stack layout. The twelve parameter subjects correspond to source parameters named `gobj`; their register locations remain unverified. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftDonkey/ftdonkeyspecials.h#L1-L18 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftDonkey/ftdonkeyspecials.c#L21-L126.

The active Donkey callback table associates both callback groups with SpecialS submotions and `FtMoveId_SpecialS`, independently establishing their paired side-special role. This is not an inference from the numeric motion-state comments. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftDonkey/ftdonkey.c#L459-L480. Headbutt naming and bury, meteor-smash, or shield-damage properties are external baseline claims not independently established by the inspected canonical code. This TU contains no explicit implementation of those hit properties.

## Entry and data flow
`ftDk_SpecialS_Enter` obtains the associated Fighter, calls `Fighter_ChangeMotionState(gobj, ftDk_MS_SpecialS, 0, 0, 1, 0, NULL)`, calls `ftAnim_8006EBA4`, clears command variable zero, and assigns `ftDk_SpecialLw_8010E0CC` to `accessory4_cb`. It contains no explicit velocity assignment. This absence does not establish that its callees preserve every velocity field.

`ftDk_SpecialAirS_Enter` obtains `fp->dat_attrs` as `ftDonkeyAttributes*`, divides `self_vel.x` by `SpecialS.x3C_MIN_STICK_X_MOMENTUM`, overwrites `self_vel.y` with zero, and performs the analogous state/helper/reset sequence for `ftDk_MS_SpecialAirS`, assigning `ftDk_SpecialLw_8010E148`. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftDonkey/ftdonkeyspecials.c#L26-L46. `Fighter_UnsetCmdVar0` writes integer zero: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/inlines.h#L207-L211.

The divisor is not compared with stick input. Division is not universally attenuation: for ordinary finite values a positive divisor greater than one reduces magnitude, one preserves it, a positive divisor below one increases it, and a negative divisor may reverse direction. There is no range, zero, infinity, or NaN validation. Exceptional arithmetic depends on the target floating-point environment; finite output and preserved direction are not invariants. Vertical assignment discards the previous value outright.

## Deferred effects, ownership, and lifetime
The assigned callbacks reside in the SpecialLw-named TU but directly serve these SpecialS entries. The grounded callback conditionally spawns effect 1222 and the aerial callback conditionally spawns effect 1223 on `FtPart_TransN`, each only when `x2219_b0` is clear, then sets that flag. Both unconditionally install effect hitlag callbacks and clear `accessory4_cb`. Thus an already-set flag suppresses spawning and setting the flag, but does not suppress callback installation or self-clearing. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftDonkey/ftdonkeyspeciallw.c#L164-L184. Installation writes `efLib_PauseAll` and `efLib_ResumeAll` to the pre/post-hitlag slots: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/inlines.h#L43-L47.

This proves a self-clearing callback, not a looping visual effect or a guaranteed invocation before cancellation. Exact dispatcher timing, cancellation, effect duration, and cleanup remain unresolved. The owned code neither allocates nor destroys objects and does not transfer ownership. Fighter and attribute pointers are borrowed associations reached through game-object user data; nonempty routines require valid initialized objects. The empty IASA routines do not dereference their argument. User-data access alone does not prove a full ownership/lifetime contract: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/inlines.h#L37-L66.

## Animation and IASA
Both animation callbacks branch on a false `ftAnim_IsFramesRemaining` result. Grounded completion calls `ft_8008A2BC`; aerial completion calls `ftCo_Fall_Enter`. A true result triggers no local transition. Both IASA definitions are empty, proving no move-specific IASA input checks or transitions, not global immunity to interruption. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftDonkey/ftdonkeyspecials.c#L48-L64.

The grounded completion dispatcher has special Hand-kind branches and otherwise calls `ft_8008A348`. The ordinary path can enter DownSpot or another exceptional common path before its normal Wait transition; additional conditional handling follows Wait. Therefore grounded completion is not an unconditional normal-ground-state guarantee. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_08A1.c#L53-L109. The exact numerical frame predicate boundary and the meaning of `ftAnim_8006EBA4` remain unresolved beyond their observed calls.

## Physics and boundaries
`ftDk_SpecialS_Phys` forwards its argument to `ft_80084F3C`. That routine reads common ground friction, multiplies it by `friction_when_above_walk_speed` only when `ABS(gr_vel) > walk_max_vel`, then calls `ftCommon_ApplyFrictionGround` and `ftCommon_ApplyGroundMovement`. Equality skips multiplication. The tuning value is not proved to increase friction. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftDonkey/ftdonkeyspecials.c#L66-L69 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_084E.c#L42-L53.

`ftDk_SpecialAirS_Phys` reads Fighter, common attributes, and Donkey attributes. Every nonzero `cmd_vars[0]` enables `ftCommon_Fall` with `SpecialS.x44_AERIAL_GRAVITY` and common terminal velocity; zero skips it. `ftCommon_ApplyFrictionAir` is always called with `SpecialS.x40_MOMENTUM_TRANSITION_MODIFIER`. The trailing repeated nonzero test has an empty body with a control-flow TODO and no additional source-level effect. No command-variable write or motion-state change occurs in this callback. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftDonkey/ftdonkeyspecials.c#L71-L85.

The fall helper subtracts gravity and clamps only when the result is strictly below negative terminal velocity; equality is unchanged. The air-friction helper writes `x74_anim_vel.x`, not `self_vel.x`: it uses `-self_vel.x` when `ABS(friction) >= ABS(self_vel.x)`; otherwise it negates the supplied friction for positive horizontal velocity and leaves it unchanged for nonpositive velocity. Equality selects the cancellation contribution. These operations do not establish unconditional damping for negative or exceptional tuning values. NaN comparisons do not establish bounds, and exceptional arithmetic is not sanitized. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftcommon.c#L253-L261 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftcommon.c#L462-L468. Runtime tuning and later integration of animation velocity remain open.

## Collision and continuation
Grounded collision selects `ft_800827A0` for nonzero command variable zero and `ft_80082708` otherwise, invoking `doAirTransition` when the selected result is false. Aerial collision invokes `doGroundTransition` on nonzero `ft_80081D0C`. These are exact Boolean-consumer contracts, not proof from rendered landing/support aliases. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftDonkey/ftdonkeyspecials.c#L89-L108.

The collision callees synchronize previous/current CollData positions, call map collision, and copy corrected positions back, so they are not pure predicates. `ft_80081D0C` additionally calls `ft_80081A00` and returns a `GroundOrAir`-typed value. Neither its enum spellings nor the local name `fall_off_ledge` in `ft_80082708` independently establish contact semantics. In particular, absence of a local transition on a false result does not prove that an exceptional callee left all fighter state unchanged. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_081B.c#L105-L123 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_081B.c#L392-L424.

Both transitions use `coll_mf = Ft_MF_KeepGfx | Ft_MF_SkipHit | Ft_MF_SkipMatAnim | Ft_MF_SkipColAnim | Ft_MF_UpdateCmd | Ft_MF_SkipItemVis | Ft_MF_Unk19 | Ft_MF_SkipModelPartVis | Ft_MF_SkipModelFlags | Ft_MF_Unk27`, select the opposite SpecialS motion, and reinstall effect hitlag callbacks only when `x2219_b0 == true` after conversion. They do not call the local entry routines. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftDonkey/ftdonkeyspecials.c#L21-L24 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftDonkey/ftdonkeyspecials.c#L110-L126.

Common inline conversions change situation first, then pass `cur_anim_frame`, rate 1, blend 0, and NULL to motion-state change, carrying the explicit animation start frame instead of restarting through entry. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/inlines.h#L71-L89. Ground-to-air resets ground velocity and selected fields, sets jumps-used to one, and locks the ECB for ten. Air-to-ground performs optional bookkeeping, restores grounded movement/jump/ECB state, and includes a ground-support assertion. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftcommon.c#L515-L594. The names of preservation flags do not prove every retained subsystem, particularly Unk19 and Unk27.

Canonical callee behavior supports the grounded-physics interpretation, but not the loop-effect claim or complete collision return semantics. The header has no substitutions or parse errors.

The librarian's major cautions about section evidence, unvalidated arithmetic, effect lifetime, and exceptional completion are confirmed. This lead additionally does not retain broad ownership claims merely from user-data access, an unqualified deferred-spawn assertion despite its optional branch, a full unchanged-state guarantee across the exceptional collision callee, or grounded animation initialization while its helper meaning remains unverified. Such baseline facts are explicitly unresolved below rather than silently narrowed and retained.
