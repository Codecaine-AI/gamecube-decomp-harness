# ftCo_WarpStar

## Scope and integration
This translation unit implements the fighter-side Warp Star ride, not the complete item implementation. Its header declares the public entry function and the ten Jump/Fall callbacks, all taking `Fighter_GObj*` and returning `void`. Four helpers have preceding static declarations in the C file and therefore internal linkage. `fpGetAttrs`, `fpGet2C4`, and `inlineA0` are source-level inline helpers. `MUST_MATCH` conditionally enables `#pragma force_active on`; no alternate gameplay implementation appears under that conditional. There are no named data definitions corresponding to the baseline `.sdata` or `.sdata2` subjects. Their compiled contents and layout remain unresolved. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_WarpStar.c#L1-L44 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_WarpStar.h#L1-L19.

The gameplay association is supported by an active caller, not merely by names: `ftp pickupitem`'s canonical function `ftpickupitem_8009447C` calls `ftCo_800C4724` in the `It_Kind_WStar` case. Pickup handling stores the item on the fighter and attaches Warp Stars at `FtPart_TopN`. The common motion-state table explicitly installs all five callbacks for each of WarpStarJump and WarpStarFall. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftpickupitem.c#L153-L181, code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftpickupitem.c#L269-L328, and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftmotionstates.c#L3489-L3510.

## Entry and ascent
`ftCo_800C4724` configures `fp->item_gobj` using `x2C4.y` and `co_attrs.warp_star_hitbox_scale`; saves facing and starting position; neutralizes active facing to zero; seeds `x1C` to 120; and zeroes the previous root-translation sample, confusingly named `mv.co.warpstar.self_vel`. It calls `ftCommon_8007D5D4`, enters WarpStarJump with `Ft_MF_None`, frame 0, rate 1, and installs damage/death cleanup callbacks after the state change. It enables `x2219_b2`, `x2222_b7`, and `x221E_b2`, invokes `ftCommon_8007E2FC`, and attaches and evaluates an item-selected animation on the fighter root. `ftCommon_8007D5D4` sets airborne state, clears several movement components, sets jumps-used to one, and locks the ECB for ten ticks. The item configuration computes a scale using an attribute denominator; the item animation selector randomly chooses from candidates excluding the previous choice. Valid item/model/data pointers and valid item attributes are prerequisites, not checked locally. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_WarpStar.c#L46-L71, code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftcommon.c#L515-L525, and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/kinds/itwstar.c#L20-L80.

`ftCo_WarpStarJump_Anim` decrements the counter before checking `cur_pos.y > Stage_GetBlastZoneTopOffset() || x1C == 0`. Equality at the height threshold does not trigger descent. Starting at 120, the timeout fires on the 120th invocation if no earlier height transition occurs; this is a callback count, not a separately proved wall-clock duration. An initially zero or invalid counter is not handled by a `<= 0` guard. Under ordinary floating comparison semantics, NaN height/boundary makes the height comparison false, leaving the timer as the fallback. `ftCo_WarpStarJump_Phys` replaces all three components of fighter self velocity with current root translation minus the previous sample, then saves the current sample. The first delta is relative to zero, not to a sampled entry translation; discontinuous or non-finite model translation is not sanitized. Jump IASA and Coll are genuinely empty. Jump Cam forwards the same object to `ftCamera_800762F4`. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_WarpStar.c#L93-L123.

## Interruption cleanup
`ftCo_800C4858` and `ftCo_800C48AC` are distinct wrappers around the same `inlineA0` sequence, installed respectively in `take_dmg_cb` and `death2_cb` in both ride states. Cleanup calls `ftColl_8007B6EC`, restores saved facing, and calls `Item_8026ABD8(item, &zero_vector, 1)`. It neither changes motion state nor clears its own callback slots, and contains no null guard or once-only latch. The item argument 1 is an `f32` stored in `xC44`, not a proved integer mode. The generic item routine invokes the dropped callback and has an additional conditional item-processing branch. Collision cleanup clears `x2221_b0`; restoration of `x198C` is conditional on `x1990 == 0`, so it is not an unconditional reset of every hit-status field. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_WarpStar.c#L73-L91, code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftcoll.c#L3309-L3340, and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/item.c#L1994-L2009.

## Descent setup and motion
`ftCo_800C4A38` asks the item to fill the ride's collision box before entering WarpStarFall. It reinstalls the two cleanup callbacks, sets `x2222_b7` and `x221E_b2`, invokes common setup, and relocates the fighter to saved starting X, the current top blast-zone offset Y, and Z=0. It passes a `Quaternion` storage object with x=π/2 and y=z=w=0 to `HSD_JObjSetRotation`, calls `it_802946B0`, and synchronizes collision position using `mpColl_80043680`. The exact transform interpretation is not established by the storage type alone; this is not a normalized quaternion. The item routine selects table state 3 and applies saved scale and hitbox scaling. Its descent role is established by this caller, not by the numeric state index. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_WarpStar.c#L125-L147 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/kinds/itwstar.c#L45-L80 and #L141-L151.

Fall Anim and IASA are empty. Fall Phys calls `ftCommon_Fall(fp, x694, x698)`, which subtracts gravity from Y velocity and clamps only when the result is strictly below negative terminal velocity. For stick X=s it computes acceleration `s*warpstarfall_drift_scaling + (s>0 ? flat : -flat)` and target `s*warpstarfall_drift_max`, then calls `ftCommon_8007D174` with current X velocity and `x6A8`. Importantly, that helper writes `x74_anim_vel.x`, not directly `self_vel.x`. A zero target invokes aerial friction and returns, so the negative flat term selected at neutral input does not establish a persistent leftward acceleration. For nonzero target, reversal, overshoot, friction, and the fighter's `air_max_horizontal_velocity` affect the result. No input dead zone or finite-value check is present here. Signed zero selects the nonpositive branch; NaN input can propagate NaN acceleration because ordered comparisons fail. Infinite or invalid tuning values are not locally rejected. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_WarpStar.c#L149-L169 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftcommon.c#L342-L372 and #L462-L468.

## Collision and rebound
Fall Coll passes the embedded ECB and `ftCo_800C4C60` to `ft_80083E64`. The helper synchronizes previous/current collision positions, transforms the supplied box using facing, performs `mpColl_8004730C`, writes resolved position back, and invokes the callback synchronously only if the collision result is true and `ft_80081A00` does not veto it. A veto is not proof that the fighter's state is otherwise unchanged: the veto helper's broader effects were not established. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_WarpStar.c#L171-L175 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_081B.c#L995-L1025.

`ftCo_800C4C60` restores facing before changing to JumpB and before reusing motion variables for jump bookkeeping. It calls collision cleanup, clears jump x0/x4, sets jump_mul=1, scales retained horizontal velocity by the ground-to-air momentum multiplier, and adds `-facing*x78*jump_h_initial_velocity`. It clamps the sum only when `ABS(sum) > jump_h_max_velocity`; equality passes unchanged. This conventional cap assumes a nonnegative finite limit. A NaN sum bypasses the ordered cap comparison. Final vertical velocity is `jump_v_initial_velocity`: the earlier multiplication by common x438 is overwritten. Z velocity is zero. The added horizontal impulse opposes facing for conventional positive tuning, but retained momentum can keep final motion forward; an invariably backward resultant velocity is not proved.

The item impact call enters item table state 5, stops and relocates the item, hides its model, clears effects, and reapplies saved scaling. The fighter constructs an effect position at world position plus ECB-bottom Y, derives an angle from `atan2f(-floor.normal.x, floor.normal.y)`, requests effect 1030 with spawn kind 5, requests `QuakeKind_Large`, and calls `ftCommon_8007EBAC(fp,14,0)`. Exact effect artwork, damage values, and the feedback identifier's presentation are unresolved here. Degenerate/non-finite floor normals are passed to atan2f without validation; platform-specific exceptional atan2f results were not established. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_WarpStar.c#L177-L230 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/kinds/itwstar.c#L173-L220.

## Camera, lifetime, and ownership
Both Cam callbacks call the same helper. Its actual body delegates to `ftLib_800866DC` with `&fp->x890_cameraBox->bone_pos`; this does not itself prove zooming, boundary clamping, or a special offscreen camera policy. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftcamera.c#L89-L93.

The TU borrows fighter, attached item, model, common data, and collision state; it performs no explicit allocation or deallocation. Damage/death wrappers are not idempotence-protected. The common motion-change tail installs the new state callbacks and clears take_dmg_cb/death2_cb; the ride reinstalls them after entry and fall changes. Full exceptional interruption ordering remains a framework-level uncertainty. Effect arguments `vec` and `param` are stack locals, but spawn kind 5 is `EF_SPAWN_POS_OFFSET_PARAM`, whose active switch case copies both values into an allocated queue record before either enqueuing or immediate processing. Their stack lifetime is therefore sufficient for this call. The collision continuation is invoked immediately rather than retained. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/fighter.c#L1370-L1389, code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ef/types.h#L16-L38, and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ef/efasync.c#L1405-L1464.

## Names and uncertainty policy

Canonical `Stage_GetBlastZoneTopOffset` and `Camera_RequestQuake` outrank rendered `stGetPlyDeadUp` and `Camera_StartQuake`. Rendered helper names such as SetIntangible, ResetVelocities, and TriggerRumble cannot independently establish semantics. The review retains direct source behavior, qualifies timing and final-velocity claims, and leaves compiled section layout, exact original aliases, transform interpretation, effect identity/damage, and broader exceptional lifetime behavior explicitly unresolved.
