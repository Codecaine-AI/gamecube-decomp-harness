## Main Rules interface

This unit builds and updates the main Rules screen, maintains a menu-local snapshot of match rules, processes controller navigation and editing, and synchronizes mode, time limit, handicap, damage ratio, the auxiliary rule byte and stock count with `GameRules`. Input and presentation run on separate GObjs; the display object is published through `mn_804D6BD0`. Construction attaches allocated user data with `HSD_Free` as its removal callback. [Input](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/mn/mnmainrule.c#L162-L386), [update and initialization](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/mn/mnmainrule.c#L882-L1109).

Navigation wraps over rows 0–6, skipping row 4 in Tournament mode. Row 1 uses a separate stock-count byte and bounds when mode equals 1; otherwise it edits time. Handicap value 1 is skipped when `mn_804D6BD4` is zero. Tournament editing excludes the minimum non-stock time value. Both acceptance and Back commit cached rules. Submenu activation starts the destination before removing the input object and committing through the retained display object; the display subsequently performs its exit transition. The row-1 repeat-delay calls apply to time as well as stock and occur only when a non-wrapping adjustment reaches the relevant endpoint.

Presentation uses table-selected label frames, focus and arrow loops, direction-dependent discrete-value animations, and decimal digit hierarchies. Zero time hides the four numeral groups. The time/stock selector has Boolean semantics: nonzero shows time and zero shows stock. The value-loop scan preserves its final table entry as a fallback when no interval matches. Contextual SIS text is replaced on relevant selection/value changes, created when absent during entry states 1/3, and removed during exit states 2/4. [Display helpers](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/mn/mnmainrule.c#L390-L880).

Entry states 1 and 3 complete into state 0; exit states 2 and 4 destroy the display GObj. Previous menus 15 and 16 restore rows 6 and 5, respectively. The VS-menu entry variant sets the handicap-availability flag only after constructing the initial snapshot; that store affects later input and reconstruction, not the already-completed normalization. Archive-based entry instead stores the caller's flag before construction. Newly created processes are stamped with the scheduler's current generation. [Entry variants](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/mn/mnmainrule.c#L1289-L1496), [scheduler](code://c302741689bd67c361cd7faadb221df3193992c3/src/sysdolphin/baselib/gobj.c#L77-L114).

The archive initializer loads shared menu and subordinate-screen resources. The `MenMainConSs_Top` family belongs to Stage Switch, not Special Melee. The final availability predicate serves Additional Rules: it excludes index 1 in Tournament mode and gates indices 3 and 5 through save-backed feature bits. Its other inputs return true; the observed menu domain is not an enforced bounds check. [Stage Switch consumer](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/mn/mnstagesw.c#L736-L790), [availability predicate](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/mn/mnmainrule.c#L1498-L1516).
