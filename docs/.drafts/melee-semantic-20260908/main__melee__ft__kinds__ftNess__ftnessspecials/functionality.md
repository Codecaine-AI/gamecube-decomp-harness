## Entry and callback lifetime
ftNs_SpecialS_Enter and ftNs_SpecialAirS_Enter obtain the Fighter, clear the entire throw_flags field and cmd_vars[0], call Fighter_ChangeMotionState with the respective canonical state and arguments 0, 0.0f, 1.0f, 0.0f, NULL, call ftAnim_8006EBA4, and then install ftNs_SpecialS_ItemPKFireSpawn in accessory4_cb. Registration is not direct projectile construction. Neither body explicitly changes ground_or_air, and the meaning of cmd_vars[0] beyond initialization is not established locally. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftNess/ftnessspecials.c#L77-L106.

The installed callback is a function pointer, not a stack closure. Fighter dispatch invokes the non-NULL slot with the fighter object when x221F_b3 and x2219_b5 are clear. The common motion callback installation block clears accessory4_cb, and these entries install it after motion setup. The spawner itself does not clear the slot. Thus one-shot behavior means one constructor attempt per consumed request, not necessarily one attempt over the entire move lifetime. Exhaustive cancellation through every exceptional transition remains unresolved. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/fighter.c#L1370-L1389 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/fighter.c#L2552-L2564.

## Request consumption, vectors, and ownership
ftNs_SpecialS_ItemPKFireSpawn resolves Fighter and ftNessAttributes before testing throw_flags_b0. A clear bit causes no projectile work, but is not a null-object-safe early return. A set bit is cleared before transform and constructor work. It calls lb_8000B1CC on parts[FtPart_R2ndNa].joint with NULL input and a local Vec3 output, adds x30_PKFIRE_SPAWN_X times facing_dir to X, adds x34_PKFIRE_SPAWN_Y to Y, and overwrites Z with zero.

Exactly ground_or_air == GA_Air selects x20_PKFIRE_AERIAL_LAUNCH_TRAJECTORY and x24_PKFIRE_AERIAL_VELOCITY; every other value selects x28_PKFIRE_GROUNDED_LAUNCH_TRAJECTORY and x2C_PKFIRE_GROUNDED_VELOCITY. Selection is made at callback execution, not fixed by which entry installed it. For angle a, speed v, and facing f, the computed velocity is (v*cosf(a)*f, v*sinf(a), 0), and rotation is a*f. One it_802AA054 call receives the original object, addresses of both local vectors, facing, and rotation. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftNess/ftnessspecials.c#L21-L73.

The constructor copies the supplied position into SpawnItem.prev_pos, obtains SpawnItem.pos separately through it_8026BB68, copies velocity, and assigns the supplied object to both parent fields. It attempts Item_80268B18 once and initializes and rotates the result only if non-NULL. The caller retains no handle, receives no success result, and does not retry a consumed request on allocation failure. The incoming vector pointers are not retained by this constructor. This proves synchronous copying into the spawn descriptor, not an exhaustive lifetime guarantee for every downstream allocator or owner-management path. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/kinds/itnesspkfire.c#L24-L51.

There is no local validation of object, attributes, joint pointers, facing magnitude, angle, speed, or offsets. Facing is multiplied, not normalized to a sign. Zero speed does not suppress construction; negative finite speed reverses the corresponding finite computed velocity relative to positive speed. NaN and infinity are not rejected. Z assignments remain explicit zeros even if X/Y calculations are exceptional. Exact exceptional trigonometric results, floating-point traps, and shipped tuning are not established. Separate attribute fields do not prove different numerical values or downward-diagonal gameplay trajectories. The event-0x60 source comment is not proof of the decoder, script producer, or timing.

## Animation boundaries
ftNs_SpecialS_Anim calls ft_8008A2BC only when ftAnim_IsFramesRemaining is false. The dispatcher has Master Hand and Crazy Hand cases; ordinary fighters use ft_8008A348. That path can return through DownSpot or another common exception before Wait, and contains additional conditional work after its Wait transition. Grounded completion therefore is not an unconditional final Wait guarantee. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftNess/ftnessspecials.c#L110-L116 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_08A1.c#L53-L109.

ftNs_SpecialAirS_Anim calls ftCo_Fall_Enter on the same false predicate, not a FallSpecial routine. Neither wrapper performs a local transition when the predicate is true. The predicate scans eligible parts: flags_b1 must be set, flags_b0 and flags_b5 clear, and lb_8000B074 must return true. It uses primary joints when blend frames equal zero and secondary joints otherwise; no qualifying active joint yields false. Under ordinary floating comparison semantics NaN blend frames take the nonzero branch. Exact terminal-frame semantics remain delegated to lb_8000B074. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftNess/ftnessspecials.c#L120-L126 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftanim.c#L515-L538.

## Physics
ftNs_SpecialS_Phys unconditionally calls ft_80084F3C. That helper reads ground friction, scales it only when ABS(gr_vel) > walk_max_vel, applies ground friction, then ground movement. Equality does not select the extra multiplier; unordered comparisons do not establish an above-threshold case. ftNs_SpecialAirS_Phys unconditionally calls ft_80084EEC, which calls ftCommon_Fall with common gravity and terminal velocity, followed by ftCommon_ApplyFrictionAir with aerial friction. These are fighter updates, separate from projectile launch calculations. Neither wrapper locally creates items or changes state. Detailed common movement behavior outside these delegated calls remains outside this proof. ## Collision and landing
ftNs_SpecialS_Coll calls ft_800827A0 and calls ftCo_Fall_Enter only on false; it does not convert to aerial SpecialS. The collision helper copies current collision position to last position, synchronizes current position from the Fighter, calls mpColl_8004B2DC, copies the adjusted position back, and returns the Boolean result. A successful guard therefore means no further local transition, not no collision side effects. Exact terrain geometry and support edge cases remain delegated. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftNess/ftnessspecials.c#L146-L152 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_081B.c#L406-L424.

ftNs_SpecialAirS_Coll resolves attributes and, for nonzero ft_80081D0C, calls ftCo_LandingFallSpecial_Enter(gobj, false, x38_PKFIRE_LANDING_LAG). There is no local else action. The false argument is allow_interrupt. The common helper selects HammerLanding when ftCo_800C5240 succeeds; otherwise it invokes ftCo_Landing_Enter for LandingFallSpecial with rate (0.1f + fp->x2EC) / landing_lag. Neither this caller nor that division has a zero, negative, or nonfinite lag guard. A helper call must not be rewritten as a universal actual LandingFallSpecial-state guarantee. The reachability of the Hammer exception specifically during ordinary Ness PK Fire is not established here. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftNess/ftnessspecials.c#L156-L167 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_Landing.c#L103-L113.
