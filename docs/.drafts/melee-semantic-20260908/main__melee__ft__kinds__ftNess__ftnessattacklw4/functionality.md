# Ness AttackLw4 translation unit

## Scope and identity
The owned C file implements fifteen `void(HSD_GObj*)` functions: entry, animation, IASA, physics and collision processing for initial AttackLw4, AttackLw4Charge and AttackLw4Release. The owned header declares all fifteen, includes the HSD forward declarations and uses include guard GALE01_11659C. These are Ness's down-smash callbacks, not a meaning inferred solely from numeric state names: the active Ness motion table associates the three groups with AttackLw4 move IDs and the appropriate submotions. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftNess/ftnessattacklw4.h#L1-L24 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftNess/ftness.c#L67-L99.

## Initial phase
`ftNs_AttackLw4_Enter` clears allow_interrupt, clears isChargeDisable, calls shared YoyoSetVarAll, changes to ftNs_MS_AttackLw4 with flags 0 and arguments 0.0f, 1.0f, 0.0f, NULL, then calls ftAnim_8006EBA4. It sets x2222_b2 and installs YoyoStartTimedRehit in deal_dmg_cb and YoyoUpdateHitPos in accessory4_cb. YoyoSetVarAll initializes the shared integer counter to 1, rehit timer to 0, position modification enabled, command variables 0 and the stored position/rate fields to zero. It does not itself create the item. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftNess/ftnessattacklw4.c#L19-L33 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftNess/ftnessattackhi4.c#L297-L309.

`ftNs_AttackLw4_Anim` increments the integer yo-yo counter before calling YoyoThink_IsRemove. Only a false result permits rehit maintenance, charge testing and animation-completion testing. Charge entry requires the updated counter to equal exactly 13, isChargeDisable to compare equal to false, and YoyoCheckNoObstruct to return nonzero. There is no return or else after Charge_Enter: ftAnim_IsFramesRemaining is still evaluated after that call, and false invokes ft_8008A2BC. The helper's true return specifically covers item-creation failure; normal scheduled removal does not necessarily return true. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftNess/ftnessattacklw4.c#L37-L55 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftNess/ftnessattackhi4.c#L423-L508.

`ftNs_AttackLw4_IASA` reads input.held_buttons[0], not the obsolete baseline spelling held_inputs. An absent HSD_PAD_A bit sets isChargeDisable true. Holding A later does not clear it. Independently, nonzero allow_interrupt delegates to ftCo_Wait_IASA. Thus the local latch preserves eligibility until an observed released-A IASA check, but exact same-tick input/animation ordering is an engine scheduling question. `ftNs_AttackLw4_Phys` calls ft_80084F3C then YoyoSetHitPos. `ftNs_AttackLw4_Coll` calls ft_80084104, then despawns the yo-yo only if the resulting ground_or_air equals GA_Air. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftNess/ftnessattacklw4.c#L59-L90.

## Charge phase
`ftNs_AttackLw4Charge_Enter` selects ftNs_MS_AttackLw4Charge with Ft_MF_SkipItemVis, frame 12.0f, rate 1.0f, zero blend and NULL; calls ftAnim_8006EBA4; sets animation rate to zero; calls YoyoApplySmash; and reinstalls the same flag and callbacks. The shared helper resets the integer counter to 0 and initializes smash charge bookkeeping, independently of the frozen animation frame. Its item-specific operation is guarded by a non-null yo-yo pointer. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftNess/ftnessattacklw4.c#L149-L162 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftNess/ftnessattackhi4.c#L313-L366.

`ftNs_AttackLw4Charge_Anim` increments the counter, calls YoyoSetUnkRate and YoyoCheckTimedRehit, then compares the converted updated integer counter against the float xAC_YOYO_CHARGE_DURATION using >=. It enters Release when that comparison succeeds. There is no local article-lifetime check or animation-end test. `Charge_IASA` enters Release when A is absent; held A is a local no-op, not a guarantee against the independent duration or collision transition. `Charge_Phys` only calls ft_80084F3C. `Charge_Coll` repeats the initial collision/GA_Air cleanup sequence. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftNess/ftnessattacklw4.c#L94-L162.

For an ordinary positive finite duration, release occurs on the first update whose converted counter reaches or exceeds it. Zero, negative finite duration and negative infinity satisfy the threshold on the first normal charge update. NaN and positive infinity do not satisfy it for finite counters; manual release remains available. There is no validation or signed-counter overflow guard. YoyoSetUnkRate divides by duration before the release comparison and does not clamp its result; zero or nonfinite duration can therefore affect its output before transition. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftNess/ftnessattacklw4.c#L101-L111 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftNess/ftnessattackhi4.c#L511-L540.

## Release phase
`ftNs_AttackLw4Release_Enter` selects ftNs_MS_AttackLw4Release with Ft_MF_SkipItemVis, frame 13.0f, rate 1.0f, zero blend and NULL, performs animation setup, calls YoyoSetChargeDamage, and reinstalls the same flag and callbacks. The shared damage helper resets the integer counter to 14, optionally changes the item state/rate, and applies charge-derived damage only for nonzero accumulated smash frames and an enabled first hit capsule. Its formula includes division by duration and a u32 conversion, so exceptional or out-of-range values must not be described as a universally valid damage scale. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftNess/ftnessattacklw4.c#L238-L250 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftNess/ftnessattackhi4.c#L371-L419.

`Release_Anim` increments the counter and uses the same false lifetime-controller guard around rehit and animation exhaustion processing as initial Anim, without charge testing. `Release_IASA` only delegates to Wait IASA when allow_interrupt is nonzero. `Release_Coll` repeats the common collision then GA_Air cleanup. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftNess/ftnessattacklw4.c#L166-L192 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftNess/ftnessattacklw4.c#L225-L234.

`Release_Phys` first calls ft_80084F3C. For integer counter <19 it computes 0.20000000298023224f * ((float)counter - 14.0f), clamps with >=1 and <=0 branches, calls YoyoSetHitPosUnk and returns. Otherwise it calls YoyoSetHitPos. Values through 14 produce zero weight; 15–18 produce approximately 0.2, 0.4, 0.6, 0.8; 19 bypasses the ramp. The upper clamp is unreachable for an ordinary valid s32 input on the <19 branch. This is recursive blending from the previously stored position toward the current target, not interpolation from a permanently captured release origin. Zero weight preserves a finite ordinary previous position algebraically, but does not protect against NaN/infinity in the target because the helper still multiplies target components by zero. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftNess/ftnessattacklw4.c#L196-L221 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftNess/ftnessattackhi4.c#L225-L260.

## Shared dependencies, ownership and callbacks
The Ness motion-variable union declares attackhi4 and attacklw4 using the same ftNess_YoyoVars type, explaining why the shared helpers access attackhi4 while this TU accesses attacklw4. This is source-level union/type evidence, not a compiled offset/layout verification. All incoming objects are borrowed fighter objects, not yo-yo objects; functions return void and assume valid fighter state. The TU does not allocate/free fighter memory or retain stack addresses. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftNess/types.h#L12-L39.

Ground physics reads ground_friction and scales it only when ABS(gr_vel) > walk_max_vel, then applies friction and ground movement. Equality does not scale it; unordered float comparisons do not enter the scaling branch. Common collision ft_80084104 calls ft_800827A0 and enters Fall if it returns false. Wait IASA runs ordered early-return input predicates. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_084E.c#L42-L53, code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_081B.c#L1043-L1050 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_Wait.c#L44-L67.

Shared positioning obtains joint 61's world position; isPosUpdateMod selects optional rotation relative to FtPart_XRotN using the floor normal. The accessory callback only copies the stored position to hit capsule 0 when it is not disabled and stored x or y is nonzero. Timed rehit starts from an s32 conversion of xB4_YOYO_REHIT_RATE; maintenance decrements only positive timers when cmd_vars[0] is zero and resets collision bookkeeping exactly on reaching zero. Terrain eligibility requires an unobstructed body-to-position test and a second floor-support test. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftNess/ftnessattackhi4.c#L30-L57, code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftNess/ftnessattackhi4.c#L195-L295 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftNess/ftnessattackhi4.c#L633-L641.

The shared lifecycle creates at counter 2, reports failed creation with an action-ending call and true result, and otherwise assumes a live item in the active frame range. Its non-up-smash branch uses removal frame 60. CreateItem records the item in yoyo_gobj and x1984_heldItemSpec, conditionally installs damage/death callbacks only into empty slots, and installs pre/post-hitlag callbacks. Explicit despawn is null-guarded and clears yoyo_gobj after delegated item operations. Repeated explicit cleanup with an already-null pointer is a no-op. This does not prove all item destruction/reentrancy or callback cancellation lifetimes: the item implementation and full fighter dispatcher were not established here. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftNess/ftnessattackhi4.c#L423-L508 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftNess/ftnessattackhi4.c#L542-L600.

## Names and uncertainties
Canonical names remain authoritative. Rendered ftAnim_Advance, ft_CheckGroundAndFall, ftCommon_ApplyFrictionGroundAndMovement, YoyoSetTexAnimRate and YoyoSetHitPosInterpolated are hypotheses, not independent evidence. Ground/friction and interpolation descriptions have direct callee support; the exact animation-setup alias and final texture consumer remain unproved here. The familiar move name Walk the Dog and exact charging damage percentages are not established by the reviewed canonical sources. No compiled section evidence establishes .sdata2 contents, addresses or ownership of these literals. The C comment gives Release_Coll the same address as Release_Phys, whereas the header distinguishes 116A9C from 1169EC; this comment discrepancy is not resolved as a binary-address claim.
