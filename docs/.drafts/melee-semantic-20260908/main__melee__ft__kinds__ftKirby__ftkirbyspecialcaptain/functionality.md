Both canonical and rendered pages were independently read to exhaustion, as were all 22 subjects and all 29 outgoing links. This review independently confirms the librarian's principal corrections: all eight callbacks are shared by Ca and Gn states; aerial launch replaces only x/y velocity; an unsupported effect hat still sets the latch; and the existing-latch helper clears the latch and destroys effects rather than updating them. ## Fresh entry
`ftKb_SpecialNCa_800F99BC` clears command slots 1 and 0 and the entire `throw_flags` field, chooses `ftKb_MS_CaSpecialN` for exactly `FTKIND_CAPTAIN` and `ftKb_MS_GnSpecialN` for every other hat, calls `Fighter_ChangeMotionState` with flags 0, frame 0, rate 1, blend argument 0 and NULL, installs effect hitlag callbacks and calls `ftAnim_8006EBA4`. `ftKb_SpecialNCa_800F9A54` performs the same operations with the aerial states. These routines do not directly assign velocity, convert ground/air status or clear `x2219_b0`. Only two command slots are cleared; this is not proof that the array has only two slots. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftKirby/ftkirbyspecialcaptain.c#L21-L56.

## Animation and IASA
Ground Anim calls `ft_8008A2BC` only when `ftAnim_IsFramesRemaining` is false. Air Anim similarly calls `ftCo_Fall_Enter`. Neither directly accesses Fighter fields. The ground completion dispatcher selects special hand paths for hand kinds and otherwise calls `ft_8008A348(gobj, 0)`; that routine has early DownSpot and hammer-related branches, conditional grounded conversion, and an ordinary Wait-state transition. Thus broad action-ending dispatch is supported, but unconditional Wait is not. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftKirby/ftkirbyspecialcaptain.c#L58-L70 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_08A1.c#L53-L109.

Ground IASA is empty: no input reads, commands, velocity mutations or transitions occur there. This does not prove global uncancellability. Air IASA consumes any nonzero `cmd_vars[0]` before arithmetic. It conditionally negates vertical stick input for magnitude, caps it at `specialn_ca_y_axis_range`, subtracts `specialn_ca_x_axis_range`, floors negative range to zero, restores negative input sign, and computes radians from `range * specialn_ca_angle_difference / (outer-inner)`. It overwrites y with forward momentum times sine, and x with forward momentum times `(facing_dir * cosine)`. It neither adds to existing velocity nor modifies z or facing. A zero command makes no velocity writes; a later raised command allows another operation. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftKirby/ftkirbyspecialcaptain.c#L72-L113.

For ordinary finite attributes with outer > inner >= 0 and arithmetic within range, magnitudes at/below inner produce zero angle and at/above outer saturate the configured angle magnitude. Outer comparison is strict `>` and negative-range comparison is strict `<`; negative zero does not take input `< 0` branches. There is no validation of range ordering, equal limits, finite values, facing normalization or overflow. Equal limits can produce division by zero/invalid arithmetic. NaN comparisons are not a sanitizing clamp. Nonfinite intermediate values can reach sine/cosine and velocity writes. Even finite inputs can overflow intermediate multiplication; exact target floating-point/library outcomes are unresolved.

## Physics and effect events
Both Phys callbacks consume `throw_flags_b1`. If there is no event, they skip local effect handling. With an event and clear `x2219_b0`, Captain spawns synchronized effect 1195 and Ganon effect 1203, passing the GObj and joints from parts 0 and 44. Any other hat spawns nothing, but the latch is nevertheless set true. The latch therefore proves neither allocation success nor that an effect was spawned. With an event and already-set latch, `ftCommon_8007DB24` clears the latch and calls `efLib_DestroyAll(gobj)`. Successive events can therefore alternate creation/latching and destruction/reset, subject to external changes. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftKirby/ftkirbyspecialcaptain.c#L115-L178 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftcommon.c#L650-L655.

Ground Phys always calls `ft_80084FA8` afterward. Air Phys switches on `cmd_vars[1]`: 0 calls `ft_80084EEC`, 1 multiplies both x/y self velocity by `specialn_ca_additional_vertical_momentum`, and 2 calls `ft_80084DB0`. Other values make no movement-switch call or assignment. The command is not consumed; case 1 repeats on each invocation. Despite the attribute name, scaling is not vertical-only and is not necessarily damping: zero, negative, greater-than-one and nonfinite multipliers are not rejected. No local z assignment exists. Detailed delegated movement semantics remain unresolved. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftKirby/ftkirbyspecialcaptain.c#L145-L191.

## Collision transitions
Ground Coll enters its local transition only when `ft_800827A0(gobj) == false`. It calls `ftCommon_8007D5D4`, selects Ca aerial state for Captain and Gn aerial state for every other hat, forwards the current animation frame with rate 1 and the shared transition mask, reinstalls effect callbacks and clamps air drift. The conversion helper sets GA_Air, zeros ground velocity and selected position/velocity components, sets jumps-used to 1 and locks ECB for 10. Drift clamping uses the common air-drift maximum. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftKirby/ftkirbyspecialcaptain.c#L198-L221 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftcommon.c#L450-L525.

Air Coll uses the literal guard `ft_80081D0C(gobj) != GA_Ground`, calls `ftCommon_8007D7FC`, selects grounded Ca/Gn by the same Captain-versus-everything-else test, forwards the saved frame and shared flags, and reinstalls hitlag callbacks. Its conversion helper includes conditional airborne bookkeeping and grounded conversion, optional x-velocity replacement, jump/walljump resets, ECB unlocking and a ground-under-ID assertion. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftKirby/ftkirbyspecialcaptain.c#L223-L245 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftcommon.c#L546-L594.

The collision query updates collision positions and Fighter position, returns GA_Ground if `ft_80081A00` succeeds, and otherwise returns GA_Air for a true `mpColl_800471F8` result. Its return must not be equated to stored ground/air status or inverted according to rendered `ft_CheckGround`. Fully proved landing and ground-loss interpretations await underlying predicates. Even the no-local-transition path can have helper side effects. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_081B.c#L105-L123.

The shared mask is exactly `Ft_MF_KeepGfx | Ft_MF_SkipMatAnim | Ft_MF_SkipRumble | Ft_MF_UpdateCmd | Ft_MF_SkipColAnim | Ft_MF_SkipItemVis | Ft_MF_Unk19 | Ft_MF_SkipModelPartVis | Ft_MF_SkipModelFlags | Ft_MF_Unk27`. Forwarding the current frame proves an argument, not preservation of every animation/script subsystem. Unknown flags and full state-change effects remain unresolved. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftKirby/ftkirbyspecialcaptain.c#L193-L245.

## Ownership, lifetime and conventions
Fighter state is borrowed from the GObj's associated user data; no Fighter allocation/free or ownership transfer occurs here. There are no null checks or model-part/attribute validity checks. No local pointer is retained by this TU, and effect results are not stored or checked. Effect resource ownership and failure behavior remain subsystem concerns. `Fighter_SetEffectHitlagCallbacks` stores `efLib_PauseAll` and `efLib_ResumeAll` in pre/post hitlag callback fields. These are persistent function pointers, not stack closures; they are reinstalled after fresh entries and collision state changes. Dispatcher invocation/removal lifetime and state-change reset rules remain unresolved. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/inlines.h#L37-L53.
