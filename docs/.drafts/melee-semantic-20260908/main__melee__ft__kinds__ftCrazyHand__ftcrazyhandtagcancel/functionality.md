## Crazy Hand positioning and return controller

This unit implements shared destination-based positioning, not an exclusively grab-specific action. `ftCh_GrabUnk1_8015BA34` accepts a fighter object, continuation callback and destination pointer. It copies the destination into `mv.ch.unk0.xC` and stores the callback in `x4`; the caller's destination pointer is not retained. Crazy Hand's action selector supplies these pairs for numerous ordinary actions and squeezing-related selections. [Setup](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCrazyHand/ftcrazyhandtagcancel.c#L50-L75), [callers](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCrazyHand/ftcrazyhandwait10.c#L220-L309).

### State selection and exceptional branches

- `ftCh_GrabUnk1_8015B8FC` enters numeric motion `0x184`, preserving the current frame only when the tracked state is `ftMh_MS_Wait1_0` or `0x184`; otherwise it starts at zero and calls `ftAnim_8006EBA4`.
- `ftCh_GrabUnk1_8015B998` similarly enters `0x185`, preserving the frame from `ftMh_MS_Wait2_0` or `0x185`.
- The general setup is asymmetric: only an initial `ftMh_MS_Wait2_0` selects `0x185`. An initial `0x185` instead reaches the other branch and restarts `0x184`. Its nested second-state restart branch is unreachable under the enclosing guard.
- `ftCh_GrabUnk1_8015BC88` clears `x20`, constructs `(attributes.x18, attributes.x1C, 0)`, and forces the tracker to `0x184` before comparing it with `0x156`. Consequently the source takes the first helper and preserves the current frame. It installs `ftCh_Init_80156198` as the continuation. Entry and Drill explicitly use this return setup on animation completion.

### Animation, movement and continuation lifetime

`ftCh_TagCancel_Anim` does nothing while frames remain. On exhaustion it writes `ftMh_MS_TagCancel`, changes motion at frame zero and rate one, then calls `ftAnim_8006EBA4`. The Crazy Hand table shares these animation/physics/collision callbacks between entries labeled TagCancel (388) and Wait1_2 (389). Thus the numeric helper destinations must not be renamed by importing Master Hand's structurally analogous state names; `0x184` is already the table's TagCancel entry, not necessarily a distinct lead-in before it. [Animation](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCrazyHand/ftcrazyhandtagcancel.c#L77-L87), [table](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCrazyHand/ftcrazyhand.c#L568-L589).

Physics first obtains animation-derived x/y velocity through `ft_80085134`, then overwrites those components through `ftBossLib_8015BE40`. The latter measures three-dimensional displacement to `xC`. If distance is strictly below `attributes.x14`, it writes zero to `x18` but still writes raw displacement to x/y velocity. Otherwise it records distance and scales normalized displacement by distance times `attributes.x10`. Neither helper writes z velocity. Equality follows the non-arrival branch; no positive-threshold validation is performed here. [Physics call](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCrazyHand/ftcrazyhandtagcancel.c#L89-L96), [animation velocity](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_084E.c#L120-L125), [destination helper](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftbosslib.c#L57-L80).

Collision consumes exact `x18 == 0`, clears all three self-velocity components and invokes `x4` if non-null. A null callback still stops movement. This routine does not clear the callback or latch completion, so one-shot behavior depends on the continuation changing the surrounding state. Setup does not explicitly initialize `x18`; its intended arrival value is produced by physics. The default continuation clears `cmd_vars[1]` and selects a wait variant using the current tracker.
