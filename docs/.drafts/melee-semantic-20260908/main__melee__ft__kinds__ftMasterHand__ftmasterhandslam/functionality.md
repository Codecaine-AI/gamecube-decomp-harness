## Slam event and victim lifetime
`ftMh_Slam_Anim` consumes nonzero `cmd_vars[0]` by clearing it before calling `ftMh_CaptureWaitMasterHand_80155D6C` on `victim_gobj`. It subsequently rechecks the stored victim pointer and, if nonnull, calls `ftCommon_8007E2F4`, `ftCo_800DE2A8`, and `ftCo_800DE7C0` in order. The event block then clears `mv.mh.unk0.x20`. This is one event per nonzero command observation, not necessarily one event for the entire animation. [Event sequence](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftMasterHand/ftmasterhandslam.c#L21-L40).

The initial helper precedes the local null check. Its canonical implementation dereferences both its input fighter and that fighter's `victim_gobj`, copies the latter's facing direction, enters `ftCo_MS_ThrownMasterHand`, restores visibility, and installs `ftCo_800DE508` as `accessory1_cb`. Therefore the later guard does not establish null-safe event handling, and cleanup cannot be guaranteed for an initially null victim. The event requires live cross-linked fighter objects through the initial handoff. [Callee and lifetime preconditions](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftMasterHand/ftmasterhandthrownmasterhand.c#L29-L42).

Independently of the command condition, animation exhaustion calls `ftMh_MS_389_80151018`. That helper clears `x20`, arranges movement toward the configured position, and stores `ftMh_MS_341_8014FFDC` as the continuation. Its own state-selection sequence should be preserved rather than inferred from the numeric function name. [Completion helper](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftMasterHand/ftmasterhandwait12.c#L115-L138).

## Paired TagCrush entry
`ftMh_MS_380_80155194` looks up `FTKIND_CREZYH`. Only when `ftBossLib_8015C31C()` is false does it invoke `ftCh_Init_8015A2B0`; regardless of that condition, it stores the lookup result in Master Hand's `x1A5C`, enters `ftMh_MS_TagCrush` with literal arguments `0, 0, 1, 0, 0`, and calls `ftAnim_8006EBA4`. There is no local null check. [Entry](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftMasterHand/ftmasterhandslam.c#L57-L67).

The Crazy Hand initializer stores Master Hand in its own `x1A5C` and selects numeric state `0x179`. Reciprocal initialization is consequently conditional, not guaranteed on every Master Hand entry. The adjacent Crazy Hand animation callback clears its partner field on either boss condition or animation completion before invoking its continuation; this does not establish the complete lifetime of Master Hand's partner pointer. [Partner initialization and cleanup](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCrazyHand/ftcrazyhandsqueezing1.c#L15-L32).
