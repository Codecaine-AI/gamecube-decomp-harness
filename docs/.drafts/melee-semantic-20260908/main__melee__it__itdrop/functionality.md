## Item-drop utility family

The canonical implementation and rendered views describe seven one-shot selection, construction, and launch helpers, not a motion-state callback family. Existing function names remain useful hypotheses; no renames are proposed.

- `it_8026F3AC` delegates selection from `it_804A0E50`. Construction and bookkeeping occur separately. The delegated selector temporarily excludes an unavailable final M-Ball entry and restores table state; that behavior depends on the table arrangement.
- `it_8026F3D4` attempts up to `num` ordinary constructions. Mode bit 0 reuses the selected kind; otherwise each iteration selects again. Selection of `-1`, a kind at or above `It_Kind_L_Gun_Ray`, or an unavailable `It_Kind_M_Ball` stops the loop. Only the high-kind case sets the terminal Boolean; it is not ordinary-spawn success. Failed construction consumes an iteration and overwrites the stored object result with NULL. Successful kinds enter an eight-element local batch, with no local bounds check, and are reported to an eligible owner after generation bookkeeping.
- `it_8026F53C` either generates a launch vector or preserves the caller's vector, then copies it into the item. Generated horizontal speed uses `x54_float * (2 * (HSD_Randf() - 0.5))`; vertical speed comes from item attribute `x18`, and depth speed is zero. False mode mutates the supplied vector.
- `it_8026F5C8` constructs one explicit kind. The supplied position initializes the previous-position/facing anchor with zero depth. A non-null source instead supplies the current spawn position through its ECB center and occupies the secondary parent field. Source-less placement uses the flattened anchor. Airborne construction and success-only spin initialization are delegated; persistent parent ownership or lifetime is not established here.
- `it_8026F6BC` checks capacity and a configurable random gate, selects from `it_804A0E60`, and invokes the source-aware constructor. Velocity changes occur only after successful construction. Existing container-enemy naming remains a supported gameplay hypothesis; this source does not hardcode the documented 1-in-128 probability.
- `it_8026F7C8` rejects a true `gm_8016B238()` result or a `-1` selection, then constructs without a source, installs velocity, and records success. The rules accessor reads `x6`; no more specific mode name is established. Canonical Castle and Mushroom Kingdom callers confirm stage-block use while retaining their own animation, visibility, and object-lifetime transitions.
- `it_8026F8B4` gates a coin request by match kind and chance, computes a configurable value budget, and forwards source, position, and velocity to the coin generator. Its true return follows the void request and is not a per-object success count. Downstream budget consumption requires successful construction; guaranteed termination on repeated allocation failure is not established.

Four existing explanations need factual corrections: the batch object's last-attempt semantics, the M-Ball exceptional check, and two descriptions that mistake the specialized helper's position anchor for its actual source-associated spawn point. Other supported knowledge and all 17 links are explicitly retained in the checkpoints. Exact `.sdata2` layout remains unresolved without compiled evidence.

Both owned files were read completely in canonical and rendered form. The header renderer reports `shadowed_binding` for three pointer-returning declarations despite substituting their definitions; this is a renderer issue, not evidence against their names.
