## Heavy-item airborne movement and jump initiation

The source defines five functions and the header declares matching interfaces. HeavyFall IASA only calls `ftCo_80094EA4`; it does not call the jump predicate. The throw selector requires a held item, selects directional ordinary/smash HeavyThrow motions from A/B plus left stick or C-stick input, includes a neutral A/B forward-throw fallback, and transitions only if the selected motion differs. Physics unconditionally delegates to `ft_80084DB0`, which checks fast fall, chooses fast-fall processing or gravity/terminal-velocity processing, then performs common movement.

Collision delegates to `ft_80082C74` with `ftDk_MS_346_800E05E4`. Its query updates collision positions and calls `ft_80081A00` before deciding whether to invoke the landing callback. Thus absence of the landing callback does not establish that the current state survived unchanged. The query's `GroundOrAir` return labels must not be interpreted as an ordinary ground/air state assignment. Landing initializes cargo-hold landing lag, enters attribute base +8, and freezes animation. Its animation callback tests the timer before decrementing and decrements even after the return-to-wait transition.

`ftDk_MS_347_800E0378` classifies common jump input and forwards a nonzero discriminator unchanged into heavy startup, returning true exactly when dispatched. Grounded HeavyWait0, HeavyWalk and enabled HeavyTurn call it after the throw check. Upward-stick input has priority over X/Y in the classifier. The predicate has no local held-item or grounded-state validation and is not an aerial-jump callback. `ftDk_HeavyJump_CheckInput` remains a supported naming hypothesis, independently supported by canonical control flow.

Heavy startup stores the discriminator, clears its startup flag, initializes cargo-hold startup lag and enters attribute base +5. Its canonically named `ftDk_HeavyWait1_Anim` tests a nonpositive countdown, calls `ftDk_MS_347_800E03C0`, and then decrements the timer even after transition. The latter entry performs common setup, selects attribute base +7 with arguments `(0, 0, 1, 0, NULL)`, sets animation rate to zero and calls `ftCo_800CB110(gobj, true, 1)`. Launch initialization writes shared jump bookkeeping, chooses short/full-hop vertical velocity, adds and clamps horizontal velocity, clears z velocity, resets the stick timer and enables jump audio with an additional conditional sound. Cross-state move-storage lifetime must be preserved; no compiled layout inference follows from these accesses.

`ftDk_HeavyFall_Enter` remains a useful hypothesis for the launch entry, not proof of absolute motion number 347 or a passive ledge-fall entry. The separately read grounded collision path reaches an entry selecting base +6 without this launch call. Absolute state mapping and callback naming should be reconciled at the family level.
