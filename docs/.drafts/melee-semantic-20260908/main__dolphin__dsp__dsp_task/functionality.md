## DSP task manager

This unit implements CPU-side cooperative DSP scheduling through mailbox protocols, persistent queue pointers, and caller-supplied intrusive DSPTaskInfo records. Existing function names fit their canonical behavior. Both rendered pages matched canonical source with no substitutions or parse errors; parameter and section names were not rendered hypotheses. Supported existing knowledge and unchanged research dispositions are retained.

### Interrupt dispatch
`__DSPHandler` transforms DSP register 5, installs a cleared temporary OSContext, reads one mailbox message, then restores the supplied context. Messages 0xDCD10000 and 0xDCD10001 assign state 1 and invoke optional initialization/resume callbacks. Message 0xDCD10002 selects an urgent task before ordinary next/wrap scheduling; an already-current urgent task or sole ordinary task instead receives continuation and its optional resume callback. Actual outgoing yield switches assign state 2. A flags mask-0x2 test converts a yield into completion. Completion invokes the optional done callback and removes the descriptor, switching without an outgoing save descriptor or stopping when the queue is empty. Request mail invokes req_cb; unknown mail asserts. These are observed numeric states, not independently verified enum names. ### Mailbox protocols
`__DSP_exec_task` serializes ten words: outgoing DRAM metadata or three zeros, incoming IRAM metadata, then an initialization vector and zeros for state 0, or a resume vector and incoming DRAM metadata for every nonzero state. It does not itself update task state or queue pointers. `__DSP_boot_task` asserts the inbound synchronization word is 0x8071FEED and sends five command/value pairs, masking the DSP IRAM address to 16 bits. Both routines wait after every send and provide no timeout. Boot diagnostics include a misleading DRAM MMEM ADDR label whose actual argument is dram_length. [Transfer](code://c302741689bd67c361cd7faadb221df3193992c3/extern/dolphin/src/dolphin/dsp/dsp_task.c#L167-L228) [Boot](code://c302741689bd67c361cd7faadb221df3193992c3/extern/dolphin/src/dolphin/dsp/dsp_task.c#L230-L282)

### Queue and cross-file lifetime
`__DSP_insert_task` performs stable ascending-numeric-priority insertion without initializing state or flags. The separate internal `__DSP_add_task` appends and assigns state 0. Public DSPAddTask in dsp.c calls ordered insertion, assigns state 0 and flags 1 under interrupt exclusion, then conditionally boots the head after restoring interrupts. DSPCancelTask sets flags mask 0x2; DSPAssertTask produces the urgent pointer/pending state consumed here. Descriptors remain externally supplied records referenced by the scheduler; no allocation or freeing occurs in these paths. [Queue insertion/addition](code://c302741689bd67c361cd7faadb221df3193992c3/extern/dolphin/src/dolphin/dsp/dsp_task.c#L284-L335) [Public producers](code://c302741689bd67c361cd7faadb221df3193992c3/extern/dolphin/src/dolphin/dsp/dsp.c#L135-L201)

Removal clears flags and writes state 3. Singleton removal clears all queue/current pointers; tail removal wraps current to first; interior removal advances current to the successor. Crucially, removing a head with a successor leaves current unchanged, so the helper does not independently guarantee a valid current pointer. Completion callers coordinate this transition. Removed descriptors retain their own next/prev fields. [Removal](code://c302741689bd67c361cd7faadb221df3193992c3/extern/dolphin/src/dolphin/dsp/dsp_task.c#L337-L361)
