## Eligibility and damage consumer
`ftCo_800C44CC` extracts the fighter and requires `dmg.x1860_element == HitElement_Disable` and clear `x2228_b2`. It rejects `x2070.x2071_b0_3` values 5, 9, 11, and 12; all other values dispatch the unchanged object to `ftCo_800C4550` and return true. Rejection returns false without local initialization. No gameplay names are assigned to those exclusions or the blocking flag. In the central damage consumer, `!ftCo_800C44CC(gobj) && !ftCo_800D2FA4(gobj)` short-circuits: true from this gate skips the next special check and enclosed reaction handling, but final `ret0` processing remains possible. Thus 'consumed' describes the guarded reaction chain, not termination of all damage processing. The aerial branch does not initialize this TU's timer. The aerial delegate checks parasol status and can call `ftCo_800CF4DC` instead of its ordinary numeric-state transition; the rendered DamageFall alias must not hide that branch. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_DamageBind.c#L47-L61 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_DamageFall.c#L95-L109.

## Active callbacks and boundaries
The active DamageBind motion-state entry installs Anim, IASA, Phys, and Coll, with `ftCo_SM_FuraFura`, `ftCo_MF_Dazed`, and `ftCamera_UpdateCameraBox`. This establishes callback roles independently of inferred names. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftmotionstates.c#L3434-L3444.

Anim first subtracts common-data `x670`, invokes `ftCommon_GrabMash(fp, x674)` and ignores its boolean result, then calls `ft_8008A2BC` when the resulting timer compares `<= 0.0F`. Both signed zeros and negative values meet that comparison. Under ordinary floating comparison semantics NaN does not. With finite subtraction amounts, positive infinity remains non-expiring and negative infinity meets the test; arithmetic involving exceptional operands may instead yield NaN. Zero or negative coefficients need not reduce the timer. Even finite positive decrements need not guarantee progress at all magnitudes because of floating rounding. Initial nonpositive timers are tested only after the first Anim decrement and mash call. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_DamageBind.c#L63-L71.

GrabMash subtracts the supplied amount once for any pressed button in the AB/XY/LR mask and once more if remembered stick direction changes, allowing two subtractions per call. Its axis tests are strict against plus/minus `x308`; with an ordinary nonnegative threshold, equality and the dead zone do not update or reset remembered direction. This qualification matters: an unproved negative threshold can make the two independent tests overlap. NaN comparisons do not update direction under ordinary semantics. The cleared shake flag disables the optional shake-counter path; the helper sets `x2224_b5` false on that path and still performs player bookkeeping. Shared grab-mash machinery does not establish that DamageBind is a conventional grab. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftcommon.c#L682-L719.

Expiration delegates to `ft_8008A2BC`, which has Master Hand and Crazy Hand alternatives; its ordinary `ft_8008A348` route also has DownSpot and other alternatives before the normal Wait transition. Expiration is therefore not an unconditional Wait destination. IASA is literally empty, with no reads, writes, calls, or argument use. Phys forwards unconditionally to `ft_80084F3C`: it reads ground friction and scales it only when absolute ground velocity is strictly above `walk_max_vel`, then applies friction and ground movement. Equality leaves friction unscaled; no local validation of these floating inputs exists. Coll forwards to `ft_80084280`, which selects its collision path using nonzero horizontal nudge and a strictly negative nudge-times-facing product, returns when collision or a subsequent special check handles the situation, and otherwise enters Fall. Thus a positive timer only suppresses Anim's expiration dispatch, not all exits. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_DamageBind.c#L63-L83, code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_08A1.c#L54-L109, code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_084E.c#L42-L53, and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_081B.c#L1081-L1099.

## Dependencies, ownership, and lifetime
The TU depends on fighter extraction and motion changes, shared common data and grab helpers, player accessors, aerial damage dispatch, Lift/Throw processing, and shared physics/collision/recovery helpers. It performs no local allocation or direct dynamic callback registration. Nonempty entry/update paths require valid fighter user data and initialized common data; wrappers delegate equivalent validity requirements. IASA alone does not dereference its argument.

The cached Fighter pointer survives across shared pre-entry calls and the motion change by framework assumption, not by local proof. `ftCommon_8007DB58` calls two shared helpers, then optional `take_dmg_cb`, then optional `death1_cb`; neither that helper nor this TU revalidates object lifetime after those callbacks. Heavy-item handling requires non-NULL item and `itIsHeavy(item) == 1`, passing a stack-local zero vector to `Item_8026ABD8`. Whether that callee retains the vector and its deeper ownership effects are not established here. Victim processing requires non-NULL victim and has two `x221B_b5` branches with different argument order and cleanup. Deeper release effects and callback scheduling after transitions remain external contracts.
