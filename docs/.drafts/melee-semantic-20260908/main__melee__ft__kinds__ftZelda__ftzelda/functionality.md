## Attribute and resource initialization

`ftZd_Init_OnLoad` obtains the Fighter, applies `PUSH_ATTRS`, then passes item resources 0 and 1 with the DinFire and DinFire_Explode kinds to `it_8026B3F8`. `PUSH_ATTRS` copies external attributes into `dat_attrs_backup` and points `dat_attrs` there. `ftZd_Init_LoadSpecialAttrs` instead copies external attributes into the existing `dat_attrs` destination. Neither callback contains local resource validation or motion transitions. ## Death reset versus projectile detachment

`ftZd_Init_OnDeath` requests selection 0 for model slots 0 and 1 and clears `u.zd.x222C`; it does not itself detach or destroy an item. The parts setter writes pending selections and raises the dirty flag, with application occurring separately. [Reset](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftZelda/ftzelda.c#L252-L258), [parts processing](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftparts.c#L555-L577).

`ftZd_Init_801393AC` delegates to `ftZd_SpecialLw_8013B5EC`. Successful DinFire creation stores the projectile and installs this wrapper in both `death2_cb` and `take_dmg_cb`; failed creation does not install them. Cleanup conditionally detaches a retained projectile and clears its fighter reference, then unconditionally clears both callbacks. Item detachment additionally checks the item payload before clearing owner, Zelda back-reference and flag x13; it does not destroy the projectile. Conversely, item destruction clears fighter tracking only when the retained Zelda back-reference still matches the owner. Side-special loops can also clear tracking on owner mismatch. Thus the fighter pointer, item ownership and callback registrations have related but distinct lifetimes. ## Item and knockback adapters

Pickup and drop forward their event boolean with fixed arguments 1,1. The shared pickup inline excludes heavy items, maps hold kinds 1/2/3/4 to selections 1/0/2/3, leaves other hold kinds without that selection call, and conditionally performs the visible presentation call. Drop always requests selection -1 and conditionally performs the invisible presentation call; it has no corresponding heavy-item guard. Visible/invisible adapters pass 1 and their shared implementations exclude heavy items. Knockback entry/exit pass selector 1; shared inlines invoke `ftAnim_800704F0` for selectors 1 and 0 with 3.0f on entry and 0.0f on exit. Those literals do not establish a compiled small-data layout. [Adapters](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftZelda/ftzelda.c#L276-L322), [shared behavior](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/inlines.h#L142-L205).

## Debug model toggle and naming review

`ftZd_Init_801395C8`, canonically annotated `Zelda_RemoveDress`, reads pending model slot 1: -1 becomes 0, while every other value becomes -1. The common side-taunt caller invokes it only for Zelda at `DbLevel >= DbLKind_DebugRom`, before selecting the taunt motion. The function itself contains no debug guard. The annotation supports the proposed name, but its operation is a toggle rather than unconditional removal. `ftZd_Init_OnDeath2` is a plausible role-based hypothesis for the other unnamed wrapper, not proof of original spelling.
