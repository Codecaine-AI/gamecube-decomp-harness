## Game & Watch Parachute article

This unit implements the attached Parachute article used by Mr. Game & Watch's neutral aerial. The constructor initializes the explicit Parachute item kind, attempts creation, and attaches a successful result to the supplied fighter part using the article's special attributes. Failure returns NULL without attachment. Fighter setup supplies the TransN position, attachment part and facing direction, retains the result, and installs lifecycle callbacks only when an article exists.

The two-entry item table selects animation IDs 0 and 1 and uses the same Boolean animation callback for both indexed states, with null physics and collision callbacks. State indices and animation IDs coincide here but are distinct concepts: the generic state changer indexes the table by motion state and then reads its anim_id field. Pickup always clears xDAC_itcmd_var0; only an owned article enters state 0 and receives an immediate animation/script update. The landing helper unconditionally invokes it_8026BB44 before selecting state 1. Its fighter-side caller supplies the retained-article and LandingAirN guards.

The lifetime callback first checks exact equality with animation frame 30.0f, not a greater-than-or-equal timeout. On equality it notifies a present owner and returns true. Otherwise an ownerless article returns true; an owned article continues only when the fighter predicate returns false. That predicate tests the inclusive numeric interval from ftGw_MS_AttackAirN through ftGw_MS_LandingAirN. The generic animation dispatcher destroys the item when this callback returns true. These semantics are established by [the article](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/kinds/itgamewatchparachute.c#L11-L121), [the fighter lifecycle](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftGameWatch/ftgamewatchattackair.c#L25-L103), and [the generic state/animation machinery](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/item.c#L1181-L1290).

Destruction notification and explicit removal are different paths. The destroyed callback only notifies a present owner. Explicit removal checks the resolved Item pointer, not the input GObj, conditionally notifies its owner, and then invokes common removal even for an ownerless item. Fighter cleanup exits shared aerial-article hitlag before clearing the retained Parachute pointer and damage/death callbacks; it does not clear the pre/post-hitlag callback fields. The fighter explicit-removal caller also invokes cleanup after the item-side removal call.

The hitlag wrappers forward unchanged item pointers. Entry sets xDC8_word.flags.x3; exit sets x5 when x7 is active and clears x3 when set. Fighter callbacks filter null retained articles, and landing paths also invoke the exit wrapper directly. The shared fighter exit routine can affect retained Turtle and Sparky articles as well as the Parachute. See [paired dispatch](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftGameWatch/ftgamewatchattackair.c#L266-L295) and [generic flag operations](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/it_26B1.c#L387-L406).

The unknown-event wrapper delegates to a generic interaction-reference cleanup helper and discards its Boolean result. Matching owner, reflector, absorber, fighter and toucher references are cleared; clearing xCEC_fighterGObj also resets xCB0_source_ply to 6. Owner clearing can subsequently trigger the article's ownerless lifetime branch. This establishes the operation, not an exclusive event trigger. See [the wrapper](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/kinds/itgamewatchparachute.c#L123-L126) and [the helper](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/it_26B1.c#L491-L525).
