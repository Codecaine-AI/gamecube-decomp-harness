## Fighter-side Blizzard lifecycle

This unit implements the Ice Climbers' paired grounded and aerial SpecialLw callbacks, a landing continuation, guarded presentation cleanup, and the shared accessory emitter. The header declares the twelve entry/action/accessory functions; the cleanup helper is defined in the C file but not declared in this header. Canonical and rendered views were reviewed completely; rendered names were treated as hypotheses, not independent evidence.

### Entry and emission
Both entries clear `throw_flags`, `cmd_vars[0]`, `cmd_vars[3]`, the emission countdown, and the emission-enable bit. They start the respective motion at frame zero with unity playback rate, invoke animation setup, and install `fn_80122D2C` as `accessory4_cb`. They do not explicitly clear the persistent presentation marker. [Entry source](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftPopo/ftpopospeciallw.c#L35-L63)

The accessory callback processes existing emission before commands. While enabled, it tests the countdown for exactly zero, derives a position from `FtPart_L3rdNa`, adds facing-relative attribute `xBC` and vertical attribute `xC0`, attempts a Blizzard spawn, reloads from `xB8`, then decrements. The return value is ignored. Thus failed creation still consumes the scheduled interval. No positive interval bound is established here; zero or negative reload values must not be described as ordinary periodic timing without additional data evidence.

Command 1 starts effect `0x4EC` on `FtPart_L4thNb`, enables emission, sets the presentation marker, installs interruption callbacks, clears the command, and chooses audio by Popo versus every other fighter kind. Initial inactive-to-active emission cannot spawn until a later invocation; repeated command 1 while already active can follow a due spawn. Command 2 disables emission and clears the command only, so a due spawn may precede shutdown. Other command values are left untouched. [Emitter source](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftPopo/ftpopospeciallw.c#L175-L211)

### Movement and environmental continuation
Both IASA callbacks are empty, establishing no move-specific interrupt processing through those slots—not universal uninterruptibility. Ground physics delegates to friction and movement, scaling friction when absolute ground speed strictly exceeds maximum walk speed. The multiplier's value is not established. Air physics delegates to gravity/terminal-velocity falling and aerial friction, without the adjacent helper's fast-fall and stick-input processing. [Local wrappers](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftPopo/ftpopospeciallw.c#L99-L111); [canonical physics helpers](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_084E.c#L8-L53)

Ground collision literally tests `ft_80082708(gobj) == GA_Ground`; that branch clears model tilt, invokes ground-to-air continuation, restores interruption/accessory callbacks, and clamps air drift. The other branch applies `facing_dir * atan2f(normal.x, normal.y)` when `cmd_vars[3]` is nonzero, otherwise zero rotation. The helper's enum ternary and naming do not justify silently replacing this guard with an off-ledge predicate.

Air collision supplies `fn_80122B54` to a conditional event helper. The continuation enters grounded SpecialLw with flags `0x0C4C5282`, preserves the current animation frame, restores callbacks, and applies guarded slope alignment. Neither continuation locally resets the emission countdown or enable bit. The inferred AirToGround name is supported by this control flow, independently of rendering. ### Completion, interruption, and separate lifetimes
Animation completion conditionally destroys fighter-owned effects, clears the presentation marker and damage/death callback slots, and resets part-zero X rotation. Ground completion then calls `ft_8008A2BC`; air completion calls `ftCo_Fall_Enter`, regardless of the presentation marker. The common grounded exit is not guaranteed to enter Wait: its downstream code includes DownSpot and another conditional early exit, plus fighter-kind-specific branches. [Completion](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftPopo/ftpopospeciallw.c#L65-L97); [common exit branches](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_08A1.c#L54-L109)

`ftPp_SpecialHi_80122898` performs the same presentation teardown only when its marker is set. The installed `ftPp_Init_8011F060` dispatcher reaches it across files. This supports the conservative inferred Cleanup name despite the canonical SpecialHi prefix. Cleanup does not itself disable emission, clear the accessory slot/countdown, or destroy Blizzard items. [Cleanup](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftPopo/ftpopospeciallw.c#L21-L33); [interruption dispatcher](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftPopo/ftpopo.c#L398-L404)

The dedicated article constructor can return NULL; successful articles receive their own movement initialization and lifetime callback. Fighter presentation teardown and item lifetime are therefore distinct. Effect destruction selects effects by parent object rather than only by Blizzard effect ID.
