## Animation, boundaries, and transition side effects
Anim caches Fighter*, invokes `ftCo_800C4F64(gobj)`, tests the then-current floating `hammerkneebend.x8 <= 0`, calls `ftCo_800C5A98(gobj)` if true, and unconditionally decrements hammerkneebend.x8 afterward. This is not a decrement-before-test or an else branch. A value of 1 at the test reaches zero without taking this invocation's transition; zero, negative zero, negative finite values, and negative infinity take it. Under ordinary IEEE floating semantics, NaN fails the comparison, positive infinity does not expire, and sufficiently large finite values may not change under unit subtraction. There is no clamp or sanitization. These are local callback observations, not a proved global takeoff-frame count. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_HammerKneeBend.c#L26-L34; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/types.h#L342-L346.

## IASA, physics, and collision

That helper only assigns true to kneebend.is_short_hop: XY requires neither X nor Y held; the matching left/C stick requires y strictly below tap_jump_release_threshold. Equality and unordered comparisons do not satisfy stick release; an unrecognized stored input matches none of the predicates. Unlike ordinary KneeBend IASA, this wrapper does not try attacks or catches. Exact Hammer-field identity with the helper's KneeBend fields remains a compiled-layout uncertainty.
