## MetroTRK cache-maintenance primitive

`TRK_flush_cache(u32 addr, u32 length)` provides synchronous PowerPC data/instruction cache maintenance for MetroTRK. Its existing name and explanations accurately describe the canonical implementation; no semantic changes are proposed.

The assembly computes `first = addr & 0xFFFFFFF1`, adds `addr - first` to the byte count, and visits addresses eight bytes apart. The mask clears bits 1–3 while preserving bit 0; it must not be described as conventional cache-line alignment. Each visit executes `dcbst`, `dcbf`, `sync`, and `icbi`. The first visit is unconditional. After each visit, the address advances and the count decreases by eight; `bge` repeats according to the signed decrement result. Thus an adjusted count of zero still causes maintenance, and ordinary nonnegative counts divisible by eight include an endpoint visit. Arithmetic is 32-bit; this is not an unsigned length-guarded loop. One final `isync` precedes return. The implementation body is guarded by `__MWERKS__`; no compiled-layout or alternate-toolchain behavior is inferred.
