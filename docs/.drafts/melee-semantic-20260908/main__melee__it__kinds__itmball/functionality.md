## Poké Ball item lifecycle

`itmball.c` defines seven source-level motion-state rows and the Poké Ball's lifecycle, collision, interaction and accessory callbacks. `itmball.h` declares the matching callback surface and state table. Both canonical and rendered files were reviewed completely; rendered names were treated as hypotheses rather than evidence.

- **State 0 — grounded/resting:** entry enables flag x15, clears velocity and selects state 0. Animation returns false and physics is empty. Collision maintains support or enters state 1 when support is lost. The table's animation selector is -1: generic state change removes animation and clears the command pointer rather than loading an animation/script.
- **State 1 — ordinary falling:** spawn clears mball.b0/b1 and enters this state. Entry chooses ITEM_UNK_0x1 while b0 is clear and ITEM_ANIM_UPDATE otherwise. It shares Motion3_Anim, applies configured falling physics, and enters state 0 only through the common helper's qualifying landing checks. Changed horizontal velocity triggers facing refresh, whose helper preserves existing nonzero facing for sufficiently small velocity.
- **State 2 — held:** pickup selects this state. Animation and physics are inert and the collision slot is null.
- **State 3 — dropped/thrown:** both release callbacks select state 3 with numeric flags 6. Physics delegates to Item_ApplyFallingPhysics. Collision treats floor contact as the opening trigger; non-floor collision bits receive a separate shared response.
- **State 4 — entered-air recovery:** distinct from ordinary falling and thrown activation. Entry derives facing from x40_vel.x + x7C.x + x88.x, with zero selecting positive facing. Animation and physics are inert. Collision can return to state 1 without support, settle into state 0 under the grounded guard, or remain in state 4.
- **States 5/6 — grounded/airborne opening:** entries clear movement-related state and velocity. Only the first entry initializes lifetime from special attribute x0, sets b0, requests effect 0x449 and sound 0x10C, and selects the opening animation with ITEM_ANIM_UPDATE. Re-entry uses ITEM_UNK_0x1 without restarting the timer or replaying the effect. Both reinstall OnAccessory after generic state change clears that slot. State 5 has empty physics; state 6 applies falling physics. Support loss and qualifying landing move between them while preserving the existing opening timer.

Opening animation callbacks return Item_TickLifetime unchanged. That helper tests lifetime <= 0 before decrementing, unlike the ordinary x15-controlled countdown's decrement-then-test behavior. Generic update guards still apply. OnAccessory tests exact equality with special attribute x4 and replaces b1 with it_8027AB64's result; it has no local success guard or timer write. Pokémon selection includes mode/debug-specific branches, and creation can fail. Destruction decrements Item_804A0C64.x1C only when b1 is clear; the callback itself neither validates the counter nor performs additional cleanup.

Damage, clank and shield-hit callbacks perform the same ordered flag-clear, hitbox-reset and victim-bounce operations, then return false. False is not evidence that handling failed. Reflection delegates a distinct response that reverses/scales horizontal and vertical velocity, flips facing and resets lifetime to xD48_halfLifeTimer. Shield-bounce mirrors velocity and synchronizes facing with its near-zero exception, without that timer reset. EvtUnk forwards the item and referenced object to common interaction-reference cleanup and discards the ownership-match result.

The rendered EnterGrounded, Held_Anim, Thrown_Phys, Open and RemoveGObjReferences names remain supported descriptive names, not recovered original spellings. Thrown_Phys also services dropped items. Numeric state and flag distinctions are preserved. No compiled section-size or literal-placement conclusion is drawn from source literals.
