## Scope and reconciliation
This review covers all 56 lines of `ftCo_CargoJump.c` and all 14 lines of its guarded declaration header, independently read in canonical and rendered form. The librarian's principal findings are confirmed: this is a cargo-jump input gate, takeoff initializer, and callback quartet; zero blend is not necessarily no blending; section and union-layout claims remain unproved. The rendered `ftCo_CargoJump_CheckInput` and `ftCo_CargoJump_Enter` are plausible descriptive names for canonical `ftCo_8009BB1C` and `ftCo_8009BB64`, not recovered original names. External rendered aliases are likewise not evidence of their own meaning.

The Donkey motion table installs the four CargoJump callbacks in its ThrowFJump entry, between cargo falling and landing entries. Directional cargo-throw entries also have active consumers. These code relationships, rather than numeric enum labels alone, support the Donkey Kong cargo-carry interpretation (code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftDonkey/ftdonkey.c#L206-L348).

## Input gate and startup
`ftCo_8009BB1C` calls `ftCo_Jump_GetInput`, forwards any nonzero discriminator unchanged to `ftCo_8009B9C8`, and returns true after that call; zero returns false without startup dispatch. It is a state-changing predicate, not a pure eligibility query (code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_CargoJump.c#L18-L26). The classifier first tests stick Y >= tap_jump_threshold and tilt timer < tap_jump_window, then pressed X/Y. Threshold equality qualifies; timer-window equality does not. NaN Y fails the ordered stick comparison but leaves the X/Y branch available. CargoJump bypasses the preliminary special-case branch of ordinary Jump_CheckInput and does not use its relaxed or C-stick alternatives (code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_Jump.c#L30-L99).

CargoWait, CargoWalk, and CargoTurn test cargo throwing before this gate. Wait and Walk suppress later checks on jump success; Turn has no later check (code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_CargoWait.c#L52-L59; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_CargoWalk.c#L42-L49; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_CargoTurn.c#L53-L57).

Startup stores input in mv.co.cargokneebend.x4, clears x0, copies cargo JUMP_STARTUP_LAG into x8, enters base+5, requests animation rate zero, and requests ShoulderedWait on the victim. CargoKneebend_Anim instead accesses canonical mv.ca.specialhi.vel.y: it calls CargoJump entry when that field is <=0 and subtracts one afterward, even after the call. Zero, negative finite values and negative infinity satisfy the guard; positive infinity and NaN do not. Equating the differently spelled startup and countdown fields requires compiled layout evidence and is not established here (code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_CargoKneebend.c#L19-L45).

## Takeoff
`ftCo_8009BB64` unconditionally obtains Fighter from gobj->user_data, calls ftCommon_8007D5D4, changes motion to x2CC->x4_motion_state+7 with Ft_MF_None and animation arguments 0,1,0,NULL, requests animation rate zero, calls ftCo_800CB110(gobj,true,1), and requests ShoulderedWait for victim_gobj. Its zero-initialized local byte array is otherwise unused; it proves neither compiled stack layout nor a constant section (code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_CargoJump.c#L28-L38).

The airborne helper sets GA_Air, clears gr_vel, selected Z components and animation Y velocity, sets jumpsUsed=1, and locks the ECB with count 10 (code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftcommon.c#L515-L525). The motion API's arguments are start, speed and blend. Where animation setup is performed, zero blend selects metadata's default; -1 selects zero effective blend. Its initial cur_anim_frame calculation is start-speed, so the supplied start=0 is not proof that every internal frame field immediately equals zero. Ft_MF_None also clears fast-fall rather than preserving it. The animation-rate setter has a frozen-state deferred-rate branch; the transition clears the corresponding flag and this caller does not request FreezeState (code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/fighter.c#L933-L936; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/fighter.c#L1072-L1103; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/fighter.c#L1220-L1295; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftanim.c#L505-L513).

Shared launch clears mv.co.jump.x4, stores multiplier 1, combines retained horizontal momentum with stick-derived velocity, chooses hop versus full-jump Y velocity from mv.co.jump.x0, zeros Z, and caps horizontal magnitude only when ABS(h_vel)>h_max_vel. Equality is left unchanged. An unordered comparison bypasses the clamp; nonfinite or unusual attributes are not sanitized and can propagate or produce nonstandard results. It sets the stick timer to 0xFE. Audio is requested, with an additional sound only when x197C is nonnull. The earlier scaling of self_vel.y is subsequently overwritten by selected launch Y. Startup/jump member overlap is not proved (code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_Jump.c#L101-L151).

Victim synchronization is conditional, not an unconditional reset. ftCo_8009C5A4 does nothing for an already-ShoulderedWait victim. Otherwise it changes motion, optionally requests FreezeState according to the victim flag, uses the reciprocal victim_gobj as animation source, performs setup, and installs accessory1_cb=ftCo_800DB464. This helper does not initialize the grab timer (code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_Shouldered.c#L28-L53).

## Callback behavior
Anim is an entirely empty body: no dereference, frame test, timer, transition, call or mutation. Unlike ordinary Jump_Anim, it does not locally enter Fall on animation completion (code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_CargoJump.c#L40-L40; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_Jump.c#L167-L172).

IASA calls only ftCo_8009BF3C through RETURN_IF. Success exits early; failure reaches the same end, with no lower-priority action. The selector requires pressed A/B, prioritizes horizontal magnitude >=x98, chooses base+10 for X*facing>0 and base+11 otherwise, then considers Y>=upper threshold and Y<=lower threshold for base+12/+13. Directional threshold equality is accepted. A zero or unordered facing product takes the nonpositive horizontal branch if reached. NaN X fails the horizontal magnitude comparison, leaving vertical choices possible; NaN Y fails both vertical comparisons. Candidate/current-motion comparison occurs before the entry helper adds four for GA_Air. The helper changes carrier motion and requests the corresponding victim thrown state; active directional Donkey table entries establish the gameplay interpretation (code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_CargoJump.c#L42-L45; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_CargoThrow.c#L54-L118; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftDonkey/ftdonkey.c#L261-L348).

Phys forwards the same object to ftCo_Jump_Phys_Inner. When mv.co.jump.x4 is clear, that helper sets it and returns without calling airborne processing. Later calls invoke ft_80084DB0, which checks fast fall, chooses fast-fall or gravity/terminal-velocity helper processing, and calls ftCommon_8007D268. The gate describes callback invocations, not a guarantee that all engine movement stops for a scheduler frame. Complete lower-helper exceptional-value and state-transition guarantees remain unresolved (code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_CargoJump.c#L47-L50; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_Jump.c#L192-L206; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_081B.c#L1363-L1375).

Coll forwards to CargoFall_Coll, which passes ftCo_8009BD4C to ft_80082C74. That helper invokes the callback synchronously on a nonzero ft_80081D0C result; it does not store it. Landing copies LANDING_LAG into mv.ca.specialhi.vel.x, calls Landing_Enter with base+8, requests rate zero and numeric victim motion 0x10A. Landing_Anim checks <=0 before returning to cargo wait and then subtracts one. This numeric victim constant is not independently assigned gameplay meaning from its value. Delegation to CargoFall_Coll does not itself enter CargoFall motion. No-event preservation against all other engine paths is not proved (code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_CargoJump.c#L52-L55; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_CargoFall.c#L41-L44; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_081B.c#L549-L556; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_CargoLanding.c#L16-L34).

## Conventions, dependencies and invariants
The header declares all six functions with Fighter_GObj pointers; the empty Anim definition spells its pointer HSD_GObj. The ordinary non-M2C typedef makes these the same source type; the M2C synthetic declaration is separate. No ABI register or object-layout conclusion follows (code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_CargoJump.h#L1-L14; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/forward.h#L52-L77).

Dependencies are the cargo startup/throw/fall/shouldered family, ordinary jump classifier and launch/physics helpers, fighter dispatch, animation-rate control, common airborne setup and Donkey attributes. These routines borrow engine-owned objects and locally allocate, free or transfer no object ownership. Nonempty paths require valid game objects, Fighter user_data, attributes and relevant victim relationships; no local null, kind or motion-range guard protects them. Anim does not dereference its argument. No stack address is captured. Motion dispatch copies table callback pointers into Fighter and clears accessory callbacks; victim synchronization can subsequently install an accessory callback. Program-lifetime function pointers are not proof of live reciprocal objects or complete teardown safety (code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/fighter.c#L1370-L1389).

All 14 owned subjects, 41 baseline facts and 17 outgoing links were enumerated. The six parameter subjects have no baseline facts and receive no writes. No dox file is owned. All .sdata2 size/order/membership/immutability claims remain unresolved without compiled evidence, as do cross-member layout, register placement, full collision/scheduler preservation and persistent victim callback lifetime.
