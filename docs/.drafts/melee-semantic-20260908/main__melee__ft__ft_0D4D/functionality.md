# TU review: main/melee/ft/ft_0D4D

## Scope and conventions
The complete owned C file and header were read in canonical and rendered form. The header declares 18 externally visible functions; the C file additionally contains the local inline tail `ftCo_800D4F24_inline`. Most functions accept a `Fighter_GObj*`, obtain its Fighter through GET_FIGHTER or user_data, and mutate it in place. `ftCo_800D4E50` instead accepts a Fighter, position pointer, integer and float. `ftCo_Rebirth_Coll` is defined with HSD_GObj* while its header uses Fighter_GObj*. Register-locator identities alone do not establish the physical ABI location of the float argument. No file-scope data objects occur in the owned source. Section sizes, literal-pool membership and compiled union/object layout remain unproved.

## Death presentation and cleanup
`fn_800D4DD4` tests `mv.co.unk_deadup.x44 == 3`, obtains Stage_GetCamBoundsBottomOffset, and calls ftCommon_8007E2FC only when cur_pos.y is strictly below that boundary. Equality does not trigger it; unordered comparisons involving NaN do not trigger it. It does not update the phase or timer. Crucially, this is installed as **accessory4_cb**, not the motion-state physics callback: ft_0D31.c assigns it at line 809 and independently defines canonical `ftCo_DeadUpFall_Phys` at line 883. The rendered substitution `fn_800D4DD4 -> ftCo_DeadUpFall_Phys` is therefore wrong, not a recovered canonical name. The actual physics callback appears in the motion-state table. ## Names, safety and remaining uncertainty
ftCo_Rebirth_Enter, ftCo_RebirthWait_Enter and ftCo_Rebirth_Accessory1_Cb are useful descriptive hypotheses, not historical-symbol proof. The Wait-only spelling proposed for fn_800D55B4 understates its use in both states. The DeadUpFall_Phys alias is rejected because a distinct canonical implementation exists. The Sleep_Enter collision must not identify two functions as one. No gameplay meaning is inferred for effect 0x43F, color-animation 0xA or unnamed flag bits beyond inspected operations. The code assumes valid Fighter, data, camera/accessory and primary-entity pointers on unguarded paths. Stack transform vectors are not stored directly by this TU, but callee retention contracts were not verified. Float-to-int initialization for NaN, infinity or out-of-range values and signed countdown overflow are not made safe here. Positive timer configuration, callback scheduling across state changes, accessory destruction and full union layout are explicit unresolved invariants.
