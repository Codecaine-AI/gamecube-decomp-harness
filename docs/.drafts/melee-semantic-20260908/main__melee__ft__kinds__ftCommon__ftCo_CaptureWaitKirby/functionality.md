## Directional branches and boundaries
inlineA0 writes vertical stick age 254 and forwards an integer sign through victim_gobj to ftKb_SpecialN_800F598C. ftCo_800BD6EC first tests y >= tap_jump_threshold and age < tap_jump_window. Success forwards +1 and returns. Otherwise it tests y <= x464, age < x468, and ftKb_SpecialN_800F597C; success forwards -1 and calls ftKb_SpecialN_800F5954. Threshold equality qualifies; age equality does not. The first branch has precedence even if configured thresholds overlap. Actual signs and ranges of these fields are not established. Writing 254 is not a configuration-independent anti-repeat guarantee. The noinline wrapper simply invokes this helper. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_CaptureWaitKirby.c#L30-L66.

inlineB0 conditionally negates negative x to form a magnitude, compares it >= dash_smash_stick_threshold, and requires horizontal age < dash_smash_window + x44. Success writes horizontal age 254 and forwards -1 for negative original x, otherwise +1, to ftKb_SpecialN_800F5A04. The integer sign is supplied to a floating parameter in that consumer. IASA invokes vertical and then horizontal processing, so a vertical early return does not prevent horizontal acceptance in the same invocation. Under ordinary ordered floating comparisons NaN axis values fail the directional threshold guards; negative zero is not negative and chooses +1 if a zero magnitude qualifies. Infinities are not filtered. Actual target compiler exceptional-float behavior and configured numeric ranges remain unverified. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_CaptureWaitKirby.c#L68-L98.

The canonical Kirby consumers establish more than the rendered labels: 800F598C acts only on GA_Ground, calls ftKb_SpecialS_800F6BB0, then writes self_vel.y = specialn_stop_momentum * direction. 800F5A04 writes gr_vel when ground_or_air is zero, otherwise self_vel.x. 800F597C tests bit 0x100 using a raw M2C_FIELD access at 0x840; this is not compiled-layout proof or a complete semantic field identification. 800F5954 calls mpUpdateFloorSkip. ## Timing, mash processing, and release lifetime
IASA obtains Fighter and JObj, then gates only directional work on ftKb_SpecialN_800F5A38. That predicate tests the linked motion_id against ftKb_MS_EatWait or ftKb_MS_EatFall and ignores its second parameter. Independently of this predicate, IASA subtracts 800F5B00's result from grab_timer and calls ftCommon_GrabMash with 800F5B10's result, storing its bool output in capturekirby.x18. The accessors return specialn_duration_divisor and specialn_inhale_resistance: despite the former's name, this TU subtracts it rather than dividing by it. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_CaptureWaitKirby.c#L90-L109, code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftKirby/ftkirbyspecialn.c#L127-L140, and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftKirby/ftkirbyspecialn.c#L185-L197.

Common mash processing subtracts resistance once for any qualifying newly pressed AB/XY/LR buttons and once if tracked stick directions change. Its strict stick comparisons use +/-x308; neutral input does not explicitly reset the remembered directions. It also updates x2224_b5 and the optional x1A52 counter when x2224_b6 is set and reports the bool result to pl_800402D0. Thus the call has additional common-state and reporting effects beyond the timer. No assumption that every call contains a mash is warranted. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftcommon.c#L682-L719.

Only after both timing operations does IASA test grab_timer <=0, including equality. On success it snapshots victim_gobj, sets facing to the negative of linked facing, applies the saved capturekirby.scale to its JObj, calls ftCo_CaptureCut_Enter on the captured fighter, and calls ftCo_800DA698(snapshot,0) on Kirby. The snapshot matters because CaptureCut cleanup clears both pair links. Passing false avoids CatchCut's optional reciprocal CaptureCut invocation. These are borrowed live engine objects: this TU contains no allocation, destruction, reference-count change, or ownership transfer. The snapshot preserves a pointer value, not an independent lifetime guarantee. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_CaptureWaitKirby.c#L102-L108, code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_CaptureCut.c#L24-L36, code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_CaptureCut.c#L101-L195, and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_CatchCut.c#L8-L22.

No local finite-value check or timer clamp exists. Positive parameters give the intended countdown, but zero/negative parameters can stop or reverse it, and finite floating subtraction can round away a decrement. Under ordinary floating semantics a NaN final timer fails <=0; positive infinity with finite deductions remains non-expiring, negative infinity qualifies, and infinity subtraction can produce NaN. An initially nonpositive timer is still processed before the release comparison. Live paired Fighters, valid model joints and attributes, and initialized timer/saved scale are external preconditions.
