## XF verification

This file is guarded by `#if DEBUG`. `__GXVerifyXF` optionally calls the effectively empty `DumpXFRegisters`, recomputes texture-type counts, runs error and warning checks, then increments the static `DumpCount`. It does not reset the shared register/RAM initialization flags. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/extern/dolphin/src/dolphin/gx/GXVerifXF.c#L958-L974.

### Vertex and texture consistency
`CountTextureTypes` classifies encoded texgen types 0–3 as regular, bump, color0 and color1; other types warn at verification level 1 or above. Vertex checks compare XF input specifications against `gx` vertex descriptors, distinguishing normals from NBT using `hasNrms`/`hasBiNrms`. Source-row checks require the corresponding vertex attributes. Texture ordering expects regular generators before bump generators, followed by other types. These are diagnostic checks, not sanitization: excessive counts and invalid ordering produce warnings without clamping counts or stopping subsequent checks. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/extern/dolphin/src/dolphin/gx/GXVerifXF.c#L54-L300 and code://c302741689bd67c361cd7faadb221df3193992c3/extern/dolphin/src/dolphin/gx/GXVerifXF.c#L894-L940.

### Initialization, matrices and lighting
`CheckDirty` warns when a required control register has a zero initialization flag; `CheckClean` warns when a prohibited/internal register has a nonzero flag. `CheckRAM` emits one callback preamble and individual uninitialized-address warnings. Bump checks require regular-texture sources, light direction components and NBT; their default normal-matrix check runs when PNMTXIDX is absent. In contrast, `CheckTextureTransformMatrices` checks an 8- or 12-word range only when the corresponding texture matrix index is present in the vertex descriptor; this condition must not be inverted in an explanation. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/extern/dolphin/src/dolphin/gx/GXVerifXF.c#L88-L100 and code://c302741689bd67c361cd7faadb221df3193992c3/extern/dolphin/src/dolphin/gx/GXVerifXF.c#L302-L440.

Color checks validate channel control/material/ambient initialization, inspect the union of color and alpha light-selection bits when either lighting-enable bit is set, and conditionally require normals and default normal matrices. Color1 activation is specifically output-color count 2, or more than one color texgen with encoded type 3 at the second color-generator position—not simply any color1 generator anywhere. `CheckLight` checks 13 words starting at each light's color register. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/extern/dolphin/src/dolphin/gx/GXVerifXF.c#L478-L720.

### Floating-point diagnostics and orchestration
Floating-point checks skip uninitialized words and both signed zeros. At level 2 or above they distinguish infinities from NaNs; at level 3 they also warn for finite nonzero encodings whose exponent is below 0x6B or above 0x96. Scans cover geometry/texture, normal and dual-texture matrix RAM, light floating-point fields excluding packed color, and viewport/projection floating-point controls. Error orchestration additionally compares XF output counts with rasterizer fields and checks required matrix-index registers; warning orchestration checks input forms and internal control-register initialization. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/extern/dolphin/src/dolphin/gx/GXVerifXF.c#L722-L956.
