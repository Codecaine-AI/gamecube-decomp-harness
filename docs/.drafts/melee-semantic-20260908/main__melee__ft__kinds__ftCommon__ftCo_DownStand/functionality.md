## Scope and canonical interface
The complete owned TU consists of ftCo_DownStand.c (59 lines) and ftCo_DownStand.h (14 lines). It supplies an input-triggered DownStand selector, a shared motion-entry wrapper, and animation, IASA, physics and collision callbacks. The header declares all six functions. Canonical address names remain ftCo_800980BC and ftCo_80098160; ftCo_DownStand_CheckInput and ftCo_DownStand_Enter are useful inferred names, not recovered canonical identifiers. The rendered alias for ft_80084F3C is likewise not independent evidence. ## Input and entry
ftCo_800980BC borrows gobj->user_data as Fighter*. Its condition is (lstick[0].y >= common x244 AND ftCo_GetLStickAngle(fp) >= common x20_radians) OR a nonzero pressed_buttons & HSD_PAD_LR. Both analog comparisons include equality. This reads Y, not vector magnitude. The angle helper computes atan2f(Y, ABS(X)); horizontal sign is folded away. Short-circuit evaluation skips the angle query when the Y comparison fails and skips the button expression when the analog conjunction succeeds. No input bits are cleared. On acceptance, exactly DownWaitU selects DownStandU; every other motion ID selects DownStandD, without validating DownWaitD or groundedness. It calls ftCo_80098160 and returns true; rejection returns false without a transition. A true result reports dispatch, not a separately verified successful completion. At source comparison level a NaN operand makes its >= comparison false; shoulder input can still accept. There is no finite-value validation or clamping. Exact atan2f behavior for signed zeros, infinities and NaNs depends on the math implementation and is not established here. Sources: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_DownStand.c#L17-L34; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftcommon.c#L606-L609.

ftCo_80098160 unconditionally forwards gobj and the caller-supplied FtMotionId to Fighter_ChangeMotionState with Ft_MF_None, anim_start=0, anim_speed=1, anim_blend=0 and NULL alternate fighter. It neither restricts the ID to DownStand nor checks eligibility. IMPORTANT: zero anim_blend does not prove no blending. Fighter_ChangeMotionState substitutes the animation-data byte (*unk_byte_ptr)[0] when anim_blend is zero; -1 is the explicitly zero-blend sentinel. NULL selects the same fighter's animation data. Actual DownStand blend duration therefore requires animation data. ## Active consumers and callback lifetime
The common motion-state table actively assigns all four callbacks to both DownStandU and DownStandD, with their corresponding animation IDs and DownU/DownD flags. This is actual table evidence, not a gameplay interpretation inferred from numeric enum values. DownWait_IASA calls the input selector after ftCo_800984D4 and ftCo_Down_CheckInput. DownWait_Anim also enters DownStand automatically when its timer is <=0; decrement is suppressed by x2224_b2 but the expiration test is not. DownDamage_Anim enters DownStand only after animation exhaustion, on the non-air path with timer <=0; otherwise it returns to DownWait or takes one of two air paths. Both automatic callers choose U only for their exact U source ID. Fighter_ChangeMotionState selects a motion-table entry and copies its callback pointers to the fighter. The TU itself allocates, frees and retains no objects or callback contexts. Arguments must remain valid during synchronous delegated calls; there are no null guards except that the inert IASA never dereferences its argument. A state change replaces the fighter's callback set; the callbacks have no local one-shot latch and a manually repeated animation callback can dispatch repeatedly. ## Update behavior
Anim calls ft_8008A2BC whenever ftAnim_IsFramesRemaining returns false, otherwise doing nothing locally. The query scans eligible parts, using joint when animBlendFrames ==0 and x4_jobj2 otherwise; an empty or entirely ineligible set returns false. NaN blend frames take the nonzero branch under ordinary C floating comparison semantics. The exit helper has special Master Hand and Crazy Hand branches; ordinary fighters go through ft_8008A348, which can enter DownSpot, take another common special path, or enter Wait with additional character/common handling. Thus a guaranteed direct transition to Wait is too strong. ## Meaning and uncertainty
Active callers and tables support DownStand as the non-attack standing-recovery branch of the down-state family. Exact player-visible face-up/face-down animation correspondence and wiki-specific neutral-get-up/jab-reset descriptions were not independently verified from assets or pinned wiki content, so detailed baseline game-mapping claims remain unresolved rather than promoted by rendered names. Threshold values, animation lengths, actual blending, math-library exceptional cases, collision predicate physical interpretation, and compiled .sdata2 content/layout remain unresolved. Dependencies are fighter state machinery and types, common input data and angle math, animation/part data, shared ground physics, collision and action-ending dispatch.
