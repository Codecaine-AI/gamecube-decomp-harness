## Shared match setup
`gm_SetupSubColors` runs only when `rules.is_teams == true`. It visits every ordered pair of distinct player slots and increments the second slot's sub-color when team, character kind, and current sub-color coincide. Mutations affect later comparisons. It neither filters inactive slots nor repeats until convergence; the purpose is tint disambiguation, not a proved general uniqueness guarantee. [Canonical implementation](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gm_1B03.c#L11-L39).

`gm_SetupSuddenDeath` changes an existing match-start payload to Stock rules, disables `timer_enabled`, and clears `x2_5`. Already-inactive slots are untouched. For other slots, qualification combines a standings-derived value with either the player's loser flag or, when `end->is_teams == 1`, its team's loser flag. For numeric match kind 1, timeout returns recorded stocks; otherwise stocks are returned when `x28 < frame_count` or stocks are nonzero. The fallback is 1, including zero stocks with `x28 >= frame_count`. Thus qualification must not be reduced to a raw positive-stock check. Qualified records receive one stock and `x12 = 300`; others become `Gm_PKind_NA`. Character values 0x12/0x13 are normalized to 0x13 when fighter kind is 7 and 0x12 otherwise. The helper does not itself detect a tie or dispatch a scene. [Complete transformation](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gm_1B03.c#L41-L104).

`gm_801B05F4` writes `slot + 1`, exchanges input values 2 and 3 for the team assignment, and otherwise uses the input for team. Both destinations are bytes, so unrestricted mathematical-integer descriptions are inaccurate. Human and CPU initializers set participation type, character, color, and stocks before calling it; CPU setup then overwrites team with 4. They do not reset the whole descriptor or initialize CPU level. [Helpers](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gm_1B03.c#L106-L136); [source field types](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/mn/types.h#L102-L139).

## CSS configuration and lifetimes
`gm_801B06B0` calls `gm_InitVsMode` on the nested versus payload, records match type and a one-based selected slot, fills that player's character, stocks, color, CPU level, and nametag, and unconditionally mirrors stocks and CPU level into player zero. `gm_801B0730` decodes the selected slot and copies five fields to independently nullable outputs. There is no slot-bounds validation or null guard for the CSS pointer. The `MUST_MATCH` pragmas are source directives, not evidence of actual emitted inlining. [Initializer and getter](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gm_1B03.c#L138-L181).

`gm_801B07B4` selects player 1 when its final argument is zero and player 0 for every nonzero value. It writes five selection fields without setting participation type. `gm_801B07E8` reads player 1 only when the stored selected-slot value minus one is zero, otherwise player 0. The complementary getter uses signed-byte outputs for character, stocks, color, and nametag, whereas the selected getter uses unsigned outputs for the latter three. Neither getter directly writes CSS fields, but that read-only description assumes outputs do not alias the payload. [Complementary helpers](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gm_1B03.c#L183-L225).

All-Star and Multi-Man callbacks move persistent settings into CSS and retrieve selections on normal exit; `pending_scene_change == 2` returns to the menu without that retrieval. The old Multi-Man citation at lines 200–320 actually includes Target Test logic; the current Multi-Man entry and exit helpers independently support the retained relationship. [All-Star](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gmallstar.c#L709-L742); [Multi-Man](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gmmultiman.c#L480-L599).

Its non-cancel exit retrieves the human and opponent through the paired getters, clones opponent data into extra inactive records, and adjusts their colors and slots. Match entry later copies persistent records, applies human/CPU setup, and disables extra CPU slots. These lifetimes belong to the Training caller, not this helper TU. [Training CSS handoff](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gmtrainingmode.c#L92-L174); [match entry](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gmtrainingmode.c#L212-L251).
