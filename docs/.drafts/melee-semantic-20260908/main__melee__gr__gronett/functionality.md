# Onett semantic review

## Registration and startup
The module registers `Gr_Kind_Onett`, `/GrOt`, six Ground callback rows, and stage lifecycle/query callbacks. Startup caches the Yakumono parameter pointer and initializes Ground objects in order 0, 2, 5, 4, 3. The installer independently guards optional callbacks, registers rendering and recurring processing, and reports a missing object without stopping subsequent startup calls. The warning-model descriptor is borrowed from retained archive data and passed to the Onett warning-interface constructor. Camera bounds are initialized before blast-zone normalization.

The demo/load hooks are inert, the unnamed stage predicate returns false, and the touch-line callback returns a null `DynamicsDesc*`. The shadow callback compares the supplied position's Y coordinate strictly against the reference joint's transformed origin. Existing structural callback names generally fit the canonical registration and rendered view.

## Dynamic scenery and lifetimes
Ground object 5 initializes two responsive records, model joints 14 and 15, fog landmarks, and a timed particle generator. Deferred startup installs collision callbacks on joints 0 and 1 and retains an initially inactive camera subject. The common Ground queue retains callback/GObj pairs until after stage start, invokes them, and frees the queue nodes. Subsequent updates couple the retained subject's state to the shared vehicle phase.

The responsive-record callback accepts collision classifications 1, 2, and 3, maps joint zero to record zero and other joint IDs to record one, and accumulates contact input. The updater applies bounded spring-like motion, settling tests, and contact feedback. Transient contact fields reset each update; the feedback cooldown persists and decrements, including on the update that sets it to 10. Canonical source calls these records awnings, whereas several baseline facts and the rendered updater name identify tree platforms. Neither naming hypothesis independently proves visible asset placement. Those conflicting mappings remain unresolved rather than being replaced speculatively.

The ambient generator uses the prior value of a post-decremented timer. Expiry removes an existing generator or attempts creation at a transformed offset from joint 6. Missing joints or nullable creation results leave the generator absent until the newly selected retry interval expires. The existing chimney-smoke interpretation is retained as a hypothesis.

## Building controller
Ground object 4 separately owns the building state machine and collision joints 3 and 4. Qualifying contacts increment a cumulative count and request threshold-dependent reactions. The recurring process commits requested states after updating the current state, removes joints at collapse frames 20 and 90, waits a randomized interval, restores collision, and flashes the model. Timer expiry tests the prior negative value; a loaded count is not an exact invocation count. State 3 must not be interpreted as proof that collision has already been removed.

## Vehicle controller
Ground object 3 retains four vehicle models and item proxies. Proxy damage-dealt dispatch retains and forwards the owning Ground pointer; the impact callback can enter spinning state 4, enter ordinary movement state 6, or merely play another impact sound when already spinning.

The two directional schedules share one update function. A executes before B, and A's exit returns skip B for that invocation. A's release logic counts all fighter objects, then filters by height; its rank loop continues after a qualifying fighter and can overwrite an earlier decision. Immediate rank-based reveal does not write shared phase 1, unlike timer-expiry reveal. Initialization sets both vehicle indices to 4, and the update performs array indexing before state-zero reselection. This ordering is preserved as an unresolved numeric/indexing concern.

The initializer resets file-local `grOt_804D69C4`, not the shared phase stored in `stage_info.x740`. The shared phase is reset by A state zero. Corrections below distinguish these lifetimes and preserve exceptional branches.
