## Shared initialization
`inlineA0` obtains the associated Fighter, copies common integer `x648` to integer `dmg.x18F4`, conditionally assigns that count to floating `dmg.x1954` only when the comparison is strictly greater, sets `x2220_b4`, and calls `Fighter_UnkRecursiveFunc_8006D044`. The self-assignment adds no abstract C state change. Equal values do not update x1954, and a NaN x1954 is not repaired. The helper invokes optional `pre_hitlag_cb`, then sets `x2219_b5`, and conditionally propagates handling to linked `x1A5C`. Thus initialization is callback-visible, not atomic; the retained Fighter pointer must remain valid across helper callbacks. A callback may change state before the entries calculate velocity. ## Response entries
`ftCo_800C3598` initializes shared state, selects magnitude x64C for exact GA_Air and x650 otherwise, obtains an angle from `ftCo_Damage_CalcAngle(fp, dmg.kb_applied)`, and calculates x=mag*cosf(angle), y=mag*sinf(angle). In air it submits (x*dmg.facing_dir_1,y) to `ftCo_Damage_CalcVel` and clears ground knockback. Otherwise it stores x*dmg.facing_dir_1 in xF0_ground_kb_vel and submits (normal.y*scalar,-normal.x*scalar). This is construction along the floor tangent, not projection onto the floor normal. Every non-air state takes that branch. Its final `ftCommon_800804FC` call, however, clears source-player tracking to 6 and x18C8 to -1 only for exact GA_Ground. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_0C35.c#L27-L49; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftcommon.c#L1786-L1792.

`ftCo_800C36DC` uses the same initializer, then stores x654*(-specialn_facing_dir) as ground knockback and submits its floor-tangent components. It has no ground/air test, damage-angle calculation, or final source-tracking reset. Neither entry directly selects a motion state. Their pointer parameters identify mutable associated Fighters; local code establishes neither ownership transfer nor a universal grounded precondition. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_0C35.c#L51-L60.

Submission is not unconditional world-knockback replacement. `ftCo_Damage_CalcVel` overwrites x/y when time-since-hit < common xFC. At equality and above it handles each axis independently: if current*submitted < 0 it adds, otherwise it replaces only when the submitted absolute value is strictly larger. Equal magnitudes can preserve the old component; z is untouched. The exact product test matters for exceptional floats and underflow: opposite signs alone do not guarantee a negative representable product. NaN comparisons can preserve old components on the merge branch, whereas the overwrite branch directly stores submitted NaNs. No owned code normalizes normals, validates facing, clamps magnitudes, or recovers from nonfinite trigonometric results. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_Damage.c#L216-L235.

## Countdown and completion
`ftCo_800C37A0` does nothing when x18F4 equals zero, regardless of the active bit. Otherwise it maps FtPart_TransN, reads the mapped part's x4_jobj2, computes yaw pi*(x648-counter)/x648 using the pre-decrement counter, decrements it, and writes temporary yaw through both rotation APIs. On the decrement to zero it clears x2220_b4, negates facing_dir, sets TopN yaw to pi/2*facing_dir, clears both temporary TransN rotations, and invokes the current non-null x21F8(gobj). It does not clear, install, own, or retain that callback. The updater itself makes no subsequent Fighter access, but its maintenance caller does, so destruction during completion is not established as safe. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_0C35.c#L62-L87; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/fighter.c#L1427-L1440.

With unchanged positive duration N and uninterrupted calls, the nominal samples are 0 through pi*(N-1)/N, subject to floating rounding, not an explicit terminal pi write. The final sample is immediately reset while logical facing and TopN commit reversal. N=1 completes with temporary yaw zero. Initializing N=0 still sets the active bit and enters hitlag handling, but the updater cannot clear it or complete. Negative counters decrement away from zero until signed overflow would make C behavior undefined. Mid-response changes to common x648 alter interpolation and can create a zero denominator. Integer subtraction precedes conversion and can overflow on invalid extremes. Normal half-turn interpretation presumes conventional facing values; no local check enforces them. Fighter/common-data/part pointers are not validated by the owned routines. Default values, loader validation, invalid-input reachability, and downstream bone/JObj validation are unresolved.
