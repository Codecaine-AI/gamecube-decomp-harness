# Ness yo-yo article

The owned C and header implement the item-side linked yo-yo used by Ness's shared up/down-smash controller. The four table rows all have anim_id -1, share rotation/lifetime maintenance, and have no item-level collision callback. Numeric states are 0 attachment-derived yo-yo model matrix, 1 fighter-position-driven string deployment, 2 force/collision string simulation, and 3 retraction. Completion of state 3 enters state 1, not state 0. The generic state changer takes its anim_id -1 branch, removes item animation and clears the command pointer rather than installing an animation/script.

Construction creates one GObj/ItemLink per configured count. The first-created string head is stored in xC; the final-created terminal yo-yo link is stored in x8, and its model JObj in x18. next runs toward xC; prev runs toward x8. Every link retains the supplied fighter attachment JObj. The declared HSD_GObj* return actually comes from the terminal GObj's hsd_obj. Zero/one-link counts leave outputs uninitialized; the first GObj failure can inspect uninitialized prev_link, and rollback reads next after destroying the link GObj. Parent spawn checks only parent allocation and ignores link-construction failure. These are source-level exceptional-path findings, not claims of observed runtime failure.

State 1 snaps x8 to cached fighter yoyo_hitbox_pos and clears its velocity before deploying/collapsing next links using scaled distance bounds. Its 0/2 helper status is ignored. State 2 tests velocity magnitudes before adding pull/gravity, so a tick may overshoot a threshold; the other branch assigns the configured magnitude. After advancing an active next link, its collision-helper call still receives cur. Inactive-link handling selects up-smash charge length only for stored action 0x156, otherwise down-smash length; early returns are 0/1 and full traversal adjusts the chain, damps x velocity by 0.9 and returns 2.

Retraction initializes x4 to 0.1 times the planar distance from x8 position to the attachment-joint origin. The solver compares unchanged dist with successive anchor distances, clears crossed active flags, and passes min(len-dist, scaled segment size) to the constraint helper with no lower clamp. Completion tests remaining prev, not zero geometric distance. The transform writer scans from xC to an active link and then walks prev, deriving direction as prev_pos-next_pos. It overrides terminal direction from facing, scales model bases, and publishes the terminal position to the cached fighter. An active-link/topology invariant is assumed by the initial unguarded scan.

Generic owner and cached x10 have distinct lifetimes. Animation accesses cached fighter rotation before checking generic owner and inclusive motions 0x156-0x15B. Teardown conditionally notifies the fighter, clears generic owner, saves next before destroying each link GObj, and either explicitly removes the article or returns true to generic animation dispatch. The event helper clears generic interaction references but only loads/compares x10 without clearing it. Fighter pre/post-hitlag callbacks independently establish the paired wrapper meanings; exit is reused during cleanup.

Most existing names remain useful. UpdateRootLinkMtx is corrected to UpdateAttachedYoyoMtx because x8 carries the terminal yo-yo model, not the first-created string root. Release/Outreach/ChargeString remain descriptive article-operation names rather than exact exclusive fighter-state identities. Header rendering leaves CreateLinks and Spawn unsubstituted with shadowed_binding; C rendering reports no parse errors.
