## Scope, naming, and ownership
The owned files are `src/melee/pl/plbonus.c` and `src/melee/pl/plbonus.h`. The header declares 21 externally visible functions. Canonical address-based symbols are authoritative; rendered `plBonus_*` and `pl_GetBonusValue` names are descriptive hypotheses, not original-name recovery. In particular, the rendered `plBonus_CheckStaleMoves` does not prove that decision 0x59 is the displayed Stale Moves award. The `fn_` prefix does not make these functions callbacks. The TU contains no allocation, deallocation, callback registration, or retention of caller-supplied pointers. Player accessors supply borrowed mutable views of static player storage; configuration is borrowed shared state loaded elsewhere. Source-level casts do not establish compiled overlay compatibility. ## Periodic qualification
`pl_8003906C` and `pl_80039238` exclude unsigned frames 0 and 0xFFFFFFFE. During frame <= interval, a measurement >= threshold enables the decision; only exact frame == interval samples the baseline and returns 1/true. Later, only divisible frames are processed: a nonzero decision is cleared if growth is below threshold, then the baseline is always updated and 1/true returned. The return reports sampling, not successful qualification. Later processing cannot re-enable a cleared decision. Missed boundaries are not caught up, and duplicate calls on a later boundary can compare against a just-written baseline. Multiple frame-counter calls assume a stable frame during execution.

kind == -1 selects external decision storage; otherwise that pointer is unused, and real callers pass NULL. Sampled baseline pointers must be valid. No pointer is retained. Aliasing decision and baseline storage is not prohibited and can alter the effective read/write sequence. A valid positive frame with interval zero reaches modulo zero. Integer delta is unsigned subtraction, so a reset/decrease may appear as large growth; conversion of large unsigned values into signed baseline/decision locals is implementation-dependent at the C level. The float helper uses ordinary >= and < comparisons: NaN does not initially enable and an unordered delta does not revoke, but sampling still stores NaN. Infinity minus itself is also unordered. Negative thresholds and signed zero are not normalized. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/pl/plbonus.c#L296-L379; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/pl/inlines.h#L22-L29; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gm_16AE.c#L93-L101.

The active consumer fn_8003F294 skips index 1 and supplies configuration intervals, thresholds, cumulative statistics, and persistent per-player baselines. It uses external decisions xDC8 and xDCC. Decision 0x44 receives the magnitude of xCDC/xCE0 and baseline xDC0; x8C is declared unsigned but accessed through a float pointer. The xDCC sampling result drives xDD1.bit5/xD5C bookkeeping. pl_8003FAA8 invokes this consumer before other periodic bookkeeping. ## Ordered recomputation
`pl_80039450` clears only flag-typed decisions 0..214, preserving point entries, and invokes fn_80039618, fn_8003B044, fn_8003B9A4, fn_8003BD60, fn_8003C340, fn_8003CC84, and fn_8003D2EC in that order. It then adds 0x4F for !xDD0.bit1, 0x55 for !single_button && !xDD0.bit2, and 0x4E for nonzero xDCC && xDD1.bit5. Ordering matters because the final evaluator reads previous decisions. Preliminary bookkeeping in fn_8003CC84 prevents assuming the whole pipeline is pure or idempotent. ## Numerical and dependency contracts
pl_CalculateAverage converts its arguments to float, asserts denominator != 0.0F, and divides; it does not multiply by 100. Both signed zeros fail the assertion, while NaN passes. Several denominators are protected only by configuration/state assumptions, so zero minimum thresholds or inconsistent totals can reach the assertion. Comparisons using !=0 admit NaN, whereas ordinary ordered comparisons reject unordered inputs. Configuration, fighter/table validity, nonzero intervals, and nonoverflowing signed calculations are not universally enforced here. MUST_MATCH pragmas constrain inlining; PAD_STACK and source declarations do not prove compiled section or register layout. No compiled artifacts were assigned. All .data/.sdata2 attribution, physical struct extents, bitfield order, and register-level parameter mappings remain unresolved. The current configuration declaration extends through x180 and explicitly says UNKNOWN SIZE; the baseline rationale saying it ends at x174 is stale.
