## CaptureWait functionality

This translation unit implements the captured fighter's held-wait entry, animation, input, physics and collision callbacks for CaptureWaitHi and CaptureWaitLw.

### Entry and character-specific setup

`fn_800DB6C8` selects the high entry only for incoming `ftCo_MS_CapturePulledHi`; every other incoming motion selects the low entry. Both entry helpers start their respective states at frame zero and rate one. A linked Yoshi activates invisibility, an accessory callback, intangible original hurt capsules and a scaled, non-grabbable replacement hurtbox. The common `ftCommon_8007E2F4(fp, 0x1FF)` call is unconditional, including in `fn_800DB5D8`; its rendered InitYoshi name therefore describes only the special branch, not the helper's entire effect. [Source](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_CaptureWait.c#L28-L108), [low entry](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_CaptureWait.c#L180-L206).

The shared dispatcher also installs Yoshi capture constraints, or calls the appropriate non-null Link/Young Link or Samus article helper. Canonical article implementations explicitly request numeric state 5; this conclusion does not depend on rendered names. Entry requests common feedback program 3, with actual controller output gated inside the common helper. ### Timer, input and release

`fn_800DB8A4` advances the capture counter, subtracts passive grab-timer decay and stores the shared mash helper's result; it performs no release transition. The high animation callback performs corresponding updates through `FighterOverlay`. At nonpositive grab time it first calls `ftCo_800DA698` on the linked participant, then selects `fn_800DC070` when the buffered byte is nonzero or the stick predicate succeeds; otherwise it enters CaptureCut. Both release branches return before animation-rate maintenance. The separately inspected `fn_800DC070` really enters CaptureJump. [Timer and animation](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_CaptureWait.c#L110-L155), [CaptureJump entry](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_CaptureJump.c#L15-L26).

While held, a nonzero rate interval is decremented. Reaching a nonpositive interval restores rate one only when current mash activity is zero. A separate volatile interval read permits interval reload and configured-rate application when the interval is nonpositive and mash activity is nonzero. The configured rate's numerical magnitude is not established by this TU. Low animation delegates entirely to high animation. [Rate logic](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_CaptureWait.c#L141-L155), [delegation](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_CaptureWait.c#L246-L249).

Both IASA wrappers call `fn_800DC014`, which sets `capturewait.xC` on newly pressed X/Y while `capturewait.x0 < x3AC`; it never clears the latch. `fn_800DC044` tests `input.lstick[0].y >= tap_jump_threshold` without an edge or timing test and without mutation. Historical unindexed stick and `input.x668` spellings are superseded. [Input helpers](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_CaptureWait.c#L312-L329).

### Position maintenance and variant conversion

High physics unconditionally invokes `fn_800DAD18` and discards its result. The canonical callee computes the linked capture attachment's world position minus the captive's XRotN world position, tests the pre-correction vertical displacement against `x3C4 * x34_scale.y`, applies all three displacement components to `cur_pos`, and returns the strict comparison. Low physics uses that return to gate its high-state conversion. Thus a false result still includes positional correction. [Callee](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_CapturePulled.c#L148-L179), [wrappers and low conversion](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_CaptureWait.c#L256-L280).

High collision skips its dispatcher when `x2226_b2` is set. Otherwise its floor-contact callback forwards through `fn_800DBAC4` to `fn_800DBBF8`, which enters CaptureWaitLw at the existing frame with `Ft_MF_UpdateCmd`, reapplies setup and passes the linked pair to the alignment helper. Its replacement hurtbox uses literal `true` for height, unlike the named height in other setup bodies. Low-to-high implementations unlock ECB, preserve the current animation frame, refresh setup and alignment, conditionally run an immediate high collision check, and finally copy the current position to model translation. The immediate check can invoke the reverse transition. [High collision and low conversion](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_CaptureWait.c#L167-L244), [high conversion paths](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_CaptureWait.c#L256-L310).

### Important revision-specific ambiguity

The low collision callback supplies `fn_800DBED4` to `ft_8008403C`. That dispatcher invokes its event on `!ft_80082708(gobj)`. However, the current predicate returns `GA_Air` for `fall_off_ledge` and `GA_Ground` otherwise, and the current enum assigns zero to Ground and one to Air. Consequently the source cannot justify the baseline's assertion that this dispatcher calls the event on the air-domain zero result. The event's high-state conversion is established, but its intended loss-of-support trigger remains unresolved. This qualification also applies to the previously checkpointed `fn_800DBED4` descriptions that use loss-of-support language.
