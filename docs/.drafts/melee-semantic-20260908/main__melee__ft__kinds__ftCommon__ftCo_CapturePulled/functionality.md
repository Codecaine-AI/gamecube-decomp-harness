## CapturePulled functionality

This translation unit implements captured-fighter entry, skeletal alignment, grounded/airborne CapturePulled callbacks, and attachment helpers reused outside CapturePulled. The header declares only `fn_800DAADC` and `fn_800DAD18`; it is not a complete declaration inventory for the implementation.

### Entry and timer calculation

`ftCo_800DA824(Fighter*)` returns the supplied fighter's damage percentage times `x368`, plus handicap-dependent terms using `x354/x358/x35C`, plus `(x364 - (Player_80033BB8(player_id) + 1)) * x360`. It does not directly write fighter state, but it is not transitively pure: the player query delegates to a game helper that can refresh cached data. The rendered `Player_GetRank` name is a hypothesis, not independent proof of the precise standing semantics.

`fn_800DA8E4` initializes the first fighter using the second as its linked capture partner, despite the canonical parameter name `victim_gobj`. It stores that object in both relationship fields, clears flags, reverses facing relative to the partner, initializes common grab timing, clears four movement-union values, and enters the caller-supplied motion at frame zero and rate one. The union's character-specific field spellings do not establish character-specific meanings for these resets. `fn_800DAADC` selects CapturePulledLw for ground and CapturePulledHi otherwise, applies alignment, invokes the current collision callback, then synchronizes root translation. [Source](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_CapturePulled.c#L17-L124).

### Alignment and state callbacks

`fn_800DAC78` writes the linked fighter's capture attachment position minus the current fighter's mapped XRotN position. `fn_800DAA40` applies this differently by situation: on ground it writes the partner's `x2170` without directly translating the captured fighter; in air it clears that field and adds the full displacement. `fn_800DAD18` always adds the displacement and returns whether its Y component strictly exceeds `x3C4 * x34_scale.y`; the comparison does not guard the position update. These routines assume valid linked objects and joints. [Source](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_CapturePulled.c#L72-L179).

Both variants' Anim and IASA callbacks are empty. Hi physics unconditionally applies skeletal alignment. Lw physics also applies alignment unconditionally, then invokes the Hi transition when the saved upward-threshold comparison succeeds. The shared Hi transition prepares airborne handling, unlocks the ECB, enters CapturePulledHi at the current animation frame with `Ft_MF_UpdateCmd`, realigns, conditionally performs landing collision, and updates root translation. Because landing collision runs immediately, entry into Hi does not guarantee Hi remains the final state. [Source](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_CapturePulled.c#L181-L332).

Ordinary Hi and Lw collision processing is suppressed by `x2226_b2`. Hi collision passes `fn_800DAECC`, a forwarding wrapper, to `ft_80083C00`; its destination routine requests CapturePulledLw and retains both grounded and airborne post-transition alignment branches. The shared floor predicate can suppress the event through `ft_80081A00` even after updating collision position. ### Persistent attachment and cross-file lifetime

`ftCo_800DB368` resolves the first fighter's TransN2 joint before its guard. If the second fighter is not already attached, it zeroes the second fighter's XRotN rotation, snapshots translation into `x2174`, creates a persistent relation to TransN2, and sets `x2226_b2`. Repeated calls avoid mutation but not the initial target-joint lookup. `ftCo_800DB464` replaces position from XRotN plus facing/scale-adjusted cached offsets and forces Z to zero. `ftCo_800DB500` conditionally refreshes `x2174` and invokes animation maintenance under the attachment flag; it does not locally remove the relation. [Source](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_CapturePulled.c#L334-L384), [relation allocation](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/lb/lb_00B0.c#L402-L408).

Yoshi CaptureWait installs the position accessory and uses the constraint helper. CaptureWait owns subsequent timer decrement, mash processing, and alternate release branches; empty CapturePulled callbacks do not imply absence of later escape processing. Throw entry reuses the constraint and installs its own equivalent position callback; its timer clearing has a Kirby/motion exception. Crazy Hand capture initializes the first fighter's timer from `ftCo_800DA824(fp2)`, not from that first fighter, installs the constraint/accessory, and enters numeric state `0x150`; that numeric state is not normalized here.
