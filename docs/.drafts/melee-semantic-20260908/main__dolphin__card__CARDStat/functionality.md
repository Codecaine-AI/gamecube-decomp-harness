## CARDStat
Implements directory-backed memory-card status inspection and presentation-metadata updates. Existing function names fit their canonical behavior; the rendered view makes no substitutions and reports no parse errors.

- `CARDGetStatus` checks the file-number range, acquires the channel control block, and checks the selected entry's access permissions. Only `CARD_RESULT_NOPERM` triggers the public-file fallback. Nonnegative access results copy identity, filename, timestamp, presentation descriptors, and sector-count-derived byte length into `CARDStat`, then derive resource offsets. Every post-acquisition path returns through `__CARDPutControlBlock`.
- `UpdateIconOffsets` computes banner and icon locations from the directory entry's formats. C8 assets use one byte per pixel; RGB5A3 uses two. A C8 banner has its own 512-byte palette; all C8 icons share one trailing 512-byte palette. Unsupported formats receive `0xffffffff` offsets without advancing the cursor. Importantly, an absent icon address clears only the output status's format/speed fields and resets the cursor: subsequent switches still inspect the directory entry and may derive assets starting at zero.
- `CARDSetStatusAsync` validates the file number, sentinel-aware icon-address bound, and comment placement within a system block. These are not file-length checks. It requires ordinary access without the getter's public fallback, copies presentation descriptors into the directory entry, and recomputes the caller's offsets. An absent icon address sets directory icon slot zero to fast speed after that computation, so directory and returned status speeds can differ. It stamps the directory entry with current time in seconds and schedules `__CARDUpdateDir`. Mutations precede scheduling and are not locally rolled back on failure.
- The directory updater checksums and flushes the directory and starts erase/write processing. Successful write completion switches and mirrors the directory copy. Completion/error callbacks release the control block only when `apiCallback` is null and clear the saved erase callback before invoking it. This conditional ownership behavior must not be flattened into unconditional cleanup.
- `CARDSetStatus` supplies `__CARDSyncCallback`, propagates an immediate negative result, and otherwise waits through `__CARDSync`.
