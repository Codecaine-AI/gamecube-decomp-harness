# ftmetal semantic review

## Scope, conventions, and reconciliation
Independently read all 235 implementation lines and all 13 header lines in canonical and rendered form, and reconciled all 39 frozen facts and 10 outgoing links. The librarian's principal corrections are supported: section placement is not established by source literals; auxiliary model construction is not by itself proof of a Metal-only overlay; permanent-state teardown preserves rather than forces the active bit; zero timers bypass the observed expiry test. These uncertainties are preserved below.

The canonical exported names are `ft_800C8170`, `ftCo_800C8348`, `ftCo_800C8438`, `ftCo_800C8540`, and `ft_800C85B8`. `enableMetal` is a canonical static inline helper. The rendered ApplyMetal, InitMetal, and MetalEnd names are reasonable descriptive hypotheses, not recovered original spellings. `ftMetal_SetupModel` additionally implies an unproved asset interpretation. The header uses an include guard and fighter forward declarations; all five functions return void. Restoration receives `Fighter*`; the others receive `Fighter_GObj*`, with activation also receiving two integers. Parameter-register locations and object layouts are not established by these source signatures. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftmetal.h#L1-L12.

## Rendering
`ft_800C8170` iterates the kind-specific `ftPartsTable` part count and processes only `flags_b1` parts. It reconstructs flags from `flags_b7` and `flags2_b0` through `flags2_b4`, mapping respectively to JOBJ_LIGHTING, JOBJ_TEXGEN, JOBJ_SPECULAR, JOBJ_UNK_B18, JOBJ_UNK_B20, and JOBJ_UNK_B19. It clears mask 0x50180 and sets the reconstructed flags; this is not wholesale replacement of all joint flags. It walks every attached DObj and modifies mask 0xE to 2 for blending zero, 8 for RENDER_XLU, or 4 for RENDER_XLU|RENDER_NO_ZUPDATE. Other masked combinations report the full material rendermode and call HSD_Panic with `ftmetal.c`, 0x73, and an empty message. Empty chains are accepted, but a nonempty chain requires non-null materials because the switch dereferences mobj without a null guard. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftmetal.c#L14-L76.

`enableMetal` visits the same eligible parts, sets joint mask 0x50180, clears 0x180000, and writes DObj value 2 under mask 0xE. It always invokes ftCommon_80080460 afterward, even for an empty eligible set. That helper sets x2225_b6; ftCommon_80080474 restores it from x2225_b5. No more specific gameplay identity is assigned to these bits. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftmetal.c#L78-L97; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftcommon.c#L1754-L1762.

## Metal lifecycle and consumers
`ftCo_800C8348` replaces metal_timer and metal_health before testing is_metal. Already-active fighters therefore refresh both limits without repeating rendering setup. Otherwise it sets is_metal and enables rendering. There is no clamping, positivity validation, accumulation, or permanent-state check, and no local attribute or collision refresh. The concrete item wrapper asserts It_Kind_MetalB, passes two item-accessor results, and separately recalculates parameters and collision state. The state-transfer path forwards source counters before cleaning the source and later refreshes destination parameters and collision data. The inspected transfer mechanics do not independently identify the character pair. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftmetal.c#L99-L114; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftlib.c#L771-L781; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftcommon.c#L1330-L1360.

`ftCo_800C8438` copies is_always_metal into is_metal and zeroes both counters. Its false branch returns without undoing rendering or recalculating derived state. Its true branch enables rendering, calls ftCo_800D105C, then ft_80081C88 using current Y scale. The reset pipeline calls it after transformation and model-scale processing. `ftCo_800C8540` always zeroes both counters. Only when !is_always_metal does it clear is_metal and call parameter recalculation, collision refresh, rendering restoration, and baseline-bit restoration, in that order. It does so even if already inactive. The permanent branch leaves the active bit unchanged, including an inconsistent false bit. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftmetal.c#L116-L148; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/fighter.c#L514-L563.

Parameter recalculation copies base attributes, applies other modifiers, conditionally applies Metal multipliers to vertical jumps, gravity, falling speeds, and weight, and invokes a fighter-kind callback synchronously. Collision refresh always copies effective weight, but geometry and ledge-snap writes require ECBSource_JObj. Thus refresh calls do not guarantee geometry changes for every collision representation. Y scale is forwarded without finite/positive validation; zero, negative, infinite, and NaN values are not rejected here. Exact machine floating-point results and callback lifetime guarantees remain unproved. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftchangeparam.c#L163-L249; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_081B.c#L70-L103.

Countdown is external. When execution reaches the observed update branch, is_metal && metal_timer != 0 gates decrement, followed by teardown if the resulting timer is zero or health <=0. Timer zero bypasses even the health test; timer one expires at the next execution of that branch. Negative timers are not normalized, and signed underflow must not be described as portable wraparound. Damage subtracts the floating damage_amount from integer metal_health only under (!x2226_b4 || x2226_b3) and metal_timer !=0; there is no is_metal test in that damage branch and no direct damage subtraction from the timer. Representable finite floating-to-integer conversion truncates toward zero; NaN/out-of-range machine behavior remains unresolved. Death cleanup also invokes teardown for active Metal. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/fighter.c#L1525-L1531; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/fighter.c#L2648-L2668; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_0D31.c#L99-L131.

## Auxiliary model construction
`ft_800C85B8` traverses fp->ft_data->x5C twice. Both passes start at runtime index/depth zero. A nonzero ftParts_8007506C result advances only the part index, not the descriptor. First-pass ordinary slots insert descriptor-address-to-runtime-JObj references into the default HSD ID table. Second-pass ordinary slots load descriptor DObj chains, resolve references, and attach them to empty runtime joints or append after existing tails through lb_8000CE30. Populated parts receive flags2_b5, each newly loaded DObj is recorded sequentially in x203C.data, non-null materials change to ftMObj, and xD receives the final aggregate index before flags2_b6 is set. Finally x203C.count receives the aggregate count. Existing ordinary DObjs are not added to this auxiliary list. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftmetal.c#L150-L234.

A null root gives count zero. A null loaded chain skips attachment and completion metadata, leaving existing part metadata untouched. The aggregate >=32 diagnostic precedes each array write: indices 0..31 fit, and the 33rd object triggers the diagnostic before its write. The >=128 per-chain diagnostic occurs only after chain traversal, not as an independent pre-write capacity defense. Its reachability depends on assertion behavior because aggregate overflow is encountered earlier. No repeat-setup guard, rollback, explicit release, descriptor cycle detection, part-index bound, or fighter-null guard is present. Reinvocation can append additional objects while replacing list bookkeeping from index zero.

The kind-specific lookup scans Fighter_804D6540 for a matching part and returns a shifted bit. Valid table sizes and shift ranges are external obligations. The iterator visits child, then sibling, then ancestor sibling, establishing preorder depth-first traversal; shared ancestor storage makes unrestricted reentrancy unsafe to assume. Its depth diagnostic occurs when incremented depth reaches 30. The caller allocates x203C.data and brackets construction with fighter PObj default-class selection. Model-event handling consumes x203C for numeric event 2 and ordinary DObjs for event 3, but these numbers do not establish Metal-only meaning. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftparts.c#L712-L758; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftanim.c#L94-L127; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_0C88.c#L13-L20.

## Ownership and explicit limitations
State and model objects are mutated in place. The auxiliary builder creates persistent attached objects and stores aliases, rather than returning ownership. Complete destruction/reference ownership and default ID-table cleanup are not shown. No callback is registered or retained explicitly by this TU; external parameter and class operations may dispatch synchronously, and preservation of the cached Fighter pointer across those operations is a caller/callee invariant, not a proved lifetime guarantee.

ftCo_800C8A64 also calls restoration before lbRefSetUnuse, establishing refraction-status teardown reuse. A full Spy Cloak item-to-status trace is not established by the inspected source. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_0C88.c#L71-L83.

The source's diagnostic strings and PAD_STACK conventions do not establish compiled sections, padding, pooling, byte extents, or register allocation. In particular, the empty string is attributed to both .data and .sdata in baseline claims; all six section-target facts remain unresolved pending compiled evidence. No rendered substitution is treated as independent proof.
