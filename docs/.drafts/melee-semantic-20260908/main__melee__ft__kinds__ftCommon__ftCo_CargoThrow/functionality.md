## Cargo throw and cargo damage recovery

This unit implements directional cargo-throw selection, coordinated carrier/victim entry, directional callback adapters, and ground/air continuity. It also contains CargoWait2 damage-recovery callbacks. The header declares the public callbacks and boolean input checker; the three address-named entry/conversion helpers have static forward declarations in the C file. Rendered names are role hypotheses, not evidence of recovered original names. [Source](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_CargoThrow.c#L20-L118), [header](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_CargoThrow.h#L1-L32).

### Input and entry

The selector begins with the current motion ID. Only pressed HSD_PAD_AB enables directional selection. Horizontal magnitude at least x98 takes priority over vertical input; positive stick-X times facing selects base+10, otherwise base+11. If horizontal input does not qualify, Y at least attackhi3_stick_threshold_y selects base+12, and Y at most xB0 selects base+13. Without a qualifying direction the candidate remains unchanged. ftCo_8009BF3C calls entry and returns true only when that candidate differs from the current motion ID. This comparison precedes airborne adjustment: it is not a comparison against the final airborne destination. [Evidence](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_CargoThrow.c#L54-L89).

ftCo_8009C02C has no local validity or victim-null guard. For GA_Air it uses supplied motion+4 and flags value 1; otherwise it uses the supplied motion and flags 0. Entry passes frame 0, rate 1 and final float argument 0 to Fighter_ChangeMotionState, advances animation through ftAnim_8006EBA4, and calls ftCommon_8007E2F4 with 0x1FF. The original supplied motion—not the adjusted airborne motion—is normalized against character base+10 and added to ftCo_MS_ThrownFF for the victim transition. These are relative motion calculations, not proof of universal absolute state IDs. [Evidence](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_CargoThrow.c#L91-L118).

### Cross-file victim lifetime

Entry synchronizes a linked victim; it does not itself establish that the victim has already been released. ftCo_800DE3FC dereferences the victim's reciprocal victim_gobj as the thrower, changes the victim motion using that linked object, and installs accessory1_cb for positional maintenance. Its generic Yoshi and Kirby branches must not be generalized into cargo-specific behavior. Later shared throw processing consumes a facing-flip flag and a release flag. Release processing checks for a non-null victim before invoking ftCo_800DE2A8 and ftCo_800DE7C0. A separate command can latch motion data, stop carrier animation, and synchronize the victim's animation stop. The generic numeric tests motion_id == 222 and Kirby motion_id == 221 remain numeric tests here; no cargo-state equivalence is inferred. ### Animation, IASA and physics

CargoThrowF_Anim and CargoThrowAir_Anim directly run ftCo_800DD724 and call ftCommon_8007D92C when no animation frames remain. B/Hi/Lw animation callbacks instead delegate to their matching Throw callbacks, which also run throw effects. CargoThrowF_Anim is therefore not interchangeable with generic ThrowF_Anim: the latter has additional processing and an x2222_b0-dependent completion branch. Common completion dispatches to fall when airborne and ft_8008A2BC otherwise. ### Collision continuity

All four grounded directional collision callbacks supply ftCo_8009C170 to ft_8008403C. That helper invokes the callback when ft_80082708 returns false. The callback first performs common airborne setup, then selects current motion+4. Air collision supplies ftCo_8009C45C, which performs common grounded setup and selects current motion-4. The shared conversion temporarily substitutes facing_dir1 for facing_dir during state entry, passes cur_anim_frame with rate 1 and final float argument 0, restores the saved facing, and calls ftCommon_8007E2F4 with 0x1FF. The exact flags are SkipMatAnim, SkipColAnim, UpdateCmd, SkipItemVis, Unk19, SkipModelPartVis, SkipModelFlags and Unk27; unknown flags and UpdateCmd should not be described as blanket preservation of all state. Conversion does not rerun the victim-entry call. [Conversion and callsites](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_CargoThrow.c#L138-L257), [ground-check callback polarity](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_081B.c#L1035-L1041).

Common airborne setup sets GA_Air, resets selected movement components, records one jump used and locks the ECB. Grounded setup resets jump/walljump state and unlocks the ECB; it also has conditional bookkeeping and a ground-validity assertion. These cross-file effects qualify the simplified rendered SetAirborne/SetGrounded names. [Evidence](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftcommon.c#L509-L594).

### CargoWait2

CargoWait2_Anim advances shared damage recovery and exits whenever the post-update x221C_b6 flag is clear, including when it was already clear. GA_Air selects ftCo_8009BC58; all other values select ftCo_8009B518. There is no animation-completion guard. The damage updater decrements a positive countdown, clears the active flag at expiry, and performs additional common recovery work. CargoWait2_Phys delegates to Damage_Phys, which distinguishes ground, active aerial damage and recovered aerial physics. CargoWait2 is consequently a damage-recovery portion of cargo carry, not simply its ordinary idle wait. [Local callbacks](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_CargoThrow.c#L24-L40), [damage behavior](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_Damage.c#L968-L1088).

CargoWait2_Coll preserves its exact comparisons: in GA_Ground, ft_80082708 == GA_Ground triggers ftCommon_8007D5D4; in the other branch, ft_80081D0C != GA_Ground triggers ftCommon_8007D7FC. These comparisons must not be rewritten as if collision helper results necessarily denote ground/air modes. No local motion change occurs in this callback.
