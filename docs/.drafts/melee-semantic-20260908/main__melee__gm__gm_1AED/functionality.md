## Memory Card scene

This unit implements the Memory Card scene's entry, frame and exit callbacks, with three local helpers for dialog construction, selection/card-condition monitoring and status-to-prompt dispatch. The header declares only the three callbacks. The complete canonical and rendered files were reviewed; rendered substitutions were treated as naming hypotheses, not independent evidence.

### Context and lifecycle

`gm_80480DA8` retains incoming configuration, an outgoing result, prompt-choice mode, numeric scene state, a monitored-card-condition latch and a binary selection. Entry clears this object, optionally copies only the incoming `unk0` configuration, starts in state 0 when its mode is zero and state 1 otherwise, and propagates configuration `unk5` into result `unk4`. It calls the card work-area allocator, archive loader with argument 0 and shared notice initializer, then resets the debug latch and message index. Exit optionally exports the nested result and unconditionally removes dialog group 0. These operations are visible at [entry/exit](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gm_1AED.c#L442-L474).

Card work areas and archives have cross-scene lifetimes: allocation is guarded by an existing work-area pointer, and archive loading is guarded by the icon-data pointer. This scene's exit does not release those resources. Separate owner routines reset the retained pointers; a pointer reset alone is not proof of freeing storage. See [work areas](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/lb/lbcardnew.c#L1119-L1137) and [archives](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/lb/lbcardgame.c#L274-L292).

### Dialog and input

`gm_801AEE6C` handles modes 0, 1 and 2; other values do nothing. Each supported mode replaces group 0. Mode 0 builds an informational message and clears `unk10`, but does not reset selection. Modes 1 and 2 create label pairs 3/4 and 2/5 respectively, reset selection to zero, apply selected/unselected styling and set `unk10`. Layout uses `1.12F * (arg2 - 2)`, horizontal choice coordinates ±3.5 and a mode-0 adjustment of -2. The two authored 23-element integer tables are indexed by `idx - 2` according to saved language, without an internal bounds check. Their values are layout metrics, not proven text-line counts. See [builder](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gm_1AED.c#L41-L84) and [lookup](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gm_1AED.c#L152-L173).

`gm_801AF0D4` first checks the configured card channel. A nonzero probe result with latch 1 clears the latch; a zero result with latch 0 sets it. Either transition requests state 1 and returns true, suppressing confirmation or operation processing for that frame. The latch is therefore inverse probe truthiness, not a direct copy of the result or a fully decoded physical-presence flag. Otherwise mask `0x40001` selects zero before mask `0x80002` can select one. Only a changed selection redraws; `unk10` gates movement audio, not selection mutation. The helper returns false even after movement. Confirmation separately accepts Start or A and plays forward audio. See [input helpers](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gm_1AED.c#L86-L150). Downstream color helpers traverse all groups without filtering their first argument, so passing group 0 does not establish group-local coloring ([color helpers](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gm_1ADD.c#L201-L259)).

### Numeric status and state handling

`gm_801AF250` obtains the primary-save status and initially sets the latch to 1. Statuses 1/2 select message 7 for zero mode or 6 otherwise and enter state 2; notably both use the metric for message 6, and nonzero mode selects choice 1. Status 3 selects message 8/state 3/choice 1; status 4 selects message 10/state 5; statuses 5 and 6 select messages 14 and 15/states 9 and 10. Status 9 selects message 16/state 11/choice 1. Statuses 10/11/13 share message 19/state 14. Statuses 12, 14 and 15 select messages 20, 21 and 22/states 15, 16 and 17; status 15 clears the latch. Statuses 0/7/8 and unknown values request exit directly without writing a success result. These are distinct status, message and scene-state domains ([status dispatch](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gm_1AED.c#L175-L243)).

The frame switch has states 0–20. State 0 calls `lb_8001CBBC`, forwards its result to `gmMainLib_8015FA34`, and records result 1/state 20 for returns 0 or 2, otherwise entering state 1. State 1 performs status dispatch. State 2 choice zero either retries state 0 in zero mode or records result 1/state 20 and updates power time in nonzero mode; both set card status 0. State 3 choice zero displays message 9 and enters state 4. State 4 tests `lb_8001CC4C`: zero leads to message 11/state 6, nonzero to message 13/state 8. State 5 choice zero also enters state 6. State 6 tests `lb_8001C8BC`: zero leads to message 12/state 7, nonzero to message 13/state 8. State 7 confirmation records result 1/state 20 and sets card status 0. States 8–10 and 13–17 route confirmation to the fallback prompt helper. State 11 choice zero calls `lb_8001B8C8` on the configured channel, choosing message 17/state 12 for zero or message 18/state 13 otherwise. State 12 confirmation returns to state 1. Rejected choices in states 2, 3, 5 and 11 also use the fallback helper.

That helper distinguishes mode exactly equal to 1 from all other values: message 23/state 18 versus message 24/state 19. In either state, confirmed choice zero records result 0/state 20 and sets card status 4; choice one returns to state 1. State 20 and unknown states request exit. Most prompt paths are guarded by `gm_801AF0D4`; states 4 and 6 perform their operation tests without a confirmation requirement. No explicit notice-completion predicate or general asynchronous wait loop appears in this frame switch ([complete switch](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gm_1AED.c#L271-L439)).

### Debug path and evidence limits

At debug-ROM level or above, holding L+R+A latches a browser. While the debug-level guard remains satisfied, L/R triggers navigate message IDs 6–24, L takes precedence, and L+R+B requests exit. The callback returns before normal state dispatch. Activation alone does not explicitly rebuild message 6. Entry resets the latch; a later debug-level change could disable the bypass despite the latch remaining set ([debug branch](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gm_1AED.c#L245-L269)).

No compiled artifacts were supplied. Source declarations and arithmetic do not prove section membership, literal-pool extent, padding or compiler-generated jump-table placement. Exact recovered names, decoded status meanings and operation synchronization contracts remain separate questions from the observed control flow.
