# Common Fall translation unit

## Scope and identity
The owned implementation is `src/melee/ft/kinds/ftCommon/ftCo_Fall.c` (212 lines); its public header is `ftCo_Fall.h` (19 lines). The header declares ten externally visible functions, including reusable animation and interrupt helpers. `ftCo_Fall_inline` is private. Canonical names remain authoritative: `ftCo_800CC988` is canonical, while `ftCo_Fall_Anim_ApplyBlend` is a descriptive hypothesis. Rendered external aliases are not independent evidence.

## Entry and routing
`ftCo_Fall_Enter` first routes `FTKIND_MASTERH` to `ftMh_MS_389_80151018`, then `FTKIND_CREZYH` to `ftCh_GrabUnk1_8015BC88`, returning immediately in either case. No gameplay meaning is inferred from the numeric state in the Master Hand symbol. The shared inline router tests `x2224_b2`, calls `ftCo_80090780` and returns true if set; otherwise it tests `ftCo_800C5240`, calls `ftCo_800C5D34` and returns true on success. Damage/Hammer interpretations remain external hypotheses.

If unhandled, ordinary entry requests `Fighter_ChangeMotionState(gobj, ftCo_MS_Fall, Ft_MF_KeepFastFall, 0, 1, 0, NULL)`, calls `ftCommon_ClampAirDrift`, initializes `mv.co.fall.smid` to `ftCo_SM_Fall` and `x4` to zero, then calls `ftCommon_8007D5D4` only if still marked `GA_Ground`. The requested flag and ordering are proved, not its complete persistence or conversion semantics. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_Fall.c#L31-L71.

`ftCo_Fall_Enter_YoshiEgg` uses the shared router without boss checks, drift clamping or explicit grounded conversion. Its fallback passes `Ft_MF_Unk06`, frame 0, rate 1 and scalar -1, then resets the same fields. Flag/-1 meanings remain unresolved. `ftCo_Fall_Enter_YoshiEgg_Kirby` forwards unchanged. Its external caller invokes it after `grab_timer <= 0`, effect spawning, velocity setup and release-related calls; those operations are not performed by the endpoint itself, and shared routing still makes ordinary Fall entry conditional. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_Fall.c#L73-L88 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftKirby/ftkirbyyoshiegg.c#L118-L145.

## Directional animation
`ftCo_Fall_Anim` runs both helpers only when `x2228_b2` is clear. It passes persistent `fall.x4` by address and `ftCo_SM_Fall`, `ftCo_SM_FallF`, `ftCo_SM_FallB` to the selector, then applies the updated scalar. These are `FtMotionId` animation motions, not motion-state IDs. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_Fall.c#L104-L112.

The selector computes `r=self_vel.x/air_drift_max`, saturates ordered values outside [-1,1], and takes `ABS(r)`. It does not clamp actual horizontal velocity. Magnitude strictly above `x444` selects forward when `r*facing_dir>0`, backward otherwise, with target `(abs(r)-x444)/(1-x444)`; otherwise it selects neutral and target zero. It updates caller-owned weight with `w += x448*(target-w)`. Only nonzero updated weight and a changed selected motion cause `ftAnim_8006EDD0(fp,smid,cur_anim_frame,1)`, skeleton evaluation, part application and a stored `fall.smid` update. Thus zero target does not imply immediate neutral installation, and exactly zero updated weight prevents any stored-motion replacement. Passing the current frame does not independently establish all callee frame-preservation effects. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_Fall.c#L153-L196.

`ftCo_800CC988` evaluates the animation skeleton only for nonzero input. Exactly 1 calls `ftAnim_8006FF74`; other nonzero inputs call `ftAnim_8006FE9C` with `(w,1-w)`. Both start at `FtPart_TransN`, traversing eligible subsequent parts up to the character's part count, rather than affecting only the translation-root joint. Eligibility requires `flags_b1` and neither `flags_b0` nor `flags_b5`; the weighted helper additionally copies directly when `flags_b4` is set. Neither local helper directly allocates or frees objects; the selector does not retain its blend pointer. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_Fall.c#L90-L102 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftanim.c#L925-L952.

Normal interpolation depends on external invariants: valid objects, meaningful positive finite drift maximum, suitable finite threshold/rate and initialized weight. No local checks guarantee [0,1] weights or convergence. Under ordinary floating comparisons, both signed zeros skip application, NaN reaches weighted application, infinite ratios saturate and NaN ratios bypass ordered saturation. Invalid initial weights, rates and divisors are not repaired. At threshold 1, an ordered saturated magnitude cannot enter the division branch; unconditional division-by-zero claims would therefore be incorrect. Compiled exceptional-float behavior is not established.

FallAerial and FallSpecial pass their own persistent `x4` and animation-motion triplets to the selector and then apply the resulting weight. The selector nevertheless accesses `mv.co.fall.smid`. Source suggests shared storage conventions, but binary layout equivalence remains unresolved. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_FallAerial.c#L10-L29 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_FallSpecial.c#L38-L46 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_FallSpecial.c#L69-L82.

It immediately returns true for the first truthy result and returns false only after all eleven reject. False does not prove side-effect-free callees or unchanged state. The extra NULL argument's meaning, opaque gameplay mappings and exact Peach/input conditions remain unresolved. `ftCo_Fall_IASA` invokes this checker through `RETURN_IF` and has no subsequent work. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_Fall.c#L114-L151 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_Fall.c#L198-L201.

## Physics and collision
`ftCo_Fall_Phys` calls `ft_80084DB0` once, without additional guards. Inherited canonical research establishes that this callee checks fast fall, chooses `ftCommon_FallFast` or `ftCommon_Fall(gravity,terminal_velocity)`, then calls `ftCommon_8007D268`. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_Fall.c#L203-L206 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_081B.c#L1363-L1375.

`ftCo_Fall_Coll` unconditionally dispatches through `ft_800831CC`, supplying `ftCo_80096CC8` and an `HSD_GObjEvent` cast of `ft_80082B1C`. The line predicate rejects -1, accepts non-platform lines, and accepts platform lines only when stick Y is strictly above `x25C`; equality rejects a platform. Inherited research establishes that the dispatcher invokes its response on successful collision processing, otherwise tries wall-jump then cliff handling. These are function addresses, not stack closures. Neither this TU nor the visible dispatcher stores a callback; deeper retention and full response semantics remain unverified. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_Fall.c#L208-L211, code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_FallSpecial.c#L134-L143 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_081B.c#L685-L696.
