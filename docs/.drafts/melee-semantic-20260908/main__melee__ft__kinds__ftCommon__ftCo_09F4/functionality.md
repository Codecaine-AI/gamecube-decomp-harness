The source declares `floats={0,0.57,0.57,0.57,0}`, an opaque-white `HSD_LightDesc node0` with flags `0x0005`, `node1={&node0,NULL}`, and the NULL-terminated table `node2={&node1,NULL}`. The cast floating array occupies the descriptor's position-description pointer slot; it is not a five-component direction vector. Source declarations do not prove section placement, byte extents, padding or literal-pool composition. ## Callbacks and current-light semantics
Both callbacks have internal linkage through preceding static declarations. `ftCo_8009F480(Fighter_GObj*)` operationally receives the lighting GObj and unconditionally animates its `hsd_obj`; it does not read Fighter user data. The callee accepts a NULL list, traverses `next`, and evaluates each object's property animation before its position and interest animation. Available authored channels control visibility, attenuation/spot parameters and RGBA; no claim is made that every resource supplies every channel. `ftCo_8009F54C(HSD_GObj*,int code)` ignores `code` for every value, replaces current lights with the attached chain and sets up the current camera. Neither callback captures stack storage. A valid GObj and appropriate payload lifetime are required. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_09F4.c#L20-L59; code://c302741689bd67c361cd7faadb221df3193992c3/src/sysdolphin/baselib/lobj.c#L127-L241.

`HSD_LObj_803668EC` clears current/active state and traverses the entire supplied chain. Despite its name, `HSD_LObjSetCurrentAll` clears the collection and adds only its one argument. `HSD_LObjAddCurrent` removes any existing occurrence, increments a reference and inserts by priority; equal priorities are passed before insertion. The priority accessor returns `u8` even though the declared field is `u16`, so ordering is by the accessor's value. Removing current entries unreferences them. Camera setup dereferences the camera view matrix, resets masks, selects eligible lights subject to visibility and hardware limits, and handles ambient, infinite, point and spot types with diffuse/specular contributions. Registry membership does not guarantee hardware activation. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/sysdolphin/baselib/lobj.c#L480-L708; code://c302741689bd67c361cd7faadb221df3193992c3/src/sysdolphin/baselib/lobj.h#L111-L115.

## Per-Fighter ownership
`ftCo_8009F578(Fighter*)` loads `node2` and unconditionally overwrites `fp->x588`, without releasing any previous field value. Normal and demo constructors call it after common model/animation setup and before optional character OnLoad. Fighter unloading calls `HSD_LObjRemoveAll(fp->x588)` before freeing Fighter storage. Shared lights instead are attached to the lighting GObj. Generic GObj attachment records kind and payload; generic deletion dispatches the kind destructor. Complete light-kind destructor registration, scene teardown ordering and prevention of stale cached pointers remain unresolved. ## Overlay preparation and boundaries
`ftCo_800C0658` selects `&fp->x408` when its colanim pointer cast to int is nonzero, otherwise `&fp->x488`. It does not search all overlays or return NULL for a valid Fighter. `ftCo_8009F5AC` first returns when selected-overlay `x7C_flag2` is clear, leaving dirty and renderer state unchanged. Otherwise `x2221_b3` gates position/color/alpha refresh only. Define `a=MTXDegToRad(x78_light_rot_yz)` and `b=MTXDegToRad(x74_light_rot_x)*root_rotation_y/M_PI_2`. The exact assignments are `y=-sinf(-a)`, temporary `z=cosf(-a)`, `x=z*sinf(b)`, then `z*=cosf(b)`, followed by `HSD_LObjSetPosition`. This supplies a position controlling illumination, not the final camera-space light vector. In ideal finite arithmetic the vector has unit length; exact floating normalization is not guaranteed. Zero angles yield positive Z; zero root rotation removes the X-angle contribution for finite inputs; root rotation ±pi/2 multiplies that contribution by ±1. No range clamp, finite check or recovery handles NaN, infinity or intermediate overflow. Exact exceptional-float and signed-zero rendering is unresolved. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftdevice.c#L16-L19; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_09F4.c#L66-L83.

Within the dirty branch, light-enable true copies template white RGB with overlay alpha and sets `LOBJ_ALPHA`; false copies full overlay RGBA and clears `LOBJ_ALPHA`. Alpha 0 and 255 have no special local branch. Refresh clears the dirty bit. Every active call, including clean calls, selects all of `lobj0` when light-enable is true or only `lobj1` otherwise, inserts `x588` and sets up current-camera lighting. Changing light-enable while clean therefore changes base selection without refreshing cached color/alpha flags. Color-animation processing re-dirties the cache. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_09F4.c#L84-L102; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftcolanim.c#L267-L289.

## Material mode and restoration
`ftCo_8009F75C(Fighter*,bool set_alpha)` requires both overlay flags. True sets `LOBJ_ALPHA` and installs the full `lobj0` chain; false clears it and installs only `lobj1`. Both insert `x588` and rebuild lighting without refreshing position/color or changing the dirty bit. The material helper calls false for an enabled overlay ineligible for its direct opaque TEV path. The enclosing material callback calls true after render-mode/PE setup when no direct expression was returned. Inactive overlays also return no expression, but this helper's guard prevents work. The refractive branch returns before this pipeline. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_09F4.c#L104-L121; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftmaterial.c#L58-L197.

`ftCo_8009F7F8` tests only `x7C_flag2`, reinstalls all of `lobj0` and rebuilds current-camera lighting. It does not restore an arbitrary saved context, free `x588`, reset its alpha flag or change the dirty bit. The two examined common display paths bracket body/hierarchy and character-specific rendering with preparation/restoration, then draw accessories, subject to their visibility/display guards. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_09F4.c#L123-L129; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftdrawcommon.c#L233-L306.
