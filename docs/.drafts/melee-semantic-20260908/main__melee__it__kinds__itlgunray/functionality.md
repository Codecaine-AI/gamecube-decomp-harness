## Ray Gun projectile

This unit implements `It_Kind_L_Gun_Ray`, the separate projectile fired by the L-Gun controller—not Samus's Charge Shot. The controller passes its owner, requested position and facing to `it_80298168`; it decrements ammunition only when positive but calls the projectile constructor unconditionally within that routine. The constructor returns no object or failure status and guards all created-item access behind a non-null creation result.

Spawn positions have distinct meanings: `Item_InitRaySpawnPosition` copies the supplied position into `spawn.prev_pos`, forces that field's Z to zero, and separately obtains `spawn.pos` through the owner-position helper. The constructor retains `spawn.pos` in the ray snapshot. On successful creation, initialization reads attributes through the new item, applies its configured lifetime, performs common setup, and requests state index 0 with `ITEM_ANIM_UPDATE`. The initializer's owner and article parameters are unused. Subsequently the constructor sets scale to zero, angle to zero only for facing exactly +1 (otherwise π), stored speed from the article, and X velocity to speed times facing. ## State and update responsibilities

The source defines one `ItemStateTable` row, whose first initializer is 0, and initialization requests state index 0. These coincident numeric values should not establish a general equivalence between table animation selectors and state indices. The animation callback forwards the article maximum scale and divisor 7 to the shared ray updater. That updater also computes XY velocity from stored speed and angle, zeros Z velocity, derives facing from whether X velocity is strictly positive, updates model orientation, grows scale by absolute speed divided by 7, applies the maximum clamp followed by the small-scale fallback, and returns `it_80273130`'s result. Thus animation is not merely cosmetic. Physics only snapshots the current position; it does not integrate velocity. Collision passes the embedded collision record to `it_8029C4D4` and forwards its truth value. ## Interactions and cross-file lifetime

Damage dealt, clank, ordinary shield hit and absorption all return true without reading their item argument or doing local cleanup. Reflection instead reverses facing, rotates the model, multiplies stored speed by `xC70`, resets ray scale to 0.001 and adds π to the angle, then returns false. The reset normalizes using strict comparisons against zero and τ; it does not directly recompute velocity, which the animation helper subsequently derives. Shield bounce is distinct from ordinary shield hit: its shared helper mirrors velocity about `xC58`, resets stored scale, derives and normalizes the angle, and returns false.
