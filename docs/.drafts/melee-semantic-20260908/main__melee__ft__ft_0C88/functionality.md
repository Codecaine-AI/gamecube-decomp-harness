## Construction-time Metal model preparation
`ftCo_800C884C` allocates `x203C.data`, installs the fighter-specific PObj default class, calls the auxiliary model builder, and clears the override. Both ordinary and demo constructors invoke it after base part and animation setup. The builder attaches auxiliary DObjs, specializes non-null materials, records pointers and counts, and has explicit capacity assertions. This is resource preparation, not activation of timed Metal status. Allocation failure is unchecked locally, and the class override is a single global assignment rather than a stacked scope. The pointer array survives this wrapper and is freed by `Fighter_Unload_8006DABC` using the same allocator; clearing the PObj override does not destroy the constructed resources.

## Spy Cloak lifecycle
Canonical item dispatch calls `ftCo_800C88D4` for `It_Kind_Spycloak`, independently grounding the mechanic. `ftCo_800C88A0` clears only local bookkeeping: b4, b5, b7, `x2030`, and `x2134_vibrateFrame`. It does not release shared refraction participation or restore model flags.

Activation always stores its integer argument in `x2030`; full setup occurs only when b4 is clear or b7 is set. Setup enables b5, clears b7, zeroes the presentation byte, changes model rendering, increments shared refraction use, and sets `x221F_b2`. Only inside that guard does the Boolean choose an activation profile request (`0x7C`) versus persistent-controller synchronization. Passing the request guard does not guarantee controller acceptance.

Restoration resets transient fields, copies b3 into b4, conditionally repeats setup, and always synchronizes the persistent controller. b3 originates in player configuration, not a saved remaining timer. Removal always clears `x2030`; b3 preserves the existing presentation, while its absence triggers local reset, controller clearing, model restoration, refraction release, and clearing `x221F_b2`. The model restoration has an unexpected-blending panic branch. Refraction release decrements a shared count and asserts if it becomes negative; removal has no independent local active-state guard making arbitrary repeated calls safe.

The external updater decrements nonzero `x2030` while b4 is active, removes the effect at zero, and requests `0x7D` at the configured warning threshold only without b3. It sets b7 only if that request succeeds. Replacement transfers the remaining value only when the source is active and b7 is clear, then removes the outgoing effect. Death cleanup also checks b4 before removal.

## Draw cleanup and visual commands
`ftCo_800C8AF0` conditionally resets TEV stage 0 to direct operation, disables indirect stages, and invalidates graphics state when b5 is set. It changes no Fighter lifecycle state. Both renderers call it after model display; the alternate renderer requires b5 clear on entry, so its call normally does no cleanup unless intervening drawing changes that flag.

`fn_800C8B1C` simply zeroes the historically named `x2134_vibrateFrame` field. `ftCo_800C8B60` unconditionally stores its two byte operands into b5 and that field. Crucially, the material callback consumes them together: b5 selects refraction setup, and the second field is passed as the index into `tobj_list`. The existing setter explanations understate this direct consumer and overinterpret the field as vibration timing. The proposed corrections preserve the canonical field name while explaining the observed texture-selection role.

Color-animation commands reach the setter through `ftAction_800730B8`; its alternate handler merely advances the command. The updater always uses normal dispatch for x508 and selects alternate dispatch for x488 when x408 is active. This is caller-side command suppression, not a guard inside the setter. `ftCo_800C8B2C` separately suppresses profile requests on b6 and otherwise returns the dispatcher's acceptance result unchanged.
