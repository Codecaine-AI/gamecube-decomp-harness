## Results participant presentation backend

This unit initializes post-match participant presentation, constructs demo fighters, lights and cameras, provisions capture images, and binds rendered images to Results-model textures. The header declares the externally visible routines; it retains an unknown prototype for `fn_8017A004` despite the source's `void (void)` definition.

### Initialization and construction

`fn_8017AA78` clears `lbl_8046E1B0.pad_000`, initializes scene subsystems and a dummy stage, allocates a shared 100×152 RGB5A3 image, snapshots the completed match, resets presentation flags, and installs packed dimension, scissor and layout tables. Four input bytes are copied into `costume_override`; their downstream use is animation-variant override, not costume application. No Contest sets each copied player standing and each referenced team standing to numeric tier 1. It does not independently iterate every team. See code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gm_1798.c#L596-L643.

Results entry calls this initializer and the light constructor, then provisions images, creates a fighter, and creates a camera for each occupied participant. Actual costume IDs come separately from match player data. See code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gmresult.c#L1818-L1837.

`fn_8017A67C` selects individual or team `is_big_loser` state. Unsupported initial archive lookup returns NULL. Zelda/Sheik selection is corrected afterward from the recorded fighter kind; Game & Watch receives facing -1 rather than 0. Tier zero selects variants 0, 1 or 2 using button priority 0x200, 0x800, 0x400, then randomness. Other tiers select variant 4. A nonzero override replaces a non-4 variant with override-minus-one without local range validation. Zero and nonzero tiers use different position, scale and Player-API ordering. The resolved character and variant are persisted for camera construction. See code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gm_1798.c#L468-L568.

`fn_8017A318` creates a participant camera with fixed scissor {270,370,124,276}, character/variant calibration, standing-dependent offsets, and asymmetric depth correction: 100 times the negative scale difference, otherwise 300 times the difference. Variants above 2 select calibration entry 3. Tier zero adds 320 depth and creates an additional camera through `fn_8017A078`. That additional camera uses eligible-zero-tier count and ordinal helpers, score-table horizontal offsets, player height, and specific Bowser/Marth/Captain Falcon variant corrections. Mode zero ambiguously represents either zero or one eligible participant. Although `fn_8017A318` is declared pointer-returning and its caller stores the result, its body contains no return statement. See code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gm_1798.c#L317-L466 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gmresultplayer.c#L1315-L1367.

### Rendering and state transitions

`fn_80179854` requests a transparent-black to alpha-60-black transition over 30 updates. It moves occupied nonzero-standing display objects to X=-300 and sets `x0_6` only when such an object is found. The standing value is also used numerically as an array index elsewhere; it must not be normalized to a Boolean. See code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gm_1798.c#L68-L95.

`fn_80179990` is the common slot renderer; four wrappers supply slots 0–3. Its middle callback argument is unused. After successful camera activation, nonzero tiers capture immediately. They always capture `player_img2`, additionally capture `player_img1` when `x0_4` is clear, clear/copy the shared image, and bind either the child-model texture or cached-panel texture. Tier zero instead requires `ftLib_800876B4(...) == 0`, a clear per-player flag, and `x0_6`; it captures once and latches that slot. Capture origins preserve integer division and rounding expressions. The successful-camera path does not invariably call EndCurrent: an ineligible tier-zero branch falls through without it. The local signed-return declaration for `ftLib_800876B4` conflicts with its void definition, so animation completion remains an intended interpretation rather than a proven C return contract. See code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gm_1798.c#L97-L239 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftlib.c#L974-L977.

The four callbacks `fn_80179DCC` through `fn_80179F04` are identical: activate the attached camera, run standard composition, replace `gxlink_prios` with 0x80, dispatch mask 7, and flush deferred drawing. The dispatcher confirms group 7 and callback passes 0–2. EndCurrent sorts/displays the Z-list; it does not restore the priority mask. Failed camera activation skips the local success sequence, but activation itself can already have changed global camera state. See code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gm_1798.c#L241-L283, code://c302741689bd67c361cd7faadb221df3193992c3/src/sysdolphin/baselib/gobj.c#L158-L183 and code://c302741689bd67c361cd7faadb221df3193992c3/src/sysdolphin/baselib/cobj.c#L485-L525.

### References, allocation and evidence limits

`fn_80179F6C` unconditionally stores a placement-marker GObj pointer supplied by Results-model construction. `fn_80179F84` caches four direct child/sibling JObjs and sets `x0_4`. Neither performs ownership transfer, bounds checking, replacement cleanup or hierarchy validation. Rendering assumes valid material/texture chains. `fn_8017A004` loads and registers authored lights; the loader's empty-list case leaves its returned first pointer undefined. `fn_8017A9B4` clears two image pointers and allocates separately dimensioned buffers. Reinitialization is not local deallocation, and this unit does not establish the complete teardown lifetime. See code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gm_1798.c#L285-L315, code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gm_1798.c#L570-L594 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/lb/lbspdisplay.c#L286-L305.

Separate globals and ResultsDisplayLayout casts express source-level workspace usage, not proof of compiled contiguity or a 9,488-byte section. Likewise, packed constants and the MUST_MATCH ordering helper do not establish compiled section ordering. Rendered names were reviewed as hypotheses only; parse uncertainty, shadowed bindings, an invalid unchanged-name guess and a Stage_Init collision were preserved rather than used as evidence.
