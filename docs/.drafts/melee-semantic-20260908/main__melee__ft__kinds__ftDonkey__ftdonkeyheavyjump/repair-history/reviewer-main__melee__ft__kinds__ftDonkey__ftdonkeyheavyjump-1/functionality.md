## Heavy-item jump family

This unit defines three HeavyJump wrappers, a startup-entry routine, and a timer-driven animation callback. The header declares all five functions. Both owned files were independently read in canonical and rendered form; rendered names remain hypotheses, not independent evidence. The empty proposal is consistent with the evidence limits below.

### Startup and countdown

`ftDk_MS_348_800E04A4` obtains the Fighter and Donkey attributes, stores its second argument in `mv.dk.unk7.x4`, clears `x0`, and initializes `x8` from `cargo_hold.x24_JUMP_STARTUP_LAG`. It selects attribute motion-state base **+5**, with flags 0, starting frame 0, rate 1 and blend 0, then sets animation rate to 0. The reviewed caller obtains `ftCo_Jump_GetInput`, calls entry only for a nonzero result, and otherwise returns false. The entry itself does not validate the argument. See [entry](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftDonkey/ftdonkeyheavyjump.c#L26-L39) and [caller](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftDonkey/ftdonkeyheavyfall.c#L32-L41).

`ftDk_HeavyWait1_Anim` tests `x8 <= 0` before decrementing. A nonpositive value invokes `ftDk_MS_347_800E03C0`; a positive value skips that call. Both paths subsequently subtract one. The destination performs common setup, selects base **+7**, freezes animation, and invokes `ftCo_800CB110`. The decrement is therefore a post-transition write through the previously obtained Fighter pointer, not necessarily an isolated update to an untouched old-state timer. See [countdown](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftDonkey/ftdonkeyheavyjump.c#L41-L48) and [destination](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftDonkey/ftdonkeyheavyfall.c#L43-L53).

### Interrupt, physics and collision callbacks

- `ftDk_HeavyJump_IASA` forwards the object to `ftCo_80094EA4`. The selector rejects a missing held item. A/B presses select left-stick input; otherwise it examines C-stick input. Magnitude, angle and timing branches choose ordinary or smash-style HeavyThrow states, with an action-button fallback to forward throw. It transitions only when the selected motion differs from the current motion. The wrapper adds no other local behavior. See [wrapper](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftDonkey/ftdonkeyheavyjump.c#L11-L14) and [selector](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_ItemThrow.c#L57-L140).
- `ftDk_HeavyJump_Phys` delegates to `ftCo_Jump_Phys_Inner`. If `mv.co.jump.x4` is false, the helper sets it true and returns; otherwise it runs common airborne processing. The downstream routine checks fast fall, chooses fast-fall or gravity/terminal-velocity processing, then invokes horizontal processing. The reviewed evidence does not prove that the gate is false on every first HeavyJump callback. This qualification applies to purpose and data-flow descriptions as well as state behavior. See [wrapper](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftDonkey/ftdonkeyheavyjump.c#L16-L19), [gate](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_Jump.c#L192-L201), and [airborne processing](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_081B.c#L1363-L1375).
- `ftDk_HeavyJump_Coll` unconditionally delegates to HeavyFall collision. That routine supplies `ftDk_MS_346_800E05E4` to the common collision helper. The landing entry initializes the configured landing timer, enters base **+8**, and freezes animation. See [wrapper](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftDonkey/ftdonkeyheavyjump.c#L21-L24), [delegation](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftDonkey/ftdonkeyheavyfall.c#L27-L30), and [landing entry](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftDonkey/ftdonkeyheavywait1.c#L30-L39).

### Evidence limits

`ftDk_HeavyJump_Enter` remains a plausible inferred family name, not proof of the exact name or callback installation of base +5. Likewise, the rendered `HeavyFall_Enter` substitution cannot establish the numeric state's identity. Family-level retained descriptions must not be read as proving that startup and airborne callbacks are installed together. No compiled artifact was available to establish `.sdata2` contents, size, order, encoding, or references. Source constants alone do not prove those claims.
