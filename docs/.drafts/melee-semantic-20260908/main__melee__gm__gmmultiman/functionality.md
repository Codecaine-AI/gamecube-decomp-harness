# Target Test and Multi-Man mode controller

## State graphs and storage
This translation unit defines seven sentinel-terminated `GameModeState` arrays: Target Test, 10-Man, 100-Man, 3-Minute, 15-Minute, Endless, and Cruel. Each has CSS at state 0 and VS gameplay at state 1. Target Test has dedicated static CSS/start/exit payloads; all six Multi-Man variants share a second payload group. CSS uses the same object for enter and exit data, whereas gameplay receives `StartMeleeData` and produces `MatchExitInfo`. These are source-level storage and dispatch observations, not proof of compiled section placement or contiguity. The header declares the public callbacks and helpers without defining additional behavior. [Source](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gmmultiman.c#L17-L231), [header](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gmmultiman.h#L1-L46).

## Target Test
`gm_801B6320` returns a non-owning interior pointer to persistent Target selection storage. Initialization writes `0x21`, `0`, and `0x78`; loading snapshots the remembered controller byte and clears the CSS-entry byte. CSS entry conditionally performs card operations only when that entry byte is nonzero, initializes selection data, requests versus preloading, and replaces the byte with the time helper's result. CSS exit treats `pending_scene_change == 2` as a menu return; otherwise it commits character, color, and nametag and calls `gm_80168F88`. Gameplay entry copies CSS rules, configures a count-up timer, initializes one human, remaps selection `0xE` to `0x20`, derives the character-dependent stage, updates the preload request, and loads rumble settings. [Selection and setup](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gmmultiman.c#L233-L319), [lifecycle](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gmmultiman.c#L411-L423).

Target result handling calls the frame-count/standing accounting helpers **before** checking `OUTCOME_RETRY`. Retry selects state 1 and bypasses subsequent record processing. Otherwise, zero remaining targets updates completion bits and minimum clear-frame records; before the first clear, the alternate record can hold maximum partial progress. Clear handling can schedule a challenger, and the generic post-match predicate can also supersede the ordinary state-0 return. The persistent selection is additionally read by common match finalization outside this unit, so its lifetime is not confined to one callback. [Result branches](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gmmultiman.c#L321-L409), [external consumer](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gm_16AE.c#L1041-L1086).

## Shared Multi-Man setup
The registry installs the same init/load pair for all six variants. Initialization delegates to `gm_InitVsMode`; loading snapshots the controller byte, clears `gm_804D68F1`, and allocates card work. The latter byte has no subsequent use in the owned source. CSS entry wrappers pass match types `0x11` through `0x16` to a common helper. It establishes one stock and unit attack/defense ratios, initializes CSS selection data, requests `CKIND_BOY`, `CKIND_GIRL`, and stage `0x11D`, and invokes DVD reconciliation. These ratios are not geometric model scaling. CSS exit callbacks share the cancellation guard and selection-transfer helper. [Lifecycle and shared CSS](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gmmultiman.c#L425-L502), [registry](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gmscdata.c#L648-L695).

The common gameplay rule initializer installs team rules, stage `0x11D`, `rules.x2C = 0.5F`, and `gm_80182174` as the match-start callback. Player setup copies six persistent descriptors, reconstructs player zero as the human, assigns opposing teams to slots 1–5, and loads rumble settings. The 10-Man path does not clear opponents' `xC_b1`; 100-Man, timed, and Endless paths do. Timed variants override the timer to count down from 180 or 900. Endless and Cruel disable the timer and apply score-rule flags. Cruel additionally sets `rules.xB = -1`, enables opponents' `xD_b4`, and clears their `xC_b1`. [Shared rules and players](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gmmultiman.c#L504-L631), [timed variants](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gmmultiman.c#L847-L928), [score variants](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gmmultiman.c#L972-L1065).

## Records and exceptional routing
Multi-Man gameplay exits check retry **before** accounting and record updates. Non-retry does not imply a successful clear. Fixed-count modes import and save either `x4` or `x2` according to `x0_0`, using `0x0FFFFFFF` for the alternate initialized record slot. Timed modes seed presence from a nonzero persistent `u16` record and later save `x2` or zero according to the runtime flag; only the 15-Minute saver invokes the additional persistent-bit setter. Endless and Cruel import signed persistent records into runtime `x2`, then save `x2` back. `UnkMultimanData.x2` is `u16`, whereas `x4` is `int`: these widths and possible narrowing must not be erased by generic score terminology. Cruel exit also explicitly casts the selected character through `u8` and `s8` for its runtime lookup. [Fixed-count saving](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gmmultiman.c#L633-L764), [timed/score helpers](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gmmultiman.c#L792-L845), [runtime types](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/types.h#L36-L40), [Cruel exit](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gmmultiman.c#L1067-L1087).

`gm_801B688C` ignores its boolean argument and queries shared result state. It performs card operations, a guarded 15-Minute unlock check, common reward processing, a guarded 100-Man challenger branch, and a generic challenger fallback. Its true result means exceptional routing was selected, not that the attempt succeeded. The challenger request is copied into static storage owned by another unit. DVD preload requests likewise refer to persistent subsystem storage; reconciliation returns early for identical descriptions and otherwise manages resource cleanup and scheduling. No local card-work release or mode-specific unload callback is demonstrated here. [Post-match predicate](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gmmultiman.c#L437-L478), [challenger storage](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gm_1736.c#L16-L70), [DVD lifetime](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/lb/lbdvd.c#L474-L567).

## Naming and evidence limits
Rendered callback names generally describe roles independently established by canonical tables and bodies; their exact spellings remain hypotheses. Rendered external record-helper names must not establish gameplay units: canonical `RecordBlock.times` receives `x2`, while `RecordBlock.scores` receives `x4`, but external gameplay code assigns frame count to the fixed-count runtime `x4` and opponent progress to `x2`. Thus score/time-backed baseline wording is retained only as a description of storage paths, not a semantic unit assignment. Unknown rule bits, sentinels, and numeric state values remain explicit. No compiled artifacts were supplied, so seven section-layout/constant-placement facts and the `.sdata2` concept link remain unresolved.
