## Dolphin matrix implementation

This unit implements synchronous matrix operations over caller-owned `Mtx` storage: identity, copy, affine concatenation, linear transpose, inverse and inverse-transpose, Cartesian and arbitrary-axis rotations, translation and scale construction/application, quaternion conversion, reflection, camera viewing, and light-texture projection. Scalar C implementations coexist with paired-single implementations. The header defines `Mtx` as `f32[3][4]`; its general affine interpretation must not obscure the projective texture-coordinate interpretation of the light constructors.

### Data flow and exceptional paths

- `PSMTXConcat` computes `A × B`, including `A.linear * B.translation + A.translation`. It captures both inputs before output stores, allowing output to alias either input. `Unit01` is explicitly loaded here to contribute the affine translation term; identity construction instead uses local zero/one constants. Source does not prove either compiled data-section association. [Source](code://c302741689bd67c361cd7faadb221df3193992c3/extern/dolphin/src/dolphin/mtx/mtx.c#L10-L192)
- Copy uses interleaved paired loads/stores: exact self-copy is safe, but general partial-overlap semantics are not provided. Transpose rearranges only the nine linear coefficients and clears translation, with exact in-place operation supported. Inverse computes cofactors, refines a reciprocal estimate, and forms `-A^-1*t`; its equality failure branch returns zero before destination stores. Completion with return one is not a finiteness or conditioning guarantee. Inverse-transpose similarly clears translation and has its own determinant guard. [Source](code://c302741689bd67c361cd7faadb221df3193992c3/extern/dolphin/src/dolphin/mtx/mtx.c#L194-L483)
- `MTXRotRad` computes sine and cosine before dispatch through a configuration-dependent macro. Non-DEBUG dispatch uses `PSMTXRotTrig`, whose unsupported-axis path performs no matrix stores; DEBUG dispatch uses the C constructor with an invalid-axis assertion. Precomputed trigonometric values are not normalized or validated. Arbitrary-axis construction normalizes into a local vector, with PS matrix stores guarded by `__MWERKS__`. [Implementations](code://c302741689bd67c361cd7faadb221df3193992c3/extern/dolphin/src/dolphin/mtx/mtx.c#L485-L704), [aliases](code://c302741689bd67c361cd7faadb221df3193992c3/extern/dolphin/include/dolphin/mtx.h#L68-L113)
- Translation and scale constructors replace the complete destination. Translation application adds to the translation column; scale application scales entire rows, including translation. Quaternion conversion uses a squared-magnitude reciprocal rather than requiring a unit quaternion, but the PS implementation has no zero-quaternion guard. Reflection uses the supplied normal directly without normalizing it. [Source](code://c302741689bd67c361cd7faadb221df3193992c3/extern/dolphin/src/dolphin/mtx/mtx.c#L706-L922)
- Look-at constructs right/up/backward rows and negative eye-position dot products. `C_MTXLookAt` lacks the adjacent entry point's pointer assertions and has no local fallback for degenerate viewing vectors. Light frustum and perspective matrices produce a third coordinate of `-z`; orthographic light projection produces one. Perspective FOV is supplied in degrees. [Source](code://c302741689bd67c361cd7faadb221df3193992c3/extern/dolphin/src/dolphin/mtx/mtx.c#L924-L1072)

### Cross-file use and lifetime

Camera setup stores the look-at result in `cobj->view_mtx` and marks its inverse cache dirty. The inverse accessor lazily allocates persistent storage, invokes `PSMTXInverse`, and clears its dirty flag without checking the return value. Instance rendering likewise ignores inverse status before consuming its stack matrix. These caller behaviors must not be mistaken for guarantees supplied by the math primitive. [Camera setup](code://c302741689bd67c361cd7faadb221df3193992c3/src/sysdolphin/baselib/cobj.c#L469-L482), [inverse cache](code://c302741689bd67c361cd7faadb221df3193992c3/src/sysdolphin/baselib/cobj.c#L785-L795), [instance rendering](code://c302741689bd67c361cd7faadb221df3193992c3/src/sysdolphin/baselib/jobj.c#L567-L600)

Shadow rendering copies and synchronizes the image before rebuilding its texture matrix. A local light-projection matrix is composed with the shadow camera view and stored in `shadow->texture->mtx`; texture setup later combines that matrix with the active camera's inverse view. [Capture](code://c302741689bd67c361cd7faadb221df3193992c3/src/sysdolphin/baselib/shadow.c#L261-L278), [projection composition](code://c302741689bd67c361cd7faadb221df3193992c3/src/sysdolphin/baselib/shadow.c#L345-L381), [texture consumption](code://c302741689bd67c361cd7faadb221df3193992c3/src/sysdolphin/baselib/tobj.c#L467-L473)
