## Input selection and exceptional destinations

`ftCo_Attack1_CheckInput` first requires newly pressed A for action selection. With an item, class 0 selects LightThrowF before the L/R test. Otherwise held L/R selects LightThrowDrop; absent that selection, class 2 calls `ftCo_Attack_800CCF58(gobj, false)` and class 3 calls `ftCo_Attack_800CDD14`. Other item classes fall through to jab handling. The classifier is called again for the switch; this is not a single cached classification.

After item handling, a positive `hitlag_mul` together with `x2218_b1` selects a continuation switch: numeric state 44 dispatches `doAttack12`, and 45 dispatches `doAttack13`. An unmatched numeric state under this active guard does not fall back to Attack11: it reaches the false-return path. When the guard is inactive, newly pressed A dispatches `decideAttack11`. Only the false-return path conditionally decrements a positive countdown. Every selected path returns true without inspecting the void entry helper's outcome. Thus true denotes accepted dispatch, not guaranteed entry into a particular jab state. [Input selection](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_Attack1.c#L41-L81).

`decideAttack11` sends Game & Watch to his dedicated entry and other kinds to the common entry. The common entry offers pickup first. If pickup declines, it clears general interruption and the continuation gate, changes to Attack11, invokes `ftAnim_8006EBA4`, loads `jab_2_input_window`, records Attack11, and clears the rapid gate, local input latch and `x1A54`. Pikachu/Pichu install `onPkPc21EC` and request `Ft_MF_SkipAttackCount`. [Opening setup](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_Attack1.c#L83-L129).

`doAttack12` restarts the common Attack11 path for Pikachu/Pichu; other kinds attempt pickup-guarded Attack12. Normal Attack12 clears interruption and the continuation gate, changes state, loads `jab_3_input_window`, records Attack12 and clears the latch. It does not reproduce every explicit Attack11 reset. `doAttack13` routes FTKIND_MARS through the restart helper; other kinds attempt pickup-guarded Attack13. Its ordinary branch has no explicit next-window, prior-state or latch initialization after the state change. These are local-write observations, not claims that the shared state changer leaves all other fields untouched. The helper named `doAttack12Rapid` does not itself enter Attack100; its Game & Watch arm is not reached from the shown Pikachu/Pichu or MARS callers under a stable kind. [Second-stage paths](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_Attack1.c#L171-L209), [third-stage paths](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_Attack1.c#L258-L274).

## Continuation-window boundaries: source versus target runtime

Both continuation predicates test the countdown before subtracting one. Inside that positive-value block, newly pressed A sets `mv.co.attack1.x0` true. They do not copy a held-button state, clear the latch when A is absent, or require the post-decrement value to remain positive. The latch-and-`x2218_b1` test is outside the countdown block, so a previously buffered press can dispatch after the capture window ends. A value of 1 accepts input on its final positive tick while becoming zero; a value strictly between zero and one can become negative while still accepting input. There is no local clamp to zero. [Second-stage buffer](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_Attack1.c#L211-L226), [third-stage buffer](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_Attack1.c#L276-L290).

At the C comparison level, positive and negative zero, negative finite values and negative infinity do not enter a `> 0` block. NaN also does not satisfy `> 0`; this statement describes the comparison result, not an absence of floating-point exceptions. These values therefore do not cause a new capture or subtraction in those source blocks, although an existing latch can still pass the separate continuation gate. Positive infinity satisfies the comparison and remains infinite after subtracting one. Sufficiently large positive finite values may round back to the same stored value after subtraction, so a positive value does not imply eventual expiration. Concrete rounding behavior and reachable attribute values are not established here.

For the outer input predicate, source-level nonpositive values or NaN make the continuation conjunction false: newly pressed A that survives item handling selects the opening path. Without an accepted action, its final subtraction also requires `> 0`. Positive infinity and large finite values have the same potential non-expiring subtraction behavior on that false-return path. Successful dispatch returns before that subtraction. [Outer comparisons](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_Attack1.c#L63-L80).

The inherited research separately reports the supplied `assembly-evidence.s`: outer guards use `fcmpo cr0, f1, f0` followed by `ble` at 0x8008AAB8/0x8008AABC and 0x8008AB20/0x8008AB24, followed on the decrement path by `fsubs` and `stfs`. This lead does not claim an independent compiled-evidence inspection or infer target NaN equivalence from that report, the C spelling, or the branch mnemonic. A target-runtime conclusion requires resolving unordered condition-register results, the branch's actual condition-bit test, and floating-exception configuration/handling, including signaling versus quiet NaNs. Those runtime details remain explicitly unresolved. No claim is made that exceptional values occur in normal character data.

## Arbitration and cross-file lifetimes

Attack11 and Attack12 IASA first try side/up/down smash and side/up/down tilt when `allow_interrupt` is set. If not already consumed, they try `ftCo_Attack_800D6A50`, then the respective buffered continuation. Finally, if interruption is allowed, they try jump, dash, `ftCo_800D5FB0`, turn and walk. Every successful predicate stops the chain. Attack13 instead gives the rapid-attack helper first priority, then calls Wait IASA only when it declines and interruption is allowed. General interrupt permission and combo permission are distinct. [Rapid helper](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_Attack100.c#L116-L162). ## Completion, physics and collision

All three animation callbacks call `ft_8008A2BC` only when no frames remain. The inherited contextual research identifies special Master Hand and Crazy Hand routes in that shared helper; ordinary handling has DownSpot and another condition-specific early path before its usual Wait transition, plus character-specific work. Completion must not be reduced to unconditional Wait. [Completion selector](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_08A1.c#L54-L109).

Attack11 physics delegates to `ft_80084FA8`. It obtains ground friction and multiplies it by `friction_when_above_walk_speed` only when the absolute ground-speed value is strictly greater than `walk_max_vel`; equality does not select that multiplier. The subsequent helper either sets `xE4_ground_accel_1` to animation translation Z times facing direction minus ground velocity, or delegates friction handling, then calls `ftCommon_ApplyGroundMovement`. The source does not establish that the above-walk multiplier exceeds one. [Physics selection](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_084E.c#L55-L89).

Ground movement obtains a separate ground-friction multiplier. Only when that value is strictly less than one does it multiply `xE4_ground_accel_1`; equality and greater values do not select the branch. At the source-comparison level NaN also fails this test. This optional scaling affects both animation-derived and friction-derived acceleration because both paths converge here. It precedes projection of acceleration into `x74_anim_vel` and ground velocity into `self_vel` along the floor tangent; both Z components become zero. This routine projects velocity components rather than directly updating position. The surface multiplier must not be conflated with the above-walk-speed factor, and neither implies a concrete magnitude or universal braking behavior. Popo and Nana receive a multiplier of exactly one from the getter; other kinds delegate to collision data. [Surface branch and projection](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftcommon.c#L133-L152), [getter](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_081B.c#L1235-L1241).

Attack11 collision delegates to `ft_80084104`. The inherited collision analysis establishes that the underlying check synchronizes fighter position with CollData around `mpColl_8004B2DC`, and a false result enters Fall. [Position flow](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_081B.c#L406-L424), [Fall guard](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_081B.c#L1043-L1050).
