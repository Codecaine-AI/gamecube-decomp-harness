# HammerWalk translation unit

## Identity and entry
The owned implementation defines an exported boolean transition wrapper, an internally linked entry routine, and four exported action callbacks. The prior static declaration establishes `ftCo_800C5614`'s internal linkage. `ftCo_HammerWalk_CheckInput` and `ftCo_HammerWalk_Enter` are inferred aliases, not recovered canonical names. Rendered external aliases likewise cannot establish helper behavior. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_HammerWalk.c#L16-L70.

`ftCo_800C55CC` invokes entry and returns true when the shared walking guard accepts; otherwise it returns false without a local mutation. The inherited research establishes the guard as `lstick.x * facing_dir >= walk_stick_threshold`, including equality. HammerWait tests walking after jump, platform pass and turn. This wrapper is therefore a transition, not a pure predicate. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_HammerWalk.c#L18-L25; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftwalkcommon.c#L58-L69; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_HammerWait.c#L86-L92.

Entry resolves the Fighter, writes `walk.accel_mul` to one or the scale-helper result, and snapshots `gr_vel` into `walk.x0`. Only those two fields are explicitly initialized. It obtains shared Hammer flags and start frame, calls `Fighter_ChangeMotionState(gobj, ftCo_MS_HammerWalk, flags, shared_start_frame, 1, 0, NULL)`, then `ftAnim_8006EBA4(gobj)` and `ftCo_800C4E94(fp)`. Shared parameter helpers preserve frame and selected flags within the inclusive HammerWait–HammerLanding range; outside it they return zero frame and no flags. Shared setup includes a numeric-106 helper path and item operations whose full gameplay semantics are not assigned here. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_HammerWalk.c#L27-L48; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_HammerWait.c#L172-L208; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_HammerWait.c#L41-L46.

## Callbacks
The active motion table separately registers Anim, IASA, Phys and Coll with HammerMove animation and the Hammer move ID. Registration does not prove engine scheduling. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftmotionstates.c#L3522-L3532.

* Anim forwards once to `ftCo_800C4F64`. Inherited research preserves that helper's `x2338.x != 0` branch and its alternative half-open animation-frame window; it is not an unconditional item operation. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_HammerWait.c#L62-L79.
* IASA checks `ftCo_800C5A50`, `ftCo_800C60C8`, then `ftCo_800C4E4C`, returning immediately after an accepted check. These represent jump startup, platform pass, and stopping walking. The rendered HammerFall CheckInput alias must not be generalized into a falling-input predicate. The inherited platform predicate accepts downward-threshold equality, rejects tilt-timer equality, and requires platform contact. Stopping accepts opposite-facing input or magnitude strictly below the walking threshold. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_HammerWalk.c#L55-L60; code://c302741689bd67c361cd7faadb221df3193992c3/src/Runtime/platform.h#L164-L169; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_0C60.c#L8-L22; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_Pass.c#L26-L36; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_HammerWait.c#L32-L60.
* Phys forwards to `ftWalkCommon_800E0060`. It consumes accel_mul for both acceleration and target velocity, using a negative base-acceleration branch at zero stick. A nonzero target permits the velocity ratio; tapering requires a ratio strictly between zero and one. It overwrites x0 with target velocity times x440 before invoking common velocity/friction and ground movement. It does not read the entry-time x0 snapshot. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftwalkcommon.c#L172-L214.
* Coll forwards to HammerWait collision handling. Inherited research establishes a synchronous conditional callback to HammerFall entry, rather than retention of the callback pointer. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_HammerWalk.c#L67-L70; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_HammerWait.c#L99-L102; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_081B.c#L1035-L1041; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_HammerFall.c#L26-L38.

## Exceptional behavior and evidence boundaries
Scale exactly one bypasses the helper and coefficient read. Otherwise the helper asserts nonzero scale, returns its base for zero coefficient, recursively forms a reciprocal for negative coefficients, uses `(scale-1)*base*coefficient+base` when scale is at least one or coefficient at most one, and otherwise uses `base*scale/coefficient`. Negative values, infinities and NaNs are not sanitized. Zero scale reaches the assertion even with coefficient zero; reciprocal branches can divide by zero. Assertion configuration, floating traps and exceptional-input reachability remain unresolved. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftchangeparam.c#L9-L22.

With ordinary finite normalized facing and positive thresholds, horizontal equality starts or continues walking. Start and stop predicates are not general logical complements for exceptional values: NaN horizontal input makes their ordered comparisons false. Physics skips its ratio for signed-zero target, not NaN target.

The wrappers do not locally allocate, free, retain or transfer their object parameter. They assume a live fighter and valid downstream shared/item state, without local null, item-kind, groundedness or finite-value validation. Complete object lifetime across motion changes and engine callback scheduling remain outside this evidence. The motion call's NULL argument, numeric 106 and unknown flag bits retain their uncertainty.

No compiled evidence establishes .sdata2 size, ordering, representation, source-to-pool attribution or read-only placement. Register-r3 attribution and compiled object layout are likewise not promoted. The source comment suggesting inlining is a decompilation hypothesis, not proof.
