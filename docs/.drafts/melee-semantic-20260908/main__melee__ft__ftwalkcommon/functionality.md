## Classification, input and entry
The public GetWalkType and private inline classifier use ABS(gr_vel), testing the inclusive fast threshold before the inclusive middle threshold, otherwise selecting Slow. Threshold grouping is accel_mul * (common threshold * walk_max_vel). No ordering or finite-positive tuning is enforced. Zero multiplier can select Fast at zero speed under ordinary finite tuning; NaN speed falls through to Slow. Input checking is only stick-x * facing_dir >= walk_stick_threshold: it does not establish groundedness or action eligibility. Ordinary teeter walking adds its own threshold.

Entry stores accel_mul before classification, changes to caller base + tier with animation arguments anim_start, 1, 0, 0, calls ftAnim_8006EBA4, then snapshots gr_vel into walk.x0 and stores the base, three destination spans and three rate denominators. The setup helper dispatches four helpers, not merely an animation advance. The Fighter pointer must remain usable across these external calls. ## Animation rate
The rate routine selects walk.x0 when ground-friction multiplier < 1, otherwise gr_vel. If basis * facing_dir <= 0 it requests zero; otherwise it divides ABS(basis) by the active tier denominator. The switch has no default, so invalid motion offsets on the else path can leave anim_rate uninitialized. Denominator sign, zero and exceptional floats are unchecked. An unordered facing comparison enters the else path rather than the zero-rate path. ftAnim_SetAnimRate caches the request in x8A0_unk when x2223_b0 is set; otherwise it updates skeleton rates and frame_speed_mul. Thus neither actual-motion synchronization nor immediate playback change is unconditional. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftwalkcommon.c#L99-L128; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftanim.c#L490-L513.

## Tier changes and callback lifetime
If desired base + tier equals motion_id, the update routine does nothing further. Otherwise it selects destination span D and obtains animation end frame E from the object or blend skeleton. For current frame C, it computes q=(s32)(C/E), then destination=(s32)(D*((C-E*q)/E)). It converts the integer destination to float for a synchronous callback invocation with the same object. This is integer-quantized approximate phase transfer, not exact preservation or guaranteed visual seamlessness. Exact positive cycle boundaries map to zero under valid arithmetic; negative frames are not floor-modulo normalized. Zero/nonfinite E and unrepresentable conversions are unguarded.

The callback is invoked at most once, is not retained and is not null-checked. A null callback is harmless only when the equality guard suppresses invocation. The helper does not use fp after the callback. Its default branch reports an error and invokes HSD_ASSERT(71,0), but valid classifier outputs with valid motion arithmetic select the three normal cases. Compiled assertion behavior is not established. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftwalkcommon.c#L130-L170; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftanim.c#L573-L581.

## Physics and cache lifetime
Acceleration is stick-x * walk_accel_mul * accel_mul plus a signed base acceleration. The positive base branch requires stick-x > 0; zero and unordered comparisons use the negative branch. Target velocity is stick-x * walk_max_vel * accel_mul. A truthy target permits ratio calculation; taper applies only when 0 < gr_vel/target < 1, multiplying by (1-ratio) * walk_accel_taper_gain. Gain is not constrained and need not reduce acceleration for arbitrary tuning. NaN targets pass the truth test, but NaN ratios fail the taper comparisons.

Physics always refreshes walk.x0 with target * x440, then calls ftCommon_8007C98C and ftCommon_ApplyGroundMovement. Thus the cache changes from an entry-time actual velocity snapshot to a scaled intended target. A zero target makes the downstream helper discard acceleration and apply friction, so the negative base branch at zero stick does not itself imply backward acceleration. Nonzero targets receive directional, overshoot, friction and conditional maximum-velocity handling. ApplyGroundMovement scales pending acceleration below unit friction multiplier and prepares floor-tangent acceleration and velocity vectors with zero z components; it does not integrate position or update gr_vel. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftwalkcommon.c#L172-L214; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftcommon.c#L51-L97; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftcommon.c#L133-L152.

## Consumers and ownership
Ordinary Walk, CargoWalk and Donkey HeavyWalk delegate animation and physics and supply action-specific entry callbacks after interruption checks. Ordinary entry adjusts its initial unit multiplier for metal, nonunit Y scale and a nonnull x197C. CargoWalk entry additionally synchronizes victim state through ftCo_8009C5A4 using public GetWalkType plus ftCo_MS_ShoulderedWait; the intended state-table mapping remains a family follow-up. Collision behavior remains outside this TU. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_Walk.c#L30-L114; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_CargoWalk.c#L16-L59; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftDonkey/ftdonkeyheavywalk.c#L14-L56.

The TU borrows objects/configuration and mutates existing Fighter storage; it allocates, frees and retains no objects or callbacks. Valid Fighter-backed objects, initialized metadata and usable animation spans are preconditions. No general destruction or reentrancy guarantee is established across external calls, and no register-to-parameter ABI mapping is inferred from #r labels.
