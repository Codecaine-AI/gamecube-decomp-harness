## Single-Button mode controller

The unit declares nine `GameModeState` array elements: eight populated descriptors and a `{ -1 }` terminator. Primary identifiers 0–4 register CSS, SSS, VS, Sudden Death and Results respectively. Auxiliary identifiers 0x80, 0x81 and 0xC0 register Approach, Approach VS and Prize Interface. Approach has no exit callback; Results and Prize have null exit-data pointers. The primary descriptors use category value 3 and auxiliary descriptors use 2; these numeric fields are not assigned additional semantics here. [Registry](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gmsinglebutton.c#L15-L113).

The local scene callbacks are thin adapters to shared Versus helpers. Selection and match-building adapters use `gmMainLib_804D3EE0->modes.unk_BD0` as persistent `VsModeData`. CSS entry passes match-type value 8. SSS exit passes cancellation identifier 0. Normal battle exit passes Results identifier 4 and Sudden Death identifier 3. Results exit passes default identifier 0. Both battle builders receive `fn_801BA1B4` and a null per-player callback. The modifier unconditionally sets the first `StartMeleeData` argument's `rules.single_button` to true and ignores its second argument; it does not directly implement input filtering. OnInit delegates initialization of the persistent record; OnLoad resets shared KO counts. [Complete adapters](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gmsinglebutton.c#L115-L185).

## Shared behavior and lifetimes

CSS entry copies persistent settings into its payload and exposes the shared KO-count array. CSS cancellation (`CSSPendingSceneChange_2`) requests GM_MENU and returns without committing selection; otherwise it copies the selection back and prepares character audio. SSS confirmation commits settings and prepares stage audio; cancellation explicitly selects state 0. Normal battle construction copies rules, applies stock/VS settings, invokes the mode modifier, copies players, and performs common setup. Its exit accounts for human participants and chooses state 4 when there are zero or one winners, or state 3 when there are multiple winners—not simply success versus failure. [Shared selection and VS implementation](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gmvsmelee.c#L107-L233).

Sudden Death reconstructs the shared start payload from persistent settings, invokes the same modifier, copies players and uses the retained ordinary-VS match end for Sudden Death setup. Its exit passes the Sudden Death outcome and retained VS outcome to `gm_80166CCC`; Results entry initializes its payload and copies the retained VS match end. Thus the ordinary exit record survives the intervening Sudden Death scene. [Sudden Death and Results](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gmvsmelee.c#L235-L275).

Results exit is not an unconditional return to CSS. The shared helper skips two processing calls for canceled matches but still updates human KO counts. With human participation and a nonterminal following descriptor, it can initialize challenger or prize data, select symbolic Approach or Prize states, archive and return early. Otherwise it archives and selects the caller's default state 0. Literal 328, unknown helper results and the precise numeric values of the symbolic auxiliary destinations remain uninterpreted here. [Exceptional Results paths](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gmvsmelee.c#L277-L344).
