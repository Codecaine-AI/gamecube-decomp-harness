# Capsule semantic review

The implementation defines seven indexed item states: **0 resting, 1 ordinary falling, 2 held, 3 thrown, 4 dropped, 5 alternate explosive break, and 6 entered-air terrain classification**. State indices are distinct from animation identifiers: the rows use identifiers `-1, -1, -1, 0, 0, 1, -1`. States 1 and 4 share their callback triplet; state 3 shares their animation callback but supplies different physics and collision callbacks. The header declares the public callbacks and state table; the source also contains a private damage-helper wrapper.

Spawn clears Capsule-local `x0` and `x4`, then selects state 1. Resting setup clears all velocity components and selects state 0. Pickup selects state 2 with transition argument 2. Because its animation identifier is **-1**, the common transition removes animations and clears the script rather than loading an associated held animation. Drop and throw select states 4 and 3 with argument 6.

Ordinary airborne physics passes the configured fall acceleration and maximum-fall threshold to `it_80272860`. That helper tests the current velocity before subtracting acceleration; it does not clamp the resulting velocity exactly to the threshold. Thrown physics additionally computes spin through `it_80274658` using common attribute `x68_float`.

Grounded collision delegates to `it_8026D62C`: loss of support selects state 1. Its supported-floor path also retains the shared helper's exceptional `Item_8026ADC0` branch. Falling/dropped landing uses `it_8026E15C`, whose nested floor-contact guards must succeed before resting setup runs. Thrown collision uses `it_8026E414`: bits `0xE` receive separate collision processing, while bit 1 invokes the Capsule break resolver. The wrapper returns stored `x0` even if no resolver invocation occurs.

Break resolution first attempts `it_8026F8B4`. Its mode-gated downstream path emits kind `It_Kind_Unk4`, with coin-range and denomination-budget handling in `it_2E5A.c`; this is not an Adventure-enemy selector. A true result bypasses the ordinary explosion roll and sets `x0=true`. Otherwise, `HSD_Randi(attr->x4)==0` invokes guarded explosion setup and sets `x0=false`; a nonzero result calls the ordinary item-emission helper with count `attr->x0` and sets `x0=true`. The ordinary helper can stop early or fail individual allocations, and its return value is ignored here. Consequently, `x0=true` does not prove that an ordinary item was successfully created. Neither the fixed count one nor an unconditional one-in-eight probability is established by these runtime attribute reads.

Explosion setup hides the model, sets animation speed to 1, sets `x4`, calls common item/hitbox setup helpers, initializes a shared lifetime, and selects state 5. `it_80272C08` separately emits visual effect `0x410` and sound. The call to `lb_800119DC` copies the current position into a type-2 dynamics descriptor: `0x78` is its count argument, not a smoke-effect identifier. The wrapper `it_8027D2DC` tests `x4`; direct setup itself has no such guard. State 5's animation callback decrements the shared lifetime and returns true at expiration, which the common item dispatcher consumes for destruction. Its physics and terrain-collision callbacks are inert.

Damage-dealt, damage-received, clank and reflection processing skip the resolver in state 5 and return existing `x0`. HitShield resolves only state 3. ShieldBounced delegates rebound only in states 3 or 4 and always returns false. These are distinct event contracts.

EnteredAir selects state 6, with inert animation/physics and terrain classification through `it_8026E8C4`. No floor selects state 1; supported terrain selects state 0 only when the helper's contact guard permits it. Renaming its animation callback to **EnteredAir_Anim** avoids confusing it with the ordinary falling callback family. EvtUnk forwards its two object pointers unchanged; its visible triggering event is not established by this wrapper.

Both owned files were read completely in canonical and rendered form. Rendering reported no parse errors; substitutions were function-name hypotheses only. Supported existing names and explanations were explicitly retained. Corrections address held-state animation handling, the special-emission mapping, dynamics-versus-smoke interpretation, fixed-probability overstatement, and the ambiguous state-6 name. Source literals and initializers do not prove compiled section layout; the affected layout/pool facts remain unresolved.
