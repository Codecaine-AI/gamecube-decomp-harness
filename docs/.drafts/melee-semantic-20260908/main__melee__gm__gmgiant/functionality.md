## Giant Melee controller

`gmgiant.c` defines Giant Melee's source-level `GameModeState[]` and thin adapters to shared Versus helpers. The eight populated descriptors comprise IDs 0–4 for CSS, SSS, ordinary VS, Sudden Death and Results; IDs 0x80, 0x81 and 0xC0 provide Approach, Approach VS and Prize Interface routes. A `{ -1 }` initializer terminates the array. Primary descriptors use preload value 3, auxiliary descriptors use 2, and all populated flags are zero. Approach has no exit callback; Results and Prize have null exit-data pointers. These are source declarations, not compiled section/layout findings. ### Selection and persistent configuration

The wrappers consistently select `gmMainLib_804D3EE0->modes.unk_F90` as Giant's persistent `VsModeData`. CSS entry supplies match type 4; the shared helper copies configuration into CSS data, attaches shared KO storage and prepares the preload cache. CSS cancellation (`CSSPendingSceneChange_2`) requests `GM_MENU` and returns before committing configuration or preparing fighter audio. SSS entry copies configuration into its payload; confirmed exit copies it back and prepares stage audio, while cancellation requests state 0, locally CSS. ### Giant player preset and battle lifetime

`fn_801B9060` unconditionally assigns `model_scale = 1.8f`, `defense_ratio = 1.0f`, `attack_ratio = 1.5f`, and `xB = 2` through its first `PlayerInitData*`; its second pointer is unused. Both ordinary and Sudden Death entry supply this callback and a null whole-match callback. Shared constructors copy player records before applying the callback across `GM_MAX_PLAYERS`, without a participation guard in those loops. The preset modifies copied match records, not the persistent source records through this callback. The meaning of `xB = 2` remains unresolved. [Preset and registration](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gmgiant.c#L130-L153), [constructors](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gmvsmelee.c#L171-L262)

Normal VS exit delegates human-player accounting and next-state selection with IDs 4 and 3. The shared multiple-winner test selects Results for its false branch, documented as one or zero winners, and Sudden Death otherwise. Sudden Death setup consumes the preceding ordinary battle's `MatchEnd`; its exit submits both preceding and tiebreaker records to `gm_80166CCC`. Results entry subsequently copies the ordinary exit-info record into its presentation payload. Thus the shared ordinary result survives across the tiebreaker and results phases; no local Sudden Death exit transition is asserted. ### Results and lifecycle

Results exit supplies persistent Giant configuration and fallback state 0. The shared finalizer skips two accounting calls for canceled matches but still updates KO counts. Challenger/prize checks require a human participant and a following non-terminating descriptor. Three ordered challenger checks can select Approach; Prize is considered only when no challenger was selected. Special routes perform archive setup before returning; otherwise archive setup precedes fallback selection. These exceptional routes must not be reduced to an unconditional Results-to-CSS edge. [Results adapter](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gmgiant.c#L165-L168), [finalizer](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gmvsmelee.c#L277-L344)

The global registry separately installs Giant's parameterless OnInit and OnLoad callbacks. OnInit forwards persistent settings to `gm_InitVsMode`; OnLoad calls `gmVsMelee_ResetKOCounts`, which clears the complete shared array. Shared KO storage is exposed to CSS and updated from human-player standings, but its precise KO Star UI interpretation was not independently established here. The header declares all thirteen functions consistently with their definitions.
