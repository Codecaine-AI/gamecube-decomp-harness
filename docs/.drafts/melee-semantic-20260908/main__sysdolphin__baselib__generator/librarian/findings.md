## Lists, lifetime and ownership

Allocation zeroes storage, increments manager counters and publishes to the active list before resource configuration. Empty list gets a head; no cursor or terminal cursor inserts after existing head; otherwise insertion is after cursor->next. This supports traversal-sensitive publication, not general append-at-tail. IDs start0x100, first issued0x101 and wrap0xFFFF to0x100; initialization does not reset them and uniqueness across wrap is not guaranteed. Reset clears globals and allocator without walking existing ownership.

Retirement first deletes owned particles only for type0x80. Nonzero child count or the exact attachment/SRT owner condition with usedCount!=1 defers by random0/genLife1. This includes malformed count0, not just sharing>1. Other paths unlink, remove SRT, unref JObj, free and decrement live count. RemoveByJObj and RemoveJObjAll merely request retirement; both can leave matched nodes attached. Hierarchy traversal stops below flag0x1000 but still attempts cleanup at that node. JObjCallback accepts NULL as an identity, so can target unattached generators; it adds shutdown0x80 only with AppSRT and type0x100.

The F6CC static callback path also puts generators in a separate one-shot JObj-bake queue. Manager drains it before link/kind masks, calls D71C, frees queue node and clears the retained joint. The generator remains in the active list. eflib comments calling the queue persistent are stale. Queue allocation asserts; no local rollback if it fails. Active-pass filters freeze count/lifetime but cannot prevent queued detachment earlier in the pass. Positive lifetime decrements after emission; zero is unlimited; expiry may defer. Negative random adds its magnitude deterministically; nonnegative random multiplies Randf in[0,1).

## Geometry and emission

D214 syncs selected translation/scale only. D71C additionally normalizes each matrix column before multiplying velocity and uses raw3x3 for line offset. Normalized columns do not remove shear, may fail on zero columns, and do not guarantee a pure rotation. DAD4 uses the same independent normalization for eligible JObj basis; its actual kind exclusion is0x30000, despite comment0x3C000. Billboard construction normalizes look/up then takes two unnormalized crosses, so lateral scale depends on angle. It ignores the camera-up accessor result and has no degenerate-basis guard.

DAD4 consumes attempts, not successful creations: the void particle wrapper discards an allocator failure. Unknown shapes without a callback still decrement. The normal residual is fractional for finite modest nonnegative count, but negative/NaN can return unchanged and very large float values can stop decreasing by1. No local callback contract prevents count/list mutation or reentrancy. Negative-angle stepping uses truncated initial count and increments phase before each radial/tornado dispatch; sphere ignores that phase and draws its own random azimuth.

Shapes0/3/4/6/7 choose fixed radius for negative radius or sampled radius otherwise;3/4 use sqrt(sample),3 also scales speed by radius factor.6 tapers XY by1-randomZ and uses cone height,7 uses cylinder-like height without taper.1 samples line offset and full velocity.2 passes tornado encoding with kind|4, zero position, azimuth/radial fraction in velocity slots and extracted angles in trailing physical slots, saving speed in aux offset0.5 samples centered rectangular coordinates, optionally snaps selected faces, transforms by aux3x3 and emits along aux Z at base speed; weighting denominators and zero Z length are unguarded.

Shape8 samples polar angle via sqrt(random), optionally mirrors across pi, and samples azimuth independently. Positive radius uses sqrt(random), so no uniform-volume/sphere-area guarantee follows. The aux union makes cone.height equal sphere.latRange and rect.x equal sphere.speed; the emitter does not read stored sphere latMid/lonMid/lonRange. Negative range flips speed in constructor. Radius0 plus negative speed executes0/0 in radial speed scaling. These are literal behaviors, not a corrected geometry model.
