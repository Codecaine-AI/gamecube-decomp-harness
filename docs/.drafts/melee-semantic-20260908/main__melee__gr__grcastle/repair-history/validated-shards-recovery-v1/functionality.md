# grcastle Functionality

Full canonical/rendered review: C2031/H90, 75 function targets, five compiled sections, 181 subjects and455 inherited facts. Zero renderer parse errors.

## Independent systems

Three switch satellites18–20 attach to random castle joints and activate geometry17/7/5. They flash before becoming touch/damage proxies, trigger linked geometry, then hide after that geometry becomes idle. Inherited Banzai Bill aliases for these actors are wrong. The independent Bill scheduler selects nine routes8–16 using three-entry exclusion history, spawns child2, and later creates explosion1 and rearms its parent.

Platform controller6 consumes collision load on joints4/5; timer guards test old values before transitions. Controller3 owns the two schedulers and12 optional dynamics descriptors. Dynamics setup requires three exports but the four constant descriptors all use type6. Wind direction update and per-descriptor scale resampling are distinct operations.

Geometry arrays have five slots per controller, with sparse map-specific entries; they are not five guaranteed global item blocks. Reveal completion returns false on the visit reaching full scale. Failed route creation disarms its parent. Failed satellite allocation is not filtered out of weighted choice. These are source preconditions, not runtime-failure assertions.

Two GrJoint records, stage descriptor, typed parameters throughx140, two pointer caches, blink/weight/target/callback/offset constants and wind mode/step were read. Exact section placement and padding remain unresolved.

Header has90 lines, forward includes, placeholder callback declarations, external descriptor and function declarations; CF750 is defined before local use without a public header declaration. Source demo bool differs from shared slot int. Empty callbacks and wider registration casts need item-owner ABI evidence. The blink initializer is s16[19] but code reads s8 bytes; do not describe it as19 abstract delay entries. MUST_MATCH order helper preserves a0.5 literal.
