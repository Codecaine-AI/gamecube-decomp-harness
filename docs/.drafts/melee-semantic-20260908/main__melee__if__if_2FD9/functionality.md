## Magnifying-glass horizontal arrow pool

This unit owns four retained UI GObjs for player-colored horizontal screen-edge arrows. The magnifier's render callback supplies direction 1 for its left boundary and 2 for its right boundary, or releases the player's request when no horizontal indicator is needed. Existing rendered names Hide, Show, Request, Draw, Update, Init and Free fit canonical behavior; they remain inferred names, not recovered original spellings. Both owned rendered files were complete and reported no parse errors.

### Requests and release

`un_802FD928` rejects slots >=4, excludes CPU slots, and selects the first direction-zero entry only if the player's registration flag is clear. It copies owner, direction and GXColor into separate arrays. This is allocation, not refresh: subsequent requests for an already registered player do not change its side or color. The CPU exclusion is not a positive human-only test. Direction is not validated: zero can set registration while leaving the entry available, and values above 2 occupy an entry without selecting a normal transform branch. The color pointer is dereferenced only on successful allocation, with no NULL check. [Request/release source](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/if/if_2FD9.c#L51-L92).

`un_802FD9D8` scans every owner entry, regardless of direction, and clears registration and direction for every match. It preserves owner and color and does not destroy objects. Unlike request, release has no slot bound. The magnifier creates six entries and derives the slot from its player-array element, so releases can receive 4 or 5. Under the source-visible ownership invariant, those slots cannot match an owner: successful requests write only 0..3 and initial static owners are zero. Thus this is not evidence of an unconditional out-of-bounds write in normal use; the indexed write is conditional on owner equality. [Caller](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/if/ifmagnify.c#L178-L238), [six-entry construction](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/if/ifmagnify.c#L596-L610).

### Update, visibility and audio

Each GObj carries a pointer to a static index byte, not a player-slot pointer. Update resets Z to zero and copies its indexed RGBA color into three materials. State 0 moves the root to Z=10000. State 1 uses X=-25 and zero Z rotation; state 2 uses X=25 and approximately pi rotation. Same-side entries are ordered by pool index and centered vertically with 2.6-unit spacing. Other byte values have no switch case: they retain prior X/Y/rotation after the initial Z reset and recoloring. Animation is evaluated unconditionally. [Update](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/if/if_2FD9.c#L101-L190).

All-zero directions reset the shared sound owner to -1 and counter to zero. A normal active branch selects an owner if none exists; this selection invocation does not advance the counter. Subsequent invocations advance modulo 51 only when the selected owner's current direction matches that branch. Sound 4 is submitted at counter zero when the initialization-time suppression byte is clear. Multiple same-side entries can advance the shared counter, so this is not inherently a 51-frame period. Releasing the owner while another entry remains active can stall cadence until ownership becomes useful again or all entries become inactive.

Hide/Show modify only a separate draw latch. Draw forwards the original GObj and pass only when that latch is zero; local request state and update behavior are not cleared by these setters. Coordinated HUD dispatchers invoke the setters, including accepted pause/unpause paths. [Latch](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/if/if_2FD9.c#L38-L99), [HUD dispatch](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/if/ifall.c#L37-L57), [pause paths](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gm_16AE.c#L1102-L1218).

### Lifetime and evidence limits

Initialization resolves `Stc_rarwmdls` from the shared IfAll archive, creates four JObj-backed GObjs, installs callbacks and stable index pointers, and evaluates animation frame zero. It clears registration and direction, but not owner or color arrays. It resets sound owner/counter, samples `gm_8016B124()` into the suppression byte, and enables drawing. No allocation-failure handling or repeated-initialization cleanup is present locally. Teardown requests destruction for non-NULL retained pointers and immediately clears them, leaving other state untouched. Aggregate HUD teardown calls it twice; pointer-table idempotence accommodates this. Physical destruction may be deferred by the engine.
