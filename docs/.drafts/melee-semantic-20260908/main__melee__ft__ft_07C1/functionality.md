## Held-Hammer cleanup
`ft_8007C114` conditionally dispatches for a non-null held Hammer and always clears `x2219_b4`, including the no-item and other-item branches. Motion-state entry invokes it when `Ft_MF_SkipHit` is absent and the flag is set. The delegated Hammer helper passes false to `it_8026C16C`, selecting `it_802725D4` regardless of the timer branch; that operation disables four item hitboxes and clears associated flags. The adjacent Hammer helper can set the cleanup flag again. This is separate from thrown-capsule maintenance.

## Capsule initialization and geometry lifetime
`ft_8007C17C` initializes the embedded `x1064_thrownHitbox`, clears victim tables through `lbColl_80008440`, selects its joint and scale from fighter data, zeros its local offset and clears collision flags. It clears the separate fighter participation flag `x2227_b2`. Its immediate call to `ft_8007C224` seeds both position endpoints and advances Enabled to Unk2; initialization therefore does not leave the capsule in Enabled or enable pair participation.

`ft_8007C224` leaves Disabled and unhandled states unchanged. Enabled samples `x4C`, copies it to `x58` and becomes Unk2. Unk2 becomes Unk3 and intentionally falls through: old `x4C` becomes `x58`, then a new position is sampled into `x4C`. Unk3 performs that same history update. These are successive update samples, not a guarantee of updates on every frame: the recurring caller has a guard. The transform helper also accepts a null joint and copies the supplied offset, so a non-null joint is not an unconditional API requirement.

## Pair selection and response
`ft_8007C4BC` rejects a source lacking `x2227_b2`, returning collision status 2, or carrying `x221F_b4`. It selects an excluded object from `victim_gobj`, otherwise from `dmg.x1868_source` only under `x221C_b6`. Traversal tests only candidates after the source object has been encountered. Candidates have additional guards, including `x2219_b1`, disabled capsule state and a conditional reverse damage-source relationship. The source does not receive every candidate guard locally; its scheduled caller supplies additional source guards. If the source is absent from the list, no pair reaches testing. Numeric status 2 and the broader meanings of opaque flags are not renamed here.

Intersection calls `ft_8007C2E0` with the candidate as `fp0` and source as `fp1`. That function checks only whether `hit0` already records `fp1`; a match returns immediately. Otherwise it registers `fp0` in `hit1`, applies the response to `fp1` when its state equals `GA_Air`, registers `fp1` in `hit0`, then applies the mirrored response to `fp0` when its state equals literal 1. Registration and movement are interleaved, not globally separated into two phases.

Each response divides source weight by recipient weight, caps only values greater than one, and multiplies by `hit_weight_mul`. For X and Y separately, a movement-component product greater than or equal to zero selects source-minus-recipient movement; otherwise it selects source movement alone. Zero components belong to the nonnegative-product branch. The result is accumulated into `x98_atk_shield_kb`; Z is untouched and no zero-weight guard appears locally.

A tested nonintersection removes the opposite Fighter pointer from each capsule's primary victim table. It does not refresh endpoint geometry. Filtered-out pairs do not reach this removal. Category-3 insertion uses an auxiliary value of zero, and a full victim table permits replacement, so suppression lasts while the relevant record remains present rather than being an unconditional physical-contact lifetime guarantee. Motion-state changes can independently clear participation unless `Ft_MF_Unk27` is set.
