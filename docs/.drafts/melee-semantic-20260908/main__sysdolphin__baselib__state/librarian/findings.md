## Setup and state transitions

Render finalization order is fallback TEV stage, PE wrappers, dirty signed TEV register flush, TEV count commit/reset, texture-generator count commit/reset, channel setup. The foreign tev.c reads confirm the count resets and marked-register flush. Custom PE selects all wrapper inputs from the descriptor and ignores render flags in PE setup; channel setup still receives the original render mode. The descriptor does not configure every possible GX pixel-engine facility: the local eight wrappers define its scope.

Channel bit0x8 installs specular and requests two channels. The ternary selecting material versus per-light shininess occurs inside that bit guard, so the per-light alternative is unreachable in ordinary local flow. NULL active slots are skipped. Mode4 uses active ambient ID0x100; ambient RGBA multiplication is componentwise product/255 in util.c. Material diffuse, specular and alpha are stored with no local reads, while ambient and shininess are consumed. No alpha or shininess clamp exists.

All cached wrappers compare requested tuples before GX calls, then assign cached fields sequentially. Boolean inputs normalize first, but enum-like ints remain unvalidated. DstAlpha compares alpha even when disabled. Static zero initialization is not proof that hardware initially matches. Primitive invalidation sets widths/sizes0 and cull-1 while preserving texture offsets: zero-size requests with matching offsets still hit. Render invalidation stores255 in byte Boolean caches, not signed-1; valid Boolean requests therefore miss. No atomicity or synchronization is established.
