## State, ownership, and API
All eight functions return void and require a valid mutable Fighter pointer. They neither allocate nor free storage, register callbacks, nor retain callback contexts. The source declaration of CpuFighter contains signed-byte sticks, unsigned-byte triggers, a u32 command_duration, s8* csP, s8 buffer[0x100], and s8* write_pos. This establishes a source-level 256-byte embedded buffer, not independent proof of compiled object offsets. x44 is an optional Fighter pointer used synchronously; this TU performs no reference acquisition or lifetime validation. The caller must keep the fighter, optional target, and table storage valid. Source: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/types.h#L991-L1015 and #L1072-L1086.

ftCo_800B462C only sets write_pos = buffer; it does not erase bytes, stop interpretation, or neutralize controls. ftCo_800B463C writes one supplied u8 at write_pos and increments the pointer, asserting if it is at or beyond buffer end. There is no lower-bound or null check. The last valid byte can be written, leaving a one-past-end cursor; another write asserts. ftCo_800B46B8 serializes cmd,arg and ftCo_800B4778 serializes cmd,arg1,arg2 through this primitive. They do not validate opcode arity or reserve the complete instruction atomically, so a later byte can fail after preceding bytes were stored. Source: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftcmdscript.c#L319-L348.

ftCo_800B49F4 appends Done at the current write cursor, points csP at buffer, and sets duration to 1. It arms execution rather than calling the interpreter immediately. It neither resets the writer nor clears controls, and repeated calls append additional terminators. ftCo_800B4A78 zeros buttons, both stick pairs, both triggers, csP, and duration, then rewinds the writer. It does not erase buffer bytes or reset x18, destination, target, or all other CpuFighter fields. Source: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftcmdscript.c#L371-L394.

## Interpreter scheduling and cursor semantics
ftCo_800B3E04 returns for null csP or zero duration. Otherwise it decrements the u32 duration exactly once and returns if still nonzero. On reaching zero, it validates only the initial csP against the buffer and dispatches successive unsigned opcodes through a local signed-byte pointer until duration becomes nonzero, a matching motion poll returns, or Done returns. Ordinary suspension publishes the advanced local pointer. Duration operands are converted to u8 (0..255); zero-duration instructions continue immediately, rather than suspending. Unknown opcodes have no default handler and are consumed without an explicit error. Neither subsequent opcode fetches nor operand fetches are bounds-checked, and no instruction budget exists. Initial-pointer validation therefore does not prove whole-stream safety. Source: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftcmdscript.c#L26-L51, #L126-L181, and #L310-L317.

WaitIfMotionId reads an unsigned byte and compares it to fp->motion_id. On equality it sets duration=1 and returns WITHOUT publishing any advancement of csP. Crucially, this preserves the beginning of the current dispatch batch, not necessarily the address of the poll opcode: any preceding immediate commands in that batch can execute again on the next call. It waits while the motion matches, not until it matches. A byte operand cannot represent every wider motion identifier. Done clears csP and duration but leaves virtual inputs held. Source: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftcmdscript.c#L232-L242 and #L310-L317.

## Opcode behavior
The header defines paired press/release commands for A, B, X, Y, R, L, Z, D-pad directions, and Start; ReleaseAll; Done=0x7F; single-operand commands starting at 0x80; OneArgEnd=0xBF; and three two-operand steering commands starting at 0xC0. The Count assertion constrains the enum to u8. In ordinary builds cmd_t and arg_t are u8. Under M2CTX they become CPUCommand and s8, and ZeroArgEnd is omitted; that preprocessing branch is not evidence of a separately working runtime build of this C file. Source: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftcmdscript.h#L6-L97.

Button instructions update the corresponding HSD_PAD bits. R press/release additionally sets rtrigger to 255/0; L press/release only changes its digital bit. ReleaseAll clears only buttons, not triggers or sticks. Timed A/B/X/Y operations change a bit and install a duration, without automatically reversing the bit afterward. Direct analog instructions consume signed bytes for stick values; storing a signed byte in an unsigned trigger field preserves its byte-domain value by unsigned conversion. WaitFor installs duration. Unk0x93 stores an unsigned byte in x18; the header's 'Set scenario ID?' remains a hypothesis. Source: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftcmdscript.c#L52-L181 and #L240-L242.

Directional instructions derive angles from destination x54 or optional x44's position relative to fp->cur_pos and use signed-byte magnitude times cosf/sinf. Null x44 still consumes the operand but leaves stick state unchanged. Destination-X chooses the positive operand only for destination.x > current.x, whereas target-X negates only for target.x < current.x; equal positions therefore differ. Direct forward-X uses facing_dir >= 0, whereas incremental forward uses > 0, so zero facing differs. Unordered comparisons take the respective false branches. Source: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftcmdscript.c#L182-L230 and #L269-L308.

The clamped destination-vector command adds separately s8-converted trig projections, computes signed projected limits, and applies asymmetric control flow: X uses if/else-if, Y uses two independent ifs. These are not universally conventional symmetric clamps when projected limits are negative. The X-only clamped commands likewise accept a signed limit without checking positivity. Byte narrowing, especially negation of -128 or sums outside s8 range, must not be described as a proved saturating operation. Source: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftcmdscript.c#L243-L308.

lb_8000D008 is an angle-like helper, not assumed to be standard atan2: for strict |x|<0.00001 it returns zero when y is also strictly near zero, otherwise signed pi/2; positive x uses atanf(y/x), negative x adjusts quadrants. A NaN x falls through and returns the input y. Thus coincident finite points yield angle zero, not a guaranteed neutral stick. Nonfinite positions, trig results, and float-to-s8 conversions are not sanitized here, and target-specific exceptional conversion results remain unresolved. Source: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/lb/lb_00CE.c#L112-L158.

## Table import is not a reliable arity parser
ftCo_800B4880 indexes Fighter_804D64FC->cmdscripts with an unchecked int and appends bytes through the writer. It does not rewind, activate, or deactivate the interpreter. It copies Done when found at the outer-loop cursor. Its second width test reads the CURRENT *cmd, after the first branch may advance cmd to an operand. Consequently an opcode >0xBF consumes its first operand, then consumes another byte only if that operand is >0x7F. A first operand of 0x7F is copied as an operand but does not trigger the second copy; a following 0x7F may then be treated as the terminator at the next outer iteration. For opcodes <=0xBF, the second test still examines the opcode. Although bytes are emitted sequentially, claiming complete-instruction traversal for all valid two-operand instructions is false. No source length, table index, or null checks exist. Authored-table constraints or actual failures need table evidence. The comment saying this function 'Runs' a script overstates its direct effect. Source: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftcmdscript.c#L350-L369.
