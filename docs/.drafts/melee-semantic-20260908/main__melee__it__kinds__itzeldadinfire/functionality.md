## Zelda Din's Fire traveling item

This module implements the traveling projectile and its stationary release phase, not the separate damaging explosion item. The source declares two ItemStateTable entries and a twelve-float special-attribute structure. These are source-level observations, not claims about compiled section extent or literal placement. [Table and attributes](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/kinds/itzeldadinfire.c#L23-L43).

### Creation and ownership

`it_802C3BAC` constructs `It_Kind_Zelda_DinFire`. The supplied vector becomes `prev_pos`, with Z cleared; `pos` is obtained separately through `it_8026BB68`. The fourth float parameter is unused. Allocation failure returns NULL without item-specific initialization. Success clears command variables, stores the originating fighter in xDE0, initializes private state, and invokes `it_802C3D74`. That initializer selects state 0, initializes lifetime and progression, derives heading and speed from attributes, attaches effect 1272, and computes planar velocity. Facing exactly +1 selects base angle zero; every other value selects π. [Creation and initialization](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/kinds/itzeldadinfire.c#L73-L166).

Zelda's grounded and airborne side-special callbacks retain the returned projectile in fighter field x222C. Their loops compare its current owner with the fighter and clear tracking on mismatch. The no-projectile timer-based ending test is in a separate branch, so a mismatch does not execute that ending test in the same invocation. Fighter-side teardown calls `it_802C3D44`, which null-checks both object and Item, clears owner/xDE0/x13, but does not destroy the projectile. Destruction separately resets hit state, conditionally notifies the still-matching originating fighter, discards xDE0, and conditionally destroys attached effects. [Fighter consumers](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftZelda/ftzeldaspecials.c#L91-L315), [reciprocal teardown](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftZelda/ftzeldaspeciallw.c#L365-L391), [item cleanup](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/kinds/itzeldadinfire.c#L105-L132).

### State 0: travel and guidance

While xDDC is zero, animation increments progression xDD8 by one and caps it at attribute x4. Uniform scale is computed as `xDD8 * ((xC - x8) / x4) + x8`; the source supplies no zero-divisor guard or actual attribute values. A non-null originating fighter that still owns the item can supply the consumable release command. The fighter helper checks numeric motion IDs 345 and 348 and clears cmd_vars[1] when consuming it. Independently, the item lifetime helper decrements lifeTimer and tests whether it is nonpositive. Both triggers enter state 1. Because these are not mutually exclusive branches, an owner-triggered transition loads the release timer before the same animation invocation decrements it; sufficiently short release lifetime can cause a second state-entry/effect replacement in that invocation. [Animation and entry helper](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/kinds/itzeldadinfire.c#L168-L211), [consumable command](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftZelda/ftzeldaspeciallw.c#L344-L361), [lifetime helper](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/it_2725.c#L458-L468).

Physics updates only when xDDC is zero, xDE0 is non-null, current owner equals xDE0, and `ftZd_SpecialLw_8013B540` returns 1. It applies an input deadzone, accumulates and symmetrically clamps the angular offset, advances speed to its configured cap, and reconstructs XY velocity. Failed guards leave velocity unchanged. The exact meaning of the external control-state predicate is not established by its rendered name. [Guided physics](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/kinds/itzeldadinfire.c#L241-L282).

Stage contact also enters state 1. After the common collision call, positive Y selects CeilingMask and nonpositive Y selects FloorMask; positive X selects LeftWallMask and nonpositive X selects RightWallMask. Zero components therefore still select masks. Either qualifying axis suffices. The collision callback always returns false, including after its internal state transition. [Directional predicate](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/kinds/itzeldadinfire.c#L51-L71), [caller](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/kinds/itzeldadinfire.c#L290-L298).

### State 1: stationary release and explosion handoff

Entry replaces any latched effect with effect 1273 and loads lifeTimer from attribute x2C. Physics resets velocity; stage collision is a no-op. Animation preserves progression-based scale and decrements lifetime on every call. On expiry it removes latched effects, then attempts `it_802C4580` only if xDE0 is non-null and still equals the current owner. The arguments include owner, traveling item, position, facing, and accumulated progression—not the interpolated model scale. Fighter notification and the true return do not depend on successful explosion allocation. Invalid ownership skips both spawn and fighter notification but still returns true. [Release and completion](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/kinds/itzeldadinfire.c#L168-L239), [stationary callbacks](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/kinds/itzeldadinfire.c#L284-L303), [separate nullable explosion constructor](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/kinds/itzeldadinfireexplode.c#L24-L54).

### Interactions and naming assessment

Reflection sets xDDC to one, reverses facing and both planar velocity components, changes model Y rotation, clears Z velocity, and returns false. It neither selects a motion state nor writes owner locally. Its latch suppresses further progression, owner release checks, steering, and acceleration, while ordinary lifetime and stage-contact processing remain available. Clank and absorption callbacks ignore their arguments and return true; they perform no local cleanup or absorber reward logic. EvtUnk forwards both pointers unchanged to `it_8026B894`; its triggering event remains unspecified here. [Interactions](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/kinds/itzeldadinfire.c#L305-L331).

The existing Spawn, CheckTravelCollision, Travel_Anim, Guided_Phys, and Spawned hypotheses remain useful and supported as semantic names, not proven original identifiers. Spawned is not evidence of engine callback registration. The header renderer leaves the spawn declaration unchanged because of `shadowed_binding` and reports the same status for GetOwner; canonical declarations remain readable. The substantive corrections distinguish release from the separate explosion, expose lifetime mutation and trigger ordering, and avoid claiming that inert stage collision excludes other item interactions.
