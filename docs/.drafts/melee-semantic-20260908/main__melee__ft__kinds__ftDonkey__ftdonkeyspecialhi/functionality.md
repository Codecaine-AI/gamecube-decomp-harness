# Donkey SpecialHi translation unit

## Scope, interface and evidence reconciliation
The owned implementation is `src/melee/ft/kinds/ftDonkey/ftdonkeyspecialhi.c`, 165 lines, and its 19-line header. Both were independently read completely in canonical and rendered form. The eleven public functions have `void(HSD_GObj*)` signatures: grounded/aerial Enter, Anim, IASA, Phys and Coll pairs, plus `ftDk_SpecialHi_DestroyAllEffects`. Private implementation elements are `coll_mf` and `setCallbacks`. The header uses a guard, a baselib forward declaration include and address comments; these comments do not independently prove compiled addresses. See code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftDonkey/ftdonkeyspecialhi.h#L1-L19.

The active Donkey table associates the two callback families with their respective submotions, motion flags, `FtMoveId_SpecialHi` and the common camera callback. Callback roles therefore have active consumer support, not merely numeric enum-name support: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftDonkey/ftdonkey.c#L481-L502. The baseline human-facing Spinning Kong name, primary-recovery characterization and relative horizontal/vertical strength remain independently unverified gameplay mappings.

The librarian's central findings were independently confirmed: aerial startup uses x54 rather than x58; the gravity selector is evaluated each invocation; the animation successor helper has an exceptional redirect; and cleanup is owner-wide rather than effect-ID-specific. This lead additionally inspected the common air-to-ground inline, resolving the librarian's uncertainty about its current-frame argument. Its call explicitly forwards `fp->cur_anim_frame` after common grounding preparation. This proves the source-level continuation arguments, not the complete preservation behavior of the motion-state engine: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/inlines.h#L81-L89.

## Entry and callback lifetime
`setCallbacks` reads `gobj->user_data` as a Fighter, assigns `ftDk_Init_8010D774` to `take_dmg_cb` and `death2_cb`, then calls `Fighter_SetEffectHitlagCallbacks`. The helper is called after both entries and each local ground/air conversion. Stored pointers refer to functions, not stack closures. No old callbacks are saved and no local teardown is provided. Engine-level reset, invocation and preservation rules remain unresolved. See code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftDonkey/ftdonkeyspecialhi.c#L27-L33.

Ground entry changes to `ftDk_MS_SpecialHi` with flags 0, frame 0, rate 1, blend 0 and NULL auxiliary argument; installs callbacks; zeros all four command variables; calls `ftCommon_ClampGrVel` with `SpecialHi.x54_GROUNDED_HORIZONTAL_VELOCITY`; copies `gr_vel` to `self_vel.x`; sets `self_vel.y` to zero; sets used jumps to the common maximum; calls `ftAnim_8006EBA4`; and requests effect 1226 on the TopN joint. Air entry uses `ftDk_MS_SpecialAirHi` with the same initial motion arguments, resets the same command variables, clamps retained `self_vel.x` using the SAME x54 attribute, and replaces `self_vel.y` with x4C_AERIAL_VERTICAL_VELOCITY. It also exhausts jumps, calls the animation helper and requests the same effect. x58 is not the aerial startup clamp. Neither body validates the attributes, proves x4C positive, checks effect creation success or saves an effect handle. See code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftDonkey/ftdonkeyspecialhi.c#L35-L65.

## Animation completion and optional successors
Ground Anim only invokes `ft_8008A2BC` when `ftAnim_IsFramesRemaining` is false. Its consumer dispatches Master Hand and Crazy Hand separately; other fighters call `ft_8008A348`. That path can return through exceptional common states before Wait and can select another state after the Wait change. Thus the callback does not unconditionally enter Wait. See code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftDonkey/ftdonkeyspecialhi.c#L67-L72 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_08A1.c#L53-L109.

Air Anim has no local state-writing work while frames remain, though it obtains its Fighter/attribute pointers before the guard. On expiration it calls `ftCommon_8007D60C`, then compares x64_LANDING_LAG to zero. Equal values select `ftCo_Fall_Enter`; all other values call `ftCo_80096900(gobj,1,0,1,1,landing_lag)`. Under ordinary floating-point comparisons both signed zeros take the zero path; negative values, infinities and NaN take the other path. There is no local positivity or finiteness test. See code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftDonkey/ftdonkeyspecialhi.c#L74-L88.

The preparatory `ftCommon_8007D60C` is not merely effect cleanup: it sets GA_Air, clears ground velocity and vertical animation velocity, exhausts jumps, sets ECB lock to 5 and sets the collision lock bit. It first makes an optional player-system call when x2227_b0 is set and used jumps are at most one. See code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftcommon.c#L527-L539.

`ftCo_80096900` normally enters FallSpecial and stores the passed landing lag, allow_interrupt=true, xC=1, x10=0 and common air_drift_max multiplied by 1. However, x2224_b2 redirects to `ftCo_80090780` before that state change. Its later landing callback forwards the stored lag to LandingFallSpecial only when x10 is nonzero or vertical speed is below a delegated threshold; otherwise it invokes the common action-ending dispatcher. This TU forwards lag but implements no landing-lag timer. See code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_FallSpecial.c#L28-L59 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_FallSpecial.c#L145-L155.

Both IASA bodies are empty: no parameter reads, calls, input checks, timers or transitions occur locally. This does not prove universal uninterruptibility through damage, collision, scripts or engine processing. See code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftDonkey/ftdonkeyspecialhi.c#L90-L92.

## Physics and numerical boundaries
Ground Phys passes threshold 0, x5C_GROUNDED_MOBILITY and x54_GROUNDED_HORIZONTAL_VELOCITY to `ftCommon_8007CADC`, then calls `ftCommon_ApplyGroundMovement`. Its body has no local guard, timer or state transition. The exact ground acceleration and clamp algorithms remain delegated rather than inferred from rendered aliases. See code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftDonkey/ftdonkeyspecialhi.c#L94-L101.

Air Phys selects multiplier 1 when cmd_vars[0] is nonzero, otherwise x50_AERIAL_GRAVITY. It multiplies common gravity, calls `ftCommon_Fall` with common terminal velocity, then calls `ftCommon_8007D344` with threshold 0, x60_AERIAL_MOBILITY and x58_AERIAL_HORIZONTAL_VELOCITY. Selection is reversible on subsequent invocations; the TU only initializes command variables to zero and does not establish a nonzero writer or script timing. Reduced gravity cannot be proved without the actual x50 value. See code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftDonkey/ftdonkeyspecialhi.c#L103-L118.

The fall helper subtracts gravity and clamps only results strictly below negative terminal velocity. Equality remains unchanged; NaN comparison does not clamp. The aerial horizontal consumer compares absolute stick input against its threshold, computes stick-scaled acceleration and target, and delegates to friction/target logic; a zero target selects friction and common horizontal limits also participate. Thus x58 is not the entire horizontal algorithm. `ftCommon_ClampSelfVelX` uses ordered comparisons with -max and +max: equality is preserved, NaN comparisons fail, and negative maxima are not normalized into valid symmetric bounds. These are source-level ordinary floating-point observations, not target exception-mode or asset-validity proof. See code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftcommon.c#L336-L372, code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftcommon.c#L415-L428 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftcommon.c#L447-L468.

## Collision continuation
`coll_mf` ORs SkipMatAnim, SkipColAnim, UpdateCmd, SkipItemVis, Unk19, SkipModelPartVis, SkipModelFlags and Unk27. Unknown flag meanings and complete engine preservation semantics remain unresolved. Ground Coll performs no further local transition when `ft_80082708` succeeds. Failure calls airborne preparation, changes to aerial SpecialHi using coll_mf and the current animation frame, rate 1 and blend 0, restores callbacks and clamps self velocity using x58. It does not locally reset command variables, apply the x4C launch, call the entry animation helper or spawn another effect. See code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftDonkey/ftdonkeyspecialhi.c#L22-L25 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftDonkey/ftdonkeyspecialhi.c#L120-L133.

Air Coll tests `self_vel.y >= 0`. Positive values and signed zero use `ft_80081D0C`; success calls `ftCommon_AirToGroundStateChange` for grounded SpecialHi with coll_mf, restores callbacks and clamps ground velocity with x54. The else branch, reached for negative values and ordinarily NaN, tests `ft_CheckGroundAndLedge(gobj,0)` first. Its success performs the same grounded conversion. Only failure permits `ftCliffCommon_80081298` and conditional `ftCliffCommon_80081370`. Accepted ground contact precedes the explicit cliff path. Failed applicable predicates request no further local transition; predicate-internal side effects are not fully established. See code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftDonkey/ftdonkeyspecialhi.c#L135-L159.

The air-to-ground inline calls `ftCommon_8007D7FC`, then changes state using the supplied flags and `fp->cur_anim_frame`, rate 1 and blend 0. This resolves source-level continuation arguments in both directions, without establishing all effects of common grounding preparation or the engine. See code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/inlines.h#L81-L89.

## Effects, ownership and conventions
The cleanup wrapper unconditionally forwards gobj to `efLib_DestroyAll`. It is not itself the installed damage/death callback: `ftDk_Init_8010D774` first calls SpecialN cleanup and then this wrapper. The inspected library traversal clears matching entries in an eight-slot owner table, scans two managed effect lists with saved next pointers, selects nonnull effects by parent_gobj equality, conditionally walks JObj trees, unlinks matching effect GObjs and conditionally walks the owner's own tree. This is managed owner-wide cleanup, not a filter for 1226. No local Fighter free or ownership transfer occurs. See code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftDonkey/ftdonkeyspecialhi.c#L161-L164, code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftDonkey/ftdonkey.c#L590-L594 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ef/eflib.c#L244-L283.

Nonempty fighter callbacks require a live compatible object, Fighter payload and Donkey attribute storage; effect entry requires a usable parts array and TopN joint. There are no local null/type guards or synchronization primitives. Parameter #r3 locators are preserved as baseline identities, not proof of register allocation. Local unused u8 arrays and header address comments do not prove compiled stack/object layout. Repeated zero/one expressions cannot prove .sdata2 bytes, size, order or relocations.

The rendered C view has 13 function-name substitutions and no parse errors; the header has none. Aliases including ftAnim_Advance, EnvironmentCollision_AllowGroundToAir and ftCo_CliffCatch_CheckInput are hypotheses, not evidence of their own semantics. Inspected callees support portions of other aliases but canonical names and exceptional branches remain authoritative. Actual attributes, scripts, effect 1226 identity/success/lifetime, full collision predicate semantics, motion flags, callback teardown, animation-helper internals and compiled layout remain explicitly unresolved.
