## Computation and ordering
The unit implements the first VS Records matchup grid and supplies shared calculations to detail, ranking and Misc Records consumers. KO totals are row sums; falls are column sums, filtered by occupied names or unlocked fighters. SD counters are separate. Name falls clamp at 999999 inside the helper; fighter KO totals clamp only in the grid caller. Ratio helpers use floating arithmetic and zero-denominator guards: hit/play percentages are scaled by 10000, average participants by 100. Play-percentage denominators include all 120 name or 25 fighter records, without eligibility filtering. Distance helpers switch units at inclusive thresholds 160934 (US) or 100000 (other saved language), not saturate at one large unit. US short conversion divides by 30.4788, non-US short conversion by 100; detail/ranking callers clamp the converted magnitude and select unit glyphs independently. Formatters emit unpadded integers, fixed-point fractional digits or variable-width minutes with two seconds digits; they do not validate destination capacity or arbitrary negative decimal-place counts.

Sorters reset fighter/default and name/identity permutations, then use strict comparisons and shift insertion for stable eligible-first descending-KO prefixes. Accessors are unchecked. Fighter next/previous helpers traverse sorted positions; name next/previous helpers test raw slots. Per-name ranking preflights actual play history independently of the supplied callback, sorts all fighters, and re-evaluates callback values during tie handling. Outer candidates are unlock-filtered but tie scans are not. Least-played seeds fighter zero without testing its unlock state, then tests candidates 1..24 and rejects zero/tied ambiguity.

## Presentation and input
The grid draws ten entry rows by seven columns, plus a right KO-total column and bottom falls row. Cursor high byte drives X/seven columns; low byte drives Y/ten rows. Input local row/column names and arrow comments transpose these axes. Exact arrow slots and packed-byte tests are safer than inferred authored orientations. Name headers read the name permutation through the +0x1C source overlay and render stored nametags, not localized fighter names. Refresh deliberately passes is_name_mode==1 to numeric rendering while selecting name headers for every nonzero mode.

Input priority is Confirm, Back, L/R page changes, X/Y mode toggle, then direction bits. Confirm swaps the input process to modal input and creates a separate popup. Back from the popup restores ordinary input and destroys only the popup. X/Y returns with error feedback if no names exist, regardless of current mode. Edge scrolling changes one origin rather than an entire page. Name origin navigation tests raw slots while visible-entry resolution uses the sorted permutation; this distinction must not be normalized away.

## Ownership and lifetimes
Init conditionally loads shared archive pointers but always sorts, constructs the main screen and creates an independent input GObj. Main screen, input, cursor and popup are distinct objects. Main construction stores the supplied byte as anim_state, clears both packed viewport origins, restores only the mode rule when names exist, and registers HSD_Free for its user data. State zero immediately constructs the cursor/grid; OnFrame completes deferred entry only for state one. Other numeric states are not normalized. OnFrame removes page0 immediately when menu remains 0x1E but page discriminator x10 is nonzero; leaving menu installs ExitAnimProc after clearing generated grid resources. ExitAnimProc animates and destroys the primary screen, not the popup. Cursor checks the same menu/page guard before dereferencing the main handle; main destruction does not clear that handle here. Generic GObj destruction and process self-removal have guarded deferred paths.

Popup data contains fourteen JObjs and five text slots; cleanup releases exactly those five nullable texts then frees the allocation. Fighter diagonal mode retains a forward KO field as well as SD, unlike nametag diagonal mode. PopupAnimProc uses a text[0] alias for every alignment assignment and updates text[3] first from node3 then unconditionally from node13. Exact end-frame equality removes only the animation process, not the popup.
