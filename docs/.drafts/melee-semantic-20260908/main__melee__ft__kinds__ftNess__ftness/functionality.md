# Ness initialization TU

## Scope and conventions
The complete owned sources are ftness.c, ftness.h and ftness.dox. The C file defines twelve exported functions, a motion-state dispatch table, resource descriptors and four-element costume storage. The header declares the interfaces and exported data. The dox repeats interfaces and documents knockback presentation, but its chara-path file annotation is stale. Address comments and baseline target addresses do not establish compiled section membership, size, ordering or padding. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftNess/ftness.h#L1-L30; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftNess/ftness.dox#L1-L29.

The independent librarian's central findings were verified against canonical source and both owned reading views. In particular, COPY_ATTRS does not install the active attribute pointer, OnDamage does not guarantee complete effect/callback teardown, and section claims remain unresolved. Its malformed revision in one OnItemDrop citation is not reused. Canonical names take precedence over rendered hypotheses.

## Dispatch table and resources
ftNs_Init_MotionStateTable has 36 explicit initializers annotated 341–376. They cover AttackS4; AttackHi4 and AttackLw4 initial/charge/release families; grounded/aerial SpecialN Start, Hold, Release and End; grounded/aerial SpecialS; grounded/aerial SpecialHi Start, Hold, End and SpecialHi itself plus aerial Rebound; and grounded/aerial SpecialLw Start, Hold, Hit, End and Turn. Each record supplies submotion, flags, shifted move ID and animation/IASA/physics/collision/camera callbacks. All camera callbacks are ftCamera_UpdateCameraBox. Both SpecialS IASA entries are NULL. Initial up/down-smash move IDs additionally OR bit 23, unlike charge/release entries. SpecialAirHiRebound uses ftNs_MF_SpecialHi. SpecialLw Turn entries reuse Hold submotions but not Hold's Loop flags. These are initializer facts, not invented interpretations of numeric enums. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftNess/ftness.c#L22-L419.

SpecialN Hold and Release both use the canonical Release callback family, with Hold0 versus Hold1 submotions; the aerial pair similarly shares callbacks. Rendered ftNs_SpecialNHold_Anim and ftNs_SpecialAirNHold_Coll are substitutions for ftNs_SpecialNRelease_Anim and ftNs_SpecialAirNRelease_Coll, not additional symbols or evidence of exclusive Hold use. The grounded Release animation implementation handles charging and transitions to Release and End. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftNess/ftness.c#L100-L187; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftNess/ftnessspecialn.c#L223-L267.

The roster's ftData_CharacterStateTables references this table; ftData_OnLoad and ftData_OnDeath reference its load/death functions. Thus these are integrated dispatch definitions. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftdata.c#L300-L366.

Resources include PlNs.dat, ftDataNess, PlNsAJ.dat; Nr/Ye/Bu/Gr costume archive, shared-joint and shared-material-animation triples; and result, intro, ending and victory-wait demo labels. ftNs_CostumeList is an uninitialized UnkCostumeStruct[4]. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftNess/ftness.c#L20-L22; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftNess/ftness.c#L421-L449.

## Loading, attribute storage and ownership
ftNs_Init_OnLoad resolves Fighter through gobj->user_data and item_list through fp->ft_data->x48_items. PUSH_ATTRS copies the complete ftNessAttributes value from ext_attr into dat_attrs_backup and assigns dat_attrs to that backup. Eleven subsequent calls to canonical it_8026B3F8 pair indices 0,1,2,8,3,4,5,6,7,9,10 with Ness_PKFire, Ness_PKFire_Flame, Ness_PKFlush, Ness_PKFlush_Explode, Ness_PKThunder, Ness_PKThunder1, Ness_PKThunder2, Ness_PKThunder3, Ness_PKThunder4, Ness_Bat and Ness_Yoyo respectively. The callee stores the Article pointer in it_804D6D38[kind - It_Kind_Kuriboh]; it does not create an item or copy an Article. The rendered itRegisterArticle hypothesis agrees with this verified body. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftNess/ftness.c#L462-L480; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/inlines.h#L21-L40; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/it_26B1.c#L204-L208.

ftNs_Init_LoadSpecialAttrs instead invokes COPY_ATTRS: resolve Fighter, cast its existing dat_attrs destination, and assign the complete external attribute value through that pointer. It neither selects backup storage nor reassigns dat_attrs. Both operations require valid typed source/destination storage. OnLoad assumes at least eleven item-list entries and valid registration indices without checking them. Registered Article pointers are retained globally; their archive lifetime must satisfy later consumers but is not established here. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftNess/ftness.c#L520-L523; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/inlines.h#L21-L40.

## Death, interruption and callback lifetime
ftNs_Init_OnDeath calls ftParts_80074A4C(gobj,0,0), clears pkflash_gobj, pkthunder_gobj, bat_gobj and yoyo_gobj, and writes false to pkthunder_gfx. It contains no explicit article-removal or callback-unregistration operation. The rendered SetPendingModelSelection interpretation is not independently proved. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftNess/ftness.c#L451-L460.

ftNs_Init_OnDamage unconditionally invokes yo-yo despawn, PK Flash cleanup, PK Thunder damage cleanup and bat removal in that order. Each callee guards its stored item reference. Yo-yo cleanup calls it_802BE958, then a secondary helper while yoyo_gobj may still be present, then clears the field; immediate deallocation must not be assumed. PK Flash cleanup tolerates NULL gobj/Fighter and clears death2_cb and take_dmg_cb after its optional item-removal call. Other cleanup paths require a valid Fighter, so the aggregate is not NULL-safe. Thunder cleanup removes a present projectile; only its nine SpecialHi-family states destroy effects and clear pkthunder_gfx. Switch fallthrough reaches callback clearing and part-0 X-rotation reset for every state. Bat cleanup removes a present bat and clears its field. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftNess/ftness.c#L482-L488; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftNess/ftnessattackhi4.c#L571-L600; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftNess/ftnessspecialn.c#L74-L94; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftNess/ftnessspecialhi.c#L211-L243; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftNess/ftnessattacks4.c#L78-L86.

Successful bat and PK Flash creation install OnDamage in both death2_cb and take_dmg_cb. Clearing these fields during cleanup does not cancel the currently executing function. The up-smash entry installs additional deal_dmg_cb/accessory4_cb functions not cleared by this fan-out. Therefore OnDamage is also a secondary-death cleanup hook, and is not a guarantee that every callback/effect is removed. Active AttackS4 creates the bat, active SpecialN creates It_Kind_Ness_PKFlush into pkflash_gobj, and AttackHi4 manipulates yo-yo state; these support the narrow move/article associations without relying on rendered names. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftNess/ftnessattacks4.c#L29-L55; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftNess/ftnessspecialn.c#L183-L215; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftNess/ftnessattackhi4.c#L602-L640.

## Absorption and numeric boundaries
ftNs_Init_OnAbsorb forwards gobj unchanged to ftNs_AbsorbThink_DecideAction. ftNs_Init_GetAbsorbHeal directly returns x94_PSI_MAGNET_HEAL_MUL from active ftNessAttributes, without validation, clamping or a hard-coded default. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftNess/ftness.c#L490-L498.

The actual consumer casts absorbed damage times the getter result to int, stores that as float, subtracts it from damage percent, and if the new percent is negative clamps it to zero while adjusting credited healing. It then updates player percent/statistics and copies absorbHitDirection to facing_dir. For finite int-representable products conversion truncates toward zero; sub-unit and zero products can give zero recovery, and negative products can increase damage. NaN, infinity and out-of-range float-to-int conversion have no portable defined healing result; target compiled evidence is required. Healing arithmetic and facing updates precede the reaction guard. A new reaction is suppressed only in grounded/aerial SpecialLwHit with cur_anim_frame <= x7C_PSI_MAGNET_UNK2, including equality. An unordered comparison causes the negated condition to select transition if execution reaches that test. GA_Ground selects grounded Hit; other values select aerial Hit, followed by state change and absorb-hit recreation. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftNess/ftnessspeciallw.c#L894-L939.

## Item and knockback adapters
Pickup forwards gobj and catchItemFlag with two true options. The shared inline skips all updates for heavy items. Otherwise hold kinds 1,2,3,4 select ftAnim_80070FB4 arguments 1,0,2,3; other kinds skip that call. catchItemFlag independently controls a subsequent ftAnim_80070C48 call inside the non-heavy branch. No gameplay categories are assigned to numeric hold kinds. Invisible/Visible forward true, and for non-heavy items invoke ftAnim_80070CC4/ftAnim_80070C48 respectively. Drop always calls ftAnim_80070FB4(gobj,true,-1), then calls ftAnim_80070CC4(gobj,true) only if dropItemFlag is true, without a heavy-item guard. These are shared event/presentation adapters, not local item spawning/releasing routines. NULL held-item behavior in itIsHeavy and deeper animation-helper semantics remain unresolved. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftNess/ftness.c#L500-L518; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/inlines.h#L142-L193.

KnockbackEnter/Exit forward selector 1. The common inlines call ftAnim_800704F0 for selectors 1 then 0 at frames 3.0f and 0.0f respectively. They do not compute local launch velocity or hitstun. The dox describes hurt/normal material-animation textures; exact calls are verified, deeper helper behavior is not. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftNess/ftness.c#L525-L533; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/inlines.h#L195-L205; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftNess/ftness.dox#L24-L28.
