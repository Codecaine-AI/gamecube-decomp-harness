# Fox initialization TU

## Scope, interfaces, and evidence
The complete owned files define Fox's motion-state table, resource descriptors, four-entry costume storage, and twelve lifecycle/initialization functions. The header declares these interfaces; the dox file additionally catalogues functions implemented in the AppealS, SpecialN/throw, SpecialS, SpecialHi, and SpecialLw translation units. Dox descriptions are documentation, not executable proof. Canonical names take precedence over rendered hypotheses. Sources: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftFox/ftfox.h#L1-L32 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftFox/ftfox.dox#L1-L324.

All twelve functions take an HSD_GObj pointer except ftFx_Init_OnLoadForFalco, which takes Fighter directly. Pickup and drop additionally take bool flag. Only ftFx_Init_800E5534 returns a value. None validates the outer object or required fighter storage. The parameter subjects have no baseline facts; source signatures establish their roles, not independently verified register allocation.

## Attribute installation, refresh, and article registration
ftFx_Init_OnLoadForFalco executes PUSH_ATTRS(fp,ftFox_DatAttrs). The macro copies the typed external attribute value into pre-existing dat_attrs_backup and installs that buffer as dat_attrs. It does not allocate storage. Fox OnLoad first enables can_walljump, performs the same copy/install, then passes item_list[0] with x1C_FOX_BLASTER_SHOT_ITKIND, item_list[1] with x20_FOX_BLASTER_GUN_ITKIND, and item_list[2] with It_Kind_Fox_Illusion to it_8026B3F8. That routine stores the Article pointer at it_804D6D38[kind-It_Kind_Kuriboh]; it does not spawn an item, copy the Article, or check bounds. Repeated registrations replace entries. Valid buffers, at least three item-list entries, valid registry indices, and adequate resource lifetimes are caller preconditions. Sources: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftFox/ftfox.c#L481-L501, code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/inlines.h#L21-L35, and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/it_26B1.c#L205-L208.

Attribute floats are copied without validation, clamping, or special handling for NaN/infinity. ## Item-event branches and presentation
Pickup/drop forward (gobj,flag,1,1); invisible/visible forward (gobj,1). The fixed boolean selectors become part-animation slot indices, specifically slot 1. For non-heavy pickup, hold kinds 1,2,3,4 write pending selections 1,0,2,3 respectively; other hold kinds leave the pending selection unchanged. A true flag additionally requests application. Heavy pickup skips both operations. Drop always sets pending selection to -1 and conditionally removes the active override when flag is true; it has no heavy-item guard. Invisible and visible skip heavy items. Sources: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftFox/ftfox.c#L461-L479 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/inlines.h#L142-L193.

Application is a no-op for pending x10=-1. Removal is a no-op for active x11=-1; otherwise it clears the active override and restores animation through the x590-present branch or costume-joint fallback. These are fighter part-animation operations, not demonstrated writes to an item-GObj visibility bit or ownership transfers. Null held-item behavior inside itIsHeavy remains unresolved. Source: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftanim.c#L1276-L1368.

Common entry/exit call ftAnim_800704F0 for selectors 1 and 0 with 3.0f/0.0f respectively.
