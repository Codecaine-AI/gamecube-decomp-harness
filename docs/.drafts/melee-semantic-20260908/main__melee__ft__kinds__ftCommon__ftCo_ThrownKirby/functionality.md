# ftCo_ThrownKirby

## Scope and naming
Victim-side Kirby release processing includes copy-kind selection, ordinary ThrownKirbyStar and ThrownCopyStar entry, shared flight/contact processing, and ThrownKirby recovery. The header declares 20 externally visible functions. Rendered aliases are descriptive hypotheses, not independent evidence; ftCo_800BDA74 is exported, not C-private. All callback arguments are Fighter_GObj pointers. Star entries take victim first and thrower second. ## Selection and initialization
ftCo_800BD9E0 marks Kirby victims through ftCo_800BDA50 and returns their hat.kind. For unsigned(victim_kind-FTKIND_BOY)<=1 or Sandbag it returns the first object's existing hat.kind; Nana maps to Popo, and other kinds pass through. The second unsigned-predicate value is not independently identified here. Marking sets x18_b1 only when hat.kind differs from Kirby; it neither removes an ability immediately nor validates fighter kind. [code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_ThrownKirby.c#L43-L70]

Ground and air Drink callers enter ThrownCopyStar before copy selection and processing. This ordering lets initialization clear x18_b1 before selection sets it. Spit instead calls ftCo_800BDB58. [code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftKirby/ftkirbyspecialn.c#L890-L941] [code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftKirby/ftkirbyspecialn.c#L1008-L1069]

Shared initialization reverses thrower facing, stores the thrower pointer, clears x8, obtains velocity and x4 through a supplied helper, updates victim model scale and saves victim root scale. It changes state with Ft_MF_SkipThrowException, installs both damage callbacks, makes the victim invisible, initializes grab timing, records the outcome discriminator and clears the removal marker. An accessory obtained through a thrower-dependent helper is scaled using victim co_attrs.xDC and passed with the YRotN joint to lb_8000C2F8. Stored-pointer and accessory ownership/lifetimes are not established locally. MUST_MATCH assertion strings and source ordering expressions do not prove compiled section membership or layout. ## Flight and contact
Shared physics computes m=sqrt(X²+Y²). When m>thrownkirby.x4, X becomes X*(m-thrownkirby.x4)/m and Y becomes Y*(m-mv.ca.specialhi.vel.x)/m; facing then follows the sign of resulting Y. Otherwise only X is cleared. Z is untouched. Timer subtraction always occurs, followed by GrabMash, x14 storage and recovery on grab_timer<=0. Equality takes the X-only fallback. There are no finite-value checks; negative tuning, zero divisors, overflow and NaN must not be silently excluded. Compiled union aliases and uniform deceleration remain unproved. [code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_ThrownKirby.c#L163-L192] [code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_ThrownKirby.c#L233-L242]

Normal selection prioritizes accepted floor, right wall, left wall, ceiling, then zero. Both collision callbacks reflect when any normal component is nonzero. lbVector_Mirror modifies only XY without normalization. A strictly negative old/new XY dot product triggers recovery; only afterward is x8 assigned by normal.x sign. That assignment cannot affect velocity setup already completed by the same entry call. Later release significance remains unresolved. ## Recovery and callback lifetimes
Recovery enters ThrownKirby with Ft_MF_Unk06, reinstalls damage callbacks and makes the victim visible. Ordinary recovery obtains a Vec2, assigns Y, and selects X using canonical mv.ca.specialhi.vel.y when truthy or existing X sign otherwise. Copy cleanup requires Kirby kind, x18_b1 and clear hat.x8_b0; it invokes two helpers and resets hat.kind. Recovery initializes duration x10 and grab_timer, coefficient xC and accessory4_cb. xC is not a duration. [code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_ThrownKirby.c#L262-L296]

Recovery physics subtracts the timer decrement. Ordinary recovery waits for a nonpositive timer; copy recovery updates model scale and enters Fall on its next physics invocation regardless of timer. The scaling callback computes f=(x10-grab_timer)/x10, multiplies by xC, and applies ((1-xC)-(-f)) to each saved scale component. There is no clamp, zero-duration guard or monotonicity/endpoint-sampling guarantee. Copy recovery can exit before a visual endpoint is sampled. [code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_ThrownKirby.c#L302-L338]

The damage callback only forwards to Fighter_UpdateModelScale. That helper computes effective scale, with x34_scale.z overriding X when not one. Framework motion-state setup clears accessory4 and both damage slots, explaining reinstallation; complete damage-dispatch ordering remains deferred.
