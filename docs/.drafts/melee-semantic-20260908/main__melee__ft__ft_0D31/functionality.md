## Common fighter death processing

This unit implements guarded blast-zone detection, shared death cleanup and accounting, four immediate directional KO presentations, and phased normal/frozen Star KO and DeadUpFall presentations. The header declares the corresponding entry helpers and callbacks.

### Detection and bookkeeping

`ftCo_800D3158` rejects death processing when any of five suppression bits is set. It tests boundaries in **right, left, qualified top, bottom** order, returning true after dispatch and false otherwise. Top exits additionally require grounded state, `x2222_b3`, or vertical knockback strictly greater than common-data `x4F0`. A player flag selects direct upper death; otherwise a 1–100 roll, `x520`, camera predicate, and DamageIce motion choose the fall/star and frozen variants. The caller invokes this check after position integration, moving-floor displacement and wind. [Dispatcher](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_0D31.c#L30-L79), [caller](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/fighter.c#L2325-L2396).

`ftCo_800D331C` performs attribution work, calls optional death callbacks in **death2, death3, death1** order, invokes capture/common cleanup, disposes held and attached objects, removes temporary conditions, and snapshots motion ID and `x2073` into `x6C/x70`. It does not itself select a death motion. The snapshots later feed `ftCo_800D34E0`, which increments indexed Falls, resets stale moves, conditionally loses stock for the selected player entity, conditionally records elimination timing, distinguishes credited KOs from sentinel-6 self-destructs, reports death data and clears indexed HP. [Cleanup and accounting](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_0D31.c#L81-L161).

### Directional presentation

Left/right/down/direct-up entries use numeric motion IDs **1/2/0/3**, respectively. They initialize the common `x500` countdown, set death/presentation flags, hide the fighter, immediately account for the death, request quake and rumble, play configured and fixed sounds, and spawn player-colored effects. Side effects clamp Y; vertical effects clamp X. The final coin/presentation helper receives a point fixed to the corresponding blast boundary. Each paired Anim callback unconditionally decrements the timer and finalizes only when the resulting value is exactly zero; this is not a saturating countdown. The four directional Cam callbacks are empty. [Directional family](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_0D31.c#L184-L579).

`ftCo_800D35FC` requests rumble program 5 for the defeated fighter and 6 for other fighters not excluded by `x221F_b3`. Downstream player/fighter eligibility checks can suppress either request. `ftCo_800D38B8` always attempts primary fighter audio and conditionally invokes the secondary mapped trigger when `x2225_b6` is clear. The primary callee separately handles sentinel sound IDs and permits the flagged path only for Samus and Game & Watch. [Rumble dispatch](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_0D31.c#L163-L177), [audio wrapper](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_0D31.c#L266-L272), [audio exceptions](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_0881.c#L12-L47).

### Star KO

Normal and frozen entries explicitly select `ftCo_MS_DeadUpStar` and `ftCo_MS_DeadUpStarIce`, initialize timer/phase and set `x68` to 0/1. Frozen setup creates the scaled ice effect; it does not remove that effect. The shared animation callback has phases 0–2: initial delay, configured camera-relative Y/depth travel with optional frozen X rotation, then disappearance/accounting and a final delay. Death statistics are deferred until disappearance, unlike directional entries. The camera callback delegates to a helper that refreshes the camera box, asserts a nonzero projection denominator, scales X and pins Y to the top blast-zone offset. [Star family](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_0D31.c#L594-L700), [ice effect creation](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_DamageIce.c#L87-L103), [camera projection](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftcamera.c#L95-L114).

### DeadUpFall / Screen KO

The shared initializer loads the first timer and movement vector from the common-data block beginning at `x520`, clears phase/scalars, and enters the caller-selected motion. Normal/frozen wrappers pass **6/9** and install selectors **0/1**. The fixed `{0, π, 0, 0}` rotation aggregate is applied only when Z scale is exactly 1. This establishes source-level usage, not compiled section composition.

The animation callback uses phases 0–4. Phase-0 expiry starts normalized interpolation progress. During phase 1, progress advances and frozen fighters rotate; expiry selects motion **10** for frozen fighters, **8** for non-unit Z scale, or **7** otherwise. The impact helper uses `Ft_MF_SkipRumble | Ft_MF_SkipColAnim`, requests feedback/audio/quake, processes conditional coin loss and installs `fn_800D4DD4` as `accessory4_cb`. Phase-2 expiry installs Y/Z velocity. Phase-3 expiry hides the fighter, performs deferred death accounting and audiovisual work, and starts the final delay. Phase-4 expiry calls the finalizer, which changes motion to Sleep rather than normally leaving this callback active for repeated finalization. [Fall initialization and animation](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_0D31.c#L702-L881).

Physics operates only in phases 1 and 3. Phase 1 gates interpolation into `x50`. Phase 3 applies falling physics and accumulates self velocity into `x5C` **before** testing the animation gate: rejection retains accumulated displacement; acceptance transfers it into `x50` and clears `x5C`. The external accessory callback instead checks phase 3 and the bottom camera bound before resetting velocity. These are distinct callbacks, despite the rendered naming collision. [Physics](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_0D31.c#L883-L912), [external accessory and camera callbacks](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_0D4D.c#L32-L53).

### Cross-file lifetime and evidence limits

The coin helper conditionally deducts integer half of the player's coins and records the loss; only emitted coin quantity is capped. The completion helper enters Sleep, hides/deactivates the fighter and camera subject, optionally removes an associated player entity through the shared cleanup path, and notifies game management.
