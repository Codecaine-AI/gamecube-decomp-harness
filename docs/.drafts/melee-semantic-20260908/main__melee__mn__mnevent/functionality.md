## Event Match browser

`mnevent.c` constructs and operates a nine-row Event Match selection window. `first_event` is the first visible event index; the byte-sized `page` is the highlighted row offset, not a page number. Selection is their sum. The progression query returns the maximum viewport-start index, with possible results 1, 6, 11, 16, 20, 21, 30, 41 and 42. Its debug override uses the strict comparison `DbLevel > DbLKind_DebugDevelop`. Otherwise completion counts, eleven character-unlock queries and a final persistent-state predicate determine the boundary. The rendered Adventure-clear name is not independent proof of that predicate's mode identity.

Rows replace their old completion-marker GObj and two text objects. Completion controls marker creation; the displayed number is the event index plus one, and authored row content is selected through event metadata. Selected-event refresh updates character node 4, description text, record text, category node 9 and arrow visibility. The canonical `name_text` field holds the record readout. Timed records display modulo-60 minutes and seconds plus the truncated value `99 * (frames % 60) / 59`; uncleared timed and score categories have distinct placeholders. The character sentinel selects frame 25, without this helper establishing downstream character-selection policy.

Input priority is shared cooldown, Back, entrance-delay countdown, deferred construction, Confirm, then mutually exclusive X/Y/Up/Down navigation. X and Y move the viewport by up to nine; Up and Down move the highlighted row before scrolling at its edges. Cursor node 0xB is translated using row spacing. Confirmation stores the combined event index, forwards `mn_802295AC()` to `gm_801677E8()`, and requests `GM_EVENT`.

Entry selects menu state 7 and a five-update cooldown. First entry delays construction by 20 eligible countdown invocations; the invocation decrementing the timer to zero still returns. The 1-P caller supplies index zero, while scene reconstruction supplies the game manager's selection and constructs immediately. The constructor publishes the singleton, builds the animated model, allocates `MnEventData`, attaches it with `HSD_Free`, populates nine rows and installs the entrance process. Allocation failure reports and asserts. The initializer assumes a suitable selection rather than validating arbitrary indices.

Entrance completion uses equality with its endpoint; departure from either entrance or active processing removes selected description and record text and installs the exit process. Exit cleanup waits for a greater-than-or-equal endpoint comparison, independently removes populated row resources, then destroys the owner. The separate input GObj and retained menu archive have surrounding-menu lifetimes; this file does not locally demonstrate their complete teardown, nor does exit cleanup clear the singleton.

Existing owned function-name hypotheses fit these roles and are retained. Rendered names remain hypotheses; two foreign SisLib constructors collide on `HSD_SisLib_CreateText` and therefore remain canonical in the rendered view. Source declarations and offset-based resource loading do not establish compiled section extents, adjacency, literal placement or aliasing of the fifth archive destination with the separately declared marker array.
