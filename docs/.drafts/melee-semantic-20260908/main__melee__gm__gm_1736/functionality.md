# gm_1736 semantic review

## Challenger context and lifetime
The unit owns one source-level static `ChallengerData` object. `gm_GetChallengerData` returns a mutable alias, without allocation or initialization. `gm_InitChallengerData` clears the whole object and installs six caller-supplied bytes; it does not schedule a transition. `gm_80173754` instead clears and populates a sentinel request only when `gm_801721EC` succeeds, then schedules `GM_CHALLENGER_APPROACH`. Failure performs none of those local mutations. On load, the previous mode is captured separately in `prev_mode`; `CHKIND_NONE` selects numeric state 2, and every other value selects state 0 without validation. `gm_801737D8` simply returns `prev_mode`. These state numbers are not assigned speculative screen meanings. [Source](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gm_1736.c#L16-L70)

The record survives across approach display, battle preparation, result handling and prize processing. Downstream battle setup consumes the fighter, color, slot and nametag fields. A result other than no-contest or retry, with human stocks remaining, unlocks `cpu_ckind`; the other branch records failure. Battle exit restores `curr_mode` only if no further follow-up is available, whereas prize exit restores it directly. Thus `curr_mode` and `prev_mode` are distinct routing values. [Consumers](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gm_1BFA.c#L66-L120), [prize exit](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gm_1BFA.c#L247-L251)

## Trophy staging, not immediate acquisition
`fn_80173834` obtains a character/mode table value, optionally clears its saved registration bit, and submits it to `fn_80172C78`. Zelda and Sheik are processed symmetrically as paired forms. The lookup and local temporaries are declared `bool` even though they carry table-derived values; this review does not infer normalization or change their types. [Wrapper](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gm_1736.c#L72-L95), [lookup](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gm_1601.c#L508-L539)

The shared submission helper calls `gmMainLib_8015D984`, then clears the saved bit after successful staging. The underlying operation timestamps the candidate and sets pending and saved bits; the wrapper's clear leaves pending work distinct from persistent registration. Prize processing later sets the saved bit and calls `Toy_SetUnlockState`. Repeated submissions therefore must not be assumed to be permanently deduplicated by the evaluator itself. [Staging helper](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gm_16F1.c#L1767-L1774), [bitmaps](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gmmain_lib.c#L658-L705), [finalization](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gm_1BFA.c#L195-L240)

The second seven-row table is cumulative and unsorted: every reached threshold is submitted. Neither declaration proves compiled section size or placement. ## Availability and bulk operations
`gm_80174180` independently enables Toy categories 4, 5 and 6. Category 4 requires both any-entry predicates, not necessarily for the same fighter; category 5 requires 200 combined VS matches; category 6 requires all unlockable characters. Toy performs locale filtering and selects temporary or persistent storage according to current mode before ORing availability/category bits. This is availability enabling, not a direct trophy grant. [Caller](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gm_1736.c#L412-L423), [Toy behavior](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ty/toy.c#L1236-L1337)

The setter has a verified debug-gated caller; deletion and broader reset pair the clearer with separate Toy reset work. Neither loop alone proves full inventory acquisition or full trophy-system erasure.
