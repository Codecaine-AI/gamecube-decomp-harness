### Initialization and channel lifetime
`gChID != 0` is the initialization test. `TTYInit` rejects an already initialized channel, calls `MCCInit(exiChannel, 5, 0)` and `MCCOpen(chID, 1, ttyMccChannelEvent)`, saves the previous event mask while installing `0x30`, and resets channel properties. No explicit rollback appears if opening fails after MCC initialization succeeds. `TTYExit` restores the saved mask and clears properties only if `MCCClose` succeeds. Independently, callback events 1 and 2 set and clear `gChID`; event 2 does not reset the other counters. These observations do not establish external callback ordering or enum meanings. ### Query and acknowledgement handling
`TTYQuery` clears its response flag and sends `0x100210`. Callback event `0x100`, with notification class `0x200000` and low 16 bits `0x210`, sets that flag. Failure to initialize or notify takes an explicit five-second busy-wait before returning zero. The successful-notify path uses `ttyWaiting(5, &gQuery)`, whose conversion of the timeout to ticks followed by comparison against elapsed seconds prevents describing it as a verified five-second timeout. Notification class `0x400000` extracts an eight-bit size and message ID, conditionally rebases head/tail counters, advances the head by size times 32, and records the acknowledged ID. A zero size still records the ID without advancing the head. Evidence: [callback](code://c302741689bd67c361cd7faadb221df3193992c3/extern/dolphin/src/dolphin/mcc/tty.c#L49-L89), [query](code://c302741689bd67c361cd7faadb221df3193992c3/extern/dolphin/src/dolphin/mcc/tty.c#L112-L124), [wait helper](code://c302741689bd67c361cd7faadb221df3193992c3/extern/dolphin/src/dolphin/mcc/tty.c#L203-L217).

### Formatting and transport bookkeeping
`TTYPrintf` uses the shared 8192-byte buffer as packet staging storage, placing an MCC header, message ID, and formatted string into it. It sets protocol `0x210`, length to string length plus `0xD`, and rounds the transfer size to 32 bytes. Tail/head bookkeeping describes an 8192-byte destination ring; writes crossing its boundary are split into two `MCCWrite` calls. Message IDs wrap through eight bits. It flushes before writing when computed free space is less than or equal to the packet size, and after writing on newline or ID `0xFF`.

Important exceptions: oversized format strings are modified despite the const-qualified parameter; `vsprintf` is unbounded and the output-length check occurs afterward. Write results are ignored, the tail advances regardless, and the function can return success without establishing successful delivery. ### Flush and diagnostics
`TTYFlush` rejects uninitialized state. The internal flush immediately succeeds when head equals tail; otherwise it sends `msgID | 0x300000`. Notification failure enters an infinite loop.
