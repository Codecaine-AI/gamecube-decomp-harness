# Shared Zako Generator

Owns two distinct facilities: callback placement from transformed segment endpoints and a singleton81-entry item registry. Registry allocation, fallible manager publication, periodic scans, two slot-release policies, a reserved tail slot and enable/global-item cleanup are local. NULL descriptors suppress ordinary item dispatch. Target creation is not performed by the manager constructor; stage-wrapper calls must not imply successful construction or immediate target spawning.

## Headers and data

All 420 owned lines were read canonically and rendered through EOF: C374, public header25 and static header21. The public header declares 12 functions; its enabled setter still uses UNK_RET while the C definition returns void. The static header defines nullable descriptor/data pointers, signed cursor and eight bitfields, of which only bit0 is used. Exact four-section layout and padding require object evidence. [Supporting types](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gr/types.h#L334-L366) define 81 entries, signed16-bit marker/cooldown, item pointer and32-bit payload.

## Failure and lifetime boundaries

The stage constructor can fail after enabling the singleton. NULL descriptors do not request immediate target spawns. Multiple manager processes would service the same current global table after repeated construction; this unit neither tears down earlier managers nor frees overwritten data. Segment configs likewise have no destructor here. Cleanup acts on global kind ranges, not a list of registry-owned objects.

Twelve aliases have no baseline/canonical collisions. Event names, InitialSpawn and Shutdown remain hypotheses where caller timing or full teardown is unverified. No source or shared KB changes.
