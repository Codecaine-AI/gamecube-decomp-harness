## Grounded physics and numeric limits

Physics directly multiplies common x64 by ground_friction, calls ftCommon_ApplyFrictionGround, then ftCommon_ApplyGroundMovement; it does not call ftCo_Catch_Phys. Friction writes xE4_ground_accel_1: a strict absolute-magnitude comparison selects -gr_vel, otherwise positive velocity negates friction. Equality takes the latter branch. Opposing friction requires ordinary nonnegative finite friction data. Ground movement applies the floor multiplier only below one and projects acceleration and gr_vel along (normal.y, -normal.x), zeroing both z components. POPO/NANA receive multiplier one; other kinds delegate to map collision. Negative and nonfinite values are not validated; NaN fails ordinary less-than comparisons. Runtime ranges, normal normalization and compiled exceptional-float behavior remain unproved.
