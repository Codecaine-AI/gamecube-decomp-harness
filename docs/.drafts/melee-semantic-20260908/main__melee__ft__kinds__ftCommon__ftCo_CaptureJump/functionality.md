## CaptureJump: airborne grab-release lifecycle

`fn_800DC070` is strongly supported as `ftCo_CaptureJump_Enter` by its canonical body and the neighboring CaptureCut entry naming pattern—not by the rendered substitution. It saves the linked participant, calls airborne initialization, sets horizontal velocity to `-facing_dir * x374` and vertical velocity to `x378`, clears `mv.co.buryjump.x0`, tears down the capture pair, and enters `ftCo_MS_CaptureJump` with flags 0, frame 0, rate 1 and blend 0. The supplied object is the captured fighter, not the grabber. [Entry](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_CaptureJump.c#L15-L26)

The Thrown updater chooses this release when a previously nonzero grab timer expires and either `mv.co.thrown.xC` or `fn_800DC044` succeeds; otherwise it chooses CaptureCut. The input predicate compares upward stick input to `tap_jump_threshold`. [Caller](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_Thrown.c#L61-L86) [Input](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_CaptureWait.c#L312-L329)

The linked object is retained locally across initialization and passed into teardown before the motion change. Teardown clears capture references on both participants; role swapping, Kirby-specific scale restoration, position correction and ground/air collision branches mean it is not merely two pointer clears. The entry's airborne initialization therefore must not be mistaken for proof that teardown cannot subsequently adjust situation bookkeeping. [Teardown](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_CaptureCut.c#L84-L196)

### Callbacks

- **Anim:** increments `mv.co.buryjump.x0` once per invocation, then calls `ftCo_Fall_Enter` if no eligible animation remains. This callback does not transition while animation remains, but IASA or collision may independently interrupt the state. The animation predicate selects ordinary or blend joints. Fall entry has special destinations for the two boss hands and guarded alternate paths; only its ordinary path enters `ftCo_MS_Fall` while preserving fast-fall. Each successful check terminates processing. The canonical field differs from the counter written by entry/Anim; neither their semantic equivalence nor an exact actionable frame is established. The drift solver writes `x74_anim_vel.x`, including friction when the target horizontal velocity is zero; this callback contains no local timer update or motion transition. Only qualifying contact not suppressed by `ft_80081A00` reaches velocity dispatch: above `ftCo_800D0EC8(fp)` it invokes `ft_8008A2BC`; otherwise it invokes basic landing.
