# ftCo_DamageSong

## Scope and canonical identities
The owned C file implements the DamageSong, DamageSongWait, and DamageSongRv callback families, two internal transition helpers, an externally callable entry routine, and a separate boolean damage-response gate. The header declares the public entry, twelve callbacks, and boolean gate; it does not export ftCo_800C3390 or ftCo_800C3480. Their preceding static declarations give those helpers internal linkage despite the definitions omitting static. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_DamageSong.c#L17-L18 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_DamageSong.h#L1-L22.

The proposed names ftCo_DamageSong_Enter, ftCo_DamageSongWait_Enter, and ftCo_DamageSongRv_Enter accurately describe the corresponding canonical routines ftCo_800C318C, ftCo_800C3390, and ftCo_800C3480, but are not recovered original names. ftCo_DamageCape_Check is a plausible descriptive alias for ftCo_800C3538 because an active HitElement_Cape caller uses its boolean result. Rendered aliases for Player_80033BB8 and other dependencies are not independent evidence of their meaning.

A true arg1 multiplies the entire result by x644. There is no local clamp or finite-value check. The second player API's semantic meaning and the signs/ranges of these coefficients remain unresolved; neither a rank interpretation nor a player-count interpretation is established here. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_DamageSong.c#L20-L44.

The inspected caller ftCo_8008E908 dispatches here for numeric damage elements 6 or 7 when x2228_b2 is clear, passing false for 6 and true for 7; otherwise it calls ftCo_8008DCE0. ## Timer and state progression
inlineB0 subtracts x63C from grab_timer, calls ftCommon_GrabMash with x640, and only then tests grab_timer <= 0. On true it calls ftCo_800C3480 and returns true. DamageSong_Anim executes this first; short-circuit evaluation prevents the animation query after expiration. Otherwise, animation exhaustion calls ftCo_800C3390. That helper selects DamageSongWait with Ft_MF_SkipMatAnim | Ft_MF_SkipColAnim and 0,1,0,NULL. DamageSongWait_Anim runs the same timer helper, ignores its boolean result, and never checks animation exhaustion. Neither transition helper explicitly reinitializes the timer. ftCo_800C3480 selects DamageSongRv with Ft_MF_None and 0,1,0,NULL. DamageSongRv_Anim does not process the timer or mashing; it calls ft_8008A2BC only when ftAnim_IsFramesRemaining returns false. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_DamageSong.c#L46-L113.

Zero, including signed zero, and negative post-update timers satisfy the expiration test. A NaN timer does not: the initial callback can still enter Wait when its animation ends, and Wait's timer comparison alone will not recover from a persistent NaN. Positive infinity remains non-expiring under finite reductions; negative infinity expires unless arithmetic first produces NaN. Negative or zero coefficients can prevent ordinary countdown behavior or make nominal mash reduction an increase. Therefore 'not expired' is not universally equivalent to 'positive', and eventual recovery is not guaranteed for arbitrary data. No compiled floating-point mode or asset coefficient validation was available.

The shared mash routine subtracts x640 once for any pressed AB/XY/LR button mask, and once more if either remembered left-stick direction changes after strict threshold comparisons. Simultaneous button and direction changes can therefore subtract twice. Merely returning the stick to neutral does not reset the remembered direction here. It also updates shake-related flags and reports the mash result to pl_800402D0. DamageSong ignores the routine's return value and tests the resulting timer. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftcommon.c#L682-L719.

The active motion table connects the three callback families to FuraSleepStart, FuraSleepLoop, and FuraSleepEnd respectively, each with ftCamera_UpdateCameraBox. This supports a sleep start/loop/end state sequence without inferring gameplay from numeric enum labels. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftmotionstates.c#L3401-L3433.

## IASA, physics, collision, and exit
All three IASA callbacks have empty bodies and do not even dereference their parameters. This establishes absence of transitions through those callbacks, not immunity from damage, collision, or other engine transitions. All three Phys callbacks forward the same object to ft_80084F3C. That helper selects ground_friction, scales it only when ABS(gr_vel) > walk_max_vel, then calls ftCommon_ApplyFrictionGround and ftCommon_ApplyGroundMovement. Equality does not take the scaling branch; unordered NaN comparison does not either. Scaling is not necessarily an increase without coefficient evidence. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_DamageSong.c#L66-L125 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_084E.c#L42-L53.

All three Coll callbacks forward the same object to ft_80084280. Its ordinary path copies positions and stick input into collision data, sets facing, runs mpColl_8004B4B0, and copies the resulting position back. Opposing nonzero player-nudge velocity selects ft_800827A0 instead. If that collision result and ftCo_8009A3C8 both fail, it enters Fall. Therefore timer and animation transitions are not the only possible exits from the sequence. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_081B.c#L1062-L1099.

ft_8008A2BC dispatches Master Hand and Crazy Hand specially; otherwise ft_8008A348 can select DownSpot or another exceptional route before its ordinary Wait transition. Its ordinary path also contains air handling and character-specific work. Recovery animation completion must not be described as an unconditional Wait transition. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_08A1.c#L53-L108.

## Separate Cape-element gate
ftCo_800C3538 returns false immediately if x2222_b2 is set. Otherwise status values 9, 10, and 11 also return false. Every other represented status calls ftCo_800C3598 and returns true. No gameplay names are assigned to the excluded status values. In ftCo_8008EC90, a preceding active-response/no-knockback branch bypasses the Cape gate; the HitElement_Cape branch uses true to jump to its common completion label, while false records facing and continues remaining logic. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_DamageSong.c#L127-L142 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_Damage.c#L838-L854.

The initializer stores x648 into dmg.x18F4, raises x2220_b4, updates another duration field if necessary, and computes response velocity using ground/air selection, damage angle, incoming facing, and floor normal. Its updater acts only when x18F4 != 0, decrements it by one, and reverses facing only when that decrement produces exactly zero, then optionally calls x21F8. Consequently unconditional eventual reversal is not proved for arbitrary timer values. A zero initial timer skips the updater body; other abnormal values may fail to reach exact zero. The owned gate does not install or own x21F8. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_0C35.c#L15-L87. The active Cape-element association is established, but a Mario-specific producer association was not independently established in this review.
