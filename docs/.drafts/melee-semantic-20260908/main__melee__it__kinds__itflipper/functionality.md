# Flipper semantic review

The unit implements seven motion states, ordered by the header enum and dispatch table: RESTING (0), FALLING (1), HELD (2), INFLIGHT (3), AIRBORNE (4), ACTIVE (5), and SPINNING (6). These state indices are distinct from the table's animation identifiers. HELD has no collision callback; ACTIVE and SPINNING share physics and collision callbacks.

Ordinary spawn initialization clears seven Flipper-specific fields and enters FALLING. Grounded RESTING resets velocity and delegates support checks; falling collision supplies the resting continuation. AIRBORNE has inert animation and physics callbacks and delegates collision with resting/falling continuations. Neither RESTING nor AIRBORNE is the timed deployment destination.

Dropping forwards directly to throwing. Throwing selects normal or smash flight duration only when an owner exists; an ownerless item retains its previous timer. INFLIGHT animation decrements this remaining timer and calls Settle at zero or below. Flight physics applies fall parameters and, when the timer is at most ten, multiplies X/Y velocity by timer/(1+timer). There is no local lower-bound guard. Flight collision conditionally multiplies X according to collision bits, but all three Y multiplications execute for every nonzero collision mask; these must not be simplified into independent wall/floor branches.

Settle clears X/Y velocity, sets settlement flags, initializes lifetime from the special attributes, performs additional stage-fixed setup, and enters ACTIVE. ACTIVE/SPINNING animation tests angular velocity before calling shared maintenance. Shared maintenance updates spin, damps residual planar velocity, refreshes hitboxes when a positive cooldown reaches zero, and decrements lifetime only for non-stage-fixed instances. Expiration returns true before the late-lifetime helper can run. The generic item update consumes a true animation result as a destruction request.

Spin impulses use contact-position quadrant comparisons, add the configured base term, and clamp angular velocity. Fighter-derived paths use planar motion magnitude or a ten-degree fallback and consume the pending fighter reference even when its eligibility check fails. UpdateSpin performs single-step ±2π corrections, signed decay, angle integration, and model X rotation—not an arbitrary-range normalization loop.

Damage-dealt, clank, and shield-contact callbacks distinguish unsettled rebound from settled spin/cooldown handling. Their threshold compares remaining flight time against six, not elapsed frames. Damage-received is inert unless settled and consumes the separate xCEC fighter reference. Repel changes the supplied Flipper's own planar velocity away from another Flipper; it does not push a fighter. Stage-fixed exclusion is imposed by its callers.

Joint-based spawning returns NULL for a null joint or failed creation. Success stores the joint pointer and stage-fixed flag before settlement. Shared settled physics follows a non-null anchor; stage-fixed instances skip local lifetime decrement and collision delegation. No ownership transfer or anchor-destruction protocol is established here. The event adapter delegates matching owner/interaction-reference cleanup to it_8026B894; that helper does not clear the Flipper's joint anchor.

Canonical and rendered views were reviewed completely. The rendered itFlipper_ClearReferences hypothesis is independently supported by the canonical shared cleanup implementation and is retained. Existing supported names and explanations are retained without cosmetic rewriting. Doxygen's debugger narratives remain documented historical observations, not newly reproduced runtime or compiled evidence. Its full-lifecycle watchpoint wording exceeds the transitions actually listed, and several baseline explanations conflate AIRBORNE/RESTING with deployment or reverse repulsion's actor. Those defects are explicitly accounted for in the exception ledger. Compiled section contents, sizes, and placement remain unverified.
