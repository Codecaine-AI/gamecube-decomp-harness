## Versus mode state coordination

`gmvsmode.c` defines two terminated `GameModeState` arrays and eleven lifecycle callbacks. The standard array registers CSS, SSS, VS, Sudden Death, Results, Approach, Approach-VS and Prize. CSS through Results use `lbDvdPreload_3`; diversion states and both debug states use `lbDvdPreload_2`. CSS, SSS and Approach reuse their respective objects for entry and exit; normal and approach battles share StartMeleeData and VS exit storage; Sudden Death shares start storage but has separate exit storage. Results and Prize have NULL exit payloads. These are source initializer observations, not compiled section/layout claims. [Source](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gmvsmode.c#L28-L159)

The header assigns standard IDs 0–4, Approach 128, Approach-VS 129 and Prize 192. Debug IDs are separately defined as 1 and 3, with NULL exit callbacks. Their array order must not be confused with consecutive numeric IDs or proof of the engine's automatic transition policy. [Header](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gmvsmode.h#L6-L18) [Debug table](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gmvsmode.c#L128-L159)

## Selection and battle setup

CSS entry delegates with `VS_MELEE`, persistent Versus configuration and the state. The helper exposes retained KO counts and copies configuration into CSSData. Cancellation value `CSSPendingSceneChange_2` requests GM_MENU before committing selections; otherwise configuration is copied back and character audio masks are accumulated across all slots. SSS entry copies configuration; SSS exit commits it and prepares stage audio only when `start_game` is set, otherwise explicitly schedules CSS. Persistent configuration comes from `gmMainLib_804D3EE0->modes.vs_melee`, while the scene payloads and KO buffer reside in `gmvsmelee.c`. [Wrappers](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gmvsmode.c#L196-L219) [Storage](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gmvsmelee.c#L23-L39) [Helpers](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gmvsmelee.c#L119-L205)

Normal VS entry supplies NULL whole-match and per-player customizers. Shared setup copies rules and players, sets the stock flag conditionally and VS flag unconditionally, and configures colors, rumble and announcer. Debug entry instead applies defaults and fixed overrides: timed rules, `St_Kind_Last`, xB/xC equal to -1, zero stocks and CPU kind 4 for every initialized player; slots 0/1 are human Link/Mario, slots 2/3 inactive Link, and rumble is disabled for the first four slots. Unknown fields are not assigned item semantics here. [Debug setup](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gmvsmode.c#L161-L194)

## Match completion and retained results

VS exit first delegates human-specific bookkeeping and winner-based routing: no multiple winners selects Results; multiple winners selects Sudden Death. It then submits x20, self-destructs and x44 for every non-NA standing, without a local cancellation guard. Canonical updater bodies independently identify KO, self-destruct and total-damage destinations; rendered names alone were not used as proof. [Exit](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gmvsmode.c#L221-L237) [Routing](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gmvsmelee.c#L207-L233) [Counters](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gm_1601.c#L1503-L1542)

Sudden Death entry combines persistent setup with the retained original VS MatchEnd. Its exit passes the separate tiebreak MatchEnd and retained original result to reconciliation. Results entry initializes ResultsMatchInfo and copies that retained VS result; the same entry callback is registered for debug Results. Neither Sudden Death wrapper makes a local successor choice. [Wrappers](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gmvsmode.c#L239-L252) [Shared lifetime](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gmvsmelee.c#L235-L275)

Results exit uses CSS as fallback, not an unconditional destination. Shared processing updates KO counts outside its cancellation guard and may select Approach or Prize when human participation and subsequent-table-entry conditions permit. Diversion paths prepare the archive and return without selecting CSS; the fallback also prepares the archive. After this helper returns, the wrapper separately tests the displayed ResultsEnterData outcome and calls `gm_801623A4` only for a non-canceled match. That routine updates persistent fighter and name records. Thus original VS storage and the Results copy remain distinct, and cancellation does not suppress every bookkeeping effect.
