## Dr. Mario pill item behavior

The unit implements launched Megavitamins, the Appeal pill, and fighter-associated presentation props. Its seven `ItemStateTable` rows use animation IDs `[0, 1, 2, 1, 3, 4, 5]`: row indices must not be confused with those animation IDs. Row 0 uses projectile callbacks, rows 1–2 share Motion2 callbacks, and rows 3–6 share Motion6 callbacks. The header declares the public constructors, lifecycle/event callbacks and table. ### Launched projectile

The ordinary constructor builds a zero-velocity spawn descriptor and gates subsequent initialization on successful creation. The initializer derives planar launch velocity from pill speed and angle attributes, mirrors X by facing direction, initializes lifetime from attribute x8 and enters row 0. Its animation callback subtracts 1 before checking for nonpositive lifetime. Physics supplies falling parameters to the common physics helper and updates spin speed—not air resistance. Collision processing tests speed only after reported contact: speed strictly below attribute x10 returns true without playing the surviving-contact sound; otherwise contact plays SFX 0x15FAE and returns false. The local square-root helper uses four reciprocal-square-root refinements for positive inputs and returns other inputs unchanged. ### Appeal and presentation props

Appeal creation first initializes both lifetime fields from 1200 and enters row 1, then selects row 2, resets command variables and installs owner-follow state. The accessory callback copies the retained fighter position and applies retained-facing Y rotation only when its private parent pointer is non-null. Motion2 animation applies child visibility from the previous item command value before sampling the fighter command. It retains the prop only while the fighter validity predicate succeeds and the retained fighter equals the item owner; otherwise cleanup clears the private pointer/accessory callback and conditionally clears reciprocal fighter tracking. The numeric fighter guard accepts 0x155/0x156, consistent with the two Mario Appeal enum entries. It tests reciprocal tracking for non-null, not equality to this particular pill. The specialized constructor uses unchecked `msid + 4` state arithmetic. Observed selectors 0 and 1 create separately retained/scaled DeadRight props; selector 2 creates the Sleep prop and alone invokes fighter-part attachment. Pickup initializes both timers and enters row 6. Motion6 animation conditionally copies the retained fighter root's Y scale uniformly when the shared Sleep/iced-camera predicate succeeds, but always returns false, including for a missing parent. Its physics and collision callbacks only clear the common x15 flag; collision returns false. These engine pickup paths do not establish ordinary player grabbability of a flying pill. ### Interactions and lifetimes

Damage-dealt, clank, shield-hit, absorption and shield-bounce callbacks play the same sound and return true. Damage-dealt clears x15 once; the other four clear it twice, which is behaviorally equivalent for this idempotent helper. The shield dispatcher interprets true as destruction, not continued survival. Reflection instead reverses/scales planar velocity, reverses facing, copies the stored half-life timer into the active lifetime and returns false. Reference invalidation clears matching common interaction fields through `it_8026B894`, but does not clear pill-private x4 or `on_accessory`. The surrounding removal loop separately destroys owner-dependent items using an owner pointer cached before the callback.
