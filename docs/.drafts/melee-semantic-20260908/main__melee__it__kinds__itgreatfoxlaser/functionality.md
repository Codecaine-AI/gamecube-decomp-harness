## Great Fox laser item

The unit creates `It_Kind_GreatFox_Laser` at an owner-model-relative offset, initially stationary and facing -1. Creation failure returns NULL without item initialization. Success applies the stage-provided scale, retains the owner and copied local offset, stores the variant, configures hitbox 0, and initializes motion state 0. The stored variant is tested as zero versus nonzero; named meanings for individual numeric variants remain unproven. [Source](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/kinds/itgreatfoxlaser.c#L27-L89)

Both table entries share animation and physics callbacks. Animation either recomputes owner-relative position or assigns variant-dependent horizontal velocity and hit configuration, according to `it_80272C6C`. These branches are not equivalent to motion states 0 and 1. Branch work occurs before the lifetime test: an already-zero counter returns true; otherwise it decrements and returns false. Initialization loads 60, and the reset routine's intermediate assignment of 1 is immediately overwritten by that initializer. [Source](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/kinds/itgreatfoxlaser.c#L14-L19) [Lifecycle](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/kinds/itgreatfoxlaser.c#L68-L131)

Reflection mutates geometry only in motion state 0. It subtracts the absolute world-space horizontal separation from the stored local offset's x component, recomputes item position, updates dynamic bone 2, and sets a pending flag. This does not generally prove that the bone coincides with the reflector. Physics subsequently consumes the flag, reverses facing, reloads the counter to 60, and enters state 1. Reflection outside state 0 is a no-op returning false. Damage-dealt, clank and absorption callbacks also return false without local processing. The final event adapter forwards both arguments unchanged to `it_8026B894`. [Source](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/kinds/itgreatfoxlaser.c#L119-L173)

The accessor deliberately reads through `likelike.x38`, with an explicit warning that `greatfoxlaser.x38` is s16. Its s32 result must not be described as an automatically unchanged copy of the spawn argument. The fighter-side caller checks Leadead hit element, capture cooldown, current motion state and a zero accessor result. Capture retains the damaging source and uses Leadead routines for attachment and release; this evidence does not establish a Great Fox-specific capture mechanic.
