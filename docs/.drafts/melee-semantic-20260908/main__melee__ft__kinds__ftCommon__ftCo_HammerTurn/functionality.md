# HammerTurn semantic review

## Scope, interface, and naming
The complete owned source and header implement a common-fighter HammerTurn entry check, a private entry routine, and animation, interrupt, physics, and collision callbacks. `ftCo_800C576C` has signature `bool(Fighter_GObj*)`; the other five functions return void. `ftCo_800C57B4` has internal linkage because of its preceding static declaration, although its definition does not repeat `static`. The header exposes the check and four callbacks, not the private helper. Its guard is `GALE01_0C576C`. There are no explicit global data definitions or owned dox files. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_HammerTurn.c#L1-L76 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_HammerTurn.h#L1-L13.

The rendered views were independently read in full. They substitute function names only, report zero parse errors, and preserve the control flow. `ftCo_HammerTurn_CheckInput` for `ftCo_800C576C` and `ftCo_HammerTurn_Enter` for `ftCo_800C57B4` are supported descriptive hypotheses, not canonical recovered names. External rendered aliases are not evidence of their own meaning. The declaration-order TODO does not establish original inlining or emitted layout.

The active motion table associates HammerTurn with `ftCo_SM_HammerMove`, `ftCo_MF_HammerTurn`, the Hammer move identifier, these four callbacks, and `ftCamera_UpdateCameraBox`. This table and the actual caller/entry chain support the Hammer action mapping without inferring gameplay from a numeric enum name. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftmotionstates.c#L3533-L3543.

## Input and entry
`ftCo_800C576C` forwards its object unchanged to `ftCo_800C97A8`; success invokes the private entry helper and returns true, and failure returns false. The predicate compares `input.lstick[0].x * facing_dir <= p_ftCommonData->x34`. Equality qualifies; an unordered comparison does not. The wrapper does not independently test item possession, grounding, or current motion. HammerWait IASA calls it after the jump and `ftCo_800C60C8` checks and before `ftCo_800C55CC`, consuming success through RETURN_IF. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_HammerTurn.c#L19-L26; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_Turn.c#L28-L46; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_HammerWait.c#L86-L92.

Entry derives the Fighter, computes flags using `ftCo_800C54C4`, and calls `ftCo_Turn_Enter(gobj, ftCo_MS_HammerTurn, flags, 0, p_ftCommonData->x6B0, ftCo_800C548C(fp))`, followed by `ftCo_800C4E94(fp)`. The shared initializer clears has_turned, just_turned, and the buffered pad field x1C; sets facing_after to negative current facing; writes frames_to_turn and x8; changes motion; and calls `ftAnim_8006EBA4`. The shared Turn IASA consumer confirms that x1C buffers A/B input, but HammerTurn does not call ordinary Turn IASA. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_HammerTurn.c#L17-L37; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_Turn.c#L49-L62; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_Turn.c#L97-L147.

The continuation condition is the inclusive HammerWait-through-HammerLanding motion range. Inside that range the frame helper returns cur_anim_frame and flags are SkipHit, SkipModel, SkipMatAnim, SkipRumble, SkipColAnim, UpdateCmd, and Unk19; outside it they return zero and Ft_MF_None. Shared setup conditionally invokes the identifier-106 helper, calls `it_8026C16C(item_gobj, true)`, sets x2219_b4, and calls `ftCommon_8007EBAC(fp, 1, 0)`. The exact meanings of 106, Unk19, and the deeper item/setup effects are not established merely by their aliases. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_HammerWait.c#L41-L46; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_HammerWait.c#L172-L208; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_HammerWait.c#L228-L232.

## Animation, optional paths, and numeric boundaries
Anim obtains a Fighter pointer before calling `ftCo_800C4F64`, then continues using it. The shared update calls `ftColl_8007AFF8` if x2338.x is nonzero. Otherwise, only for `cur_anim_frame >= 0 && cur_anim_frame < frame_speed_mul`, it calls `ft_800892A0`, `ft_80089824`, and `it_8027B070`. Zero is included and the upper endpoint excluded; an unordered comparison fails that interval. There is no returned transition/lifetime status checked by HammerTurn afterward. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_HammerWait.c#L62-L79.

Turn-specific work requires a nonzero `mv.co.walk.fast_anim_frame`. It resolves TransN and its secondary JObj, decrements the floating counter, and, unless x2222_b6 is set, computes `M_PI * ((x6B0 - remaining) / x6B0)` and supplies it to both `ftPartSetRotY` and `HSD_JObjSetRotationY`. The decremented counter is then compared with zero; if <= 0, facing_dir is negated and `ftCo_800C4ED8` enters HammerWait. Suppression skips only the rotation calculation/setters, not part lookup, decrement, or completion. This callback does not call ordinary Turn Anim or set has_turned. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_HammerTurn.c#L39-L60; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_HammerWait.c#L48-L60.

Under ordinary floating semantics, initial +0 or -0 skips the entire turn-specific path and does not complete. A negative nonzero counter completes after decrement, provided preceding calls return. A positive fractional counter can overshoot below zero and produce yaw beyond pi. NaN passes the nonzero guard but not <= 0; positive infinity does not expire, negative infinity passes the terminal comparison, and sufficiently large finite values can stop changing under subtraction by one. A normal positive integral counter with exact unit decrements reaches zero and, with positive nonzero duration and rotation enabled, yields the source's pi-based final yaw. This is not an exact real-number or arbitrary-input guarantee. x6B0 is declared int, whereas the counter and division are floating-point. There is no local positivity, finite-value, clamp, or zero-denominator check. A zero duration with a nonzero counter reaches division by zero when rotation is enabled; target trap/optimization behavior and runtime prevention of these cases remain unresolved. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_HammerTurn.c#L43-L58; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/types.h#L48-L69; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/types.h#L470-L470.

The union source annotates walk.fast_anim_frame and turn.frames_to_turn at the same offset. This supports an intended overlay, not verified compiled offsets or binary alias equivalence. The initialization-to-animation connection must retain that qualification.

`ftPartSetRotY` selects the primary joint unless it uses quaternion rotation, in which case it checks and writes the secondary joint. The extra explicit secondary setter in Anim therefore need not target a distinct joint. The inline setter asserts non-null and non-quaternion mode, writes rotate.y, and requests matrix dirtiness unless JOBJ_MTX_INDEP_SRT is set. Assertion failure calls a declared nonreturning assertion routine; normal completion cannot be assumed after a failed assertion. MUST_MATCH changes diagnostic line selection, not the condition. None of this proves literal attribution to this TU's data sections. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftparts.c#L1007-L1019; code://c302741689bd67c361cd7faadb221df3193992c3/src/sysdolphin/baselib/jobj.h#L315-L323; code://c302741689bd67c361cd7faadb221df3193992c3/src/sysdolphin/baselib/debug.h#L11-L33.

## Interrupt, physics, and collision
IASA contains only `RETURN_IF(ftCo_800C5A50(gobj))`, without a timer gate or lower-priority local check. The handler gets the shared jump discriminator and invokes `ftCo_800C5B88` for nonzero input. The classifier prioritizes upward stick >= threshold within a strictly-less-than timing window, then pressed X/Y. A NaN stick value does not accept the stick branch but does not prevent X/Y acceptance. Entry stores the discriminator in hammerkneebend.x4, clears hammerkneebend.x0, writes cargokneebend.x8 from jump_startup_time, and enters HammerKneeBend. Its Anim tests hammerkneebend.x8 <= 0 before decrement and calls HammerJump entry on that path. The exact compiled equivalence of the differently named timer members remains unresolved. Actual entry and callback-table consumers support the Hammer-specific startup route. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_HammerTurn.c#L62-L65; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_HammerJump.c#L15-L35; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_Jump.c#L30-L44; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_HammerKneeBend.c#L11-L34; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftmotionstates.c#L3544-L3575.

Phys forwards gobj to `ft_80084F3C`. That helper starts with ground_friction, scales it only when ABS(gr_vel) > walk_max_vel, applies ground friction, and then ground movement. Equality uses unscaled friction; an unordered comparison does not select scaling. Neither the wrapper nor immediate helper explicitly transitions motion. Universal transitive state preservation and unconditional deceleration for arbitrary attribute values are not proved. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_HammerTurn.c#L67-L70; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_084E.c#L42-L53.

Coll unconditionally delegates to HammerWait_Coll, which passes `ftCo_800C5D34` to `ft_8008403C`. That helper synchronously calls the supplied callback when `ft_80082708` returns false; it does not store the function pointer. The callback enters HammerFall, conditionally calls `ftCommon_8007D5D4` if grounded, and performs shared Hammer setup. Full lower-level terrain policy is not established. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_HammerTurn.c#L72-L75; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_HammerWait.c#L99-L102; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_081B.c#L1035-L1041; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_HammerFall.c#L26-L38.

## Ownership, dependencies, and reconciliation
All six owned parameter locators correspond to source Fighter_GObj* arguments. Locally these are borrowed engine objects: no owned function allocates, frees, retains, or transfers them. Fighter, common-data, part-array, item, and JObj validity are caller/engine preconditions, not locally validated guarantees. The retained Fighter pointer across shared animation processing needs a transitive lifetime guarantee not established here. Persistent callback-table entries are ordinary function pointers, not captured stack closures; the inspected collision callback is consumed synchronously. Register placement denoted by #r3 is not independently verified compiled ABI evidence.

Dependencies are shared Turn, HammerWait, HammerJump/KneeBend, fighter motion machinery and common data, ground movement, part lookup/rotation, JObj assertions/matrix invalidation, and math/platform definitions. No compiled artifacts were assigned. Exact .data/.sdata/.sdata2 contents, sizes, alignment, string/literal ownership, object offsets, and timer overlays remain unresolved.

The librarian's main source analysis and unresolved section/layout findings were independently confirmed. This lead additionally avoids retaining broad option-restriction claims solely from Hammer names, treats the explicit obsolete input field spelling as a repair, and does not promote the opaque item Boolean call into independently proved activation semantics. Half-turn and physics-state guarantees are replaced with guarded source behavior. Link relations are preserved individually, including duplicates; retained turning relations are qualified descriptions, not unconditional presentation guarantees.
