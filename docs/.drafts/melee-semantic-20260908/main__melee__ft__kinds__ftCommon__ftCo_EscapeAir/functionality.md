## Interrupt flow, ownership, and lifetime
IASA tests timer != 0, not timer > 0. In that phase it copies the saved Vec3 to a local before calling ftCo_80095328(gobj,&b). Success with b=true restores the entire copied vector. Success with b=false does not restore it. Both successes immediately return, skipping timer decrement and the final AirCatch check. Only first-phase failure calls ftCo_800D705C, ignores its result, decrements timer, and proceeds. Timer zero skips the first phase only. Any path reaching ftCo_800C3B10 scales then-current X by 0.1f if that helper succeeds. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_EscapeAir.c#L77-L96.

The item helper initializes b on every success where the caller reads it: direct throw paths write true; ftCo_80095744 writes true for its parasol branch and false otherwise. Neither retains the bool pointer. Failure need not initialize it because IASA does not read it then. Non-parasol release can succeed without a local motion-state change, so helper success must not be equated with transition. Copying velocity before item handling avoids rereading the saved move-state value after other move-state writes; compiled overlap offsets are not established here. No gameplay meaning is assigned to numeric throw IDs. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_ItemThrow.c#L190-L335.

ftCo_800C3B10 rejects used_tether, kinds other than LINK/CLINK/SAMUS, occupied accessory2/death1/accessory3 callbacks, and held items. LR held plus A pressed invokes setup and marks used_tether. Setup changes motion only for GA_Air, so success is not an unconditional state transition for arbitrary caller state. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_AirCatch.c#L54-L100.

Fighter and common-data pointers are borrowed and assumed valid; this unit contains no allocation, freeing, or ownership transfer. Parameter source types are established, but register labels and compiled ABI placement are not. Callback and local-output lifetimes are synchronous in the verified consumers.

## Physics and numerical boundaries
Phys multiplies current X/Y by escapeair_decay when command zero is zero; any nonzero command value instead calls ft_80084DB0. The local body does not update the timer or call a state setter. The alternate helper checks fast fall, applies fast-fall or gravity/terminal-velocity handling, and calls ftCommon_8007D268. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_EscapeAir.c#L98-L107; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_081B.c#L1363-L1375.

A name containing decay is not proof of damping bounds. For ordinary finite arithmetic, factor 1 preserves components, 0 zeros finite components, negative factors can reverse direction, and magnitude above 1 can amplify. Negative force reverses the mathematical directional vector. There is no local finite-value validation. Under ordinary floating comparisons NaN does not satisfy a strict deadzone comparison; zero or negative deadzones can send centered input to atan2f. Target-specific NaN, infinity, signed-zero, subnormal, and transcendental results remain unverified. Timer 1 becomes zero after first-phase failure yet still reaches the final check that invocation. Negative timers are active and are not guaranteed to terminate; extreme decrement behavior requires type/compiler evidence.
