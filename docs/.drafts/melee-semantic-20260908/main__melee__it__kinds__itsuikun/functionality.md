## Suicune summoned-item lifecycle

The unit defines a two-entry `ItemStateTable` and Suicune-specific spawn, terrain, animation, physics, accessory, and reference-lifetime callbacks. The canonical Pokémon registry associates `it_803F7E08`, `itSuikun_Logic14_Spawned`, and `it_802CFCB8` with Suicune. Existing Poké Ball/Blizzard mappings remain appropriate context; this unit does not directly implement damage or freezing. [Registry](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/it_279C.c#L325-L342)

### Appearance and landing

Spawn runs shared setup, clears command variables 0, 1, and 2, forwards special attribute `x0` to shared Pokémon setup, and enters state-table index **1**. This index has motion selector **-1**, distinct from the state index itself. Its animation callback delegates shared appearance scaling and always returns false. Its physics callback delegates falling/appearance processing and ignores the helper's completion result. The helper decrements a positive appearance timer; final scale restoration occurs on a call that starts with a nonpositive timer, not immediately after decrementing to zero. [Spawn and table](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/kinds/itsuikun.c#L15-L34), [State 1](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/kinds/itsuikun.c#L142-L162), [Shared updates](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/it_279C.c#L1077-L1129)

State-1 collision delegates terrain processing with `it_802CFCD8` as the floor-contact event. The shared wrapper always returns false even when the event changes state. Terrain processing handles other surface contacts separately; qualifying floor contact performs generic landing setup, invokes the Suicune event, and then restores model scale. The Suicune event requests a large quake, plays sound `0x9`, resets velocity, and initializes state **0**, whose motion selector is **0**. State 0 installs effect-hitlag callbacks, assigns `it_802CFF30` as the accessory callback, and copies the configured Pokémon timer. ### Active audiovisual behavior

The accessory callback is inert until command variable 0 is nonzero. It consumes that command, enables variable 2, requests effect `0x469` attached to the item's root joint with a local `1.0f` scale argument, and plays sound `0x2749`. Effect dispatch synchronously creates effect resource `0x2E` and, on allocation success, copies the pointed-to float into all three scale components. It does not retain the stack-local scalar pointer on this path. Suicune ignores the spawn result: timing is enabled and the initial sound is requested even if effect allocation fails. Reissuing command 0 can request another effect; there is no existing-effect guard. [Accessory](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/kinds/itsuikun.c#L126-L140), [Synchronous routing](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ef/efsync.c#L70-L80), [Effect-specific consumption](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ef/efasync.c#L1034-L1042)

State-0 animation processes shutdown command variable 1 first: it clears variables 1 and 2 and destroys the object's effects. It next returns true if the shared animation/lifetime predicate returns false. Otherwise, only an enabled variable 2 permits timer progression. The timer is predecremented, and exactly zero selects one of `0x274A`, `0x274B`, or `0x274C` through `HSD_Randi(3)`, plays it, and reloads the configured timer. There is no nonpositive-value clamp or immediate-expiry branch. Shutdown does not clear a pending variable-0 activation command, so these local bodies alone do not establish global precedence between activation and shutdown across callback scheduling. [Animation control](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/kinds/itsuikun.c#L69-L104)

State-0 physics applies configured falling physics only for `GA_Air`. Collision selects `it_8026E248` for `GA_Air` and `it_8026D62C` for every other value, passes the same empty `it_802CFCB4` hook, and always returns false. The hook's concrete terrain-callback use is recoverable and corrects the baseline explanation that its intended hook cannot be determined from call sites. ### Reference lifetime and rendered-name assessment

`it_802CFCB8` forwards the item and referenced object to common relationship cleanup, discarding the owner-match result. Matching owner, reflector, absorber, fighter/source, auxiliary-fighter, and toucher references are cleared; source-player metadata becomes 6 when the fighter/source reference matches. The outer event caller separately retains the previous owner and may request item destruction under its own flag condition. That outer lifetime policy must not be confused with this void cleanup wrapper. [Wrapper](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/kinds/itsuikun.c#L41-L44), [Cleanup and caller](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/it_26B1.c#L475-L525)

Both owned canonical and rendered files were read completely. Existing `Blizzard_Anim`, `Attack_Phys`, `Fall_Anim`, `Appear_Phys`, `OnGroundContact`, and `Logic14_EvtUnk` hypotheses fit their demonstrated roles; synonym-only renaming is unwarranted. `Fall_Anim` and `Appear_Phys` belong to the same state, not separate phases. The header spells the event's second argument `Item_GObj*`, whereas its definition spells it `HSD_GObj*`; the renderer preserves this source difference. No renderer parse or substitution defect was observed. Compiled section extents, padding, and the attribution of the local float literal to `.sdata2` remain unverified.
