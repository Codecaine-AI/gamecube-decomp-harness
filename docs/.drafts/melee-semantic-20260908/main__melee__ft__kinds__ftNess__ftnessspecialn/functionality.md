# Ness fighter-side PK Flash TU

This TU implements the fighter-side neutral-special lifecycle, not the projectile's complete simulation. Its public interface comprises two entries, six animation callbacks, six IASA callbacks, six physics callbacks, six collision callbacks, and three association helpers. Canonical names and rendered aliases are distinct evidence.

## Dispatch and naming

The active table assigns Start and End families to their corresponding states, but shares each canonical Release callback family between Hold and Release, on ground and in air. Hold and Release use Hold0 and Hold1 submotions. Rendered Hold-only aliases are therefore incomplete role descriptions, not recovered original names. Independently verified dispatch: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftNess/ftness.c#L100-L187.

## Entry and startup

Both entries change to Start, clear command variables 0–3, copy four signed timing attributes into move counters, clear the fighter's item reference and death2_cb/take_dmg_cb, and call ftAnim_8006EBA4. Air entry also zeros vertical velocity. Overwriting the reference does not detach an existing item. On animation completion, Start enters Hold and conditionally attempts construction only when the reference is absent. The supplied position comes from FtPart_L2ndNa, with Z zeroed and Y increased by three times fighter Y scale. The constructor separately derives spawn.pos and copies the supplied vector to spawn.prev_pos. Callbacks are installed only for a non-null construction result. Maximum jumps are assigned regardless of allocation success or an existing reference. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftNess/ftnessspecialn.c#L105-L221; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftNess/ftnessspecialn.c#L302-L342; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/kinds/itnesspkflash.c#L84-L119.

## Hold/Release animation and input

Both shared animation callbacks decrement frames_to_loop_charge_ground whenever nonzero and frames_to_loop_charge_air only when the reference is absent and that counter is nonzero. These field names do not restrict execution to the named environment. With an absent reference, both post-update counters nonpositive cause immediate End entry; otherwise Release is selected if necessary with the current animation frame. Release may be skipped. With a reference, owner mismatch clears only the fighter reference and returns, leaving callbacks unchanged. Otherwise item predicate it_802AA7F0 can select Release. That predicate tests item state 2, which is collision-associated, not a generic full-charge or explosion condition; normal release/expiration uses state 1. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftNess/ftnessspecialn.c#L224-L267; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftNess/ftnessspecialn.c#L345-L385; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/kinds/itnesspkflash.c#L46-L60; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/kinds/itnesspkflash.c#L202-L229; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/kinds/itnesspkflash.c#L342-L356.

Release IASA subtracts from charge_release_delay before eligibility testing, clamps nonpositive results to zero, returns on a positive result or held B in input.held_buttons[0], and otherwise clears the fighter reference and both interruption callbacks. An initial delay of 1 can release during the same call. No motion change, item ownership clearing, or explosion creation occurs directly. Late null guards do not protect initial Fighter/counter access. Start and End IASA are empty, which proves no local input transitions rather than global non-interruptibility. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftNess/ftnessspecialn.c#L414-L519.

## Association and cross-file lifetime

CheckSpecialNHold checks only non-null GObj/Fighter/reference and ground or air Hold motion. It does not validate fighter kind, item identity, lifetime, owner, or B input. SetNULL clears fighter association and callbacks with early null guards. ItemPKFlushSetNULL additionally invokes it_802AAA50 before clearing the fighter reference; that helper clears current and recorded item owners and flag x13 without destroying the allocation. The installed OnDamage invokes this stronger cleanup. Item destruction separately notifies the Ness fighter when recorded and current owners agree; charging and steering add their own ownership checks. Thus B-release association clearing, interruption detachment, destruction notification, and explosion creation are distinct operations. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftNess/ftnessspecialn.c#L32-L94; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftNess/ftness.c#L482-L488; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/kinds/itnesspkflash.c#L121-L158; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/kinds/itnesspkflash.c#L202-L229; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/kinds/itnesspkflash.c#L241-L328.

## Ending, physics, and numeric boundaries

Every End animation invocation reloads all four counters, clears fighter association/callbacks, and resets part 0 X rotation. Completed ground End calls ft_8008A2BC rather than directly writing Wait. Completed air End selects ordinary Fall for exact zero landing lag and ftCo_80096900 otherwise. The latter normally enters FallSpecial but has an x2224_b2 alternate branch; unconditional helplessness is not established. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftNess/ftnessspecialn.c#L269-L300; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftNess/ftnessspecialn.c#L388-L412; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_FallSpecial.c#L28-L59.

Ground Start physics decrements nonzero gravity delay before the common ground movement/friction helper; ground Release and End only call that helper. All three air physics callbacks decrement nonzero delay and skip gravity for that invocation, or apply PK Flash falling acceleration and common terminal velocity when delay begins at zero. Air friction runs in either case. A delay of 1 postpones acceleration until a subsequent call, unlike release-delay eligibility. Repeated End-animation reloads prevent treating End as a one-shot countdown without scheduler evidence. Negative signed counters continue decreasing rather than saturating; signed-minimum subtraction has no portable defined C result. Exact-zero lag includes both signed zeros; other finite values, infinities, and NaN take the other call without local validation. Falling velocity clamps only on a strict less-than comparison. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftNess/ftnessspecialn.c#L521-L611; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftNess/types.h#L41-L53; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftcommon.c#L462-L468.

## Collision discrepancy

Ground callbacks return on nonzero ft_80082708 and convert on zero to AirStart, AirHold, or AirEnd. Air callbacks return on zero ft_80081D0C and convert on nonzero to Start, Hold, or End. Shared Release collision therefore selects Hold even from Release. Conversion helpers preserve the current frame with rate 1/blend 0 and forward FTNESS_SPECIALN_COLL_FLAG. They also change common jump/ECB bookkeeping, so startup's maximum-jumps assignment is not a terrain-conversion invariant. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftNess/ftnessspecialn.c#L614-L689; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/inlines.h#L71-L89; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftcommon.c#L515-L594.

The pinned ground query returns fall_off_ledge ? GA_Air : GA_Ground, with Ground=0 and Air=1. Its literal result conflicts with the baseline support-loss explanation for these callers. This review preserves that discrepancy without silently repairing source or claiming binary equivalence. Query calls also update collision positions; a no-transition branch is not side-effect-free. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_081B.c#L393-L404; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/forward.h#L442-L445.
