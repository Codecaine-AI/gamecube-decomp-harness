## Mario resource metadata

This data-only translation unit defines eighteen writable character arrays: Mario's base archive/public data name, fifteen strings grouped into five costume resource triples, and the animation archive name. Costume rows are ordered Nr, Ye, Bk, Bu, Gr, each pairing an archive with model-joint and material-animation-joint names. It also defines four standard demo labels, two additional demo-motion pointers, and a separate five-element `UnkCostumeStruct ftMr_CostumeList` without an explicit initializer. These are source declarations, not proof of compiled section membership or layout. [Source](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftMario/ftmariostrings.c#L5-L44)

The header exports the standard demo descriptor and additional motion table. Both owned rendered views match canonical source with zero substitutions and no parse errors; their function-only rendering does not independently validate data-section names. Existing metadata explanations remain useful and require no cosmetic rewrite. [Header](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftMario/ftmariostrings.h#L1-L9)

Generic fighter tables register Mario's metadata. Preloading normalizes an out-of-range ordinary costume to zero; `0xFF` instead requests every costume. Non-null base, costume and animation filenames produce queue requests, with a separate conditional effect preload. Resource names have static storage duration; this unit does not itself allocate or release loaded archives. Generic costume loading stores archive/joint results separately and skips loading when the cached joint exists. Its switch has no default and leaves the offset uninitialized for other inputs; no safe fallback is established. The adjacent callback leaves outputs untouched for unsupported selectors.
