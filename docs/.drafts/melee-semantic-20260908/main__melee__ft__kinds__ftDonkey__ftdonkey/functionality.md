## Donkey Kong initialization and dispatch

The unit defines a five-element costume-resource cache, fighter and animation resource names, five costume resource triples, four demo-motion names, and 46 motion-state descriptors. The header declares the public objects and twelve callbacks. The table comments identify states 341–350 as heavy-item movement, 351–368 as cargo movement and grounded/airborne directional throws, 369–378 as neutral-special phases, 379–380 as side special, 381–382 as up special, and 383–386 as down-special phases. Heavy callbacks are Donkey-specific; cargo callbacks are shared ftCo_Cargo routines. Every descriptor supplies ftCamera_UpdateCameraBox. NULL animation and IASA slots remain meaningful exceptions, and airborne cargo throws reuse grounded submotions while selecting shared airborne callbacks. ## Item and knockback adapters

Pickup forwards the caller boolean plus fixed 1,1 options; drop forwards its boolean plus true,true. Visibility and knockback callbacks forward true. Shared item visibility excludes heavy held items. Shared pickup also excludes heavy items, maps hold-kind values 1–4 to animation selections 1,0,2,3, and conditionally performs the show operation. Drop always requests selection -1 and conditionally performs the hide operation, without a local heavy-item guard. Shared knockback entry applies animation value 3.0 to selectors 1 and 0; exit applies 0.0 to those selectors. The shared knockback selector is s32 despite the wrapper's true literal. ## Hand Slap placement and exceptional paths

SpecialLw loop setup clears throw_flags and installs ftDk_Init_8010DB3C in accessory4_cb. Its invocation first tests and consumes throw_flags_b3, then tests floor contact. Consequently, a set B3 event is consumed even when floor contact is absent: the baseline's claim that this path has no effect is incorrect. With both conditions satisfied, four offsets are computed as x68*i - x68*1.5 + x6C*facing_dir. Each floor query receives the current floor index, fighter position and x70. Query failure substitutes the fighter position; every result, including fallback, receives y += 2.0 before updating the corresponding x914 entry. No hitbox position is updated when either condition fails. The down-special effect helpers explicitly clear accessory4_cb, so installation is not a permanent fighter property.
