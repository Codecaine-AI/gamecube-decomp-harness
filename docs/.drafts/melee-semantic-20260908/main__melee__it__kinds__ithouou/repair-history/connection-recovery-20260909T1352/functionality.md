## Ho-Oh and Sacred Fire

The unit defines six Ho-Oh parent states and a separate, single-state Sacred Fire child. The header declarations agree with the canonical implementations. Both owned files were reviewed completely in canonical and rendered form, and all 73 subjects, 205 facts and 53 links were enumerated and explicitly dispositioned.

Ho-Oh initialization saves its release position, clears animation-command variables, loads the depth-phase countdown, enters airborne state 0 and initializes shared Pokémon appearance processing. The parent attribute named `timer` is passed to common setup as a model-scale argument; the Sacred Fire spawn callback separately uses its attribute `timer` to initialize `xD44_lifeTimer`.

State 0 separates appearance-scale animation from physics-controlled activation. Its physics helper performs movement processing and decrements a countdown even when returning false; that path is not mutation-free. State 1 advances on animation inactivity. State 2 applies animation-derived movement and an accumulated attribute-selected vertical contribution, transitioning strictly above the camera-adjusted upper blast boundary. State 3 loops its animation while independently decrementing its private countdown: the previous timer value controls whether configured depth velocity continues or state 4 begins. State 4 seeds and advances its vertical accumulator and zeros vertical velocity below the saved release height minus 10; it does not clamp position. Its animation callback independently enters state 5.

State 5 installs an accessory callback and enables the generic boundary-removal gate `xDCC_flag.b3`. Its two accessory command branches are independent: each clears its command before dispatch, so both can execute during one invocation. The first requests paired effects on dynamic bones 16 and 17 at scale 1.3; the second attempts Sacred Fire creation. Parent animation completion returns true, which the generic item dispatcher consumes as a destruction request.

Sacred Fire construction first queries from the saved release position to the bottom blast boundary. Only if that fails does it query from the top blast boundary to the saved release position. The fallback is not an upward-directed query originating at the release point. Both failures produce no spawn. On success, the hit position supplies `prev_pos`, the saved release position supplies `pos`, ownership and parentage are propagated, and the returned line ID is stored in the child's `houou.timer` field. The constructor immediately dereferences the spawn result without a local allocation-failure check.

The child's line ID is distinct from its lifetime. Child physics conditionally obtains movement from the selected line and adds it to position; it does not decrement the line-ID field. Child animation delegates lifetime progression. Child collision propagates the shared floor-query result, always synchronizes collision position and conditionally records the floor index. A true collision result is consumed by the generic dispatcher as a destruction request, not merely informational contact reporting. Parent and child reference-event wrappers independently delegate matching-reference cleanup, including source-player reset when the fighter reference is cleared.
