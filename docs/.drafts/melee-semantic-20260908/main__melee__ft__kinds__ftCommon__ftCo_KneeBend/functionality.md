## Scope and interfaces
The owned unit comprises ftCo_KneeBend.c and its header. Enter accepts Fighter_GObj* and ftCo_JumpInput; Anim, Check_ShortHop, IASA, Phys and Coll accept Fighter_GObj* and return void. It implements common pre-jump startup, conventionally jumpsquat. Header address annotations are not compiled evidence.

## Entry and completion
Enter stores the initiating jump source, clears kneebend.is_short_hop and requests ftCo_MS_KneeBend with flags 0U and animation start/speed/blend 0,1,0. It provides no local pointer, eligibility, state or discriminator validation. Anim completes when cur_anim_frame >= jump_startup_time OR no animation frames remain. Equality completes startup, and animation exhaustion can complete it earlier; the animation helper is skipped when the comparison succeeds. A held non-NULL It_Kind_ScBall selects ItemScrew, otherwise ordinary Jump. ## Release latch
Check_ShortHop sets true for XY with neither X nor Y held, LStick with left-stick Y strictly below tap_jump_release_threshold, or CStick with C-stick Y strictly below that threshold, each matched to the stored source. Holding either button prevents XY release. Equality and unordered NaN comparisons do not satisfy stick release; unsupported source values match no branch. Live-input tests precede source equality tests, so unrelated inputs can still be evaluated. Otherwise the field is preserved. The helper never clears it or validates the active state; Enter is the only explicit false assignment in this TU, not a proved global exclusive reset. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_KneeBend.c#L19-L57.

The field is declared int despite Boolean usage. The later jump initializer selects hop versus jump vertical velocity using jump.x0 rather than an explicitly spelled kneebend.is_short_hop read. Compiled compatibility and preservation through state change remain unresolved. ## Interrupts and naming
IASA checks canonical ftCo_Attack100_CheckInput, Catch and NoD0 AttackHi4 in order, immediately returning on each true result. Only all-false execution performs release detection. Despite its name, Attack100_CheckInput checks for a non-NULL ftData_SpecialHi entry and dispatches it when x686 == 0; it is not rapid-jab continuation. Rendered naming is supported by this canonical body, not independent evidence. True establishes handling by the predicate, not independently verified transition success for every per-kind handler. Catch includes preliminary handling before eligibility and held-L/R plus pressed-A checks. NoD0 omits the ordinary stick tilt timer condition and can select an item throw, Ness-specific attack or common up smash. These are optional branches, not an exhaustive grab/up-smash-only interpretation. ## Physics and collision
Phys forwards to ft_80084F3C, which starts with ground_friction, scales it only when ABS(gr_vel) > walk_max_vel, then applies ground friction and movement. Equality uses unscaled friction; NaN makes the ordered comparison false. Nonfinite or negative attributes are not sanitized, so ordinary deceleration language assumes valid data. Coll forwards to ft_80083F88. Its query copies collision current position to last position, seeds current position from the Fighter, invokes mpColl_8004B108 and writes processed position back. True maps to GA_Air and false to GA_Ground; Fall is entered specifically on GA_Ground. Physical support polarity remains unresolved rather than inferred from names.
