## Moltres item lifecycle

The canonical Pokémon registry binds `it_803F7C10`, `itFire_Logic6_Spawned`, and `itFire_Logic6_EvtUnk` to **Fire (Moltres)**, separately from Entei. This unit implements Moltres's appearance and upward departure, associated with the existing Fly mechanic. It does not establish Entei's Fire Spin behavior. [Registry](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/it_279C.c#L181-L305)

- **Spawn:** retrieves special attributes, clears facing and item-command variable 0, enters the common air/state-0 initialization sequence, then calls shared Pokémon setup with attribute `x0`. The air-entry inline installs effect pause/resume callbacks and initializes descriptor 0. [Spawn](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/kinds/itfire.c#L25-L33), [inline](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/kinds/inlines.h#L100-L108)
- **Motion state 0:** animation advances shared appearance scaling. Physics evaluates the side-effecting appearance helper every invocation. Its false result does not mean the entire callback was inert: the helper calls common processing and decrements the appearance timer. On true, the callback creates effect `0x464` at scale `1.1f`, calls velocity reset, loads vertical velocity from `x4`, enters motion state 1 with argument 2, installs effect hitlag callbacks, and sets `xDD1_flag.b1`. Shared appearance phase numbers are distinct from these motion-state numbers. [Local callbacks](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/kinds/itfire.c#L113-L142), [shared appearance logic](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/it_279C.c#L1043-L1130)
- **Motion state 1:** physics is empty, but that does not imply zero existing velocity or disabled common movement. Animation waits while the model-animation predicate succeeds; on false it creates effect `0x463`, loads vertical velocity from `x8`, requests state 2 with argument 2, and installs effect hitlag callbacks. The predicate tests active joint animation, so the false case includes absence of active animation, not solely elapsed animation duration. [State 1 and entry helper](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/kinds/itfire.c#L42-L70), [predicate](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/lb/lb_00B0.c#L39-L66)
- **Motion state 2:** animation repeats equivalent effect/velocity/state-entry setup whenever the animation predicate is false, then independently returns whether `pos.y` strictly exceeds the top blast-zone offset. Equality returns false; refresh can occur before a true removal result. Physics adds attribute `xC` to vertical velocity without a clamp. Attribute values and signs are not supplied by this source. The collision callback simply returns false; it does not prove immunity to all collision systems. [State 2](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/kinds/itfire.c#L72-L106)

## Terrain and cross-file lifetime

State 0 delegates through `it_8027A118` to common terrain processing with empty endpoint `it_802CC740`. Position, floor and surface handling still occur, including scale restoration on the floor-contact branch. State 1 uses `it_8026E7E0` with empty endpoint `it_802CC7D4`; invocation of that endpoint requires the floor bit and additional `it_8026DE98`, `it_8026DC24`, and `it_8026DD5C` checks. Neither empty endpoint supplies a Moltres-specific transition. [Terrain helpers](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/itgroundcoll.c#L583-L745)

The event callback forwards both objects to common reference cleanup and discards its owner-match result. Matching ownership and interaction references are cleared independently; a fighter-reference match also sets source player to 6. The outer event dispatcher can separately remove an item based on its saved owner and a flag, so the local cleanup callback is not the complete lifetime policy.
