# ftCo_0D8E

Five fighter-object helpers support common Catch/CatchDash processing and Link-family article cleanup. Canonical symbols are fn_800D8EC8, fn_800D9228, fn_800D949C, ftCo_800D94D8 and fn_800D952C. Rendered aliases remain hypotheses; the inherited renderer reported seven parse errors.

## Timed controllers

Only FTKIND_LINK and FTKIND_CLINK run the controllers. fn_800D8EC8 increments mv.ca.specials.grav, creates at converted signed threshold x84, and processes later events only in (x84,x90]. Its ordered equality ladder tests x88, x8C and x90. Creation obtains the right-thumb position, constructs the attribute-xBC article, stores it in u.lk.xC and installs accessory2/death1/accessory3 callbacks. Failure calls ft_8008A2BC and returns true. At x88 a horizontal stage test runs from collision-position x to thumb-matrix x plus 8*facing_dir*scale.y, at thumb-matrix y; both character branches calculate the same endpoint. Obstruction removes the article, calls ft_8008A2BC and returns true. Otherwise the controller submits horizontal velocity and plays a character-selected sound. At x8C it calls it_802A77DC and plays another sound; at x90 it requests removal. Ordinary paths return false. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_0D8E.c#L25-L108.

fn_800D9228 increments mv.co.catch.x0, creates at x94, and processes events only in (x94,xA0], with ordered x98/x9C/xA0 tests for vector submission, phase command and removal. It has no local obstruction test; only failed creation returns true. Its submitted (TetherAttributes.pos_x_0*facing_dir,0,0) vector is copied by it_802A78B8 to ItemLink.vel, not an offset. That callee selects item state 1; it_802A77DC selects state 4. Numeric selectors and rendered names do not prove firing/retraction semantics. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_0D8E.c#L110-L167; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/kinds/itlinkhookshot.c#L2136-L2166.

These are equality schedules, not catch-up schedules. Creation wins over subsequent events, and earlier equality branches win coincident converted thresholds. Out-of-interval and skipped thresholds are not recovered. Nonintegral counters, invalid ordering, negative/zero thresholds, float conversion and rounding can prevent events; NaN selects no event, and infinities cannot satisfy the finite active interval. Large float counters can stop advancing. Vector, facing and scale inputs are not validated. Both active intervals dereference the presumed live article even on nonevent frames. Catch entry initializes mv.co.catch.x0, but compiled aliasing with mv.ca.specials.grav remains unproved. Catch/CatchDash animation consumers short-circuit on a true controller result. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_Catch.c#L106-L141.

## Ownership and cleanup

Construction creates linked objects and records a fighter back-reference; linked construction can fail. Successful controllers replace three callbacks without saving predecessors. it_802A7AF0 reads the current xC and invokes the article's optional x10 callback. it_802A7AAC removes a present article or clears the three callbacks if xC is absent. it_802A7B34 updates linked geometry only with a present xC. Removal tolerates NULL, but clearing the article callback, fighter slot and callbacks, destroying linked GObjs and removing the item all require non-NULL item data, stored fighter object and fighter data. There is no ownership-identity or callback-replacement check. This is not a general stale-pointer-safe protocol. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/kinds/itlinkhookshot.c#L282-L367; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/kinds/itlinkhookshot.c#L2199-L2269.

fn_800D949C dispatches removal only for Link and Young Link, with no local xC check or clear. Both collision callbacks dispatch through fn_800D8E30, which calls this helper, fn_800D9C64 and then Fall entry. The external dispatcher's exact support condition remains deferred. ftCo_800D94D8 has no kind check: it removes a non-NULL xC, explicitly clears it and always calls the read-only ftLk_Init_BoomerangExists, discarding its result. ftLk_800EAF58 calls it after boomerang cleanup. Repeated calls do not resubmit the same cleared slot; valid Link-family state and article lifetime remain preconditions. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_0D8E.c#L169-L187; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_Catch.c#L163-L178; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftLink/ftlink.c#L296-L304; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftLink/ftlink.c#L350-L357.

## Eligibility and uncertainty

fn_800D952C is read-only and returns false exactly for Samus with non-NULL u.ss.x223C. Short-circuiting avoids reading that slot for other kinds. Three input routes use the predicate after their item-handling and Link-family prerequisites; ftCo_800D8B9C enters CatchDash without it. Beam identity, activity and a separate-model causal explanation remain unproved. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_0D8E.c#L189-L196; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_Catch.c#L16-L94.

Dependencies include fighter transitions and sounds, joint transforms, stage collision, item construction/operations and Link's boomerang predicate. The padded local attribute declaration does not prove compiled layout compatibility, and source does not establish either owned data section's placement or contents. Original names, exact sound meanings, item-state gameplay, scheduler/reentrancy guarantees and cross-file lifetime safety remain unresolved.
