## Shared visual-scene infrastructure

`vi.c` provides four shared operations, with declarations and an inline camera wrapper in `vi.h`.

- **Character animation lookup:** `viGetCharAnimByIndex` returns `vi_animation_table[index]` directly. The table contains 26 fighter-prefixed ViWait archive filenames; valid indices are 0–25. There is no bounds check, fallback, allocation, copying, or mutation. Scene setup passes the selected filename to the archive loader and retains the returned archive separately in scene-local globals. Source declarations do not establish compiled section placement of the literals.
- **Rumble cues:** `vi_8031C9B4`, rendered as `vi_TriggerRumble`, obtains the Adventure player's rumble-eligible slot and suppresses dispatch for sentinel 4. Otherwise both signed request arguments are forwarded unchanged. The downstream helper performs another preference check using literal nametag 120, then selects loaded `LbRb.dat` data and submits a rumble program. A zero duration becomes -2 downstream. The existing inferred name is supported independently by this canonical call chain.
- **Shared rendering:** `vi_8031CA04` selects camera values 2, 1, and 0, assigning `gxlink_prios` masks 9, 8, and 8 respectively. Each phase calls `HSD_GObj_80390ED0` with render-pass mask 7—not GX link index 7. The dispatcher traverses selected link lists and invokes callback passes 0, 1, and 2. The helper then calls `Camera_800313E0(gobj, 1)`. `vi_RunCamera` runs this sequence only when `HSD_CObjSetCurrent` succeeds, sets the erase color, clears with arguments 1/0/1, applies the caller's final link mask, dispatches again, and ends the current camera. On failed camera activation it skips the entire body. Neither wrapper restores the incoming link mask.
- **Start-driven departure:** `vi_8031CAAC` reads the Adventure-selected controller-map slot's trigger field. If Start is present, it stops the audio driver and clears associated bookkeeping, keys off sound effects, removes rumble programs and calls rumble-on for every port, then writes scene command 1. The scene loop runs while that command is zero, supporting the scene-departure interpretation without implying an immediate scene destruction or archive free. Without Start, no cleanup occurs. The helper does not consume the trigger or latch completion; repeated calls against the same trigger state repeat the sequence.

Canonical and rendered views were reviewed completely. The rendered `HSD_GObj_SetTextureCamera` hypothesis is misleading for this use: the canonical implementation dispatches render callbacks using separate pass and link masks. The header also reports an unchanged `viGetCharAnimByIndex` declaration as `shadowed_binding`; no source mismatch was observed.
