## Entry paths and boundaries
`ftCo_8009B4D0` forwards the carrier unchanged to `ft_8008A1FC`; on success it calls `ftCo_8009B518` and returns true, otherwise false. The predicate is `(stick_x * facing_dir < 0) || (ABS(stick_x) < walk_stick_threshold)`. CargoWalk IASA calls this after throw, jump, and platform-pass checks, before its continuing walk update. It is a stop-walking gate, not the five-way CargoWait dispatcher and not a ground-mode test. Equality to the magnitude threshold does not satisfy that branch; reverse-facing input can independently satisfy the product branch. Signed zero requires a positive magnitude threshold. Under ordinary IEEE comparisons, NaN stick input satisfies neither branch; NaN facing or threshold disables only the corresponding comparison. Infinite inputs are not rejected: a negative infinite product can accept, whereas infinite magnitude is not less than an infinite threshold. No local validation or clamping occurs. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_CargoWait.c#L20-L27, code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_08A1.c#L17-L27, code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_CargoWalk.c#L42-L49, and code://c302741689bd67c361cd7faadb221df3193992c3/src/Runtime/platform.h#L198-L198.

Both entry wrappers call `inlineA0`. It obtains `Fighter* fp = gobj->user_data`, changes the carrier to `fp->x2CC->x4_motion_state` with `Ft_MF_None`, animation start 0, speed 1, blend 0, and NULL final object argument, then invokes the selected callback with `fp->victim_gobj` and 266. The carrier state is data-driven; this TU neither validates that ID nor explicitly grounds the fighter or zeros velocity. The local zero-initialized 16-byte arrays have no subsequent source use; their emitted stack representation is unknown. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_CargoWait.c#L29-L48 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/fighter.h#L44-L48.

That updater skips its entire setup block only when current and requested motion are both ShoulderedWait; otherwise it changes motion with FreezeState or no flags according to victim `x2222_b6`, performs held setup, and stores `accessory1_cb = ftCo_800DB464`. `ftCo_8009B56C` chooses `ftCo_8009C640`, which first calls `ftCommon_InitGrab` with zero and `(int)(damage_percent * x4A0 + x4A4)`, clears shouldered work x0 and x4, then calls the updater. Initialization therefore still occurs if redundant ShoulderedWait entry is subsequently skipped. Finite representable conversion truncates toward zero; no sanitization establishes a portable result for non-finite or out-of-range expressions. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_Shouldered.c#L28-L53.

A completed unflagged throw uses the ordinary exit; unfinished animation does not take that exit merely because the conjunction is false. The existing-carry path is called on CargoTurn animation completion, when CargoLanding's counter is already <= 0 at callback entry, and from CargoWait2 recovery when `x221C_b6` is clear and the fighter is not airborne. CargoLanding decrements its work expression after calling the state-changing entry. ## Ownership, conventions, dependencies, and reconciliation
Nonempty entry paths require live carrier user data, valid cargo attributes, and a live victim. There are no null checks, allocations, reference acquisitions, destruction, or explicit ownership transfers here. The helper obtains fp before carrier motion change and reads victim_gobj afterward; it relies on preservation of that object and relationship across the change. Its callback is invoked synchronously and not stored. The collision callback is also synchronous. The victim updater separately stores a static accessory callback, whose teardown and complete lifetime contract are outside this TU. No general reentrancy-safety claim follows.

Dependencies are fighter motion-state services and types, common input/friction/collision processing, Donkey cargo attributes, the five outgoing action families, CargoFall, and Shouldered. Header guards and forward declarations expose the interface; RETURN_IF supplies first-success arbitration. Parameter locators ending #r3 identify baseline subjects but are not compiled register-assignment proof. Source field access likewise does not prove object offsets or layout.

The independent librarian's core entry, dispatcher, physics, and collision conclusions were verified. This synthesis preserves its unresolved section and persistence issues, repairs the overly broad unfinished-throw alternative by superseding that fact, treats unsupported visual lifting language as unresolved, and adds CargoKneebend to the collision consumers. The three .sdata2 facts remain unresolved: source literals do not establish object-section attribution, size, ordering, bytes, or deduplication. No compiled artifact was supplied. Original aliases, generated stack layout, exceptional float-to-int machine results, runtime attribute validity ranges, and complete lifetime/reentrancy guarantees remain unknown.
