## Functionality and semantic assessment

`textlib.c` primarily implements the mutable DevText character-grid API. Creation searches only the active draw list for duplicate IDs, removes an object from the shared free pool, attaches caller-provided storage, installs default geometry and appearance, and clears two bytes per cell. It does not register the new panel for rendering. Pool exhaustion invokes an assertion-report path, rather than guaranteeing an ordinary recoverable NULL return.

Printing writes each ordinary character and its two-bit palette index before advancing the cursor. Normal right-edge advancement wraps or scrolls immediately; no-wrap mode instead repeatedly overwrites the final cell. Explicit newlines still advance and scroll. Scrolling shifts rows upward and clears the final row; full erasure clears contents without resetting the cursor or presentation state. Cursor bounds assume positive dimensions for a valid-grid postcondition: the actual clamp tests the upper bound before testing negativity.

Position setters impose an eight-unit lower bound, while scale setters assign values unchanged. Color setters return displaced values. The active color byte is not range-checked: printing narrows it into two-bit metadata, whereas palette replacement uses the full stored index. Existing glyphs resolve their colors through the live palette during rendering. Visibility setters manipulate separate stored bits, but the renderer nests cursor drawing and blink-counter advancement inside the text-visible branch.

Integer output delegates to the signed-decimal converter through a 16-byte local buffer. Formatted output uses a 64-byte local array but passes `-1`, not that capacity, to `vsnprintf`; this must not be described as bounded 64-byte formatting. The integer converter's signed-minimum negation is likewise not established as safe for every integer input.

The final two functions expose the current descriptor-menu record and replace its fallback callback. Sibling canonical code independently supports the rendered hypotheses `DevMenu_GetCurrent` and `DevMenu_SetFallbackCallback`; `DevText_SetNoWrap` is also supported by its canonical consumer. Menu initialization publishes the current pointer before buffer/panel allocation succeeds. Teardown temporarily publishes each closing record during callbacks and restores the surviving parent afterward. The getter therefore provides neither ownership nor a fully-initialized-panel guarantee. Fallback dispatch reads the globally current record after entry handling, so a callback-induced hierarchy change matters.
