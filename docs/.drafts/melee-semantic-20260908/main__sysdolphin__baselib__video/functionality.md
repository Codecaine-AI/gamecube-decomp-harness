## Presentation state and lifetimes
`HSD_VIData` holds current configuration, three XFB records, EFB bookkeeping, callbacks, GX waiting state and published renewal accounting. Initialization copies the VI configuration by value but retains caller-owned framebuffer pointers. Non-null slots become FREE and null slots NONE. The initial full-screen copy targets the first FREE slot without changing its status or calling `VISetNextFrameBuffer`; it does not independently establish displayed-frame ownership. All-null framebuffer input is unsafe because the final lookup can return -1 and the inline pointer accessor does not check bounds. The two private pre-retrace counters survive repeated initialization, although the published renewal count is reset. [video.c](code://c302741689bd67c361cd7faadb221df3193992c3/src/sysdolphin/baselib/video.c#L393-L442), [accessors](code://c302741689bd67c361cd7faadb221df3193992c3/src/sysdolphin/baselib/video.h#L124-L142), [counters](code://c302741689bd67c361cd7faadb221df3193992c3/src/sysdolphin/baselib/video.c#L99-L109).

For multiple XFBs, acquisition first reuses DRAWING, otherwise reserves FREE as DRAWING. Submission copies the EFB, changes DRAWING to WAITDONE, snapshots current configuration and clears the current change flag, then serializes and arms GX draw completion with the slot index. WAITDONE therefore does not mean GPU-complete. The internal GX callback clears the waiting flag and invokes an optional registered callback; it does not directly advance XFB ownership. Melee startup explicitly registers `HSD_VIDrawDoneXFB`, which changes WAITDONE to NEXT or DRAWDONE depending on whether NEXT already exists. [acquisition](code://c302741689bd67c361cd7faadb221df3193992c3/src/sysdolphin/baselib/video.c#L163-L200), [submission and completion](code://c302741689bd67c361cd7faadb221df3193992c3/src/sysdolphin/baselib/video.c#L267-L320), [internal callback](code://c302741689bd67c361cd7faadb221df3193992c3/src/sysdolphin/baselib/video.c#L142-L149), [startup registration](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gmmain.c#L147-L161).

## Retrace processing
Pre-retrace prioritizes NEXT, stages its framebuffer and changed configuration, and requests a VI flush. Otherwise, exactly one XFB plus EFB_DRAWDONE selects DISPLAY or asserts a FREE slot exists, marks COPYEFB and optionally stages saved EFB configuration. Post-retrace prioritizes NEXT, retires an existing DISPLAY, promotes NEXT to DISPLAY and one DRAWDONE to NEXT. Without NEXT, COPYEFB triggers a full-screen copy followed by XFB DISPLAY and EFB FREE bookkeeping. That bookkeeping follows command submission, not an explicit CPU wait for GPU completion. The producer of the single-XFB EFB_DRAWDONE state remains unresolved. [callbacks](code://c302741689bd67c361cd7faadb221df3193992c3/src/sysdolphin/baselib/video.c#L63-L140).

The low-level VI interrupt handler increments a software retrace counter and forwards it to both callbacks. Hardware triggers the event, not the counter value. VI attempts to apply pending registers between callbacks, but `VISetRegs` can defer a mode change. Renewal accounting uses a nominal 60-callback window for VI_NTSC and 50 otherwise; this is not proof of gameplay FPS or PAL mode-selection behavior. [VI handler](code://c302741689bd67c361cd7faadb221df3193992c3/extern/dolphin/src/dolphin/vi/vi.c#L145-L229), [window selection](code://c302741689bd67c361cd7faadb221df3193992c3/src/sysdolphin/baselib/video.c#L432-L437).

## Copy geometry and exceptional paths
The copy routine installs filter, gamma, update, depth and clear state. SCREEN uses the full EFB and the requested XFB/EFB height ratio. The returned scale line count is passed to `GXSetDispCopyDst`, but that implementation ignores height and programs only width-derived stride. TOPHALF and BOTTOMHALF use unit scale and a four-line overlap. The bottom destination is offset by padded width times copied lines times two bytes; its remaining overlap strip is copied to the 5120-byte aligned scratch array with clearing requested. All supported paths issue pixel-mode synchronization; unsupported passes panic, including OFFSCREEN despite its presence in the enum. No XFB ownership status is changed by this routine. [copy implementation](code://c302741689bd67c361cd7faadb221df3193992c3/src/sysdolphin/baselib/video.c#L202-L265), [GX destination behavior](code://c302741689bd67c361cd7faadb221df3193992c3/extern/dolphin/src/dolphin/gx/GXFrameBuf.c#L408-L420), [scale behavior](code://c302741689bd67c361cd7faadb221df3193992c3/extern/dolphin/src/dolphin/gx/GXFrameBuf.c#L491-L516), [constants and enums](code://c302741689bd67c361cd7faadb221df3193992c3/src/sysdolphin/baselib/video.h#L9-L43).

## Selection, synchronization and configuration
Status search scans all three records in ascending index order, without checking the configured count or buffer pointer. LastDrawDone selects by WAITDONE, DRAWDONE, NEXT, DISPLAY priority; neither the status ladder nor slot ordering establishes chronological recency or guaranteed completion. Screenshot code separately drains the queue before using the returned index. [search](code://c302741689bd67c361cd7faadb221df3193992c3/src/sysdolphin/baselib/video.c#L13-L23), [selector](code://c302741689bd67c361cd7faadb221df3193992c3/src/sysdolphin/baselib/video.c#L361-L379), [screenshot consumer](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/db/dbscreenshot.c#L72-L87).

Both flush variants return immediately for fewer than two XFBs and otherwise wait only for WAITDONE, DRAWDONE and NEXT to disappear. The ordinary variant sleeps through VI retraces; NoYield polls continuously. Neither advances ownership itself, excludes new producers after return, nor guarantees progress if required callbacks cannot run. The framebuffer-handoff caller drains before selecting current and remaining pointers. [waiters](code://c302741689bd67c361cd7faadb221df3193992c3/src/sysdolphin/baselib/video.c#L322-L359), [VI sleep](code://c302741689bd67c361cd7faadb221df3193992c3/extern/dolphin/src/dolphin/vi/vi.c#L464-L475), [handoff consumer](code://c302741689bd67c361cd7faadb221df3193992c3/src/sysdolphin/baselib/hsd_393C.c#L273-L334).

Configuration setters copy values and unconditionally dirty current state. The XFB snapshot is taken at submission, not GPU completion; pre-retrace reads the saved flag without clearing it. Black output is implemented through VI active-video timing, not framebuffer pixel clearing. Callback setters read the previous pointer before disabling interrupts, protect only the replacement store, restore the prior interrupt state and return the earlier snapshot; they are not atomic read-modify-write exchanges. [setters](code://c302741689bd67c361cd7faadb221df3193992c3/src/sysdolphin/baselib/video.c#L381-L391), [snapshot](code://c302741689bd67c361cd7faadb221df3193992c3/src/sysdolphin/baselib/video.c#L277-L290), [blanking](code://c302741689bd67c361cd7faadb221df3193992c3/extern/dolphin/src/dolphin/vi/vi.c#L631-L677), [callback registration](code://c302741689bd67c361cd7faadb221df3193992c3/src/sysdolphin/baselib/video.c#L25-L61).

## Review outcome
The three expressly reported defects are corrected in their own facts: destination-height data flow, latest-completed-frame selection and hardware-supplied counter provenance. Additional supported corrections distinguish initial copying from presentation, submission from completion, and protected callback stores from atomic exchanges. Existing useful names remain unchanged. Numeric XFB and EFB state domains remain distinct, assertions do not substitute for index bounds checks, and no compiled ordering, section padding or constant-pool attribution is inferred from source alone.
