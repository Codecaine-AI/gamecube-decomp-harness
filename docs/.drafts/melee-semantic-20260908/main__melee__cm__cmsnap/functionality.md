## Initialization and dependency semantics
cmSnap_800316B4 resets status to Sleep, clears image_ptr, creates a GObj with classifier 0x12, process link 0x12, and process priority 0, and registers cmSnap_80031640 at render priority 4. GObj_SetupGXLinkMax assigns gx_link_max+1, not link 4 or exactly gx_link_max, and orders the object into GX lists. GObj creation requires p_link <= p_link_max and can return null on allocation failure; cmsnap immediately passes the result to a function that dereferences it, with no local recovery. Library initialization, valid link configuration, and successful object creation are operational dependencies. ## Ownership, lifetime, and boundaries
No local destructor, free, unregister operation, idempotence guard, lock, or reentrancy protection exists. The GObj is retained by library lists, not a cmsnap handle; its callback uses static storage rather than a stack capture. Reinitialization resets even a pending lifecycle, clears the prior descriptor reference without releasing the prior storage, and creates another callback object. Without external cleanup it can leave multiple drivers against the same singleton and lose a buffer reference; this does not prove old client pointers are freed or invalid. GObj destruction can unlink render objects, but the scene-specific teardown for this object and buffer is unproved. Request-before-init can arm the software state but has no locally installed driver or configured storage guarantee. These APIs rely on external lifecycle discipline.
