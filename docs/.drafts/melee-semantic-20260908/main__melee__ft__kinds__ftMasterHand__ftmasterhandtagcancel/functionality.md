## CaptureMasterHand entry

The unit defines one two-object initializer, `ftMh_MS_388_80155A58`; its header declares the same `void(HSD_GObj*, HSD_GObj*)` interface. The first object's Fighter is the captured opponent, while the second supplies the captor association, facing direction and grab-initialization input. Master Hand's Grab initializer registers this function through `ftCommon_8007E2D0` ([caller](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftMasterHand/ftmasterhandbackdisappear.c#L138-L145)). The proposed name `ftMh_CaptureMasterHand_Enter` is a supported semantic hypothesis, not a recovered original name.

The routine calls three outgoing-state helpers before replacing the first Fighter's `x1A5C` and `victim_gobj` with the second object. It clears `x221B_b5` and `x221B_b7`, copies facing, calls `ftCommon_InitGrab` with zero and the result of `ftCo_800DA824(ft_2)`, invokes `ftCo_800DB368(ft_2, ft_1)`, and stores `ftCo_800DB464` in `accessory1_cb`. It then applies airborne bookkeeping and calls `Fighter_ChangeMotionState(gobj_1, ftCo_MS_CaptureMasterHand, 0, 0, 1, 0, 0)`. Finally it sets invisibility and `x2220_b3`, passes 511 to `ftCommon_8007E2F4`, and invokes the animation and common finalization helpers ([complete body](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftMasterHand/ftmasterhandtagcancel.c#L15-L43)). The `388` embedded in the original function name is not evidence of the numeric value of the named common capture state.

There are no local guards, loops or alternate returns, and both inputs are dereferenced as Fighter-bearing objects. This does not make all called behavior unconditional: `ftCommon_8007DB58` invokes outgoing callbacks only when present, and old-partner handling in `ftCo_800DD168` skips a NULL partner and otherwise branches on the old `x221B_b5` ([callbacks](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftcommon.c#L657-L680), [old relationship](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_Throw.c#L57-L70)). The airborne helper also sets one jump used, a ten-frame ECB lock, and collision-lock bookkeeping; it is more than a single ground/air assignment ([helper](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftcommon.c#L515-L525)).

The stored captor references and accessory callback outlive this call; this unit does not contain their eventual teardown. That choice is conditional, not an inevitable local consequence of capture entry ([Squeeze](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftMasterHand/ftmasterhandsqueeze.c#L18-L50)).
