# Star Rod swing translation unit

## Scope and canonical identity
The complete owned unit is `src/melee/ft/ftstarrodswing.c` (75 lines) and its guarded public header (14 lines). It defines six void functions: entry routine `ftCo_800CD82C`, four canonically named `ftCo_StarRodSwing_{Anim,IASA,Phys,Coll}` wrappers, and accessory callback `ft_800CD914`. The header declares all six using `Fighter_GObj*`; the four wrapper definitions spell their argument `HSD_GObj*`. The rendered identifiers `ftCo_StarRodSwing_Enter` and `ftCo_StarRodSwing_Accessory` are useful role hypotheses, not recovered canonical symbols. External rendered aliases likewise are not independent evidence. Header: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftstarrodswing.h#L1-L13.

## Entry and active consumers
`ftCo_800CD82C(gobj,arg1,arg2,arg3)` retrieves the Fighter, sets `cmd_vars[0]=540000` and `cmd_vars[1]=0`, calls `ftCo_800CD140(gobj,arg1,0,arg2,arg3)`, then installs `ft_800CD914` in `accessory4_cb` and `ft_800CD31C` in `take_dmg_cb`. Thus callback installation follows the motion transition, rather than preceding it. There is no local argument validation, allocation, ownership transfer, or return value. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftstarrodswing.c#L11-L19.

The actual caller `ftCo_Attack_800CCF58` classifies item kind 22 as family 4 and forwards a table-selected motion ID, requested variant, and table-selected rate. Family 4's ordinary row is `{136,137,138,-1,139}`. Variant 3 bypasses that motion row: Captain receives family+341, hence 345; other fighter kinds hit a diagnostic assertion. The rate table is still indexed by variant. Variants outside the valid table domain are not bounded by the visible dispatcher. This is not evidence that arbitrary integers are accepted safely. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftswing.c#L15-L19 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftswing.c#L27-L98.

The common motion table actively installs all four wrappers for StarRodSwing1, StarRodSwing3, StarRodSwing4, and StarRodSwingDash; Captain's table also installs them for its StarRodSwing4 entry. The numeric suffixes are not independently interpreted as tilt/smash mechanics. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftmotionstates.c#L1630-L1673 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCaptain/ftcaptain.c#L66-L76.

## Shared lifecycle behavior
The wrappers forward their object unchanged. Anim calls `ftCo_800CD1BC`; IASA calls `ftCo_800CD204`; Phys calls `ftCo_800CD278`; Coll calls `ftCo_800CD2C4` with the non-null function pointer `ft_800CD31C`. No wrapper adds a local condition or timer. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftstarrodswing.c#L21-L39.

The common initializer clears throw flags, calls `Fighter_ChangeMotionState` with frame zero and the forwarded rate, initializes animation, sets `mv.co.swing.x0=1`, stores the variant in `mv.co.swing.x4`, and invokes `ftCommon_8007E79C(gobj,1)`. Anim runs `ft_8008A2BC` followed by `ftCommon_8007E7E4(gobj,1)` only when no animation frames remain. IASA permanently clears the current swing's x0 latch upon observing A released; `ftCheckThrowB3` consumes its event before x0 is tested, and a true event with nonzero x0 requests variant 3. Phys uses `ft_80084FA8` for every variant except 4; variant 4 calls `ft_80085030` with common x420 multiplied by ground friction and the facing direction. Coll calls its supplied callback and then `ftCo_Fall_Enter` when `ft_800827A0` returns zero. The supplied callback calls `ftCommon_8007E7E4(gobj,1)` only if a held item exists. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_0CD1.c#L14-L71 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/inlines.h#L255-L263. Detailed item-operation semantics of the common helpers are not expanded into an unsupported detach/drop claim.

## Accessory events, ammunition and position flow
`ft_800CD914` retrieves the Fighter and reads `fp->ft_data->x8->x10` before testing whether `item_gobj` is null. Consequently a null held item suppresses event side effects, but does not make the callback safe for a null Fighter or invalid fighter-data chain. With an item present, the callback asserts `itGetKind(item)==It_Kind_StarRod`. This is an invariant assertion, not a defensive kind-filter branch.

Sound processing and projectile-event processing are separate. Any `cmd_vars[0]` value other than exactly 540000 causes one `ft_PlaySFX` request: that command value when ammunition is available, or 234 when depleted, always with arguments 127 and 64. The command is then reset to 540000. Values below or above the sentinel are not otherwise range-checked here. A sentinel command causes no sound even for an empty rod. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftstarrodswing.c#L41-L58.

`ftCheckThrowB0` tests and clears bit 0 when true. With no item the helper is not called and the event is not consumed. With an item, a true event is consumed even when ammunition is empty. The callback copies a rod attribute vector through `it_80292394`, transforms it using `fp->parts[x].joint` and `lb_8000B1CC`, and separately queries ammunition again. For Star Rod, `it_8026B594` returns true exactly when signed item field xD4C is <=0. Positive values therefore select effect 1070 followed by `it_802923BC(item,&v2,facing_dir,cmd_vars[1])`; zero and negative values select only effect 1032 with a local float initialized to +0.0. The sound branch does not itself spend ammunition. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftstarrodswing.c#L49-L73, code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/inlines.h#L245-L253, and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/it_26B1.c#L300-L320.

The item helper initializes xD4C from an article attribute, copies the article's vector on request, decrements positive xD4C by one, and passes the item's owner—not a newly established ownership relation—to `it_802988E4`. That helper requests `It_Kind_StarRod_Star`, copies the supplied vector into prev_pos but forces its z to zero, separately obtains si.pos from the owner, and stores the shot selector only if allocation succeeds. The selector is tested as zero versus nonzero by projectile initialization; negative values therefore take the nonzero path too. Ammunition is already decremented if projectile allocation fails, and there is no rollback in this chain. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/kinds/itstarrod.c#L33-L55 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/kinds/itstarrodstar.c#L36-L80.

`lb_8000B1CC` has important optional branches: a null joint copies the input vector unchanged; a zero vector selects joint translation; parented/nontrivial transforms use the matrix, while a root with identity rotation/scale adds translation directly. Therefore unconditional 'world-space conversion' requires the intended valid joint context. Parts-array indexing itself is unchecked here. No source-level finite-number validation is performed on offset, facing direction, animation rate or friction. NaNs, infinities, signed zeros and atypical facing magnitudes are forwarded or participate in downstream arithmetic; this review does not claim a sanitized gameplay result for them. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/lb/lb_00B0.c#L105-L140.

## Effects and lifetime
Both effect calls use spawn kind 5 and a null joint. The enum maps 5 to `EF_SPAWN_POS_OFFSET_PARAM`; `efAsync_Spawn` copies both the vector and pointed-to float into an allocated queue record before returning or processing it. Thus `&v2` and the empty-branch `&f` are not retained as stack pointers by this interface. It conditionally links the record to the Fighter-associated queue when the current GObj exists with s_link<9; otherwise it processes it immediately through the deferred-processing helper. The visible allocator result is dereferenced without a null guard. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ef/types.h#L16-L38 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ef/efasync.c#L1405-L1464.

The effect dispatcher supports 1032/0x408 by creating generator 0x3E and assigning the scalar to rot.z if creation succeeds; 1070/0x42E forwards position and facing to generator 0x13C creation. These establish parameter roles, not an artistic name or guaranteed visual success. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ef/efasync.c#L308-L321 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ef/efasync.c#L634-L640.

The installed accessory function is persistent code, not a stack closure, and does not unregister itself. This TU neither owns nor frees the Fighter, held item, joint, or effect queue. Global callback reset/dispatch and queue destruction remain external lifecycle responsibilities; their complete ordering is unresolved here.
