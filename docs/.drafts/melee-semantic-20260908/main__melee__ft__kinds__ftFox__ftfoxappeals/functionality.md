## Direction and phase progression
ASID_AppealS is canonically static s32[2][3]. Its first row contains ftFx_MS_AppealSStartR, ftFx_MS_AppealSR and ftFx_MS_AppealSEndR; its second contains the L counterparts. Enter initializes animCount to zero and facingDir to the result of comparing facing_dir with exactly 1.0f: equality selects row zero, every unequal value row one. This is not a sign test. Under ordinary floating-point comparison semantics, positive and negative zero, infinities, NaN and any other value unequal to +1 select row one. No normalization or epsilon is applied. Entry clears the entire throw_flags field and passes the selected phase-zero ID to Fighter_ChangeMotionState with arguments 0, 0.0f, 1.0f, 0.0f, NULL. Direct entry bypasses all eligibility guards. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftFox/ftfoxappeals.c#L76-L104.

Anim first calls ftCheckThrowB3, whose true path clears the set bit before returning. Fox then calls grCorneria_801E2B80, Falco grCorneria_801E2C34; a true result assigns the static OnTakeDamage function to death1_cb. Other kinds consume the event but perform no stage dispatch. A false stage result leaves the existing slot unchanged. Independently of the event branch, exhausted animation frames increment animCount. A resulting count >= 3 calls ft_8008A324 and returns; otherwise the stored row and incremented column select the next motion with the same literal arguments as entry. The initialized path visits columns 0, 1 and 2, then exits at 3 without reading column 3. There is only one phase increment per callback. There is no lower-bound or row validation; safety depends on valid initialized and preserved move-local state. Arbitrary corrupted counters cannot be assumed safe, including increment overflow. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftFox/ftfoxappeals.c#L109-L146; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/inlines.h#L255-L263.

Both Fox and Falco motion tables actively use this Anim/IASA/Phys/Coll quartet for the six AppealS motions. That relationship is verified from consumers rather than inferred from numeric enum names. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftFox/ftfox.c#L343-L408; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftFalco/ftfalco.c#L343-L408.

## Stage coordination and callback lifetime
On Corneria, either character-specific stage helper returns false if object 12 exists. Otherwise it requests creation of object 12, asserts a nonnull result, initializes it using HSD_Randi(5) plus 8 for Fox or plus 13 for Falco, and returns true. Venom forwards arguments 2 and 20 respectively to grVenom_80206BF0. Other stages return true without the Corneria creation path. The normal input gate excludes those other stages, but direct entry does not; therefore a true helper result is not universally proof of presentation startup. Numeric selection arguments do not prove dialogue contents. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gr/grcorneria.c#L2691-L2731.

OnTakeDamage obtains the Fighter, calls grCorneria_801E2AF4, then sets death1_cb to NULL. The stage helper returns early on Corneria if object 12 is absent; otherwise it passes that object to Ground_801C4A08, conditionally processes object 5 through Ground_801C5544 and Ground_801C4A08, and calls HSD_SisLib_803A5F50(1). Venom delegates grVenom_80206CB0(1); other stages do nothing. Local slot clearing still follows stage-side early return. Registration overwrites the previous slot without saving it. Clearing prevents later dispatch through this slot until rearmed, but is not a lifetime-wide once-only guarantee or a reentrancy guard: clearing occurs after the stage call. There is no local explicit callback clearing or stage abort on normal animation completion. Common damage and death paths conditionally invoke death1_cb, supporting the explicit source comment identifying the callback's damage/death role. The TU does not allocate or free fighters and does not directly own stage objects. ## Remaining callbacks and boundaries
IASA immediately returns without using gobj, reading inputs, writing state or calling another function. This means no transitions through this hook, not global uninterruptibility. Phys forwards gobj unchanged to ft_80084F3C. That helper chooses ground_friction, scales it by friction_when_above_walk_speed only when ABS(gr_vel) > walk_max_vel, calls ftCommon_ApplyFrictionGround, then ftCommon_ApplyGroundMovement. Equality does not scale; unordered comparisons do not enter the scaling branch. Exceptional or invalid attributes are not sanitized in this helper, and unconditional speed reduction is not established. Coll forwards gobj unchanged to ft_80084280, also used by Wait. That helper chooses a collision path according to nonzero nudge velocity and whether its product with facing_dir is strictly negative, returns on successful tests, and otherwise enters Fall. Zero and unordered products do not satisfy the negative comparison. Thus the baseline claim that all departures wait for animation completion is too strong. Full teeter handling and Landing sharing remain unresolved. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftFox/ftfoxappeals.c#L148-L161; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_084E.c#L42-L53; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_081B.c#L1081-L1099; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_Wait.c#L69-L78.

## Conventions, hypotheses and uncertainties

PAD_STACK and the MUST_MATCH-only order_sdata2 helper are matching-related source constructs, not evidence of a gameplay state. order_sdata2 mentions 0.0f and 1.0f, has float return type but no return statement, and has no local caller. Neither it nor the source table proves compiled section extent, placement, ordering or relocations. All .data/.sdata2 attachment claims remain unresolved without compiled evidence.

Canonical names outrank rendered hypotheses. The rendered stage-active/start/abort aliases, plBonusLib_OnAppeal, ftCo_Wait_Enter, ftCommon_ApplyFrictionGroundAndMovement and ft_EnvironmentCollision_WaitLanding are not independent evidence. Checked helper bodies support narrower stage coordination, friction and collision descriptions, but do not prove every implication of those aliases. The source comment, character/stage gate and active tables support the broad Fox/Falco special-taunt association, not stronger exact-input or once-per-match guarantees.
