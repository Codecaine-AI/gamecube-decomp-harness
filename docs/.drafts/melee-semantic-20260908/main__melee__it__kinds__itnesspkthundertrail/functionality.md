## Ness PK Thunder trail

The module defines one item-state dispatch row and a six-entry kind lookup: indices 0–2 select PKThunder1, followed by PKThunder2, PKThunder3 and PKThunder4. The constructor rejects indices outside 0–5, flattens the supplied position to Z=0, initializes zero velocity, and returns NULL if item creation fails. Successful creation stores the supplied ball reference, segment index and zero flicker counter, clears item-command variables, optionally registers the fighter association, and enters state 0 with ITEM_ANIM_UPDATE. The head schedules six spawn attempts on opening counter values 0, 2, 4, 6, 8 and 10; allocation success is not guaranteed.

Animation clears the child hierarchy's hidden flag on even counter values and sets it on odd values, increments the counter, then returns true exactly when the ball reference is NULL. Thus even a terminal invocation performs its visibility update. Physics performs no transform updates without that reference. Otherwise it obtains positions at history entries 2*index and 2*(index+1), scales the root JObj's Z axis by half the ball's stored speed, and computes facing-adjusted X rotation from the current-minus-next displacement. The local variable named `radius` does not establish radius semantics: the canonical scalar getter ignores the index and returns xEEC, initialized from PKTHUNDER_SPEED. Collision is a side-effect-free false return; this does not imply absence of item hitboxes elsewhere.

Two cleanup operations have distinct lifetimes. it_802AC58C resets hitbox state and clears the ball reference, owner and x13; the head subsequently clears its corresponding trail slot. The segment's animation callback supplies the terminal result rather than this helper directly freeing it. it_802AC5D8 checks both GObj and Item nullness and clears only owner and x13, preserving path following and the ball's trail slot. Its caller is guarded by numeric xF00 == 0, whose broader state meaning is not assigned here.
