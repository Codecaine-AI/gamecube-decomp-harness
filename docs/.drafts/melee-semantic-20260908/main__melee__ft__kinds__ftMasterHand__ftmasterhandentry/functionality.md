## Camera state machine

The phase enum is sequential from 0 through 10; the literal assignment `3` therefore matches `ftMh_UnkEnum0_Unk03`. Phase 0 queries another fighter using the current position and GObj, passes the converted result to `Camera_8002E6FC`, or passes zero when no object is found. It issues camera parameters 40, 45 and -π, applies targets, changes the angle argument to zero, and requests a transition with argument 120. Phases 1–3 advance only when `Camera_8002F260()` is nonzero: phase 1 installs `ftMh_MS_343_80151428` through the camera API and requests 20; phase 2 requests 60 with π/2; phase 3 applies parameters 90, -π/9 and -π/12. [Opening phases](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftMasterHand/ftmasterhandentry.c#L62-L109), [enum](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftMasterHand/forward.h#L8-L20).

Phase 4 calls `Camera_8002F274`, loads `x8 = 120`, and advances. Phase 5 consumes that 120-count hold, then loads 30. Phase 6 consumes 30 and reloads 30. Phase 7 consumes the second 30, configures the final shot and loads 50. Phase 8 calls `Camera_8002F274` and advances without decrementing the 50. Phase 9 consumes it, restores standard camera mode and writes terminal phase 10. Countdown guards are predecrement equality-to-zero, not nonpositive checks. Every handled case returns; there is no same-invocation phase fallthrough. Phase 10 and other unhandled values do nothing through default. [Later phases](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftMasterHand/ftmasterhandentry.c#L110-L161).
