## Launch sampling and startup boundary

`db_GetGameLaunchButtonState` waits for retrace and samples four PAD channels repeatedly while any channel reports -2 or -3. It then stores the buttons from the lowest err-zero channel, or zero if none exists. It retries `CARDProbeEx(0, ...)` only while the result is -1. Neither loop has a timeout; exiting the card loop does not imply success. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/db/dbinit.c#L31-L61.

Retain the inherited contextual findings: an err-zero PAD result need not imply meaningful physical input; startup configuration applies `/develop.ini` and launch-button decisions to DbLevel, with X taking precedence over Y; the timestamp is printed externally; and db_804D6B20 has external writers and a configuration-path consumer. Its complete gameplay interpretation remains deferred rather than renamed speculatively.

## Setup and archive lifetime

At `DbLevel >= DbLKind_DebugRom`, setup clears current, pressed, released and repeat for four records, but leaves prev untouched. It loads `dbLoadCommonData` from `DbCo.dat`, publishes three name-table pointers, and invokes nine feature initializers. Below threshold it does nothing. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/db/dbinit.c#L63-L97.

Independently verified `lbArchive_LoadSymbols` allocates rounded file-data storage and a separate archive descriptor from heap 0, loads/parses the archive, and performs fatal public-symbol lookup. Parse failure and missing symbols reach assertions. dbinit discards the returned descriptor and dereferences commonData without a local recovery branch. Published pointers refer to archive data, not the local pointer variable. There is no local free or repeated-setup guard; reclamation and lifetime across scene/heap resets remain unresolved. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/lb/lbarchive.c#L17-L35 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/lb/lbarchive.c#L76-L125.

## Input processing and scheduling

`db_RunEveryFrame` returns below threshold without clearing state. Master Hand or Crazy Hand presence restricts refresh to slots 0 and 1; otherwise all four refresh. Button and repeat masks are filtered independently using ordered, mutating UP and DOWN branches. An inner RIGHT test still runs after LEFT processing clears the outer branch's direction. All four directions therefore leave DOWN alone; opposite directions without perpendicular input remain. Stored current advances to prev; pressed is `current & (prev ^ current)` and released is `prev & (prev ^ current)`. Repeat is taken from the master repeat mask rather than generated by a local timer. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/db/dbinit.c#L153-L220.

The accessors return stored fields without bounds checks, threshold guards or consumption. Every feature-check loop still visits all four slots. Camera receives stored current/pressed masks together with current master C-stick values, so hand-excluded slots can combine stale masks with current analog input. Shared CPU-handicap and animation updates follow their respective four-player checks. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/db/dbinit.c#L99-L112 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/db/dbinit.c#L221-L256.

Match initialization calls setup and installs the dispatcher through `gm_801A4B40`. The setter stores the callback in scene state; general scene initialization clears it. The scene loop invokes it when non-null inside each processed queued-input iteration, after audio handling and before GObj processing. Rendering follows the queue loop. Invocation is outside the gameplay on_frame pause/step gate, with the threshold guard inside dbinit. Thus the established name does not promise exactly one invocation per displayed frame. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gm_16AE.c#L1976-L1985, code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gm_1A45.c#L160-L163, code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gm_1A45.c#L214-L220 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gm_1A45.c#L295-L369.

Retain the inherited consumer findings concerning held/pressed sound chords, held/repeat item navigation and the allocation limiter's additional exact-level guard. Central enablement does not imply every feature is active at every enabled level.
