## Lugia and Aeroblast

The unit defines two distinct dispatch domains: six Lugia body states (0–5) and a separate, single state 0 for Aeroblast projectiles. Numeric states are not recovered animation names. Existing FlyUp, FlyIntoBackground, BackgroundApproach, ReturnToAttack and Attack/Aeroblast names fit their respective phases; their historical spelling and precise animation labels remain uncertain.

Spawn saves the original position, writes facing_dir = 0.0, clears the command gate, seeds the depth timer from attributes and enters the shared appearance state. State 0 delegates scaling, appearance physics and terrain handling. Its physics guard is not side-effect free: the shared helper processes movement and decrements the appearance timer even when it returns false. Success enters body state 1 and installs effect-hitlag callbacks. State 1 extracts root motion and advances to state 2 when animation activity ends. State 2 updates its vertical accumulator using different attribute increments depending on animation activity and enters state 3 only above the effective upper stage boundary. State 3 loops its animation independently of a post-decrement depth timer; a zero pre-decrement value stops z motion and enters state 4. State 4 initializes a displacement-derived vertical trajectory and advances to state 5 when its updated vertical velocity is positive, not when a position threshold is crossed. Body collision callbacks for states 1–5 are inert.

State 5 samples bone 25 once as the stored launch origin, initializes a persistent waypoint from the saved summon position, and installs an accessory scheduler. A nonzero item-command gate enables three independent fractional accumulators, seeded at 1.0, 0.7 and 0.4. Each uses a single threshold test and subtraction, allowing at most one emission of each variant per invocation, not catch-up looping. Only the primary emission chooses a sound from 0x274D–0x274F. Immediate primary eligibility assumes a nonnegative configured increment. Body animation completion returns true; body physics itself does not create projectiles.

Each projectile request stores the sampled origin as prev_pos, obtains a separate current position through the common position helper, computes launch velocity, and supplies both the summoner's owner and the Lugia object as distinct parent references. The constructor returns the generic creator's result without a local success check. Waypoint selection performs a persistent randomized walk, modifying x/y while retaining z, rejecting candidates outside the configured three-dimensional radius and adding 180 to the persistent heading on rejection. It has no retry limit and does not select an opponent object. Velocity calculation divides displacement by distance/speed without guards for zero distance, zero speed or nonfinite inputs.

Three spawned callbacks request effects 0x465–0x467 and then use the same projectile initializer. The 0.8 argument is a scale denominator: the effect helper computes item model scale multiplied by its reciprocal, not a fixed effect scale of 0.8. Projectile state 0 ticks its own attribute-backed lifetime, multiplies only z velocity by a kind-selected coefficient, and forwards common map-collision results. An unsupported kind retains multiplier zero; the usual zeroing interpretation assumes finite velocity. Body animation completion and projectile lifetime are separate mechanisms.

Both two-object event wrappers delegate reference cleanup. The shared helper clears matching owner and interaction references and resets source-player metadata to 6 when the fighter reference matches. This is lifecycle maintenance, not attack creation.

Both owned files were read canonically and in the rendered view. The header renderer reports shadowed_binding for it_802D1E8C and leaves that declaration unchanged despite substituting itLugia_SpawnAeroblast in the C file. This rendering discrepancy does not undermine the canonical constructor interpretation. No compiled artifact establishes section extent, adjacency or constant-pool placement.
