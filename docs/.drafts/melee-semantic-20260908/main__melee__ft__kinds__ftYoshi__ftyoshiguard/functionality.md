# Yoshi guard semantic sweep

## Scope and evidence
Inherited research covers all canonical and rendered pages of `ftyoshiguard.c`, `ftyoshiguard.h`, and `ftyoshiguard.dox`, all 64 subjects, 167 facts, and 53 links. This lead independently inspected restored canonical evidence for both proposals and all non-retain claims, and explicitly read the previously missing common shield-hit dispatch range. Rendered names remain hypotheses. No compiled artifacts establish section layout or literal-pool placement.

## Guard lifecycle
- **Normal startup:** `ftYs_Init_8012BECC` enters `ftYs_MS_GuardOn_0`, initializes animation and common shield registration, disables ordinary hurt capsules, resets guard working fields and joint translation, refreshes presentation and shield scale, and plays sound `0x6E`. Its animation callback increments `guard.x0`, records release input, and prioritizes the common shield-health event over animation completion and continued presentation maintenance.
- **Held guard:** `ftYs_Shield_8012C1D4` enters GuardHold, associates animation with the costume hierarchy, selects model variant 1, and installs a mid-height grabbable replacement capsule after making ordinary capsules intangible. Hold animation prioritizes the shield-health event; otherwise `xC || (!x221B_b0 && !reflecting)` selects release. IASA offers item throw, two escape checks, catch, and pass in first-success order.
- **Release:** `ftYs_Shield_8012C49C` enters numeric state `343`, restores model variant 0 and enabled capsules, and requests effect `1231` at mapped part 4. Inherited common dispatch and Yoshi state-table evidence support the release-entry interpretation. GuardOff animation calls `ft_8008A2BC` only after animation exhaustion. This is not an unconditional Wait transition: common completion retains Hand dispatch and neutral-state exceptions, including DownSpot. GuardOff IASA separately permits held-trigger, timely downward-stick EscapeN input.
- **Shield-hit reaction:** `ftYs_Shield_8012C600` enters `0x158`, installs common hitlag and post-hitlag callbacks, sets the horizontal tilt timer to `254`, conditionally selects model variant 1, and installs the replacement capsule. Inherited state-table evidence identifies GuardDamage. When `arg1` is false, it computes `((x28C * (x19A4 * (1 - lightshield_amount))) + x290) * x294` and retains that value for negative `specialn_facing_dir`, otherwise negating it. When `arg1` is true, the ground-velocity assignment is skipped, not replaced with zero. The common caller derives the boolean from `x19B0 == 10` and subsequently calls `ftCo_800C36DC` on that exceptional branch. Yoshi's entry does not reproduce the generic entry's animation-rate scaling or recoil clamp. GuardDamage IASA is empty; animation waits for completion and selects release or held guard according to `xC`.
- **Reflective startup:** `ftYs_Shield_8012C850` preserves the current animation frame with numeric transition flag `16`, clears two flags, sets three others, initializes two windows, and registers the reflector callback. `ftYs_Shield_8012C914` instead starts at frame zero and performs fresh guard-local, capsule, joint, presentation, and sound initialization. Common processing clears the one-update flag, decrements enabled windows, and expires them strictly below zero. Expiry of `x14` disables reflection and re-registers the ordinary shield; expiry of `x18` clears its associated flag. GuardOn_1 delegates IASA, physics, and collision to common GuardReflect routines.

## Cross-file lifetimes and exceptions
`ftYs_Init_8012BDA0` is used by Yoshi's directional Escape entry, supporting the inferred EscapeHurtbox name. Its endpoint vector is defined in `ftyoshi.c`, not this unit. The roll animation consumer zeros ground velocity at completion and calls `ftYs_Shield_8012CC1C`. Held L/R with `shield_health >= 0` resumes GuardHold and returns before fallback cleanup. Rejection invokes `ftYs_Init_8012BE3C`, then common neutral completion, and still reaches the subsequent Yoshi presentation update. EscapeN entry also invokes the restoration helper when model variant 1 is active.

`ftYs_Init_8012BE3C` restores model and capsule state before requesting effect `1231`; it does more than spawn an effect. Calls pass fighter-owned effect storage, a joint, and an attribute address, but do not establish asynchronous completion, ownership transfer, or cancellation guarantees.

The installed hitlag callback requires grounded state and `allow_sdi`; the post-hitlag callback requires grounded state without the same `allow_sdi` guard. GuardDamage collision independently selects its common collision path using `allow_sdi`. Installed callback teardown is outside the demonstrated local lifetime.

`ftYs_Shield_8012CACC` is an empty on-reflect callback, not the mechanism that reflects projectiles. Its non-static definition and external header declaration contradict the baseline's file-local qualifier.
