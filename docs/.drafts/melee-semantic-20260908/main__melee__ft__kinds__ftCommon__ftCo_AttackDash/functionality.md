# Common dash-attack semantic review

## Input and entry
`ftCo_AttackDash_CheckInput` accepts a newly pressed A button. A held item takes priority: held L/R or item classification `0` selects `LightThrowDash`; otherwise classification `2` selects item-swing variant `4`. Remaining cases dispatch by fighter kind. Each normally completed accepted path returns true; absent A input returns false without dispatching. The numeric classifications and variant are preserved rather than replaced with an unverified taxonomy. The swing subsystem asserts on unsupported item kinds rather than providing a general fallback. [Input](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_AttackDash.c#L26-L47), [swing dispatch](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftswing.c#L27-L99).

`decideFighter` forwards the unchanged fighter object to Kirby's dedicated entry or the common `doEnter` routine. Common entry clears `allow_interrupt`, requests `ftCo_MS_AttackDash` with no preservation flags and animation arguments `0, 1, 0`, invokes shared animation initialization, then clears `attackdash.x0`. Kirby's dedicated entry similarly clears that slot. Importantly, the supplied blend argument zero selects the animation's default blend byte in the applicable `Fighter_ChangeMotionState` branch; `-1` explicitly selects zero blend. The call therefore does not establish an effective zero-frame blend. [Common entry](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_AttackDash.c#L49-L69), [Kirby entry](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftKirby/ftkirbyattackdash.c#L22-L30), [blend selection](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/fighter.c#L1288-L1295).

## Cross-file move-variable lifetime
Dash, Run and RunDirect invoke `SetMv0` after any successful return from the input predicate, including Kirby and item substitutions. It writes common configuration `x68` to the first integer slot of the move-variable union. For common and Kirby dash-attack entries this replaces the entry-time zero. It is not universally a write to an active common AttackDash state: item substitutions also receive it. The source union makes `attackdash.x0` and `common.x0` aliases. The shared catch helper tests that integer as a nonzero grab window and conditionally decrements it. This is not an unconditional per-frame countdown, and the tested condition is nonzero rather than positive. [Setter](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_AttackDash.c#L78-L82), [union](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/types.h#L32-L125), [consumer](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_Catch.c#L60-L81).

## Lifecycle and exceptional branches
The animation callback does nothing while frames remain. On expiry it invokes the shared action-ending dispatcher, which preserves dedicated hand-boss handlers and exceptional neutral-state paths instead of guaranteeing an unconditional return to Wait. [Callback](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_AttackDash.c#L71-L76), [completion dispatcher](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_08A1.c#L54-L109).

IASA always tries `ftCo_800D8AE0` first. That helper offers a held-item dash throw before its additional eligibility checks and nonzero-window CatchDash branch. Successful priority handling can already have changed state. Only a false result followed by a true `allow_interrupt` value reaches `ftCo_Wait_IASA`; skipping that fallback does not establish continued AttackDash. Early helper returns also bypass the counter decrement. [IASA](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_AttackDash.c#L84-L90), [priority helper](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_Catch.c#L60-L81), [throw alternative](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_ItemThrow.c#L179-L186).

Physics supplies `x50 * ground_friction` and facing direction to shared movement processing. With `x594_b0` set, that helper derives ground acceleration from facing-relative animation displacement; otherwise it applies the supplied friction. Both branches perform shared ground movement. Collision delegates unconditionally to a shared check that enters Fall when its ground check declines.
