## Tiny Melee controller

`gmtiny.c` defines eight populated `GameModeState` descriptors followed by a `-1` sentinel. Primary IDs are 0 Character Select, 1 Stage Select, 2 ordinary VS, 3 Sudden Death, and 4 Results. Auxiliary registrations are 0x80 Approach, 0x81 auxiliary VS, and 0xC0 Prize Interface. These are source-object observations, not compiled-section layout claims. [State table](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gmtiny.c#L10-L108)

The selection and gameplay adapters consistently use persistent Tiny `VsModeData` at `gmMainLib_804D3EE0->modes.unk_E50`. CSS entry supplies match type 5, attaches the shared KO-count array and copies settings. CSS cancellation changes to `GM_MENU` and returns before persistence; otherwise settings are committed and character audio prepared. SSS entry copies settings; SSS exit commits them only when `start_game` is true, otherwise scheduling Tiny state 0. Confirmation does not itself explicitly schedule a next state in these helpers. [Adapters](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gmtiny.c#L110-L128), [shared selection behavior](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gmvsmelee.c#L119-L169)

Both ordinary and Sudden Death construction supply no whole-match callback and use `fn_801B8E50` as their player callback. Shared constructors copy all player slots before invoking callbacks with destination and persistent source pointers. The Tiny callback unconditionally writes `model_scale = 0.35f`, `defense_ratio = 0.5f`, `attack_ratio = 1.0f`, and `xB = 1`; its second argument is unused. These writes customize the copied match payload rather than the persistent source through this callback. Sudden Death setup additionally consumes the preceding ordinary match result. [Preset and adapters](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gmtiny.c#L130-L153), [construction ordering](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gmvsmelee.c#L171-L262)

Ordinary exit passes destination IDs 4 and 3: the shared helper chooses Results when there are not multiple winners, including zero winners, and Sudden Death otherwise. Human-specific accounting is guarded. Sudden Death exit forwards its result alongside the stored ordinary result for reconciliation; Results entry initializes its payload and copies the ordinary result record. These local adapters do not independently implement reconciliation or choose a transition on Results entry. [Exit and Results adapters](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gmtiny.c#L144-L168), [shared result handling](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gmvsmelee.c#L207-L275)

Results exit delegates with persistent Tiny data and fallback state 0. The shared routine skips two bookkeeping calls for canceled matches but still updates KO counts. Exceptional progression checks require a human player and a nonterminating following descriptor. Challenger checks are ordered; prize selection is considered only without a selected challenger. Archive setup occurs before the exceptional early return or ordinary fallback write. Named exceptional destinations are retained without assuming their numerical equality to Tiny's auxiliary IDs. [Full Results exit](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gmvsmelee.c#L277-L344)

`gm_Mode_TinyVs_OnInit` delegates initialization of the persistent Tiny record to `gm_InitVsMode`; `gm_Mode_TinyVs_OnLoad` separately resets the complete shared KO-count array. That array is later attached to CSS and updated from human-player standings.
