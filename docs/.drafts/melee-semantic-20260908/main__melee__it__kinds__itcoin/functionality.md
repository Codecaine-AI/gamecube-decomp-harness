## Trophy-bearing Coin item

This unit implements `It_Kind_Coin` objects carrying a selected trophy display, with Figure Get integration and an ordinary collectible variant. The internal Coin name is not sufficient evidence that these callbacks implement Coin Battle currency. The constructor stores the display/trophy identifier in `coin.x0`, the numeric variant in `coin.x4`, and a context pointer in `coin.x14`; it replaces the attached model and applies uniform stage-relative scaling. Allocation failure returns NULL. Only nonzero variants initialize specialized falling parameters. Cases 2 and 3 select separate attribute pairs; every other nonzero value takes the default pair. ## State dispatch

The six table rows represent initial falling (0), grounded rest (1), pickup/held (2), damage flight (3), thrown (4), and entered-air handling (5). Every animation callback returns false. Physics callbacks 1, 2, and 5 are empty; row 2 has no collision callback. State 0 selects ordinary or instance falling parameters by variant, whereas state 4 always uses ordinary ItemAttr values. State 3 multiplies horizontal velocity by an attribute and uses instance falling parameters. Landing setup clears velocity and model rotation, selects state 1, and invokes the numeric `xD0C = 2` setter. These facts do not establish a semantic enum meaning for that numeric mode. See code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/kinds/itcoin.c#L48-L349 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/ithitbox.c#L149-L158.

Collision helpers are not interchangeable. States 0 and 4 use floor-contact settlement; state 3 uses additional qualifying guards. State 1 returns to falling when support is lost, but its common helper also contains a supported-floor exceptional branch. State 5 returns to falling immediately when no floor is found; supported-floor settlement is conditional on the helper's flag/counter guard. ## Damage and presentation

Damage handling obtains a response vector, substitutes planar fallback components before normalization when X and Y are both zero, applies position/direction-dependent reflection and attribute scaling, and uses one-sided horizontal caps. At world X zero neither reflection guard applies, but the nonpositive-X scaling branch does. Z and accumulated damage are cleared, a variant-selected attribute is added to `coin.x8`, and state 3 is entered unconditionally. An unconditional center-directed or symmetrically bounded launch is not established for arbitrary helper outputs and attribute values. ## Cross-file lifetime and collection

Figure Get retains spawned item pointers and immediately sets their collision-joint selector to zero without checking the constructor's NULL result. Its collector retrieves the trophy ID after initial kind/capacity checks but before duplicate and position checks. Accepted objects within inclusive X bounds [-4.5, 4.5] receive a sound/velocity-settling mutation and are recorded with their IDs. Collection does not select another motion state. Destruction of a nonzero variant reports through the stored context; the ground-side helper tolerates NULL and increments a destroyed count otherwise. Completion tests captured plus destroyed counts against three. Ordinary destruction bookkeeping is instead gated by item flag x13; generic cleanup runs on every path. The Rest Area calls the same constructor with NULL context and variant zero under progress and identifier guards.
