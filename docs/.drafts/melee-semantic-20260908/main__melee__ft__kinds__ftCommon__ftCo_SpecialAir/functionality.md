## Input selection and result contract
The function borrows `Fighter* fp` from `gobj->user_data`. If `input.pressed_buttons` lacks `HSD_PAD_B`, it returns false without a callback or local state write. Otherwise it selects, in order: Hi for left-stick Y >= common x21C; Lw for Y <= -x21C; S for ABS(left-stick X) >= x218; N otherwise. The selected `ftData_SpecialAirHi`, `ftData_SpecialAirLw`, `ftData_SpecialAirS`, or `ftData_SpecialAirN` entry is indexed by `fp->kind`. A NULL entry immediately returns false, with no lower-priority fallback. An available entry receives the original gobj synchronously; after it returns, the cached fp's x2227_b5 is set true, then the function returns true. Callback return values do not control success. Success establishes dispatch, not independently a particular resulting motion state. False paths leave an already-set x2227_b5 unchanged. This routine does not clear the B bit, validate airborne state, or locally consume an input event. ## Facing behavior and boundaries
Hi and Lw have no local facing changes. After confirming S callback availability, the function calls `ftCommon_UpdateFacing(fp)` only when X*facing_dir < -x220. That helper assigns +1 for X >= 0 and -1 otherwise, rather than unconditionally negating facing. After confirming N callback availability, it negates facing only when x676_x < x224 and either (facing_dir == -1 and x2228_b7 == 1) or (facing_dir == +1 and x2228_b7 == 0). Other facing values cannot satisfy those neutral clauses. Selection comparisons are inclusive; facing-adjustment comparisons are strict, so equality does not trigger a facing adjustment. Availability checks precede all local facing writes. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_SpecialAir.c#L31-L54 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftcommon.c#L621-L630.

There is no clamp or validation of thresholds. With x21C zero, Y zero selects Hi; negative x21C can overlap vertical conditions and Hi wins. ABS expands to `((x) < 0 ? -(x) : (x))`, so it is not a finite-value validation operation and can preserve negative zero. Under ordinary floating comparison semantics, NaN Y or x21C prevents both vertical selections; NaN X or x218 prevents S selection; NaN in the side product or x220 prevents its facing update. Infinities follow the written comparisons without rejection, and products such as zero times infinity can be NaN. Signed zeros compare equal. These are source-level consequences, not verified compiled exceptional-float guarantees; production threshold ranges remain unknown.
