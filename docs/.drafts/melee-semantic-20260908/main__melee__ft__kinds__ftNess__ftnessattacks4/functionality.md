# Ness forward-smash translation unit

## Scope, identity, and integration
The complete owned implementation and header define nine functions taking `HSD_GObj*`. Eight return void; `ftNs_AttackS4_CheckNessBatRemove` returns bool. The header uses `GALE01_114BF4`, includes baselib forward declarations, and declares all nine functions. Source comments, address annotations, scratch URLs, and unused padding arrays are documentation/decompilation conventions, not compiled-layout proof. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftNess/ftnessattacks4.h#L1-L19 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftNess/ftnessattacks4.c#L1-L166.

The forward-smash mapping has active caller/table support rather than being inferred from a numeric motion identifier. The common AttackS4 dispatcher sets facing direction and selects `ftNs_AttackS4_Enter` for `FTKIND_NESS`. Ness's motion table pairs `ftCo_SM_AttackS4` and `FtMoveId_AttackS4` with this unit's Anim, IASA, Phys, and Coll callbacks. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_AttackS4.c#L145-L167 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftNess/ftness.c#L22-L33.

Dependencies include fighter motion/state access, animation setup and completion, common ground physics and collision, Wait input selection, reflector creation, fighter sound playback, Ness attributes/shared damage cleanup, and Ness-bat item creation/removal.

## Entry and article ownership
`ftNs_AttackS4_Enter` clears `allow_interrupt` and `cmd_vars[0]`, changes to `ftNs_MS_AttackS4` with flags 0 and floating arguments 0.0f, 1.0f, 0.0f, then calls `ftAnim_8006EBA4`. It calls `it_802AD478(gobj, &fp->cur_pos, 0x2A, fp->facing_dir)` and stores the returned handle in `u.ns.bat_gobj`, including a NULL result. Only successful creation installs `ftNs_Init_OnDamage` in both `death2_cb` and `take_dmg_cb`. There is no local retry, rollback, previous-bat removal, or failure-branch clearing of callbacks. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftNess/ftnessattacks4.c#L29-L56.

The canonical constructor selects `It_Kind_Ness_Bat`, allocates through `Item_80268B18`, zeroes four item command variables, records the fighter reference, calls `it_80275158` with 1200.0f, and attaches the successful result using the supplied part. Its nullable result is independently verified; it is not inferred from the rendered Spawn alias. Part 0x2A is commented Item Hold Bone, but compiled skeletal layout is not established. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/kinds/itnessbat.c#L48-L75.

`ftNs_AttackS4_CheckNessBatRemove` returns true for a motion mismatch or NULL tracked bat, and false only for the exact motion match plus non-NULL slot. It is observational, does not validate liveness, and does not compare the slot with the particular calling item. The item motion-0 animation callback passes its stored fighter reference and clears ownership/returns true when the predicate succeeds; absent fighter references also take that cleanup path. Its visibility is separately controlled by item command variable 0. The item state table and pickup selection connect the zero-command constructor to this callback. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftNess/ftnessattacks4.c#L60-L74 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/kinds/itnessbat.c#L17-L45 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/kinds/itnessbat.c#L125-L167.

`ftNs_AttackS4_ItemNessBatRemove` passes a non-NULL tracked article to `it_802AD6B8` and clears the fighter slot after that call. The callee clears the item's fighter and owner references before calling `Item_8026A8EC`. `ftNs_AttackS4_ItemNessBatSetNULL` only conditionally clears the fighter slot; it does not dereference or destroy the item. Item-side reciprocal cleanup calls SetNULL when its recorded fighter equals its owner, without checking that the fighter currently tracks this particular bat. Thus these are reciprocal bookkeeping operations, not reference counting or comprehensive stale-handle protection. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftNess/ftnessattacks4.c#L78-L98 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/kinds/itnessbat.c#L24-L45 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/kinds/itnessbat.c#L115-L123.

The shared registered damage handler calls bat removal after three other Ness cleanup routines. Registration and reachability are proved; global callback reset/invocation ordering, reentrancy, and destruction completion are not. Bat cleanup locally clears neither damage/death callback slots nor the reflector callback. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftNess/ftness.c#L482-L488.

## Animation, reflection, and completion
`ftNs_AttackS4_Anim` first synchronizes reflection. When `reflecting` is false, any nonzero `cmd_vars[0]` creates a reflector using `dat_attrs->xB8_BASEBALL_BAT` and `ftNs_AttackS4_OnReflect`. When already reflecting, zero command clears `reflecting`; nonzero leaves the existing reflector intact. Bat presence does not gate creation. The common creator sets `reflecting`, stores `reflect_hit_cb`, and copies descriptor damage, speed, behavior, bone, size, and offset fields. Local deactivation does not clear the callback pointer. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftNess/ftnessattacks4.c#L102-L117 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftcoll.c#L3189-L3203.

A separate subsequent completion test removes and clears any tracked bat and calls `ft_8008A2BC` when `ftAnim_IsFramesRemaining` is false. Creation can therefore occur on the same invocation as completion. The completion helper scans eligible parts and returns false if none report remaining animation. Blend frames equal to either signed zero select ordinary joints; other values, including NaN and infinities under ordinary floating comparison semantics, select alternate joints. No local numeric final-frame threshold is used. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftNess/ftnessattacks4.c#L119-L132 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftanim.c#L515-L538.

For Ness, the common completion dispatcher calls `ft_8008A348(gobj, 0)`. That routine normally enters Wait but has earlier DownSpot and other common-condition branches. Unconditional return-to-idle wording is therefore too strong. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_08A1.c#L54-L109.

`ftNs_AttackS4_OnReflect` unconditionally invokes `ft_PlaySFX(GET_FIGHTER(gobj), 0xE0U, 0x7FU, 0x40U)`. It implements audio feedback, not a visual effect, reflection decision, timer update, or local motion transition. Sound asset identity and the semantic interpretation of the latter constants remain unverified. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftNess/ftnessattacks4.c#L21-L25.

## Interrupt, movement, and collision
`ftNs_AttackS4_IASA` does nothing when interruption is disallowed. For any nonzero `allow_interrupt`, it removes and clears a tracked bat before invoking `ftCo_Wait_IASA`, even if all input checks fail. The delegated function performs ordered early-return action checks; calling it does not first enter Wait. Subsequent non-reentrant invocations with the cleared slot do not remove that same tracked handle again. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftNess/ftnessattacks4.c#L136-L149 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_Wait.c#L44-L67.

`ftNs_AttackS4_Phys` always calls `ft_80084FA8`, then `ftColl_8007AEF8`. The former conditionally negates negative ground velocity for comparison and scales friction only when that magnitude strictly exceeds `walk_max_vel`; equality does not scale. Its delegated `ft_80085030` either writes `xE4_ground_accel_1 = x6A4_transNOffset.z * facing_dir - gr_vel` when `x594_b0` is set, or applies ordinary ground friction. Both paths apply ground movement. NaN velocity makes both comparisons false, signed zero is not negated, and infinite magnitude exceeds a finite threshold. A NaN threshold makes the greater-than test false. Inputs are not sanitized; safe downstream behavior for nonfinite values is not established. The ftColl follow-up only clears `reflect_hit.skip_update_pos`; it does not itself calculate a reflector position. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftNess/ftnessattacks4.c#L153-L158 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_084E.c#L55-L89 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftcoll.c#L3082-L3085.

`ftNs_AttackS4_Coll` delegates to `ft_80084104`, which calls Fall only if `ft_800827A0` returns false. That helper synchronizes collision last/current positions, calls `mpColl_8004B2DC`, and copies the adjusted position back. There is no local bat removal in the wrapper; the item's motion-mismatch predicate is a separate lifecycle path. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftNess/ftnessattacks4.c#L162-L165 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_081B.c#L406-L424 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_081B.c#L1043-L1050.
