# Peach SpecialLw semantic review

## Scope, interface, and naming
This translation unit implements Peach's down-special item-pull lifecycle, conventionally called Vegetable. The active Peach motion table registers the grounded and airborne animation, physics, and collision callbacks with `ftPe_SM_SpecialLw`, `ftPe_MF_SpecialLw`, and `FtMoveId_SpecialLw`; both IASA slots are NULL. This classification is supported by a consumer table, not numeric state suffixes. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftPeach/ftpeach.c#L153-L174.

The guarded header declares ten public `void(HSD_GObj*)` functions. Their object argument is a fighter, not the produced item. `pickVeg`, `spawnVeg`, `handleAirColl`, and `handleColl` have internal linkage through static declarations. Additional private helpers are `getVeg`, `setupVeg`, `throwVegIfHeld`, and `doAnim`. The local unused arrays and vectors do not prove compiled stack layout. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftPeach/ftpeachspeciallw.h#L1-L17 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftPeach/ftpeachspeciallw.c#L29-L59.

Canonical `handleAirColl` and `ftPe_SpecialLw_8011CFA0` must remain distinguishable from descriptive hypotheses `ftPe_SpecialLw_GroundToAir` and `ftPe_SpecialLw_OnDeath2`. Their observed roles support those aliases, but neither original symbol recovery nor baseline opcode-identity assertions are proved. The renderer substitutes function names only; it does not independently prove constructor, destructor, physics, transform, pickup, or animation semantics. Both owned files were independently read completely in canonical and rendered form. No parse errors were reported; ambiguous `doAnim` and shadowed `cb` were left unchanged.

## Entry and held-item priority
`throwVegIfHeld` returns false only when `item_gobj` is NULL. Every held item suppresses a new grounded pull, but only `It_Kind_Peach_Turnip` invokes `ftCo_800957F4`. Grounded entry supplies `ftCo_MS_LightThrowF4`; aerial entry supplies `ftCo_MS_LightThrowAirF4` and ignores the Boolean result. Aerial entry neither starts a fresh pull nor installs `spawnVeg`. Empty-handed grounded entry clears all throw flags, requests `ftPe_MS_SpecialLw` with `Ft_MF_None`, start 0, speed 1, blend 0, calls `ftAnim_8006EBA4`, and installs `spawnVeg` in `accessory4_cb`. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftPeach/ftpeachspeciallw.c#L126-L154.

The common throw entry actually clears command/throw state, computes animation speed, changes to the supplied motion, and installs and immediately invokes its own accessory callback. Thus this is a verified throw-entry path, not a conclusion from the F4 spelling. Exact trajectory and strength still depend on active motion-indexed data and command overrides. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_ItemThrow.c#L319-L335 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_ItemThrow.c#L463-L494.

## Selection, boundaries, and event consumption
`getVeg` defaults to `It_Kind_Peach_Turnip` and calls `pickVeg` only when `HSD_Randi(da->x14)` is zero. `pickVeg` sums integer table weights, draws against the sum, and returns the first entry whose cumulative threshold is strictly greater than the draw. Equality advances to a later interval; zero-weight entries have no interval under valid nonnegative data. This selects an ItemKind, not a turnip face or damage variant. The item constructor separately selects a turnip variant and reads its associated damage. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftPeach/ftpeachspeciallw.c#L34-L59, code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftPeach/ftpeachspeciallw.c#L84-L94, and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/kinds/itpeachturnip.c#L119-L127.

The selector does not validate count, weights, totals, or arithmetic. It initializes from entry zero even for zero count, initializes result to -1, and indexes the result without a fallback. Its loop reads `table[idx + 1].randi_max` even after selecting an entry. The source declares three entries, so selecting index two evaluates an access beyond that declared array. Whether compiled code eliminates the unused final read, or runtime data avoids the path, is unresolved; neighboring fields and offset comments are not a safety proof. Excessive count, negative weights, nonpositive totals, and signed overflow are not handled locally. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftPeach/ftpeachspeciallw.c#L34-L59 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftPeach/types.h#L23-L35.

`HSD_Randi` multiplies its signed bound by the 16-bit result of `HSD_Rand` and divides by 65536. Bounds zero and one return zero while advancing the RNG. Large positive bounds can overflow the signed multiplication; exact uniformity is not established by this scaling algorithm. No active x14, count, weights, or alternate-kind table values were available, so rarity and named exceptional outcomes remain unresolved. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/sysdolphin/baselib/random.c#L3-L21.

`spawnVeg` performs selection and construction only when `ftCheckThrowB0` succeeds. That inline clears bit zero before returning true: this is one attempt per consumed event, not a proved one-attempt-per-move guarantee. Failure is not retried absent a new event. The callback obtains a position using `FtPart_109` and `lb_8000B1CC` with NULL input position. The transform helper uses matrix translation for a parented joint and joint translation for a root; a NULL joint would dereference the NULL input position, so a valid joint is required. Part 109's anatomical identity remains unknown. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftPeach/ftpeachspeciallw.c#L110-L124, code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/inlines.h#L245-L253, and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/lb/lb_00B0.c#L105-L140.

## Construction and ownership
`setupVeg` passes fighter, position, `fp->ft_data->x8->x10`, kind, and facing direction to `it_802BD4AC`. Both `item_gobj` and `u.pe.veg_gobj` receive its result, including NULL. Success alone invokes `ftpickupitem_80094818(gobj, false)`, effect 1234 at `cur_pos`, and installation of `ftPe_Init_OnDeath2` in both death2 and damage slots. Failure does not explicitly clear those callback slots. The constructor initializes and attaches the produced item and conditionally initializes turnip variant, damage, lifetime, and saved owner. Sword exclusion and BombHei/Dosei/Turnip branches show constructor support, not active selection-table outcomes. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftPeach/ftpeachspeciallw.c#L96-L108 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/kinds/itpeachturnip.c#L104-L148.

`ftPe_SpecialLw_UnsetVeg` only clears the tracker when non-NULL. It neither destroys the item nor clears `item_gobj`. `ftPe_SpecialLw_8011CFA0` requires a non-NULL tracker equal to the currently held object and a Peach-turnip kind; only then does it call `it_802BD45C` followed by tracker clearing. Mismatch and non-turnip cases preserve the tracker. Repeated cleanup after unsetting is a no-op for a valid fighter, but pointer equality does not validate dangling references. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftPeach/ftpeachspeciallw.c#L61-L82.

The installed aggregate death/damage handler calls this cleanup function. The item wrapper forwards to `Item_8026A8EC`, and the turnip Destroyed callback clears the saved owner's tracker without checking that the destroyed item is still that tracker. Independently inspected additional evidence shows `itPeachTurnip_Logic56_EvtUnk` clears the saved owner when it equals the notified reference object, then calls `it_8026B894`; this is a concrete invalidation path, not a proof of complete notification ordering or lifetime safety. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftPeach/ftpeach.c#L453-L458, code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/kinds/itpeachturnip.c#L89-L102, and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/kinds/itpeachturnip.c#L279-L287.

## Ground/air continuity and completion
Ground collision delegates to `ft_8008403C`, which synchronously invokes `handleAirColl` on a false `ft_80082708` result. Air collision delegates to `ft_80082C74`, which synchronously invokes `handleColl` on a true `ft_80081D0C` result. These wrappers do not store the supplied callbacks. The handlers request the opposite SpecialLw state and reinstall `spawnVeg`. The transition inlines perform the corresponding ground/air conversion and pass `cur_anim_frame`, speed 1, blend 0, and NULL to `Fighter_ChangeMotionState`. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftPeach/ftpeachspeciallw.c#L156-L174, code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftPeach/ftpeachspeciallw.c#L205-L213, code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_081B.c#L549-L556, code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_081B.c#L1035-L1041, and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/inlines.h#L71-L89.

`coll_mf` is exactly SkipMatAnim | SkipColAnim | UpdateCmd | SkipItemVis | Unk19 | SkipModelPartVis | SkipModelFlags | Unk27. Complete subsystem preservation is not proved from flag names. Reinstalling `spawnVeg` is not equivalent to setting its event bit; preservation of a pending bit across the complete motion-state consumer remains unverified. Consequently, this lead review is stricter than the librarian on baseline claims that assert pending-event preservation. No-callback collision paths also must not be described as leaving the whole fighter unchanged without auditing query side effects.

`doAnim` calls the supplied completion callback first and unsets the tracker second, only when `ftAnim_IsFramesRemaining` is false. Ground animation supplies `ft_8008A2BC`; air animation supplies `ftCo_Fall_Enter`. Completion is independent of successful production. The common grounded dispatcher normally requests Wait, but has DownSpot and other conditional paths, so unconditional Wait is incorrect. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftPeach/ftpeachspeciallw.c#L176-L193 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_08A1.c#L53-L98.

The frame predicate scans eligible parts, choosing primary joints when blend frames compare equal to zero and alternate joints otherwise. Both signed zeros select primary joints; NaN and nonzero values select alternate joints. It is not a direct current-frame/end-frame comparison. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftanim.c#L515-L538.

## Physics, invariants, and remaining uncertainty
Ground physics delegates to `ft_80084F3C`: ground friction is scaled only when `ABS(gr_vel) > walk_max_vel`, then ground friction and movement helpers run. Equality does not scale. An unordered NaN comparison does not take that branch; infinite magnitude exceeds a finite threshold. Air physics delegates to `ft_80084EEC`, which calls common fall with gravity and terminal velocity, then air friction. No local stick-control or fast-fall branch exists. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftPeach/ftpeachspeciallw.c#L195-L203 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_084E.c#L33-L53.

Dependencies are fighter motion/animation, common collision and physics, Peach attributes and lifecycle, item throw/pickup, turnip construction/destruction, joint transforms, effects, and shared RNG. Valid fighter user data, attribute pointers, part arrays, joints, and live referenced items are external prerequisites. Stored callbacks are static function addresses, not escaping stack closures. Scheduler resets, constructor retention of position data, reentrant lifetime ordering, downstream exceptional-float propagation, effect identity, active item probabilities, and compiled layout remain unresolved. No compiled artifact establishes .sdata2 contents, size, placement, or consumers; all five section facts remain unresolved. The librarian's item-kind/variant, event-rearming, and conditional-completion corrections are adopted, with the stricter pending-event qualification and additional saved-owner invalidation evidence noted above.
