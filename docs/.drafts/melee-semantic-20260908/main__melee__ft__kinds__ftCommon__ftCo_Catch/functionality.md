## Common Catch / CatchDash

This translation unit implements standing- and dash-grab input arbitration, shared entry setup, item-pickup completion, animation/physics callbacks, and environmental support-loss handling.

### Input arbitration
`ftCo_Catch_CheckInput` and `ftCo_800D8A38` first offer the corresponding held-item transition, then apply Link-family and Samus tracked-tether eligibility predicates. Only afterward do held L/R and newly pressed A select `ftCo_MS_Catch` or `ftCo_MS_CatchDash`. A true return can therefore mean item handling rather than grab entry. `fn_800D8E94` is read-only: it rejects only Link or Young Link with non-null `u.lk.xC`. [Input routes](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_Catch.c#L16-L81), [Link gate](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_Catch.c#L181-L191).

`ftCo_800D8AE0`, called by AttackDash IASA, accepts held L/R while `mv.co.common.x0` is nonzero. Its final failed-input branch decrements a nonzero counter; earlier item success or eligibility failure bypasses that decrement. Expiration is not intrinsically permanent: AttackDash entry zeros its window and a separate setter writes `p_ftCommonData->x68`. `ftCo_800D8B9C` is a distinct guard-window route: newly pressed A and nonzero `mv.co.guard.x24` select CatchDash, otherwise an active window decrements. It performs neither local tether checks nor a held-shoulder test. [Window routes](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_Catch.c#L60-L95), [AttackDash lifetime](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_AttackDash.c#L61-L90).

It does not validate the motion ID or explicitly zero every velocity field. The inherited research identifies callback storage rather than immediate invocation, pull-side numeric motion selection (`0xD4` to `0xD5`, otherwise `0xD7`), a Yoshi timing branch, and character-specific attachment references. `fn_800D8BFC` transfers `target_item_gobj`, clears `x1A64` and the target reference, and initializes numeric pickup motion `0x5D` with looping enabled. The inherited helper review preserves primary/secondary possession and attachment branches and the B3 command loop. The numeric motion is not silently renamed here. ### Per-frame behavior and exits
Both animation callbacks offer Link-family handling before Samus handling and run ordinary completion only if both return false and animation frames are exhausted. False handler results do not imply no mutations: the inherited research records timers, tether-article operations and installed accessory/death callbacks, including creation-failure and obstruction branches. Completion dispatch is not an unconditional Wait assignment. Both IASA callbacks are empty, establishing only the absence of interruption work in these slots. [Animation and IASA](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_Catch.c#L118-L145).

Standing physics applies `p_ftCommonData->x64 * co_attrs.ground_friction` and then ground movement. Dash physics supplies that coefficient and facing to its helper; the inherited helper review preserves its animation-translation alternative. Both collision wrappers use the shared support-check helper and the same response callback. That response calls the Link and Samus exit helpers, in order, then the Fall dispatcher. These callbacks concern environmental support rather than opponent capture detection. Calling the exit helpers does not itself prove that all tether references and accessory callbacks have been cleared. [Physics/collision](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_Catch.c#L147-L179).
