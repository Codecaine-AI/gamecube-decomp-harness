## Thunder / Zapdos item lifecycle

The Pokémon registry identifies this implementation as Zapdos and installs its three-row state table, spawn callback, and reference-cleanup event ([registry](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/it_279C.c#L199-L216)). Both owned files were read completely in canonical and rendered form. The rendered local names fit descriptive hypotheses; they do not establish original symbols.

- **Spawn and motion state 0:** Spawn clears facing and item-command variable 0, enters the initial airborne state, and passes attribute x0 to shared Pokémon setup. State-0 animation advances shared appearance scaling. Its physics guard is side-effectful even when false: the shared helper performs an appearance update and decrements its countdown. On success, the local path resets velocity, initializes the effect countdown from attribute xC, selects state 1, installs effect-hitlag and accessory callbacks, and sets xDD1.b1. Shared appearance-phase numbers are distinct from Thunder motion-state numbers ([local setup](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/kinds/itthunder.c#L148-L185), [shared guard](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/it_279C.c#L1106-L1120)).
- **Motion state 1:** Animation extracts motion from the model grandchild and enters state 2 when the joint-animation predicate becomes false. Missing joints propagate as null; the shared motion extractor tolerates a null bone. Physics applies stored animation displacement to velocity. The accessory callback is inactive when x64 is zero, decrements positive x60 once per invocation, and otherwise clears the gate before spawning effect 0x460 on dynamic bone index 2 with a pointer to local 1.0f. Decrementing to zero does not spawn until another invocation ([callbacks](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/kinds/itthunder.c#L43-L99), [motion helper](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/it_279C.c#L1145-L1200)).
- **Cross-state effect lifetime:** State changes clear on_accessory. State-2 entry does not reinstall it, so an unfinished countdown is not guaranteed to emit an effect. Accessory dispatch is also gated by the shared item update flag. Electrical presentation is not evidence that these callbacks directly implement damage ([callback reset](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/item.c#L1229-L1236), [dispatch](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/item.c#L1420-L1425)).
- **Motion state 2:** Entry and animation restart clear x68 and item-command variable 1. Physics first applies shared animation velocity, then consumes nonzero variable 0 to seed x68 from attribute x4 and enable accumulation. The separate second guard immediately adds attribute x8 on the trigger frame; x68 finally overwrites Y velocity. Repeated triggers can reseed it. Animation restarts state 2 when joint animation is inactive and independently returns true only for position.y strictly above the top blast-zone offset. The dispatcher interprets true as destruction. Attribute signs and numerical values are not established here ([state 2](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/kinds/itthunder.c#L92-L146), [destruction dispatch](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/item.c#L1280-L1290)).
- **Collision and references:** States 0 and 1 use different shared terrain paths but both supply the empty it_802CCB10 event. Generic terrain bookkeeping still occurs. State-2 collision is completely inert. The two-object event wrapper delegates independent matching-reference clears, including source-player sentinel 6, and discards the helper's owner-match result ([local events](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/kinds/itthunder.c#L36-L41), [reference cleanup](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/it_26B1.c#L491-L525)).
