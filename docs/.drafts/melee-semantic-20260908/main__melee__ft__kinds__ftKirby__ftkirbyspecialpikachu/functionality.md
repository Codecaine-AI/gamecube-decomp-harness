## Entry and command state

It calls `Fighter_ChangeMotionState(gobj, msid, 0, 0.0f, 1.0f, 0.0f, NULL)`, clears `ftPk_SpecialN_Cmd0..3`, then calls canonical `ftAnim_8006EBA4`. ## Release, position, sound, and ownership
Both animation callbacks consume slot 0 only when it equals `true` exactly; other nonzero values are not release cues. They clear that cue even if slot 1 is already nonzero. If slot 1 is zero, they set it before switching on the hat. Pikachu/Pichu attempt one spawn and call sound 240076/230067 respectively, each with arguments 127 and 64. Unsupported hats consume and latch the cue but neither spawn nor sound. The guarantee is at most one attempt while slot 1 remains set, not guaranteed successful creation or proved action-wide immunity to other command writers.

For the selected copy and ground/air offset, x is `cur_pos.x + scale.y * (offset.x * facing_dir)`, y is `cur_pos.y + offset.y * scale.y`, and z is zero. Air uses `specialairn_*_spawn_offset`; ground uses `specialn_*_spawn_offset`. Both pass the corresponding `specialn_pk_itkind` or `specialn_pc_itkind`, owner object, stack position, and facing direction. There is no finite-value, sign, facing, scale, or item-kind validation here. Unconditional 'in front' placement is therefore unproved. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftKirby/ftkirbyspecialpikachu.c#L56-L145.

The spawner copies the input vector into `SpawnItem.prev_pos`, obtains another position from the owner, and may collision-adjust the created item. The input vector is not proof of the final item position. The spawner can return NULL; this TU ignores the result, still plays sound, and does not roll back the latch or retry. Successful spawning stores owner references; this TU retains no item handle and installs no cleanup callback. The original stack position pointer is consumed by copying rather than retained by this implementation. Full owner invalidation remains external. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/kinds/itpikachutjoltground.c#L60-L104.

## Completion and exceptional paths
Ground animation exhaustion calls `ft_8008A2BC`; its exact destination is not established in this review. Air selects the copy-specific landing-lag attribute and, after animation exhaustion, calls `ftCo_Fall_Enter` for equality with zero, otherwise `ftCo_80096900(gobj, 1, 0, true, 1.0f, landing_lag)`. Either signed zero compares equal. Negative values, infinities, and NaN are not sanitized locally; under ordinary floating comparisons NaN takes the unequal branch. An unsupported hat leaves `landing_lag` uninitialized: completion has undefined behavior, not a deterministic default. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftKirby/ftkirbyspecialpikachu.c#L96-L164.

The nonzero-lag helper first checks `x2224_b2`: it can call `ftCo_80090780` and return rather than enter FallSpecial. Otherwise it enters `ftCo_MS_FallSpecial`, stores lag and interrupt permission, derives mobility from common air-drift maximum, and handles jump usage. Thus the baseline unconditional two-outcome description is too strong. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_FallSpecial.c#L28-L59.

## IASA and physics
Both IASA definitions are empty and ignore their arguments. They introduce no local input-driven cancellation; global non-interruptibility is not established. Ground physics unconditionally forwards to `ft_80084F3C`; air physics forwards to `ft_80084DB0`: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftKirby/ftkirbyspecialpikachu.c#L167-L179.

The ground helper starts with common ground friction, multiplies it by `friction_when_above_walk_speed` only when `ABS(gr_vel) > walk_max_vel`, then applies friction and ground movement in that order. Equality does not scale; an unordered NaN comparison is false under ordinary floating semantics. Neither field naming nor multiplication proves friction increases. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_084E.c#L42-L53. The air helper checks fast fall, selects `ftCommon_FallFast` or `ftCommon_Fall` with gravity and terminal velocity, then calls `ftCommon_8007D268`: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_081B.c#L1363-L1375.

## Collision continuity and conventions
Ground collision takes its conversion branch exactly when `ft_80082708(gobj) == GA_Ground`; it calls `ftCommon_8007D5D4`, saves the animation frame, and selects the aerial Pikachu motion by default or Pichu motion for a Pichu hat. Air collision branches exactly when `ft_80081D0C(gobj) == GA_Air`; it calls `ftCommon_8007D7FC`, zeros `self_vel.y`, saves the frame, and selects the corresponding ground motion with the same default. Both pass saved frame, rate one, blend zero, NULL, and `coll_mf`. The exact mask is `Ft_MF_KeepGfx | Ft_MF_SkipMatAnim | Ft_MF_SkipColAnim | Ft_MF_UpdateCmd | Ft_MF_SkipItemVis | Ft_MF_Unk19 | Ft_MF_SkipModelPartVis | Ft_MF_SkipModelFlags | Ft_MF_Unk27`; unknown bits remain unknown. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftKirby/ftkirbyspecialpikachu.c#L181-L231.

These return enum labels are not the resulting Fighter ground/air state. The ground guard updates collision positions and returns GA_Air for a true `mpColl_8004B108` result, whereas this TU takes the opposite result. The air guard returns GA_Air when `mpColl_800471F8` succeeds and `ft_80081A00` does not veto. Both can update Fighter position even without this TU changing motion. Exact lower-level physical predicates are not proved by rendered names or the local `fall_off_ledge` name. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_081B.c#L105-L123 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_081B.c#L393-L404.

The airborne converter sets GA_Air, clears selected ground/position/animation-velocity components, sets one jump used, and locks ECB for 10. The grounded converter performs optional knockback/player bookkeeping and delegates to setup that sets GA_Ground, resets jump/walljump state, unlocks ECB, and can assert on invalid supporting ground. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftcommon.c#L515-L594.

## Callback lifetime, invariants, and reconciliation
Nonempty callbacks require a valid fighter object and, when accessed, valid Kirby attributes. No fighter allocation/free, captured callback, or private mutable persistent state appears in this TU. Command state belongs to Fighter. Motion change installs callbacks from the selected motion-table record and clears several accessory/damage callback slots. `UpdateCmd` can call `ftAction_8007349C`; passing the same frame does not prove preservation of every command variable. Callees can also alter velocity despite the entries having no direct velocity writes. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/fighter.c#L1333-L1389.
