# Independently verified Link SpecialHi TU

## Scope, identity, and conventions
All 166 implementation lines, 25 header lines, and 30 doxygen lines were independently read in canonical and rendered form, along with all 33 subjects, 80 baseline facts, and 22 outgoing links. The librarian's principal findings are confirmed: the ground-collision polarity discrepancy, anomalous aerial landing access, ineffective selected FallSpecial mobility-cap branch, and boomerang consumers are real properties of this pinned source. This review does not treat the librarian packet or rendered aliases as independent proof.

The TU defines two static helpers, ten entry/state callbacks, and three exported accessors. Link and CLink active motion tables install the paired animation, IASA, physics, and collision callbacks under FtMoveId_SpecialHi. This independently establishes shared up-special dispatch rather than inferring gameplay from numeric state IDs. Spin Attack is the baseline gameplay identification of this dispatch; hit counts, visual asset appearance, and rising motion are not established by these tables. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftLink/ftlink.c#L192-L213 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCLink/ftclink.c#L200-L221.

Canonical names govern this review. Rendered ftAnim_Advance, ftCo_FallSpecial_Enter, ftCommon_ApplyAirMovementWithParams, ftCommon_ApplyFrictionGroundAndMovement, EnvironmentCollision_AllowGroundToAir, ftCo_CliffCatch_CheckInput, ftCommon_SetAirborneNoJumps, and ftLk_GetBoomerangConfigFlag are hypotheses replacing canonical function names, not independent semantic evidence. In particular, GetFv4 returns a raw int, and doColl is a directly called static helper, not a demonstrated registered callback.

## Entry and deferred effects
ftLk_SpecialHi_Enter requests ftLk_MS_SpecialHi with Ft_MF_None, frame 0, rate 1, blend 0, and NULL; calls ftAnim_8006EBA4; then installs onAccessory4. ftLk_SpecialAirHi_Enter performs the corresponding fresh SpecialAirHi request and animation call, multiplies self_vel.x by x34, assigns x40 to self_vel.y, sets jumpsUsed to max_jumps, and installs the same callback. Neither body directly assigns ground_or_air. The ground entry has no direct velocity or jump write, but that does not prove its callees cannot change them. No local range validation proves x34 reduces speed or x40 is positive. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftLink/ftlinkspecialhi.c#L48-L69.

onAccessory4 obtains a remapped TransN joint and directly indexes L2ndNa for exact FTKIND_LINK, otherwise L3rdNa. These lookups occur before the x2219_b0 guard, even when spawning is suppressed. With the flag clear, exact GA_Ground selects effect 1211, every other value selects 1212, and the flag is set. Fighter_SetEffectHitlagCallbacks and clearing accessory4_cb are unconditional. Thus the callback is self-clearing scheduling with conditional spawning, not guaranteed successful creation. Its else branch is not a runtime CLink-only test. Neither entry explicitly clears the effect flag. No stack-local object is retained; fighter and model pointers are borrowed and passed to external subsystems. Effect destruction, cancellation before execution, callback persistence through state changes, and lifetime guarantees remain external. The effect IDs and two supplied joints do not establish rendering geometry 'between' those joints. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftLink/ftlinkspecialhi.c#L26-L69.

## Animation and input phases
Ground animation calls ft_8008A2BC only when ftAnim_IsFramesRemaining is false. For ordinary fighters the dispatcher calls ft_8008A348; x2224_b2 and ftCo_800C5240 can divert before the normal Wait request, and additional processing follows that request. It is not an unconditional direct Wait transition. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftLink/ftlinkspecialhi.c#L71-L77 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_08A1.c#L53-L108.

Air animation obtains dat_attrs before testing completion and, on false, calls ftCo_80096900(gobj,1,1,false,specialairhi_drift_stick_mul,x30). The callee identifies the final arguments as mobility and landing_lag. Its ordinary path enters FallSpecial, stores air_drift_max times mobility, xC=1, x10=1, landing_lag, and allow_interrupt=false. x2224_b2 diverts through ftCo_80090780 instead. Critically, FallSpecial physics uses the stored mobility cap only in the xC==0 branch, not the xC=1 branch selected here. Passing and storing this multiplier therefore does not prove customized post-move drift. If these state fields persist until the landing callback, x10=1 selects the special landing call regardless of the vertical-speed comparison. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftLink/ftlinkspecialhi.c#L79-L87 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_FallSpecial.c#L28-L59 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_FallSpecial.c#L84-L155.

Completion is a skeleton predicate, not a local numeric frame threshold. ftAnim_IsFramesRemaining scans eligible parts, using joint when animBlendFrames equals zero and x4_jobj2 otherwise. It returns false if none qualifies, including zero parts. Signed zero selects the zero branch; NaN does not. Exact lb_8000B074 endpoint behavior remains unresolved. Both IASA functions are empty: they do not even dereference gobj. This establishes no local input/interrupt work, not engine-wide uninterruptibility. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftanim.c#L515-L538 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftLink/ftlinkspecialhi.c#L89-L91.

## Physics and numeric boundaries
Air physics passes common gravity times specialhi_grav_mul and unchanged terminal_velocity to ftCommon_Fall, then calls ftCommon_8007D344 with threshold zero, scaled stick acceleration, and scaled target drift. Fall subtracts gravity and clamps only below negative terminal velocity; equality is unchanged. NaN is not sanitized and defeats the ordered clamp. The drift helper tests ABS(stick_x)>=threshold; finite zero passes the zero threshold and produces zero products for finite multipliers, whereas NaN stick input selects zero acceleration and target. This does not mean the complete horizontal update is a no-op: downstream friction and existing velocity still matter. No local guard constrains negative, infinite, or NaN attributes. These are source-expression observations, not compiled floating-point-mode proof. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftLink/ftlinkspecialhi.c#L93-L104 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftcommon.c#L350-L428 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftcommon.c#L462-L468.

Ground physics delegates to air physics only for exact GA_Air; every other ground_or_air value calls ft_80084F3C. This differs from the effect callback's exact-GA_Ground split. No local motion-state or timer change occurs. Stationary ground motion or upward air motion is not implied. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftLink/ftlinkspecialhi.c#L106-L115.

## Collision and source inconsistencies
ftLk_SpecialHi_Coll calls doColl exactly when !ft_80082708(gobj). The common helper synchronizes collision position, runs mpColl_8004B108, and returns fall_off_ledge ? GA_Air : GA_Ground. The pinned enum gives GA_Ground=0 and GA_Air=1. Literal composition therefore selects doColl for GA_Ground, contrary to the baseline loss-of-support narrative. Intended gameplay and executable behavior require compiled reconciliation; neither the canonical comment nor the rendered alias repairs this discrepancy. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftLink/ftlinkspecialhi.c#L117-L123, code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_081B.c#L392-L404, and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/forward.h#L442-L445.

doColl itself calls ftCommon_8007D60C and requests SpecialAirHi at cur_anim_frame, rate 1, blend 0, NULL. Its exact mask is KeepGfx|SkipHit|SkipMatAnim|SkipColAnim|UpdateCmd|SkipItemVis|Unk19|SkipModelPartVis|SkipModelFlags|Unk27. The common preprocessing conditionally calls pl_8003FC44 when x2227_b0 and jumpsUsed<=1, then sets GA_Air, clears gr_vel and vertical animation velocity, sets jumpsUsed=max_jumps, sets ecb_lock=5, and sets CollData_X130_Locked. doColl does not call fresh aerial entry, directly reapply x34/x40, or reinstall accessory4_cb. Full mask effects and callback preservation remain unresolved. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftLink/ftlinkspecialhi.c#L136-L147 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftcommon.c#L527-L539.

Air collision gives ft_CheckGroundAndLedge(gobj,0) priority. A true result calls ftCo_LandingFallSpecial_Enter(gobj,false,fp->facing_dir1); only false invokes ftCliffCommon_80081298. Here fp is declared Fighter* but initialized from dat_attrs. It is not the normal fighter pointer. No compiled offset/extent evidence establishes a recovered Link attribute or safe object-layout interpretation. The ordered calls are proved; precise landing value, complete ground/ledge eligibility, and absence of callee side effects on false results are unresolved. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftLink/ftlinkspecialhi.c#L125-L134.

## Accessors, consumers, and ownership
ProcessPartLThumbNb returns ftParts_GetBoneIndex(GET_FIGHTER(gobj),FtPart_LThumbNb) unchanged, with canonical return type Fighter_Part. GetPosWithAdjustedY copies cur_pos to a required writable Vec3 and adds specialhi_pos_y_offset to y, preserving copied x and z. It does not retain pos, reject null, validate finite values, or enforce non-aliasing; aliasing pos to cur_pos changes fighter position. GetFv4 returns raw int u.lk.x4 without mutation or normalization. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftLink/ftlinkspecialhi.c#L149-L165.

The boomerang launch consumer tests GetFv4 against zero: every nonzero int, including negative values, selects attrs->x4; zero selects attrs->x0; the selected value goes to it_80275158 before angle setup and the thrown callback. The position helper supplies a point used for planar distance and conditional steering when the stored owner is nonnull. The thumb result is passed to Item_8026AB54 after ftLk_SpecialS2_Enter under item-state, strict distance, owner, and SpecialS guards. Equality at the distance threshold does not take that branch; NaN also fails its strict less-than test. These demonstrated consumers invalidate exclusive Spin Attack interpretations based solely on helper prefixes. Full stored-owner lifetime and the property configured by it_80275158 remain unresolved. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/kinds/itlinkboomerang.c#L244-L252, code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/kinds/itlinkboomerang.c#L564-L600, and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/kinds/itlinkboomerang.c#L741-L792.

Cross-file attribute loading also scales specialhi_pos_y_offset by fighter scale.y when scale.y!=1; CLink delegates its special-attribute loading to the Link loader. Thus the accessor reads a runtime-adjusted attribute, not necessarily an immutable raw data-file value. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftLink/ftlink.c#L401-L407 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCLink/ftclink.c#L389-L392.

## Interfaces and limits
The header agrees with implementation signatures: HSD_GObj* inputs, Vec3* output for position, Fighter_Part thumb result, int raw-field result. Doxygen correctly describes the position output but incorrectly declares the thumb function void and uses the older baselib include path. It is not ABI authority. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftLink/ftlinkspecialhi.h#L1-L24 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftLink/ftlinkspecialhi.dox#L1-L29.

Dependencies are fighter extraction and attributes, motion and animation dispatch, common fall/drift and ground physics, collision/cliff/landing systems, effect synchronization, model-part lookup, and item consumers. Except for the empty IASA functions, callers must provide valid fighter objects and required backing data; no defensive validation is supplied here. Object association does not imply ownership transfer. Padding arrays are not gameplay state. No compiled artifact establishes .sdata2 size, contents, placement, relocation consumers, object offsets, or matching status. All such claims remain unresolved.
