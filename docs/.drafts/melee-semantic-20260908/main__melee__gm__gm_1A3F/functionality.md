# Central game-flow controller

This unit maintains a private `state_machine` for top-level GameMode routing and mode-local GameModeState routing. Current, previous, pending and backup routing are distinct from the pending-mode-change latch and override callback. Source asserts sizes of 0x6 for routingInfo and 0x14 for stateMachine; these assertions do not establish compiled `.bss` extent or padding. [Source](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gm_1A3F.c#L26-L47).

## State selection and lifecycle

`findState` searches numeric identifiers from the current identifier through 254 and returns the first matching table entry for the smallest available identifier in that range. It can return NULL, which its caller does not guard. `nextState` instead chooses the first table entry whose identifier exceeds the current identifier, otherwise returning the first entry, or zero for an empty table. Consequently these helpers are not generally equivalent to incrementing an array index. `firstState`'s next_id comparison does not change its returned first-entry result. [Source](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gm_1A3F.c#L81-L124).

`gm_801A4014` publishes the selected state identifier, prepares resources, invokes optional state entry, resolves the associated GameScene, initializes scene runtime, publishes the embedded GameSceneInfo pointer, invokes optional scene entry and runs the common frame loop. Normal completion invokes scene exit and then state exit before updating routing. Scene lookup is also required to succeed without a local NULL guard. The frame callback is checked downstream, not directly by this dispatcher. The proposed name `gm_ProcessGameModeState` remains a descriptive hypothesis, not a recovered symbol. [Dispatcher](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gm_1A3F.c#L126-L169); [downstream pointer storage and frame runner](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gm_1A45.c#L180-L313).

## Resource and payload lifetimes

`preloadState` applies the state's DVD preload policy and creates a SisLib arena of 0xC000 bytes for Staff Roll/Results, 0x2400 for CSS, or 0x4800 otherwise. Heap-status zero for heaps 2 and 3 forces the respective persistence flag true; the exact numeric test is stronger evidence than the rendered IsDestroyed hypothesis. Reconciliation is invoked before the remaining support calls and can return early when cache descriptions match. SisLib resets its allocation-list roots and allocates the requested arena; this pass does not establish reclamation of the preceding arena or every support subsystem's lifetime. [Helper](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gm_1A3F.c#L49-L79); [reconciliation](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/lb/lbdvd.c#L532-L567); [arena initialization](code://c302741689bd67c361cd7faadb221df3193992c3/src/sysdolphin/baselib/sislib.c#L459-L476).

The payload getters return opaque pointers unchanged, without allocating, copying or transferring ownership. The scene-runtime unit retains the GameSceneInfo pointer for current-payload access. Adventure entry/exit callbacks use those pointers as concrete configuration/results objects, and Challenger Approach separately retains a copy of the previous mode. ## Routing commands and exceptional values

`gm_SetGameModeStateId` synchronizes current and previous identifiers without clearing a staged next identifier. `gm_SetNextGameModeStateId` stores input plus one in a byte. Normal completion decodes a nonzero value by subtracting one and clears it; input 255 wraps to zero and therefore does not arm a request. The decoded identifier is subsequently subject to findState's upward search. Documentation describing the argument as the scene preceding the desired destination is misleading. Destination-only mode staging, latch-only publication and the combined deferred-mode command remain separate APIs. The combined command accepts int but stores into a byte. [Commands](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gm_1A3F.c#L202-L253); [consumer](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gm_1A3F.c#L153-L168).

## Mode execution and overrides

`runGameMode` resolves a required mode descriptor, clears the transition latch and local state identifiers, passes the descriptor's preloaded flag to the DVD subsystem, and invokes optional on_load. That DVD call only assigns a policy flag; it does not itself load assets. Each loop iteration either dispatches the ordinary mode or polls an override callback. Any result unequal to GM_COUNT takes the override branch—not merely a result below GM_COUNT. Invalid identifiers can consequently produce an unguarded NULL descriptor. An override saves routing, resets local identifiers and dispatches one state without the override mode's load/unload callbacks. Unless resetting, routing is restored afterward, but the pending-change latch and callback are not part of that snapshot. Thus an override may leave a transition latch set while its requested destination is discarded by restoration. Ordinary termination optionally unloads the original mode and returns the stored pending destination. [Runner](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gm_1A3F.c#L276-L326); [flag setter](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/lb/lbdvd.c#L824-L827).

## Reset and startup

Reset suppresses ordinary exit callbacks and state progression. Cleanup includes the literal status-11 wait, conditional OSResetSystem after DVDCheckDisk returns zero, a device-communication wait, global reinitialization, clearing the complete controller, setting skip_intro and staging GM_BOOT. The outer loop clears resetting before both previous/current mode assignments; reset-cleared history need not identify the interrupted mode. [Reset branch](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gm_1A3F.c#L170-L189).

`gm_801A4510` clears controller state, invokes registered initializers, chooses Progressive Scan when DTV status is nonzero and either launch B or persisted progressive mode equals one, otherwise chooses Boot, and initializes previous mode to GM_COUNT. It then runs modes indefinitely. The source comment attributes `Scene_Main` to UnclePunch; rendered substitution adds no independent proof. No regional restriction is established here. `gm_Is1PMode` is a pure membership test for the thirteen listed Classic, Adventure, All-Star, Training, Target Test, Home-Run, Multi-Man and Event identifiers. [Startup loop](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gm_1A3F.c#L328-L361); [classifier](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gm_1A3F.c#L255-L274).
