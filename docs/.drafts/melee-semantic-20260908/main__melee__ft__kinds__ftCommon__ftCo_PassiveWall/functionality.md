# PassiveWall translation-unit review

## Scope, conventions, and evidence reconciliation
Both owned files were read completely in canonical and rendered form: the 201-line implementation and 16-line header. The header declares seven public functions; `inlineA0` is a private inline helper. The canonical address-named functions remain `ftCo_800C1D38`, `ftCo_800C1E0C`, and `ftCo_800C1E64`. The rendered aliases `ftCo_PassiveWall_Check`, `ftCo_PassiveWall_CheckJumpInput`, and `ftCo_PassiveWall_Enter` are defensible role hypotheses, not recovered original symbols. Callback names Anim/IASA/Phys/Coll are canonical. Source signatures, rather than baseline register-locator suffixes, establish parameter types. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_PassiveWall.h#L1-L15.

The independent librarian's principal findings were verified: the predicate has two local consumers; conversion sets the upward-stick timer to 254, not zero; launch is a decrement-to-zero event rather than any zero-timer condition; horizontal movement uses the zero-target friction path; and no object artifact proves the .sdata2 claims. This review also avoids retaining entry descriptions whose precise feedback/alignment semantics have not been established, and narrows the detector's false result to no local initialization dispatch rather than a guarantee about all delegated side effects. The librarian's malformed citation for the inferred Check name is corrected in its disposition below.

## Detection and jump input
`ftCo_800C1D38(Fighter_GObj*)` obtains Fighter and CollData. It requires either wall-hug flag, then calls `ftCo_800986B0`. If eligible, it selects PassiveWallJump when `ftCo_800C1E0C` succeeds and PassiveWall otherwise. Right-wall-hug takes precedence when both flags exist. It calls entry with common x760, exponent zero, and side -1 for right-wall-hug or +1 otherwise, then returns true. False means this routine did not dispatch entry; it does not independently prove the eligibility helper had no effects. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_PassiveWall.c#L33-L51.

The eligibility helper tests `!ftCo_800C5240(gobj)`, `x680 < x250`, and `x684 >= x1C`; the last two comparisons respectively exclude and include equality. The input producer resets x680 on L/R press and preserves its previous value in x684. The DownDamage airborne collision caller tries this detector before `ftCo_800C17CC`, returning on success. These are active recovery/input consumers, not an inference from enum numbers. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_DownAttack.c#L87-L96; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/fighter.c#L2107-L2111; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_DownDamage.c#L79-L101.

`ftCo_800C1E0C(Fighter*)` only reads state and returns `x67E < x250 || input.lstick[0].y >= tap_jump_threshold`. Equality fails the timing test and passes the stick test. It is not a stick-edge test. The input producer resets x67E on XY press and otherwise increments it up to 255. Initial selection and nonzero-timer IASA latching both consume the predicate. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_PassiveWall.c#L33-L61; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_PassiveWall.c#L157-L175; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/fighter.c#L2083-L2087.

## Parameterized entry and data flow
`ftCo_800C1E64` accepts a borrowed Fighter_GObj pointer, int motion ID, int timer, int vertical-velocity exponent, and float side/direction. There is no local eligibility, null, motion-range, timer-range, or finite-value validation. It sets cmd_vars[0], stores the negated direction as facing, and calls `ftCommon_8007E2FC`. It chooses the ECB left vertex for right-wall-hug and the right vertex otherwise, with offset z zero. Calling entry without either wall flag still selects the latter branch. The local offset is passed to `ftKb_SpecialN_800F1F1C` before motion change; that helper's precise transformation and pointer-retention contract remain unresolved.

Entry changes to the supplied motion at frame zero, Ft_MF_None, rate zero for every nonzero timer and rate one for timer zero, blend zero and NULL final argument. Both stick-tilt timers become 254. The action variables receive timer and exponent; x4 becomes zero and x8 false. The effect vector is formed from current position plus offset in x/y and current z. `efAsync_Spawn` receives gobj, the Fighter x60C queue head, spawn kind 2, gfx expression `(1<<0)|(1<<2)|(1<<3)|(1<<4)|(1<<10)`, NULL joint, and the local vector pointer. Only afterward is current x assigned `-(x68C_transNPos.z * -facing_dir - pos_x_offset)`. Exact geometric interpretation is not needed to establish this ordering and arithmetic.

The tail calls `ft_80081F2C`, `ft_800881D8` with character x24 sound data and 127/64 arguments, `ftCommon_8007EBAC(fp,12,0)`, SFX 3 only when timer is zero, `ftCo_800BFFD0(fp,120,0)`, and `ftColl_8007B760(gobj,x764)`. Rendered rumble, color-animation and intangibility aliases are not independent proof of these helpers' complete semantics. Numeric IDs are not assigned specific visual or gameplay meanings here. Evidence for the complete sequence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_PassiveWall.c#L63-L113.

Ordinary wall jumping also uses entry. `ftWallJump_8008169C` checks can_walljump, wall contact, approach/input timing, stored side, horizontal stick threshold and tilt age. Its successful branch passes PassiveWallJump, x774, and the pre-increment walljumpUsed count; it then resets the input timer to 254 and increments walljumpUsed only below 255. Thus this TU is not exclusive to damage recovery. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftwalljump.c#L16-L123.

## Animation, release and boundaries
`inlineA0` enters PassiveWallJump at the current animation frame with rate one, sets y stick-tilt age to 254 and sets the action timer to zero. Anim decrements any nonzero timer. Only a decrement resulting in zero plays SFX 8 and either executes queued conversion or restores rate one, then assigns launch velocity. PassiveWall receives only a new self_vel.x, facing times passivewall_vel_x. The else branch is literally any motion other than PassiveWall, not a dedicated equality test for PassiveWallJump: it assigns wall-jump x and y attributes, and multiplies y by `powf(passive_wall_vel_y_base,vel_y_exponent)` only if walljumpUsed is nonzero.

Timer one releases on the next Anim invocation. Entry with timer zero skips the release-velocity block entirely, despite immediate animation playback and enabled physics/interrupts. Negative timers are not rejected or clamped; ordinary decrement moves them away from zero, and eventual integer overflow behavior must not be invented. Independently of timer, no remaining animation frames enters Fall. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_PassiveWall.c#L115-L155.

## Interrupt, physics and collision callbacks
With nonzero timer, IASA only checks the shared jump predicate; true latches x8 and false preserves its existing value. At zero it executes RETURN_IF checks in this exact order: `ftCo_SpecialAir_CheckInput`, `ftCo_80095328(gobj,NULL)`, `ftCo_800D7100`, `ftCo_800C3B10`, `ftCo_80099A58`, `ftCo_AttackAir_CheckItemThrowInput`, `ftCo_800D705C`, `ftCo_800CB870`, `cmd_vars[0]==0`, and `ftCo_800CEE70`. Each true condition stops processing. The command variable gates only the final predicate. Detailed action meanings of address-named external checks remain unresolved rather than being proved by their rendered aliases. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_PassiveWall.c#L157-L175.

Physics does no local movement work for nonzero timer. At zero it checks fast fall, runs FallFast if the flag is set or Fall with gravity and terminal velocity otherwise, then `ftCommon_8007D140(fp,0,0,aerial_friction)`. The latter forwards to `ftCommon_8007D174`, whose zero-target branch calls ApplyFrictionAir: this invocation is horizontal friction, not stick-directed drift. Fall subtracts gravity and clamps strictly below negative terminal velocity; FallFast assigns negative fast-fall velocity. Fast-fall activation requires no existing fast-fall flag, downward velocity, stick y <= -x88, and y-tilt timer < x8C. Activation sets the flag and tilt timer 254 and plays SFX 0x96. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_PassiveWall.c#L177-L191; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftcommon.c#L336-L348; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftcommon.c#L462-L506. The surrounding fighter update performs additional velocity work, so a skipped local Phys body does not prove total engine-level immobility: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/fighter.c#L2150-L2297.

Coll selects `ft_80083318` for nonzero timer and `ft_800831CC` for zero, both receiving gobj and function pointers `ftCo_80096CC8` and `ft_80082B1C`. The exact distinction between these helpers, landing consequences, and callback retention remains unresolved. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_PassiveWall.c#L193-L200.

## Registration, ownership, dependencies and explicit uncertainties
The active motion table assigns all four callbacks to both PassiveWall and PassiveWallJump, using distinct submotions and shared flags. Combined with recovery callers and input/launch behavior, this supports wall-tech and wall-tech-jump relations without interpreting numeric enum names alone. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftmotionstates.c#L2356-L2377.

Dependencies include Fighter/CollData/common attributes, motion/animation and Fall transitions, the shared airborne input family, common movement helpers, effect queuing, sound/presentation/collision helpers, and the Kirby offset helper. No Fighter allocation, freeing or ownership transfer is performed locally. Valid live gobj/Fighter/common-data pointers are caller obligations. For efAsync spawn kind 2, the enum and active switch prove that the vector contents are copied into an allocated queue record before the call returns; the stack vector itself is not retained by that path. Depending on scheduler state the record is linked to the queue or passed to deferred processing. Allocation failure handling is not locally checked in the inspected helper, and queue cleanup/Fighter teardown remain external obligations. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ef/types.h#L16-L22; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ef/efasync.c#L1405-L1464. Function-pointer arguments do not have stack-local function lifetime, but their associated Fighter lifetime and retention contract still require external verification.

No local finite checks protect direction, offsets, positions, stick thresholds, movement attributes or powf inputs/results. Under ordinary unordered floating-comparison semantics NaN makes the stick comparison false; a true timing comparison can still short-circuit the predicate to true. Infinity, signed zero, arbitrary directions and exceptional powf bases/exponents are passed through the shown arithmetic without normalization or recovery. Exact target-library exceptional results, floating compilation semantics, valid configuration domains and scheduler ordering are unresolved. Source does not prove .sdata2 pool membership, a double-zero tail, padding, read-only placement, concrete object layout or parameter register allocation. No compiled artifact was assigned, and all four section facts remain unresolved.
