# TPichu semantic review

## Scope and rendering
Independently reviewed all 171 canonical and rendered lines of `src/melee/gr/grtpichu.c`, all 9 lines of its header, all 40 subjects and all 27 links. Existing descriptive names generally fit the canonical callback positions; inconsistent naming styles alone do not justify replacements. The renderer reports no parse errors, but leaves `grTPichu_80222C3C` and `grTPichu_80222E6C` unchanged because of shadowed bindings. The supported `OnTouchLine` hypothesis therefore is not fully reflected in the reading view. Rendered callee names were checked against canonical implementations rather than accepted as evidence.

## Registration and initialization
The source defines a non-const four-row `StageCallbacks` array and a `StageData` descriptor identifying `Gr_Kind_TPichu` and `/GrTPc.dat`. Rows 0–2 are populated; row 3 has null callbacks and zero flags. Only row 2 contains `(1 << 30) | (1 << 31)`. The header exports the descriptor. These are source declarations, not proof of compiled section contents, object placement or bitfield layout. The common initializer explicitly requests IDs 0, 1 and 2 rather than traversing a sentinel. It clears `stage_info.unk8C.b4`, sets `.b5`, ignores each factory result, and then calls `Ground_801C39C0`, `Ground_801C3BB4`, `Ground_801C4210` and `Ground_801C42AC` in order.

## Factory, ownership and scheduled work
`grTPichu_80222C3C` forms the callback-row address without a local bounds check, then calls `Ground_GetStageGObj` with the same ID. Despite its name, that callee creates a stage-class GObj rather than looking up an existing object. It allocates Ground user data, attaches it with the `mem_free` destructor, initializes selected fields, loads archive joints or constructs fallback joints, attaches the resulting hierarchy, installs common processes and registers the object through `Ground_801C2BBC`. The allocation is not a blanket zero-initialization of Ground data.

GObj allocation failure returns NULL after reporting. Ground-data allocation failure destroys the newly created GObj and returns NULL. The wrapper reports its own diagnostic on a returned NULL and performs no callback setup. Archive assertions are additional exceptional paths. The joint helper reports allocation failure and enters a nonreturning loop; consequently not every joint failure becomes a nullable return, even though the caller contains later NULL-cleanup branches. The delegated constructor also contains an optional camera-object branch guarded by `flags_b2` and archive data; no compiled bitfield interpretation is inferred here.

On success, `Ground_SetupStageCallbacks` clears `gp->x8_callback` and `gp->xC_callback`, registers the common display callback, installs callback3 in `gp->x1C_callback`, invokes `on_init` immediately, and schedules the TU's `gobj_proc` at priority 4. It does not install or invoke callback1. Thus table membership must not be confused with demonstrated predicate dispatch.

The constructor already schedules `Ground_801C1CD0` at priority 1 and `Ground_801C1D38` at priority 4. The former animates the hierarchy, updates materials, increments `mpColl_804D64AC`, and invokes an optional `x8_callback`; the latter invokes an optional `xC_callback`. These common processes are distinct from the additional priority-4 TU process. An empty TU process therefore does not imply that the object receives no recurring animation work.

## Component callbacks and delegated state
- **Row 0:** `grTPichu_80222D24` reads `Ground.map_id` and calls `grAnime_801C8138(gobj, map_id, 0)`. The callee optionally selects the first child, applies available archive joint data, resets material state, removes existing animation, attaches joint/material/shape animation resources selected at index 0, requests frame 0, conditionally applies an archive animation flag and evaluates the hierarchy. Optional resource arrays remain optional; archive assertions remain relevant. Its third argument is spelled `bool` but is represented as int and used as an array index; the negative-index early return is not taken for this TU's fixed zero. Row 0's predicate returns false, and its TU process and callback3 are empty.
- **Rows 1 and 2:** Their initializers call `Ground_JObjInline1`. This first binds/updates collision joints using archive and matching descriptor entries through `Ground_801C2ED0`, then performs the same animation-index-0 setup. The collision-binding helper also attempts `Ground_801C3214`, whose state change specifically requires the map flag to equal 1 before changing it to 0; it does not clear arbitrary nonzero values.
- **Row 1 process:** `grTPichu_80222E48` forwards its object to `Ground_801C2FE0` and discards the Boolean result.
- **Row 2 process:** `grTPichu_80222DB8` first calls `lb_800115F4`, then performs the same Ground collision update. The lb helper walks a global effect list, sums pre-decay scales of type-1 entries, decays/clamps scales, decrements positive lifetimes, increments an angle counter and recycles entries whose lifetime reaches zero. It sets the aggregate state to 1 or 2 when the sum exceeds 0.1, otherwise to -1 or 0 depending on the prior positive state. These numeric states are preserved without inventing higher-level meanings.
- Both rows' predicates return false and callback3 hooks are empty.

`Ground_801C2FE0` processes only when `Ground_804D6950[map_id] == 0`. It increments a static s16 pass marker, processes every matching descriptor entry and writes its collision-joint marker, then processes archive entries only when their marker differs. The descriptor loop has no deduplication guard. The archive loop suppresses repeated indices marked in this invocation, but the finite-width marker must not be described as indefinitely monotonic or as proving universal duplicate suppression. The TPichu descriptor initially supplies NULL joints and count zero; archive resources remain relevant. A disabled map returns false, as does an enabled invocation that processes no entries. The TU ignores both outcomes. Visible terrain identities for IDs 1 and 2 remain unestablished.

## Lifecycle and generator lifetime
The demo-initialization hook is empty. Its source signature is `void(bool)`, and this project's `stdbool.h` defines bool as int. `StageData.on_demo_init` is `void (*)(int)` and `Ground_DemoInit` forwards an s32 unchanged. Source-level compatibility is therefore resolved; neither a two-value input restriction nor the higher-level meaning of the integer follows from these declarations. The load hook is also empty.

The start hook unconditionally requests `grZakoGenerator_801CAE04(NULL)` and discards its result. The callee allocates generator state through an asserting allocator, initializes entries and global enable/cursor state, then creates a GObj. On GObj failure it reports, frees the newly allocated state and returns NULL; this does not undo the earlier global enable/cursor writes. On success it installs a priority-0 process and stores the supplied descriptor and allocated state in `lbl_8049F030`. The descriptor remains literally NULL, not a substituted default descriptor. The process later calls `grZakoGenerator_801CA8B4(0)`, which gates on global state and skips descriptor-driven enemy creation when the descriptor is NULL. A separate special-entry path exists. This is shared Zako-service startup, not proof that the call creates the ten Target Test targets.

State survives the start callback through the shared globals and scheduled process. This creation path does not attach the allocation as GObj user data or install its destructor. The reviewed cleanup routine disables the service and removes selected items; it does not establish release of the generator allocation. Repeated-start safety and the ultimate successful-allocation release path remain unproven.

## Stage policies and retained knowledge
`callback4` is parameterless and always false; its higher-level condition is not named here. The touch-line callback ignores its integer-compatible `enum_t` input and returns no `DynamicsDesc`. The shadow callback ignores its vector, integer and joint arguments and returns true: this stage hook never vetoes a request, but that does not guarantee final rendering through all other engine gates. Existing Target Test associations and descriptive callback names are retained, with no cosmetic renaming. Baseline animation and collision-callee knowledge is preserved, with the specific deduplication and numeric-width corrections above.
