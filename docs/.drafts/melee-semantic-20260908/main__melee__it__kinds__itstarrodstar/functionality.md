## Star Rod star projectile

This unit creates and governs `It_Kind_StarRod_Star`, distinct from the physical rod. The header declares the constructor, initializer, callbacks and state table consistently with their definitions.

### Creation and configuration

The fighter swing path obtains a joint-transformed emission position and forwards facing and `cmd_vars[1]` through the held rod. The rod supplies its owner to `it_802988E4`. The constructor copies the supplied vector into `SpawnItem.prev_pos`, forces its Z component to zero, obtains `SpawnItem.pos` through the fighter-position helper, initializes velocity and accumulated damage to zero, and assigns both parent references. Projectile-specific writes, initialization and the debug hook occur only when creation returns non-null. The integer variant is stored unchanged, not normalized to a Boolean. A nonzero variant selects lifetime `x10`, horizontal speed `facing_dir * (x0 * x8)`, and damage input `x18`; zero selects `xC`, `facing_dir * (x0 * x4)`, and `x14`. ### Active state and event outcomes

The one-row state table installs animation, physics and collision callbacks. Its first member is animation ID 0, not a state-identifier field; the initializer separately requests state index 0. Animation subtracts 1.0 from the lifetime and returns true at or below zero without applying another rotation. Otherwise it adds the stored Z increment and returns false. Physics performs no local update; this does not imply absence of shared movement processing. Collision returns the shared terrain helper's Boolean result. That helper refreshes collision data, copies the collision position into the item, conditionally records the floor index, and combines additional tests before checking mask `0xF`. [Local state processing](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/kinds/itstarrodstar.c#L21-L106), [table member definitions](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/kinds/types.h#L12-L24), [terrain helper](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/itgroundcoll.c#L366-L387).

Damage dealt, clank, ordinary shield hit and absorption unconditionally return the terminal result true, without reading their arguments or performing local cleanup. Reflection and shield bounce instead invoke their respective shared response, set absolute model Z rotation to `atan2f(vel.y, vel.x)` afterward, and return false regardless of the helper result. These local bodies neither restart the timer nor recompute the persistent spin increment. Ordinary shield-hit handling must not be conflated with the separate nonterminal shield-bounce event. [Combat callbacks](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/kinds/itstarrodstar.c#L108-L146).

The reference event forwards both objects to `it_8026B894`, discarding its result. The helper clears matching owner, reflector, absorber, fighter/source, auxiliary-fighter and toucher references; clearing the fighter/source reference also sets source player to 6. This callback does not itself destroy the projectile or change its motion state. The surrounding owner-death loop may independently destroy a flagged owner item after the callback, so reference cleanup is not an unconditional guarantee of survival.
