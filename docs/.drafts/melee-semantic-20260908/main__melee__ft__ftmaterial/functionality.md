## Class and template conventions
`ftMObj` is declared as `HSD_MObjInfo`, initialized with `ftMaterial_800BF260`. That initializer registers it beneath `hsdMObj` using library `sysdolphin_base_library`, class `ft_mobj`, descriptor size `sizeof(HSD_MObjInfo)` and instance size `sizeof(HSD_MObj)`, then assigns the fighter setup function through an `HSD_MObjSetupFunc`/`Event` cast. The common initializer sets initialized flags, names, sizes, parent and counters; clears child/next links; lazily initializes the parent; checks size compatibility; copies the inheritable region; and inserts the child into the parent's list. It does not visibly replace `head.info_init`. The installed function has program lifetime; no captured stack callback state exists. The cast does not prove portable callback ABI compatibility. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftmaterial.c#L21-L56; code://c302741689bd67c361cd7faadb221df3193992c3/src/sysdolphin/baselib/class.c#L32-L58.

A private `struct ft_MObjInfo` places a TEV descriptor and constant template after an `HSD_MObjInfo`. Separate static declarations initialize a default descriptor and RGB/U8 constant. Both overlay helpers cast `&ftMObj` to the larger structure and copy template fields locally. This proves a source access convention, not actual extended allocation, valid portable out-of-object access, compiled adjacency or section placement. The declared descriptor preserves previous alpha by default. Helpers specialize local copies rather than writing their changes back into the templates. `.data` and `.sdata` layout claims remain unresolved without compiled evidence. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftmaterial.c#L21-L48; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftmaterial.c#L162-L191; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftmaterial.c#L284-L357.

## ftMaterial_800BF2B8: fighter-aware material setup
Parameters are `HSD_MObj* mobj`, `u32 rendermode` and unread `u32 unused`. The fighter is obtained from current render GObj `HSD_GObj_804D7814`, not from the material. With `x2226_b5`, the original material and incoming mode are forwarded to `lbRefract_80022998` with `smash_attrs.x2134_vibrateFrame`, and ordinary setup is skipped. Otherwise substitution is allowed by `!x2223_b2 && (!x2228_b0 || !x2224_b0)`. Within that guard, `is_metal` selects `ft_804D6580`; only otherwise can `x2227_b3` select `ft_804D6588`. The second status is not assigned an invented gameplay name.

Normal setup resets TEV state and replaces the incoming mode with the selected material's mode. It submits ambient, diffuse, specular and alpha; shininess is conditional on `RENDER_SPECULAR`. `RENDER_SHADOW` plus non-null `tobj_shadows` appends the shadow chain to the local head or material texture tail. `RENDER_TOON` additionally requires a non-null toon object and image descriptor, then prepends it by changing its `next`. Texture setup, coordinate generation and virtual `setup_tev` consume this chain.

After base TEV setup, `x61D != 255` adds translucency and disables depth updates. The lighting helper receives writable stack expression storage and adjusted mode; its returned pointer, possibly NULL, feeds the tint helper. `x2223_b2 && !x2223_b3` also disables depth updates. `x2223_b3 && x61D == 255` selects a local PE descriptor with flags 56, destination alpha 0, type 0, source/destination factors 4/5, logic operation 15, Z comparison 3, alpha comparisons 7/7, references 0/0 and alpha operation 0; otherwise `mobj->pe` is used. Final mode and PE state are submitted. A NULL lighting expression triggers `ftCo_8009F75C(fp, true)`. Normal completion detaches the appended shadow chain, but does not restore `tobj_toon->next`. Evidence for the complete sequence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftmaterial.c#L58-L154.

These are borrowed texture/material objects, not newly allocated ownership. Valid current fighter, material and virtual method pointers, acyclic/disjoint texture lists and serialized rendering are prerequisites rather than locally enforced guarantees. Shadow cleanup is not unwind-safe. Alpha, shininess and refraction values receive no local finite/range checks; downstream behavior for NaN, infinity, signed zero and out-of-range values remains unresolved.

## ftMaterial_800BF534: lighting augmentation
Parameters are fighter, material, writable expression storage and mode. `ftCo_800C0658` selects embedded `x408` if its colanim pointer is nonzero, otherwise `x488`; it allocates nothing. Both `x7C_flag2` and `x7C_light_enable` must be enabled. With those set, clear `RENDER_XLU` and clear `x2223_b2` select the TEV path. It copies the constant template into caller storage, allocates a free register, points it at `x50_light_color`, uploads it, copies the descriptor, assigns a stage and color channel 2, and selects combiner inputs zero/register/raster alpha/previous color. Registers below 4 also require a konst selector. Success returns exactly the supplied pointer. Disabled paths return NULL without initializing output; enabled but ineligible paths call `ftCo_8009F75C(fp, false)` and return NULL. That callee conditionally changes `LOBJ_ALPHA`, selects a light set, adds `fp->x588` and initializes lighting. Consequently, ordinary setup's enabled-but-ineligible path calls false mode and later true mode. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftmaterial.c#L156-L197; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftdevice.c#L16-L19; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_09F4.c#L104-L120.

The allocator result temporarily passes through `bool`, but this project's bool is typedef int, so it is not normalized to 0/1. Allocation reserves material expression registers, material descriptor color outputs and supplied expression-chain registers. Search runs from its requested start through 6 inclusive and returns -1 when exhausted; this helper asserts on exhaustion rather than taking its NULL fallback. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/MSL/stdbool.h#L4-L14; code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/lb/lb_00B0.c#L657-L704.

## ftMaterial_800BF6BC: conditional tint augmentation
Parameters are fighter, material and nullable preceding expression chain for resource reservation. The function returns no expression and emits at most one stage. `x2223_b3` skips all work. Otherwise the candidate index starts as `x61A_controller_index`; when both `x2228_b0` and `x2224_b0` are set, `is_metal` changes it to 4, or otherwise `x2227_b3` changes it to 5. These active branches support Metal rendering participation, not gameplay inference from numeric names.

Color priority is exact: `x2223_b2` selects `x610_color_rgba[1]`. Otherwise a nonzero candidate index selects a composite of `x610_color_rgba[0]` and enabled overlay color; only with overlay color disabled does it read `((GXColor*)&p_ftCommonData->x6D8)[index]`. With index zero, enabled overlay color is used directly; otherwise no stage is emitted. There is no local palette bounds check. This corrects the baseline's misleading common-color-before-composite priority. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftmaterial.c#L218-L283.

Compositing uses integer arithmetic, not an interchangeable idealized blend. `temp_alpha=((255-fighter.a)*(255-overlay.a))/255`; if it equals 255, overlay color is copied, avoiding a zero denominator. Otherwise `inv_alpha=255-temp_alpha` is 1..255. Each RGB channel is interpolated toward overlay RGB using overlay alpha, multiplied by 255, divided by inv_alpha and narrowed to a byte without saturation. After red narrowing, nonzero red sets alpha to `temp_r7/sp168.r`; zero red uses `((inv_alpha-temp_r8)*255)/255`, avoiding division by zero. Alpha is red-dependent; signed truncation and byte narrowing must not be simplified away. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftmaterial.c#L241-L274.

A selected color is uploaded as RGB in reg1. Its local node then links to the preceding expression for second-register reservation. The second search starts at 4 if reg1 is below 4, otherwise 0; both exhaustion cases assert. Reg2 receives selected alpha replicated into RGB. Non-255 `x61D` adds a scalar node at reg2 alpha; otherwise that node is omitted. The upload chain no longer includes the preceding lighting expression. Descriptor color B/C select reg1/reg2, a corresponding konst selector is set, and non-255 x61D changes alpha D and possibly konst alpha. Exactly one stage submission occurs on this branch. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftmaterial.c#L284-L360.

`HSD_TExpSetReg` consumes node values synchronously and submits GX colors by value, without retaining node pointers. Its local register array is not fully initialized, and its RGB/U8 path reads a whole GXColor then preserves existing local alpha. The tint ratio color initializes only RGB. Thus no deterministic unused-component or portable-defined-behavior claim is made. The declared template is U8; floating conversion branches are not the intended overlay path, subject to unresolved physical template recovery. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/sysdolphin/baselib/texp.c#L1037-L1166.

## ftMaterial_800BFB4C: diffuse propagation
Parameters are fighter GObj and readable GXColor pointer. From `GET_JOBJ(gobj)`, the function processes each visited JObj's DObj chain, skips null MObjs/materials and copies `*diffuse` into every reached material's diffuse field. It descends children only with clear `JOBJ_INSTANCE`, otherwise advances siblings or ascends to find an ancestor sibling. It terminates when no parent remains, not at a saved initial-root boundary. A proper model root is therefore needed for model-limited traversal. A null JObj root is harmless; this does not establish nullable-GObj safety. Cycles are not detected. Shared materials observe in-place mutation; nothing is cloned or freed. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftmaterial.c#L362-L468.

The verified Game & Watch load caller passes `x4_GAMEWATCH_COLOR[x619_costume_id]` and independently assigns `x14_GAMEWATCH_OUTLINE` to the second fighter color. This proves costume-indexed body recoloring, not loaded palette bytes or black/red/blue/green index ordering. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftGameWatch/ftgamewatch.c#L522-L553.
