## Attack11 and Greenhouse lifecycle

This unit implements Mr. Game & Watch's opening Greenhouse jab and fighter-side management of its insecticide-sprayer article across Attack11 and Attack100 start, loop, and end. The header declares all thirteen functions with signatures matching the implementation.

### Entry and setup
`ftGw_Attack11_Enter` first calls the pickup predicate. Only a false result permits Attack11 initialization: interruption and continuation fields are cleared, the motion transition receives 0.0f/1.0f/0.0f, `jab_2_input_window` is copied into `hitlag_mul`, literal 44 is stored in `unk_msid`, and Greenhouse setup is scheduled through `accessory4_cb`. Literal 44 should not be conflated with the character-specific Attack11 enum. [Entry](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftGameWatch/ftgamewatchattack11.c#L152-L171)

Setup reuses an existing article through `DecideAction`, or attempts creation using the left-hand joint position, attachment part and facing direction. Successful creation fills only empty death/damage callback slots, but assigns both hitlag callbacks. Every setup path—including failed creation—clears `accessory4_cb`. `DecideAction` itself does nothing without an article; with one, it dispatches the four named fighter phases and installs callbacks even if the motion matches none of those phases. ### Article lifetime and numeric states
The four item wrappers select numeric item states 0, 1, 2 and 3 respectively. These are item states, not fighter motion IDs. `CheckAll` returns false inside the inclusive Attack11-to-Attack100End interval and true outside it. Item animation callbacks consume this result as removal eligibility; an ownerless item is also eligible. The state-2 callback can restart state 2 before checking lifetime. `CheckAttack11` returns false only for Attack11, and true for every other motion—not merely rapid-jab motions. The owner-guarded picked-up callback maps that Boolean to item state 0 or 1. [Predicates](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftGameWatch/ftgamewatchattack11.c#L131-L147), [item consumers](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/kinds/itgamewatchgreenhouse.c#L68-L138)

Hitlag callbacks null-check the stored article before forwarding paired item operations. `SetFlag` calls ExitHitlag before clearing the pointer; it does not clear the callback slots. Explicit removal calls the item removal routine and then SetFlag. The item routine first notifies its non-null owner, then terminates the item, so the normal owner path clears the tracked reference before termination and the subsequent explicit SetFlag is harmless. This independently supports `ItemGreenhouseOnDestroy` as a descriptive naming hypothesis, not recovered historical spelling.
