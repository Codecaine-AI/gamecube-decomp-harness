## Thrown Sheik needle lifecycle

This unit implements the item-side projectile lifecycle for Needle Storm. The constructor builds a nullable item, using the caller's position as `SpawnItem.prev_pos` and deriving the actual spawn position from the parent. Successful creation initializes command variables, lifetime setup, the collision-line sentinel, surface-angle history, and the saved position. The setup dispatcher requires both item and owner pointers: mode 0 selects fired setup, mode 1 selects dropped setup, and other modes do nothing. Both initializers store the owner; destruction clears the item-side owner reference. The fighter's normal firing path constructs a needle and selects mode 0. Its stock-loss path constructs mode-1 needles while consuming the stored count. Both callers guard setup on successful creation; the fighter-side count is consumed even when creation fails. The stock-loss path also clears its held-item reference and conditionally removes its damage/death callbacks. These fighter-side lifetimes are distinct from the thrown item's owner cleanup. ## Five numeric motion states

- **State 0 — fired flight:** setup computes an owner-dependent launch angle, velocity at attribute `x8`, and a reference point three velocity steps behind the projectile. Animation snapshots position and delegates lifetime processing; physics is empty. Collision aligns the model to its trajectory. A qualifying terrain hit selects state 2 in three of five random outcomes, with velocity reset and sound, or state 4 in two outcomes, with randomized upward bounce and no sound in that branch.
- **State 1 — dropped needle:** initialization selects state 1 before resetting velocity and installing drop parameters. Horizontal speed is zero; spin, downward acceleration, and terminal speed are randomized. Animation snapshots position, spins the child joint, and delegates lifetime processing. On qualifying terrain contact it enters state 4 and plays the contact sound. Its `ABS` operation uses vertical velocity after the shared ground-hit helper has run, not necessarily the incoming free-flight velocity.
- **State 2 — stopped/surface-attached:** animation reapplies the saved orientation and delegates lifetime processing; physics is empty. Collision resets free velocity, then follows a stored active line and applies changes in its normal angle to model rotation. A missing or inactive line leaves reset velocity and does not cause a local state transition.
- **State 3 — stationary numeric mode:** animation delegates lifetime processing, physics resets velocity, and collision returns false without processing. No entry into state 3 is demonstrated by this unit's release or terrain paths; its numeric naming is retained.
- **State 4 — tumbling bounce:** animation snapshots position and adds spin but does not decrement lifetime or request termination. Physics applies the configured horizontal speed and bounded downward acceleration. A qualifying terrain hit saves the current child rotation, enters state 2, and resets velocity.

## Combat and reference events

Damage-dealt, clank, damage-received, and direct shield-hit callbacks share a one-in-three conversion to state 4: reset hitbox-related state, install the contact lifetime, zero X/Z velocity, choose upward speed, and randomize bounce coefficients. That branch returns false; the other outcomes return true without local item mutation. Reflection instead mirrors the saved trajectory reference, reverses facing, rebuilds XY velocity at the configured speed, and assigns the stored half-life duration to the active timer. This assignment can increase or decrease remaining life; it is not necessarily a shortening. ShieldBounced is separate from HitShield: it reflects planar velocity, wraps the heading, and updates visual facing without a local state or lifetime change. The unknown event wrapper forwards both objects unchanged; its exact trigger remains unproven.
