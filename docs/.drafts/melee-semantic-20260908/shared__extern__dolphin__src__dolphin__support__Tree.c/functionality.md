## Tree.c semantic review

This file implements an intrusive tree with doubly linked sibling lists and a root sibling list. Branch metadata is accessed through an object-relative offset. `DSInitTree` clears the root and computes that offset; it does not initialize an object's branch fields. [Canonical evidence](code://c302741689bd67c361cd7faadb221df3193992c3/extern/dolphin/src/dolphin/support/Tree.c#L17-L21)

- **DSInsertBranchBelow** appends the object to the cursor's child list, or to the root list when the cursor is null. It sets the object's previous sibling, next sibling, and parent, but preserves its children. It does not first detach the object from an existing list. [Evidence](code://c302741689bd67c361cd7faadb221df3193992c3/extern/dolphin/src/dolphin/support/Tree.c#L23-L52)
- **DSInsertBranchBeside** walks from the cursor to the end of its sibling list and appends there—not necessarily immediately after the supplied cursor. A null cursor selects the root list. In the exceptional null-cursor, empty-tree case, it installs the object as root and clears all four branch pointers, including children; the ordinary append path preserves children. [Evidence](code://c302741689bd67c361cd7faadb221df3193992c3/extern/dolphin/src/dolphin/support/Tree.c#L54-L79)
- **DSRemoveBranch** updates the parent’s child-list head or the tree’s root when applicable, reconnects adjacent siblings, and clears the removed object's previous, next, and parent pointers. It neither clears children nor updates their parent pointers, and performs no deallocation. [Evidence](code://c302741689bd67c361cd7faadb221df3193992c3/extern/dolphin/src/dolphin/support/Tree.c#L81-L104)
- **DSExtractBranch** saves each child's original next pointer, appends that child to the extracted object's parent-level list, then removes the object. Children therefore move to the end of that list rather than replacing the object at its original position. The extracted object's `Children` pointer is not cleared, so extraction does not leave fully reset branch metadata.
