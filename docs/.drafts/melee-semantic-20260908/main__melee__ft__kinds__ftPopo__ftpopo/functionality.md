### Loading and shared attributes

Popo's load callback sets `x2222_b5`, copies `ftIceClimberAttributes` into fighter-owned backup storage and installs it as `dat_attrs`, copies attribute `x0` into `x40`, and registers item resources 0, 1, and 2 for Ice, Blizzard, and GumStrings respectively. Registration stores article pointers rather than spawning items. The Nana helper accepts `Fighter*`, performs only the shared attribute installation, and leaves Nana's caller to copy `xC4` into `x40`. `LoadSpecialAttrs` instead copies external attributes into the already-active attribute storage. The gameplay meanings of `x40` and the load flag remain unnamed. ### Event adapters

Pickup and drop forward their object and boolean with fixed additional arguments `1, 1`; invisible and visible callbacks forward `1`. Shared pickup handling excludes heavy items, maps hold kinds 1–4 to presentation selections 1, 0, 2, and 3, and conditionally performs the visibility update. Visibility callbacks likewise exclude heavy items. Drop always requests selection -1 and conditionally performs its hide-side update. These branches belong to the shared inline implementations, not local wrapper guards. Knockback entry and exit forward `true`; the shared parameter is actually `s32`, and the shared routines dispatch selectors 1 and 0 with values 3.0f on entry and 0.0f on exit. These adapters do not calculate launch distance. [Adapters](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftPopo/ftpopo.c#L339-L357), [shared behavior](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/inlines.h#L142-L205).

### Death reset versus interruption teardown

`OnDeath` unconditionally schedules model groups 0 and 1 for selection 0 and clears `x2234`, `x222C`, `x2230_b0`, `x2238`, `x224C`, and `x2250`. The model setter records pending selections and raises a dirty flag; application is separate. This callback does not itself destroy the tracked articles or clear interruption callbacks. `ftPp_Init_8011F060` unconditionally dispatches four cleanup stages in order: retained ice, Blizzard effects, retained Belay string, and side-special coordination. The first three stages guard their respective retained pointer or active flag. Side-special cleanup always restores local part-0 X rotation and invokes the common reset; it additionally resets and unlinks the referenced partner when present. Blizzard clears `death2_cb`; Belay clears `death3_cb`. Both clear `take_dmg_cb`. Actual callback assignments support the inferred name `ftPp_Init_OnDamage`, but its use is not damage-exclusive. ### Ice-item lifetime and exceptional paths

Successful neutral-special item creation stores `x222C` and installs damage and secondary-death cleanup. Release launches the item and clears fighter tracking without destroying the released projectile. Item destruction notifies this unit only for the native Ice Climber ice kind; the other branch notifies Kirby. `ftPp_Init_8011F16C` clears the tracked pointer and both callbacks only on pointer equality. A stale nonmatching notification changes nothing, but NULL/NULL equality still clears callbacks. `ftPp_Init_8011F190` returns immediately for a null retained pointer; otherwise it requests item removal and then reads `x222C` again for the bookkeeping helper. It does not preserve the original pointer in a local variable, so a claim that both calls necessarily receive the same pointer is unresolved.
