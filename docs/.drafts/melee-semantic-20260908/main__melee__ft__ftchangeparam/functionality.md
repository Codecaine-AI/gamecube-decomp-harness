## Scalar response
Let F(b,s,c) denote ftCo_CalcYScaledKnockback. It first asserts s != 0, even when c is zero. It returns b for c == 0; b/F(1,s,-c) for c < 0; (s-1)*b*c+b when s >= 1 or c <= 1 after those branches; otherwise b*s/c. The coefficient controls response rather than acting as an exponent. For ordinary finite negative coefficients recursion is only one level. At c=1 and at positive-coefficient s=1 the linear expression is used. For fixed c>1, the below-unit expression need not meet the unit-scale result continuously. Both signed zero scales fail the assertion; negative scales, NaNs and infinities are not explicitly rejected. Ordinary unordered comparisons allow NaN scale past the nonzero test, and c=0 still returns b. There is no clamp or finite/positive-result guarantee. For example s=-1,c=-0.5 produces a zero reciprocal denominator. Exact arithmetic identities are not universal floating-point evaluation identities; the compiled floating-point environment remains unverified. ## Common-attribute mutation
ftCo_800CF6E8 takes writable ftCo_DatAttrs and a scale. Unit scale bypasses all pointer accesses. Otherwise it transforms selected current fields using Fighter_804D6524 coefficients: walk/dash/run parameters, jump startup and jump/hop velocities, gravity and aerial movement, fast fall, weight, shield-break velocity, ledge-jump velocities, throw multipliers, size, xDC and its next addressed float, landing lags, name-tag height, screw-attack and ice-jump parameters, x170 components and x17C. The three x170 components share coefficient x94. Unselected fields are untouched. The cur[1] access is a source operation, not proof of compiled object layout. Direct repeated calls can compound; the full refresh first restores common attributes. [code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftchangeparam.c#L24-L107]

## Loading, refresh ordering and lifetime
ftCo_800D0FA0 copies *ft_data->x0 into co_attrs, *x40 into x294_itPickup and *x50 into x2C4. These are value assignments, not allocation or ownership transfer. This TU's read-only use does not prove global source-record immutability. [code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftchangeparam.c#L148-L157]

ftCo_800D105C repeats those three copies. Non-unit Y scale invokes the common scaler, scales all four components of each ground-light, ground-heavy and air-light pickup offset, and scales x2C4.x/y. The x197C branch, commented bunnyhood, multiplies dash, jump, gravity, fall and ledge/wall-jump attributes. The independent metal branch multiplies vertical jump/hop, gravity, fall, weight and vertical ledge/wall-jump attributes. x2229_b1 then independently multiplies gravity and weight; its gameplay identity remains unresolved. Coefficient values are not established, so these operations do not prove increased capabilities.

Next it asserts a non-null ftKindCalcIndiviParamTable[fp->kind] and calls it synchronously with the same GObj; no local kind bounds check precedes the assertion. The active table contains Init_LoadSpecialAttrs callbacks. After dispatch, non-null x2D0 triggers the jump modifier. Finally x2222_b0 selects a branch that reloads user_data, obtains x2CC through ftDonkeyAttributes*, and scales x14/x18/x1C for non-unit Y scale. That type supports a Donkey association, not an exclusive flag identity or recovered field meanings. [code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftchangeparam.c#L164-L250] [code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftdata.c#L1160-L1178]

Only the three initial blocks are visibly restored. Whole-refresh idempotence depends on optional-data restoration by callbacks. The callback is invoked, not retained or registered here. The original Fighter pointer is used after dispatch; GObj/Fighter and dependent records must remain valid across it. No allocation, freeing, direct timer update or direct action-state transition occurs in the owned bodies, but callback effects cannot be excluded. Inherited attachment equip/removal callers support the refresh role without proving every callback's behavior.
