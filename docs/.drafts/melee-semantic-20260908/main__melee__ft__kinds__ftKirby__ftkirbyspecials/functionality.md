## Hammer side special

Ground and aerial entries clear `cmd_vars[0]`, request their corresponding SpecialS motion state, call `ftAnim_8006EBA4`, and install `fn_800F53AC` in `accessory4_cb`. Aerial entry first assigns `specials_aerial_vertical_momentum` to `self_vel.y` only when `u.kb.x64` is false, then sets that flag. This is an unchecked assignment, not an additive or necessarily upward impulse. A universal once-per-airtime invariant requires external-reset auditing. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftKirby/ftkirbyspecials.c#L98-L122.

The shared accessory callback recognizes command values 1 and 2 through independent tests. Command 1 obtains the R3rdNa joint position, calls the Hammer constructor, stores its nullable result in both `u.kb.hat.x0` and `x1984_heldItemSpec`, and consumes the command even if construction fails. Successful construction accepts a NULL death callback or `ftKb_Init_800EE74C`; any different non-NULL callback reports and asserts. It then installs death/damage callbacks and spawns effect 0x497 for GA_Air, otherwise 0x496, at HipN with the facing-direction address, marking the effect active and installing hitlag callbacks. Command 2 destroys a non-NULL retained article and clears its pointer. Other commands are unchanged. Repeated command-1 requests have no existing-item guard. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftKirby/ftkirbyspecials.c#L26-L87.

This proves synchronization, not the precise upstream Inhale phase.
