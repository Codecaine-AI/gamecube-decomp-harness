# ftCo_Pass semantic review

## Scope, interface, and naming
The complete owned source and header define and declare four boolean helpers, two void transition executors, and four void Pass callbacks. All take Fighter_GObj*; ftCo_8009A184 additionally takes FtMotionId msid, MotionFlags mf, and float anim_start. The header includes melee/ft/forward.h and uses GALE01_099F1C as its include guard. The source depends on fighter payload definitions, common movement and animation helpers, collision helpers, and the common airborne-input subsystems included at lines 7–24. There is no assigned dox file. Source signatures establish the C interface, not compiled register placement. In particular the owned parameter locator ending #r6 does not prove where float anim_start is passed. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_Pass.h#L1-L18 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_Pass.c#L1-L24.

Canonical address-named functions remain authoritative. ftCo_Pass_Enter and ftCo_Pass_EnterWithMotion are useful descriptive hypotheses for the fixed and parameterized executors, not recovered names. The proposed ftCo_Pass_CheckInput alias collides between ftCo_80099F1C and ftCo_8009A080; the renderer leaves both canonical. These functions are behaviorally different: the former only tests eligibility, while the latter requires held shoulder input and invokes entry. CheckInputFromSquat is contextual naming, not an exclusive caller contract. External rendered aliases do not establish callee semantics.

## Eligibility and requests
ftCo_80099F1C obtains Fighter* from gobj->user_data and tests, in short-circuit order, input.lstick[0].y <= -p_ftCommonData->x464, x671_timer_lstick_tilt_y < p_ftCommonData->x468, and mpColl_IsOnPlatform(&fp->coll_data). Equality passes the stick comparison and fails the timer comparison. No state or timer is changed locally. NaN in either stick-comparison operand makes the ordered comparison false; infinities are not explicitly rejected. Calling this a negative-input test assumes the intended sign of x464, which is not validated here. mpColl_IsOnPlatform tests LINE_FLAG_PLATFORM on coll->floor.index; it does not independently test ground_or_air or establish validity of that index. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_Pass.c#L26-L36 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/mp/mpcoll.c#L4502-L4505.

ftCo_80099F9C prioritizes ftCo_800C5240. A true result returns ftCo_800C60C8 directly, including false, with no ordinary fallback. Otherwise, only a clear mv.co.pass.x0 and successful eligibility test cause x0=true, x4=p_ftCommonData->x470, and a true return. Other ordinary paths return false without those writes. It does not decrement x4. The delegated checker itself gates ftCo_800C6110 on eligibility; that executor calls ftCo_8009A184 with ftCo_MS_HammerFall and then ftCo_800C4E94. The exact condition represented by ftCo_800C5240 remains unresolved rather than inferred from the rendered Hammer_IsHeld alias. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_Pass.c#L38-L51 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_0C60.c#L8-L22.

Squat IASA calls ftCo_80099F9C before its countdown helper. That helper reads mv.co.squat.x0/x4, subtracts 1.0 only when both are nonzero, and enters Pass only when the resulting x4 equals zero and the platform test succeeds. Initial zero does not trigger entry. This is not a <=0 countdown. Fractional, negative, NaN, infinite, or sufficiently large floating values do not establish a finite countdown-to-zero guarantee. Ordinary request acceptance returns before this helper on that invocation. The producer/consumer relationship suggests shared pass/squat storage, but compiled object-layout proof is absent; this review does not retain that layout as proved. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_Squat.c#L78-L115.

ftCo_8009A080 first requires input.held_buttons[0] & HSD_PAD_LR to be nonzero, then tests eligibility. Success calls ftCo_8009A228 and returns true; rejection returns false without entry. The actual Guard IASA caller supports shield-drop initiation, but the wrapper itself does not require a Guard motion state. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_Pass.c#L53-L62 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_Guard.c#L539-L548.

ftCo_8009A134 tests the current indexed floor's platform flag and conditionally copies floor.index to floor_skip. True means that update was invoked; false leaves floor_skip unchanged, not cleared. It has no input, timer, velocity, or motion-state operation. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_Pass.c#L64-L74 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/mp/mpcoll.c#L4502-L4515.

The lead independently verified more of the recovery consumers than the librarian packet. Mewtwo's collision handler increments unk4, checks ground/ledge contact, then uses a threshold-first helper: unk4 >= x54 returns true without calling ftCo_8009A134; otherwise a successful platform skip returns false and suppresses the AirToGround call. Sheik likewise increments xC, compares its float conversion with x3C, and only on comparison failure tests platform skipping before deciding whether to call ftSk_SpecialHi_801137C8. Both destination helpers perform common ground conversion; Sheik's numeric motion destination is not assigned a gameplay meaning from its number. Threshold equality takes precedence over platform skipping. A NaN float threshold makes >= false, so 'below threshold' is not an exhaustive description of the fallback branch. Skipping this grounded-conversion branch does not rule out subsequent ledge or other collision transitions. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftMewtwo/ftmewtwospecialhi.c#L285-L358, code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftSeak/ftseakspecialhi.c#L282-L368, and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftcommon.c#L546-L594. ## Transition executors
ftCo_8009A184 unconditionally performs ftCommon_8007D5D4, ftCommon_ClampAirDrift, self_vel.y=x46C, Fighter_ChangeMotionState(gobj,msid,mf,anim_start,1,0,NULL), mpUpdateFloorSkip, and timer=0xFE, in that order. ftCo_8009A228 has the same sequence but supplies ftCo_MS_Pass, Ft_MF_None, and animation frame zero. Neither validates eligibility, current grounded status, destination, flags, animation frame, or floor index. The floor copied is the floor index present after the motion-state call, not a separately saved pre-transition index. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_Pass.c#L76-L99.

Common setup sets GA_Air, zeros gr_vel, x98_atk_shield_kb.z, cur_pos.z, and x74_anim_vel.y, sets jumpsUsed=1 and ecb_lock=10, and sets CollData_X130_Locked. Drift clamping compares self_vel.x first against -air_drift_max and then against +air_drift_max. Finite nonnegative bounds establish the usual clamp interval; equality is preserved. NaN velocity is not repaired, and negative or NaN bounds invalidate the usual interval guarantee. x46C and anim_start are forwarded without sign/finiteness checks. Thus downward velocity is an intended configuration interpretation, not an unconditional mathematical invariant. The 0xFE write is exact; universal retrigger suppression additionally depends on x468 and external timer maintenance. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftcommon.c#L447-L460 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftcommon.c#L515-L525.

Verified Reflector callers gate the parameterized executor through ftCo_80099F1C, supply named aerial startup or loop continuation states and the current frame, then recreate their reflect hit. The executor need not enter ordinary Pass and does not restore every move-specific resource itself. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftFox/ftfoxspeciallw.c#L181-L200 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftFox/ftfoxspeciallw.c#L328-L344.

## Callbacks and lifetime
The actual motion-state table binds the four Pass callbacks alongside ftCo_SM_Pass and ftCo_MF_Pass. This is active association evidence, not meaning inferred from a numeric enum. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftmotionstates.c#L2819-L2828.

Anim calls ftCo_Fall_Enter only when ftAnim_IsFramesRemaining returns false. Fall entry has special fighter routes and an ordinary ftCo_MS_Fall route with Ft_MF_KeepFastFall; 'always enters ordinary Fall' is too strong. The animation query's exact exceptional-float behavior remains unresolved. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_Pass.c#L101-L106 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_Fall.c#L47-L71.

IASA invokes, in order, ftCo_SpecialAir_CheckInput; ftCo_80095328(gobj,NULL); ftCo_800D7100; ftCo_800C3B10; ftCo_80099A58; ftCo_AttackAir_CheckItemThrowInput; ftCo_800D705C; ftCo_800CB870. The lead resolved the librarian's macro uncertainty: RETURN_IF evaluates its condition once and returns from the void caller when nonzero. Later checks are therefore skipped after the first success. No direct field writes occur in the callback, but callees may mutate state even on paths not described locally. Exact accepted actions and the optional NULL argument's contract remain external. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_Pass.c#L108-L118 and code://c302741689bd67c361cd7faadb221df3193992c3/src/Runtime/platform.h#L164-L169.

Phys forwards once to ft_80084DB0, which checks fast-fall, chooses fast-fall velocity or gravity/terminal-velocity handling, then calls ftCommon_8007D268. Gravity subtracts the configured value and uses an ordered terminal comparison; exceptional values are not generally sanitized. Coll forwards once to ft_80082F28. Its exact landing/ledge responses and floor-skip clearing lifecycle remain unresolved. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftCommon/ftCo_Pass.c#L120-L128, code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_081B.c#L1363-L1375, and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftcommon.c#L462-L506.

The TU neither allocates nor frees objects nor transfers ownership. It borrows the game object and fighter payload; no local null protection exists. Executors cache Fighter* across Fighter_ChangeMotionState and use it afterward, assuming payload lifetime and identity survive. Callback references are ordinary static function references, not closures capturing stack state. Dispatch lifetime and replacement guarantees belong to external motion-state machinery. Repeated unused eight-byte zero-initialized locals are source facts, not compiled stack-layout or constant-pool proof. All .sdata2 size, contents, placement, relocation, and read-only claims remain unresolved without compiled evidence.
