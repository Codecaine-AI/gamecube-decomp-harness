## Tournament flow
The unit defines seven GameModeState entries, all using lbDvdPreload_3, followed by a -1 sentinel: 0 setup, 1 bracket, 2 alternate interface, 3 stage select, 4 VS, 5 sudden death and 6 results. The header exports only the table. States 1 and 2 have no local callbacks. Canonical evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gmtoumode.c#L31-L117 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gmtoumode.h#L1-L8.

Setup ignores its argument and invokes memory-card allocation and archive loading with variant 0. Those callees guard persistent pointers; initialization is not repeated while those pointers remain populated, and separate reset routines can clear them. Stage-select entry writes x1=0, no_lras=1, force_stage_id=-1 and unk_stage=0. Exit prioritizes start_game: it requests state 4 and saves the selected stage in TournamentData.x28. Otherwise match_type==0 calls gm_8019A828 and requests state 1; all other values clear x32 and request state 2. VS exit performs human-results bookkeeping only when a human participated; independently, it requests sudden death only if both winner predicates succeed, otherwise results. gm_MatchHasMultipleWinners excludes NO_CONTEST and uses team winners only when is_teams==1.
