# Zelda Target Test controller

Both owned files were reviewed completely in canonical and rendered form. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gr/grtzelda.c#L38-L67 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gr/grtzelda.h#L1-L8.

Most existing knowledge fits the canonical behavior and is explicitly retained in the checkpoint ledger. The previous artifact's four identical TU-level replacement writes are not carried forward: the existing distinct facts already describe the module adequately. Their retention evidence includes the actual process and terminal-hook bodies at code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gr/grtzelda.c#L122-L155. The existing row-2 process purpose is also retained without introducing an unnecessary Figure1 comparison. Corrections address unsupported compiled-layout wording, the demo-init typedef interpretation, and unsupported callback1 dispatcher provenance.

## Configuration, defaults and storage lifetime

The file-scope `static StageCallbacks grTZd_StageCallbacks[4]` has three populated rows and a fourth row containing four null function pointers and zero flags. The members are `on_init`, `callback1`, `gobj_proc`, `callback3`, and a flags union. Row 0 uses `grTZelda_80223FB8`, `grTZelda_80223FE4`, `grTZelda_80223FEC`, and `grTZelda_80223FF0`; row 1 uses `grTZelda_80224084`, `grTZelda_802240D4`, `grTZelda_802240DC`, and `grTZelda_802240FC`; row 2 uses `grTZelda_80223FF4`, `grTZelda_80224044`, `grTZelda_8022404C`, and `grTZelda_80224080`. Rows 0 and 1 have zero flags; row 2 spells its mask `(1 << 31) | (1 << 30)`. These are source initializer facts, not a compiled bitfield-layout measurement. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gr/grtzelda.c#L38-L46 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gr/types.h#L131-L149.

`grTZd_StageData` initializes `grkind` to `Gr_Kind_TZelda`, `callbacks` to that array, and `data1` to `/GrTZd.dat`. It registers `OnInit`, `OnDemoInit`, `OnLoad`, `OnStart`, `grTZelda_80223EC8` as `callback4`, `OnTouchLine`, and `OnCheckShadowRender`, then initializes `flags2` to 1. The omitted `joints` and `joint_count` members receive the C aggregate defaults NULL and zero. Thus 1 is the last explicitly supplied initializer, not the final field of the structure. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gr/grtzelda.c#L48-L60 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gr/types.h#L157-L171.

The callback array, descriptor and string literal have static storage duration. The descriptor therefore does not point into a temporary stack array. The setup helper reads a row synchronously, stores a function pointer in Ground user data and hands another function pointer to process setup; it does not retain the address of the helper's local pointer variable. Callback code and configuration must remain available while registered users exist. No compiled section membership, adjacency, size or binary address claim is made from declaration order or the header's address comment. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gr/grtzelda.c#L38-L60 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gr/inlines.h#L33-L49.

## Initialization, acquisition and failure behavior

`grTZelda_OnInit` delegates to `Ground_InitTargetStage(grTZelda_80223ED0)`. The inline clears `stage_info.unk8C.b4`, sets `b5`, requests objects 0, 1 and 2 in that order, and then calls `Ground_801C39C0`, `Ground_801C3BB4`, `Ground_801C4210`, and `Ground_801C42AC`. It discards the three factory results; there is no early exit or rollback here if one request returns NULL. The meanings of those numeric state bits and the four final operations are not renamed from this call sequence alone. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gr/grtzelda.c#L64-L67 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gr/inlines.h#L51-L62.

The factory forms `&grTZd_StageCallbacks[arg0]` before calling `Ground_GetStageGObj(arg0)`. A nonnull result enters callback setup; a null result produces an `OSReport` containing the filename, fixed diagnostic value `0xC3`, and requested ID. The result is returned unchanged. There is no local bounds check, row scan, retry or terminator test. The normal initializer supplies valid populated-row indices 0–2. Index 3 names the zero row but is not requested by this initializer; other indices are not made safe by the later null-result guard. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gr/grtzelda.c#L81-L95.

Despite its name, `Ground_GetStageGObj` performs creation. Its reviewed body allocates a GObj and Ground user data, initializes selected fields including `map_id` and callback pointers, attaches user data with `mem_free`, builds a joint hierarchy, installs shared processes, and returns the object. It has allocation-failure returns and archive-dependent branches. Its source explicitly warns that the allocated Ground block is not wholly cleared; the Zelda callbacks must not assume every field is zero. Successful acquisition is not proof that arbitrary map IDs or malformed archives are valid. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gr/ground.c#L817-L936.

`Ground_SetupStageCallbacks` clears `x8_callback` and `xC_callback`, registers the display callback with GX link 3 and priority 0, stores nonnull `callback3` into `x1C_callback`, invokes nonnull `on_init`, and schedules nonnull `gobj_proc` at priority 4. It neither copies the complete row nor consumes `callback1` or the flags word. A null `callback3` does not itself clear `x1C_callback`, although the reviewed acquisition path initializes that field. Ground destruction later invokes a nonnull `x1C_callback`, clears a matching map-object reference and performs shared teardown. The Zelda callback3 bodies add no cleanup of their own. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gr/inlines.h#L33-L49 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gr/ground.c#L2790-L2827.

Failure to consume flags in this setup inline must not be generalized to the whole Ground system. Separate consumers inspect `flags_b1` while selecting an archive fog descriptor and `flags_b0` while selecting lighting data. Those scans use archive counts rather than stopping at the zero row, so table/archive consistency is a cross-file precondition. Exact raw-word-to-bitfield packing is not independently established by compiled evidence here. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gr/ground.c#L1084-L1137 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gr/ground.c#L2639-L2677.

## Object callbacks and delegated operations

Row 0's initializer reads `gobj->user_data` as Ground and calls `grAnime_801C8138(gobj, gp->map_id, 0)`. Rows 1 and 2 instead call `Ground_JObjInline1`, which obtains Ground and JObj pointers, calls `Ground_801C2ED0(jobj, map_id)`, then invokes the same animation loader with set 0. These wrappers have no local null checks. They require a suitable live Ground GObj, initialized `map_id`, a usable joint hierarchy and valid shared stage/archive state. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gr/grtzelda.c#L97-L115, code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gr/grtzelda.c#L130-L133 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gr/inlines.h#L24-L30.

The reviewed animation loader supports the existing detailed animation facts: it asserts archive availability, selects a child JObj when present, optionally reapplies joint data, resets material state, removes old animations, selects nullable joint/material/shape channels, requests frame 0, conditionally applies the archive's per-set flag and evaluates the hierarchy. Set 0 does not take its negative-index early return. Archive and index validity remain preconditions; nullable channel arrays are handled explicitly, but arbitrary invalid indices are not. The wrapper owns neither the archive nor its descriptor arrays and performs no release; these shared resources must remain valid for their downstream users. The precise deeper attachment/copy lifetimes are not inferred beyond the reviewed loader. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gr/granime.c#L988-L1048.

All three callback1 bodies ignore their pointer and return false. Their table positions support the existing slot-based names, but the reviewed setup path does not establish runtime dispatch of these predicates. Row 0's process is empty. Row 1's process calls only `Ground_801C2FE0(gobj)`. Row 2's process first calls `lb_800115F4()` and then `Ground_801C2FE0(gobj)`. Both ignore the Ground operation's Boolean result. All three callback3 bodies are empty. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gr/grtzelda.c#L103-L145.

`Ground_801C2FE0` reads `map_id` and updates collision joints only when `Ground_804D6950[map_id] == 0`. It increments a shared tag, processes matching descriptor joints, then available archive joints, suppressing already-tagged archive entries. Otherwise it returns false. Zelda's source-default descriptor joint count is zero, but archive joint data may still supply work. This explains the rendered collision-update name without pretending every call necessarily updates anything. Valid map indices, joint indices and live shared arrays are required; the shared tag's long-run rollover semantics are not normalized into a new state model. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gr/ground.c#L1674-L1732.

### Row-2 list maintenance and exceptional numeric inputs

The parameterless `lb_800115F4` operates on shared active/free lists, not on the incoming Zelda GObj. For active nodes with `x0 == 1`, it accumulates their scale before decay. It then subtracts `x24` from each scale, clamps only results strictly below zero, decrements positive counts, increments an angle counter, and removes nodes whose resulting count is zero. Removal relinks the active list and pushes the node onto the free list rather than freeing it. A node expiring on this invocation can therefore still contribute to the total. Negative counts are not decremented and do not satisfy the zero-removal test. Traversal assumes a well-formed live list; no cycle protection or counter-overflow handling appears in this body. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/lb/lb_00F9.c#L939-L977.

The accumulated `float total_scale` is tested with the source expression `total_scale > 0.1`. Above that threshold, the global numeric state becomes 2 if its previous value was positive, otherwise 1. On the other branch it becomes -1 if previously positive, otherwise 0. The code does not establish gameplay names for those four values. An empty list uses the low-total branch. Under ordinary IEEE comparison behavior, NaN fails both the negative-scale clamp comparison and the total's greater-than comparison; positive infinity exceeds the threshold unless accumulation has produced NaN, while negative infinity does not. Subtracting like-signed infinities can create NaN; a negative decay can increase scale. Signed zero is not strictly negative and is not forced through the clamp. There is no finite-value validation, and the double literal `0.1` is preserved rather than silently rewritten as `0.1f`. These are bounded source-level consequences, not compiled floating-point-mode measurements. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/lb/lb_00F9.c#L939-L992.

## Lifecycle and terminal hooks

Demo initialization and loading are empty. The demo-init declaration spells its input `bool`, while the definition and `StageData.on_demo_init` use `int`. This is not an established signature incompatibility: the canonical library defines `typedef int bool`. The input is ignored, and neither the body nor that typedef restricts it to a proved two-value mode domain. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gr/grtzelda.c#L17-L20, code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gr/grtzelda.c#L62-L74, code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gr/types.h#L157-L171 and code://c302741689bd67c361cd7faadb221df3193992c3/src/MSL/stdbool.h#L4-L14.

`OnStart` calls `grZakoGenerator_801CAE04(NULL)` and discards its return. The reviewed callee obtains data, creates a GObj, frees that data and returns NULL on GObj-creation failure, or installs a process and retains the descriptor pointer and data in globals on success. Thus startup is a request, not a success guarantee. No temporary descriptor lifetime is introduced by NULL. The creation body alone does not prove that the subsystem spawns breakable targets. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gr/grtzelda.c#L71-L74 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gr/grzakogenerator.c#L313-L329.

The parameterless `callback4` returns false. `OnTouchLine` ignores its `enum_t` input and returns NULL, selecting no `DynamicsDesc` through this hook. `OnCheckShadowRender` ignores its vector, integer and JObj inputs and returns true: it never vetoes a query through this callback, but does not guarantee a final rendered shadow. Null pointers and unusual vector contents are not dereferenced by these terminal bodies. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gr/grtzelda.c#L76-L79, code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gr/grtzelda.c#L147-L155 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gr/forward.h#L194-L196.
