- `__CARDSeek` acquires channel control, checks cached position and directory-recorded bounds, resets backward seeks to the start block, and follows FAT successors. Success stores the exact requested offset and returns the acquired control block without releasing it. A request may end exactly at EOF, but may not begin there. Channel/file-number validity and directory-entry occupancy include assertion-only checks; the routine should not be described as comprehensive runtime validation.
- `CARDReadAsync` checks segment alignment, positions the file, checks access, and tries public access only after `CARD_RESULT_NOPERM`. It invalidates the full destination range, installs the supplied or default callback, and launches a transfer capped at the current sector boundary. Buffer validity/alignment and positive length are assertion requirements. Immediate startup errors return directly; the low-level startup-error branch releases control but does not clear or invoke `apiCallback` here.
- `ReadCallback` handles incoming errors before cancellation. Otherwise it subtracts the distance to the next sector boundary, not necessarily the actual final transfer length. Exhaustion completes before advancing the logical offset or FAT block, so a successful partial-sector completion can leave a negative remaining length. Only continuing reads advance offset and follow the FAT. Terminal callback handling captures and clears `apiCallback`, releases control, then invokes the captured callback.

- `CARDCancel` protects its test and update with interrupt disabling/restoration. An unattached card returns `NOCARD`; a busy operation whose stored file pointer matches is marked with length `-1` and returns `CANCELED`; otherwise it returns `READY`. This marks cancellation for later callback observation rather than aborting the physical transfer immediately.
