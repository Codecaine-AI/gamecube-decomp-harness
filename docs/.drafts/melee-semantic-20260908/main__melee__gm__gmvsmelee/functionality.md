# Versus/Melee scene support

`gmvsmelee.c` provides shared scene-boundary helpers rather than the state table itself. It declares CSS, SSS, match-start, ordinary-match exit, Sudden Death exit, and Results-entry objects, plus a local per-player byte counter array. Persistent `VsModeData` resides in `gmMainLib_804D3EE0->modes.vs_melee`; its accessor returns a mutable alias, not a copy. The header exposes the helpers, shared objects, and two callback signatures. Its `gmVsMelee_ApproachData` declaration is extern and does not establish ownership here. [Source declarations](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gmvsmelee.c#L22-L39), [header](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gmvsmelee.h#L11-L50).

## Initialization and counters

Mode initialization calls `gm_InitVsMode` and then `gmMainLib_8015CDEC`. Independently read callees establish default rules/player records, three -1 sentinels, and writes of 5 to available default-slot bytes. Mode load clears the entire KO array; unload is empty. The mutable counter accessor and CSS pointer attachment share the same storage. Results exit updates human slots through `lbTime_8000AF74`, whose byte-input arithmetic saturates at 0 and 255; non-human slots are unchanged by this updater. The mutable accessor means this updater is not a proof that no other caller can modify those slots. [Lifecycle](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gmvsmelee.c#L101-L127), [counter update](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gmvsmelee.c#L41-L61), [saturation](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/lb/lbtime.c#L41-L52).

## Selection and battle entry

CSS entry copies settings, attaches counters, records the supplied match type, and sets up preload caching. CSS exit requests GM_MENU and returns early only for `CSSPendingSceneChange_2`; every other value commits settings and performs the character-dependent audio sequence. SSS entry copies settings and calls common setup. Its exit commits settings and submits stage-dependent audio arguments only when `start_game` is true; otherwise it selects the supplied cancellation state. [Selection helpers](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gmvsmelee.c#L119-L169).

Ordinary battle entry first prepares persistent rules, copies them, conditionally sets `is_stock` for Stock, and sets `is_vs`. It does not explicitly clear `is_stock` for other kinds. A nullable whole-match callback runs before player copying; a nullable per-player callback runs after all player records are copied. Subcolors, rumble, and announcer setup follow. Sudden Death entry preserves the callback/copy ordering but does not locally repeat ordinary rule preparation, flag writes, or announcer loading; it finishes against the retained ordinary MatchEnd. Tiny and Giant callers independently demonstrate player callbacks for both entry paths; Super Sudden Death supplies its modifier for ordinary entry only. [Battle entry](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gmvsmelee.c#L171-L262).

## Completed-match lifetime

Ordinary exit submits per-human character/outcome accounting and gates aggregate Results/play-time setup on human participation. It then chooses between caller-supplied destinations using `gm_MatchHasMultipleWinners`. Standard Versus supplies Results and Sudden Death. Importantly, the predicate returns false for OUTCOME_NO_CONTEST regardless of stored winner counts; otherwise it uses team winners when `is_teams == 1`, or player winners. Thus the routing is not simply an unconditional raw winner-count comparison. [Exit](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gmvsmelee.c#L207-L233), [predicate](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gm_1601.c#L3241-L3262).

The standard state table reuses the start buffer but gives Sudden Death a separate exit record, preserving ordinary results across the tiebreak. `gm_80166CCC` reconciles these records, including propagation of NO_CONTEST/RETRY and conditional ranking updates; it can mutate both arguments and is not a wholesale replacement. Results entry initializes its payload before copying the ordinary record. Approach and debug gameplay also reuse ordinary start/exit objects. [State bindings](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gmvsmode.c#L28-L158), [reconciliation](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gm_1601.c#L3159-L3239), [Results copy](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gmvsmelee.c#L264-L275).

## Results exit and exceptional paths

Cancellation suppresses only the initial two result-processing calls; the KO update still runs. Human-specific processing begins before the `state[1].id` termination check. Eligible continuation selects the first human minimum ranking key: individual loser value, plus team loser value shifted by eight when teams equal 1. Strict comparison preserves the first equal candidate. An unchanged U16_MAX sentinel asserts, including any case where no human key is strictly below that sentinel; the source contains a subsequent return 0.

Three character-kind checks run in priority order and select Approach on success. Additional progression calls still run after a successful character check. Only if no earlier diversion occurred can the later predicate choose Prize. Preserve the literal 328 comparison and literal 120 challenger argument without assigning unsupported meanings. Prize binds to GS_PRIZE_INTERFACE, not necessarily a battle. Both diverted and ordinary paths call archive setup; diversion returns before the fallback next-state write. The standard wrapper subsequently performs its own non-canceled update using the Results-entry snapshot, so returning from this helper does not end all caller-side processing.
