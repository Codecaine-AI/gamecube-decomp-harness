# Shared smash-charge helpers

The owned TU comprises `src/melee/ft/ft_0DF0.c` and its six-prototype header. Its canonical exported names remain `ftCo_800DEE84`, `ftCo_800DEEA8`, `ftCo_800DEEB8`, `ftCo_800DEEE8`, `ftCo_800DEF38`, and `ftCo_800DF0D0`. The rendered SmashCharge names are useful descriptive hypotheses, not recovered symbols. The header's `ftCo_800DEEE8` substitution is reported as `shadowed_binding`; its canonical declaration agrees with the definition.

## Complete behavior

* `ftCo_800DEE84(Fighter_GObj*, u32, float, float)` obtains the Fighter and unconditionally installs PreCharge, zero elapsed frames, the supplied hold duration, damage multiplier, and presentation identifier. It does not initialize the saved animation rate, shake index/count, or sound flag; those are initialized on ordinary charge entry. It neither validates configuration nor cleans up a previous active session. The animation-command caller reads two smash-charge records, multiplies charge_rate by the literal `0.003906f` (approximately, not exactly, 1/256), converts color_anim to s32, and passes these values to this initializer. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_0DF0.c#L16-L26 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftaction.c#L1252-L1266.
* `ftCo_800DEEA8(Fighter_GObj*)` only assigns None. It preserves counters and configuration and does not restore animation or cancel feedback. Fighter reset and common motion-transition cleanup call it. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_0DF0.c#L28-L31, code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/fighter.c#L472-L512, and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/fighter.c#L1053-L1107.
* `ftCo_800DEEB8(Fighter*, f32)` returns its scalar unchanged outside Release. In Release it evaluates `arg1 * ((damageMul - 1.0F) * (frames / holdFrame) + 1.0F)`. It has no writes or calls. This is damage scaling rather than application of damage to a victim: `ftColl_8007ABD0` calls it after optional size scaling, converts its result into `unk_count`, and passes the floating result through another helper into hit-capsule damage. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_0DF0.c#L33-L42 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftcoll.c#L2987-L3003.
* `ftCo_800DEEE8(Fighter*, Vec2*)` enables a shake-table lookup in Charging or literal state 4. It copies the indexed entry into caller-owned storage and returns that same pointer; otherwise it returns NULL without writing the buffer. It does not return a pointer into the global table. The caller adds the successful result into x18B8/x18BC after separately optional damage and grab-mash shifts. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_0DF0.c#L44-L54 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftcommon.c#L1709-L1731.
* `ftCo_800DEF38(Fighter_GObj*)` increments elapsed frames and the shake index in Charging and literal state 4, resetting the index to zero when the incremented value is at least x212D. Only Charging tests the hold limit: equality releases without assigning the timer again; overshoot first clamps the timer. Release is written before restoring the saved animation rate, calling the color reset helper, and requesting removal of logical rumble ID 0x24. The sound test follows this release sequence, so a release update may also request SFX 0x7B with arguments 0x7F and 0x40. Both supported states set the sound latch after a request when the latch was clear and frames are at least the common x7C8 threshold. Other states do nothing. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_0DF0.c#L56-L97.
* `ftCo_800DF0D0(Fighter_GObj*)` tests the current held A bit in `input.held_buttons[0]`, not a press/release-edge field. PreCharge with A enters Charging, saves the animation rate, clears shake index and sound latch, copies the table count, and requests animation rate zero. Color start is skipped exactly when x2128 equals 0x7B; the rumble request is still made. PreCharge without A only writes None. Charging without A writes Release and performs the same restore/reset/remove sequence as timed release. Charging with A and every other state are no-ops. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ft_0DF0.c#L99-L134.

## Dependencies, scheduling, ownership, and optional effects

State lives in the caller-owned Fighter's embedded SmashAttr; this TU allocates, frees, or retains no input pointer and installs no callback. The shared Fighter update directly invokes the timer helper before the optional anim_cb inside a `!x2219_b5` branch. The input pipeline directly invokes the input helper before optional input_cb, also under `!x2219_b5`; therefore 'once per frame' means eligible processing, not an unconditional real-time tick. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/fighter.c#L1660-L1696 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/fighter.c#L2127-L2138.

The TU depends on Fighter extraction/types, animation-rate control, color animation, common controller feedback, fighter SFX, common-data sound timing, and Fighter_SmashChargeShakeTable. Feedback calls are requests, not guarantees of visible or physical feedback. `ftCommon_8007EBAC` has player/flag gates; removal has a player gate and translates the logical ID by +2 before HSD_PadRumbleRemoveId. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftcommon.c#L1158-L1186.

The exit color helper rejects identifiers >=0x7B by reporting/asserting and returning. For ordinary identifiers it resets a selected controller, can invoke a character callback, and may restart other active color effects. Thus the entry sentinel 0x7B is not a safe symmetric no-color exit path in the inspected source. No proof establishes that this sentinel reaches release in valid game data, or that all delegated callbacks preserve object/state lifetime. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/ftcolanim.c#L197-L227.

Literal state 4 has concrete cross-file support: the Ness yo-yo code writes it, initializes duration to 60 and the shake sequence, and starts feedback. A separate yo-yo damage routine consumes held frames. This establishes a yo-yo consumer, not a universal recovered name for state 4 or the complete lifetime of that branch. The inspected setup does not clear x2130_sfxBool. Evidence: code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftNess/ftnessattackhi4.c#L349-L365 and code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/ft/kinds/ftNess/ftnessattackhi4.c#L371-L418.

## Boundaries and uncertainties

The initializer accepts zero, negative, non-finite, or otherwise unusual floats without guards. Release scaling has no zero-denominator check, finite-value check, or fraction clamp. The usual neutral/full-charge endpoints require appropriate finite nonzero duration and finite operands; they are not universal guarantees. Under ordinary IEEE comparisons, a NaN duration defeats the timed-release comparisons, and NaN elapsed frames also defeat sound comparisons. Infinity, zero division, and overflow may produce non-finite results; exact target floating exception/rounding behavior is not proved by source alone. A finite nonpositive duration is reached on the first normal increment from zero and can clamp the timer to zero or a negative duration. A sound threshold above the clamped limit need never fire; a nonpositive threshold can fire on the first eligible update. The latch records a request, not confirmed playback.

The shake accessor checks neither table pointers nor index bounds. Entry copies the count without validation; a zero count still permits lookup at index zero and is not proof of an empty-table-safe path. Source search identifies x212C as u8, but compiled layout and table allocation/count validity are not proved. Caller-supplied Fighter/GObj pointers must be valid; an enabled accessor additionally needs writable Vec2 storage and a valid table entry.

The header supplies declarations, not parameter-register evidence. The owned #r3/#r4/#r5/#r6 entities have no baseline facts; this pass does not infer their physical ABI mapping from argument order, especially for floating arguments. PAD_STACK and field-offset spellings likewise do not prove compiled object layout. The .sdata2 section's size, ordering, contents, and read-only mapping remain unresolved without compiled artifacts. Source literals alone cannot establish those claims. Exact historical function names, universal charge duration/multiplier constants, full state-4 lifecycle, and callback lifetime guarantees remain unresolved.
