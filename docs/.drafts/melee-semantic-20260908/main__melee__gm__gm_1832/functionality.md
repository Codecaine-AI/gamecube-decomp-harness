# gm_1832: IntroEasy matchup presentation

This translation unit implements the retained single-player pre-match IntroEasy presentation: scene construction, two demo-fighter lineups, animated encounter information, localized text, and a captured-image tile effect. The surviving `IrAls` and `ScItrAllstar_scene_data` asset names do not independently establish ownership of a dedicated All-Star lifecycle. No Training implementation remains in the owned source.

## Entry, construction, and completion

`gm_Scene_IntroEasy_OnEnter` checks payload bytes at offsets 0x10 and 0x11. If either equals 0x1A, it sets completion and returns before initialization. Otherwise it resets completion and three counters, copies the 0x20-byte source payload into retained configuration, constructs the scene, initializes the audio-handle sentinel, and invokes the final GM helpers. `fn_80186634` loads the layout table from `GmIntEz.dat`, initializes presentation subsystems, and loads encounter and roadmap scene resources. Archive selection uses the incoming `game_type` **before** non-3 model kinds reset it to zero. Kinds 0–2 construct both fighter groups; kind 3 uses authored mode text; kind 4 constructs captured costume imagery plus the first lineup. Unknown kinds have no switch-default object construction. The main model process animates the hierarchy and increments its counter only while below 140. The following invocation sets completion; the counter does not exceed 140. Outside kind 3 it freezes encounter-number texture frames, populates names at counters 5 and 6, and dispatches audio milestones at 10, 70, and 100. Kind-4 team text changes word ordering with saved language. The separate roadmap process wraps one counter at 49 and saturates another at 49, selecting encounter-specific 50-frame animation banks. The scene OnFrame callback consumes completion, stops streamed audio, and requests exit—it does not produce normal completion. ## Fighter arrangement

Two transform helpers start from separate retained scene anchors and combine character, participant-count, and model-kind-dependent layout records. Six wrappers bind presentation indices 0–2. The first helper adds slot-specific depth offsets and changes auxiliary scene nodes after counters 80 and 90; the second uses additional character-specific offsets and scale for kind 2. Both copy final translation and scale to an optional second logical entity belonging to the same player. [Evidence](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gm_1832.c#L144-L340)

Preloading resets player/demo state and replaces Giga Bowser with Bowser only in the second configured character array. The first lineup packs accepted entries into consecutive slots and returns its count. The second starts at a supplied slot and installs callbacks at table index `i + 3`; importantly, it tests `xF1[i]` for sentinel 0x21 while constructing the character from `xF4[i]`. This asymmetry is preserved, not repaired by interpretation. [Evidence](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gm_1832.c#L861-L937)

## Capture-to-tile pipeline

Kind-4 setup caps costume count at three, allocates paired RGB5A3 and Z24X8 image descriptors, builds ten alternating-direction image selections, and registers a capture camera, a one-shot constructor, and a persistent SObj updater. Capture players occupy slots beginning at 1. Character value 0xE receives an additional pose offset; the source identifier `gm_1832_SamusOffset` is not sufficient evidence to identify that numeric character value. A zero count is not guarded before division/modulo in setup, and the player initializer's return is uninitialized on its zero-iteration path. [Initialization](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gm_1832.c#L539-L567) · [Setup](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/gm/gm_1832.c#L791-L859)

The capture callback isolates each temporary fighter, renders it, and copies color/depth images. It sets readiness even when camera activation fails. Once ready, the constructor removes the temporary camera, creates ten image-backed SObjs on a separate display GObj, and removes itself. Tile loop index `i` determines grid position; the selected image index is independent. Delays are 1, 9, …, 73; flags are ORed with 9 rather than assigned exactly 9. The updater decrements nonzero delays and clears bit 0 on transition to zero. Image storage remains needed after camera destruction; local code does not demonstrate its eventual release. ## Rendering and resource boundaries

The depth-mask helper ignores its integer argument and emits one fixed-depth quad using top/bottom/left/right float bounds. It disables color writes, enables depth testing/writing, restores color writes, and invalidates HSD state rather than restoring every GX setting. The splash display callback applies the right-side mask before the SObj camera pass. Secondary-camera callbacks use successful activation guards, the camera compositor, and masks 0x1001/7; the kind-4 version additionally selects slot-0 visibility.
