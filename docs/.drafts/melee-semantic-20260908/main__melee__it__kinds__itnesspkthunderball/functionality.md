## PK Thunder head

This unit implements Ness's PK Thunder head with one motion-state callback tuple, sixteen position and heading samples, and six linked trail slots. The nullable constructor initializes article lifetime, histories, counters and the originating fighter reference, then explicitly calls post-creation setup. Setup selects state 0 and initializes velocity to `(0, speed, 0)` independently of the configured heading. The constructor preserves a separate stage-ID `0x54` branch. [Source](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/kinds/itnesspkthunderball.c#L110-L230)

The animation callback attempts trail creation at counter values 0, 2, 4, 6, 8 and 10. The trail count advances even if creation returns NULL. Control-loss checks apply only when `xF00 == 0` and `xF04 != NULL`: leaving Ness's hold state returns true; an owner mismatch explicitly invokes shared cleanup before returning true. Other paths delegate the final result to the common lifecycle helper. [Source](code://c302741689bd67c361cd7faadb221df3193992c3/src/melee/it/kinds/itnesspkthunderball.c#L232-L281)

Physics steers only with matching ownership, active hold and sufficiently large input on either stick component. Angular error is split at 45 degrees; cross-product sign selects turn direction, and a zero cross product produces no turn. Steering wraps heading within ±2π, whereas interaction normalization uses the inclusive interval from zero to 2π. Both histories advance even without steering. The position accessor reads `positions[idx * 2]` without bounds checking; the speed accessor returns stored speed, not a measured velocity magnitude. Trail physics consumes these interfaces for placement, orientation and scale. Stage collision selects ceiling versus floor and left-wall versus right-wall masks from velocity signs; zero velocity takes the floor/right-wall branches. ## Interaction and lifetime distinctions

Actual item-logic registration identifies `it_802AC098` as reflected, `it_802AC074` as clanked, `it_802AC338` as absorbed, `it_802AC35C` as shield-bounced, and `it_802AC3F8` as hit-shield. This is stronger evidence than analogous function order or rendered hypotheses. Reflection clears the originating-fighter association, assigns `xF00 = 1`, reverses heading by π, detaches existing trails, resets trail scheduling and collapses old history before continuing with false. It does not itself clear the current `Item.owner`. Shield bounce only mirrors velocity, planarizes it and synchronizes the leading angle, also returning false. Shared teardown conditionally notifies Ness only for a matching nonnull originating fighter with numeric mode zero. It clears that private fighter reference and the ball's trail slots, but does not itself clear `Item.owner`. Trail cleanup immediately resets hit state and clears each trail's ball/owner links; the trail subsequently returns true from animation when its ball link is null. Ownership detachment is different: it preserves private ball/trail links and only clears ownership and flag state. Generic reference invalidation is also distinct and does not clear PK-Thunder-private references. Its dispatcher may separately destroy an item using the saved pre-callback owner and the post-callback flag.
